### 1.2 模块落点建议

保留现有五个应用／包入口。下表是职责落点，按首个真实调用建立目录，不预先生成空模块。

| 位置 | 建议容纳的实现 | 不进入此处的事实 |

| `apps/zotero-host` | 原包装载、共享兼容环境、对象／SQL／DOM 适配、专属缓存 | 第二份可自由编辑的当前文献库 |

## 2. 内核发现、认证与生命周期

### 2.1 启动与单实例

已决议：同一应用数据配置一个内核；Electron 和 CLI 可以启动或连接；CLI 查询／停止不创建实例；浏览器开发启动命令负责发现或启动并安全传递连接信息。工作台关闭不停止内核，明确停机后现有客户端不自动重新拉起。

**建议启动流程：**

1. 将数据配置解析为一致的配置身份；开发与测试使用独立目录。
2. 读取当前实例的发现信息，连接并验证实例身份、协议和数据配置；端口可达本身不能证明是目标内核。
3. 发现信息缺失或已确认原实例退出时，进入同一配置的启动协调区；胜出者启动独立 Node，其余入口等待就绪并连接。
4. 内核就绪后发布连接坐标与实例标识，失败则报告实际启动错误。发布与读取不能让客户端拿到半份记录。
5. 锁遗留、进程身份不明或存活但不可达时保留诊断，不凭 PID 或超时强删记录、杀进程、覆盖实例。

发现文件建议放应用数据目录的运行区，并限制当前用户访问。实例标识用于区分一次内核启动，不能作为长期任务身份。跨平台锁机制、路径别名处理及遗留锁恢复在首个生命周期变更中实验选择，不在本稿指定未验证的库。

### 2.2 本地连接与权限

已决议本机监听及客户端身份校验。建议采用当前用户可访问的引导凭据，握手后才允许业务请求；凭据不写入 URL、浏览历史、构建产物或日志。

Electron 通过窄 preload 桥取得连接资料；浏览器由本机开发引导路径提供。浏览器 WebSocket 的认证需选择其支持的机制，例如连接后认证首帧；不能假设浏览器可自由设置 Authorization 请求头。未认证连接设置有限握手时限，并拒绝领域请求。

本机地址仍需校验来源与权限：开发引导端点限定允许的 Origin／Host，拒绝任意网页读取 token 或借本机服务执行操作；工作台、CLI 和内部宿主的来源策略按入口分别确定。认证确认客户端身份后，领域操作仍受任务授权与材料范围约束。局域网可见的开发页面不自动获得远程内核支持。

harness 消费的 MCP 能力经插件系统接入：插件声明能力、配置及启动或连接方式，宿主管理生命周期和有效授权，不提供脱离插件管理的任意 MCP 服务入口。进程内能力和原生图使用自身接口。Scholoom 对外 MCP 服务另作候选设计，复用领域操作与授权，开放范围、认证和部署待定。统一执行基础不接入 ACP 外部 Agent，依据 [#07](../.scratch/scholoom-foundations/issues/07-agent-runtime-boundaries.md#answer)。app-server 的 stdio 适配仍按具体需求确定，不与插件所用传输混为一层。

### 2.3 断线、停机和重启

| 情况 | 客户端行为 | 内核／任务行为 |
| --- | --- | --- |
| 短暂断线 | 有界退避重连，恢复快照与订阅 | 已接收任务继续；请求结果未知不盲目重发 |
| 认证或协议不兼容 | 停止反复尝试，显示原因和处理入口 | 不授予业务访问 |
| 内核存活但不可达 | 显示异常，可重试；不替换实例 | 不假定任务失败或已停止 |
| 确认内核退出 | 等用户重试后重新启动 | 先核查未正常结束的执行，再决定继续方式 |
| 明确停止 | 收到停机信息后停止自动重连 | 拒绝新工作，保存必要状态，协调执行与宿主退出 |
| 停机超时或连接丢失 | 保留“无法确认”及查询入口 | 不能把网络断开当成停止成功 |

CLI 提供停止操作，工作台菜单提供明确的停止内核动作，并说明它影响连接到该内核的所有客户端。

内核重启后不直接凭执行记录中的旧 PID 终止进程，也不先假定旧程序已经消失。进程识别与跨平台控制见 §8。来源：[#09](../.scratch/scholoom-foundations/issues/09-electron-architecture.md)、[#23](../.scratch/scholoom-foundations/issues/23-kernel-entry-and-lifecycle.md)。

## 3. 共同协议与有界状态投影

### 3.1 接口面建议

沿当前 JSON Schema 推导类型的做法扩充响应、错误、通知和业务 DTO，并在输入边界实际校验。候选操作名与输入输出集中在[模块接口设计](module-interfaces.md)，在对应 OpenSpec 中定案；本节仅保留接口面的总体职责。

| 接口面 | 输入应表达 | 返回应表达 |
| --- | --- | --- |
| 连接与状态 | 协议、客户端身份、配置范围 | 实例身份、可用能力、实际状态 |
| 领域查询 | 所属库／项目、对象引用、筛选、分页或大小限制 | 有界结果、版本依据、下一页和缺失情况 |
| 领域命令 | 操作对象、参数、授权上下文；有风险时带操作身份或版本依据 | 已确认结果、实际对象引用，或局部冲突／未知状态 |
| 材料读取 | 材料版本、位置、范围或长度限制 | 可消费内容、来源引用、定位与覆盖情况 |
| 任务／能力执行 | 任务目标或身份、所选能力、输入材料、授权与交付要求 | 稳定任务／调用引用；进度另行查询订阅 |
| 人类介入 | 待决定事项身份、提案依据、答复 | 本次是否实际应用、当前决定与失效原因 |
| 订阅 | 对象或项目范围、关注主题 | 初始状态及增量流，失效时明确要求重新读取 |

长任务的 RPC 返回“已受理及引用”，不一直占用请求等待完整研究。WebSocket 请求 ID 只用于关联一次往返。二进制附件与大文件优先返回受权限控制的读取引用／有界内容，避免塞入所有状态事件；具体数据通道由材料接入确定。

错误建议区分校验、权限、未找到、局部冲突、资源暂不可用、不兼容、执行失败及效果未知，并携带相关对象与可恢复性。用户提示由界面组织，不把完整文案作为协议契约。

### 3.2 快照与订阅之间不丢变化

订阅队列是内核 app-server 的 `StateFeed` 向客户端推送变化的临时缓冲，不是科研任务调度队列或 Agent 持久收件箱。领域模块与 harness 保存事实并提供变化，`StateFeed` 管理范围与发送，`packages/client` 处理接收和重同步，工作台维护展示及独立草稿。

**建议接线：** 每个订阅建立有界队列，先挂接变化收集，再读取一致快照与基准序号；返回快照后只发送基准之后的变化。建立过程在内核内协调，调用者不承担“先读还是先订阅”的竞态。

队列溢出或序号连续性失效时，仅该订阅失效。客户端停止沿用旧增量，保留旧画面并显示刷新状态，重新取得该范围快照后更新，不清空整个工作台。Composer 草稿和未保存编辑独立于服务端投影，不被快照替换。重连读取当前事实与未处理事项后重建订阅；每次内核启动的序号作用域由实例标识区分。

允许省略中间展示过程，已保存结果与待处理正式决定必须可从持久记录查询，不靠无限通知队列保证可靠性，也不要求全量历史事件回放。可合并同一执行的绝对进度等明确可替代更新；追加消息片段不能只保留最后一条。订阅粒度、容量及刷新成本在真实负载中确定，观察队列占用和重复重同步情况。

大列表分页或按视口读取，材料选区仅读取目标范围，图谱投影限制节点／边及展开范围。

### 3.3 多客户端修改与请求结果未知

领域服务在自身事务内校验待决定事项是否仍待处理、答复者权限及依据是否适用，然后应用一次。另一客户端的过期答复取得当前结果，而非再次推动流程。依据改变时只重新核对相关决定，不因任何无关文件变化使全部批准失效。

对迁入批次、外部提交等高风险或不可轻易重复的操作，保存与实际效果关联的操作身份和结果，重连后查询。普通读取可以重试；普通编辑先读取当前目标再调整；网络超时不触发所有写命令的自动重放。无需为每次普通操作建立通用持久命令日志。

## 4. 数据布局、模型与恢复边界

### 4.1 建议物理布局

下面的目录名仅示意。正式路径、保留策略和迁移版本在存储变更中确定。

```text
<应用数据>/
  library.sqlite             库领域事实
  library-files/             托管附件、笔记和可复用分析文件
  runtime/                   实例发现、当前运行信息
  execution/                 库级执行恢复信息
  cache/                     可重建解析和搜索缓存
  host/                      兼容宿主专属配置与缓存
  projects.*                 项目位置登记，可重新发现

<研究项目>/
  .scholoom/
    project.sqlite           项目领域事实
    execution/               项目执行恢复信息
    history/                 有界编辑历史与草稿恢复
    cache/                   可重建项目缓存
  <用户已有目录>/             稿件、代码、数据、图件和科研工作工件
```

项目根与文件路径可以变化，内部身份不能依赖绝对路径。项目内文件优先用相对定位；外部链接材料明确标为外部依赖，缺失时支持重新定位。项目数据库应足以恢复项目事实，缺库或环境时准确列出受影响能力。

有界本地历史和草稿恢复是产品能力，Git 保持为可选工程工具，不作为打开或恢复研究项目的前提。

凭据存系统凭据库或使用明确环境注入，项目仅存连接引用；配置文件不能成为密钥备份。checkpoint 数据与领域表分开管理；无论最终是否共享 SQLite 文件，Schema 所有权及迁移职责都不能混淆。

### 4.2 最小数据模型建议

以下是需要共同表达的信息组，并非一组必须逐一建表的实体。精确字段先在对应领域 Schema 中确定，再建立物理表和协议映射。

| 信息组 | 必须保留的关系与约束 |
| --- | --- |
| 库／项目范围与对象引用 | 对象稳定身份和所属范围分开；引用库对象不复制其当前权威 |
| Source／MaterialVersion | 来源身份、实际材料版本、位置与可达性；题录更新不等于材料内容换版 |
| Evidence／Claim | 证据指向材料版本与位置；解释、适用条件、核验状态及项目采用关系分开 |
| ResearchTask／Plan | 持续目标、范围、计划、产物、决定、问题和下一步；可跨执行和会话 |
| CapabilityInvocation／ExecutionRecord／Session | 明确科研使用、一次执行尝试、交互记录分别标识；关联负责的任务与实际成果 |
| Manuscript | 源文件或文件组、格式与工程入口、投稿目标、轮次、主张与审稿关系 |
| Issue／Change／Decision | 问题与解决标准、拟修改及实际应用、正式授权选择各有状态 |
| 分析与综合产物 | 目的、方法、输入版本、实际依赖、发现范围、可读成果及当前更新过程 |
| 迁入与外部身份映射 | 来源库身份与原对象键、目标身份、处理结果；citekey 不充当内部主键 |

材料版本以定位与成果可解释性为目的建立。关键证据、重要结果和提交稿按需留存实际内容；普通读写不强制完整冻结输入或给所有文件持续计算哈希。保留关键材料时才需要相应内容指纹或版本标识，并明确它解决的识别问题。

### 4.3 SQLite 与文件各自承担的保证

SQLite 事务覆盖所属数据库内的结构化变更。内核是业务写入入口，renderer、Worker 和插件通过共同领域接口修改受管理事实；候选对外 MCP 入口同样遵守该边界。

better-sqlite3 的同步访问作为初步实现假设：读取有界、查询分页、批处理拆段、事务保持短，不在事务中等待模型、网络或外部程序；大解析和图计算移出主调度线程。同步访问是否留在主线程不是固定设计原则。开发中使用真实规模和并行工作验证调度、交互及取消响应，交付前在目标环境复验；根据证据调整查询、索引、批处理、线程安排或访问方式。WAL、busy 策略及连接布局同样经真实负载确认，不预设查询 100ms／事务 50ms 为统一门槛。

库引用与项目关系不依赖跨库原子提交；先取得有效对象引用，再在项目事务中建立关系。跨库对象不可用时返回缺失，不复制一份当前对象掩盖问题。需要同时改变多个权威的特定业务在其变更中设计恢复步骤。

普通产物保存先得到文件工具或领域工具的实际结果，再记录可读取引用。文件成功而关系尚未保存就崩溃时，恢复核查相关目标并补建必要关联；数据库记录指向缺失文件时标记不可用。保留可识别输出与有限恢复线索，不将所有普通保存升级为分布式事务。

产物关联允许部分成功，保留已确认关联，逐项报告未关联或结果未知项；重试补缺，不重复登记相同关联。关联失败不删除实际文件，文件可读不能代替数据库提交成功，部分关联不代表任务完成。具体事务与分批安排由实现确定，接口见 `ResearchWork.recordArtifacts`。

Schema 升级和高影响迁移另设受控路径：检查前置条件、制作可恢复副本、在副本核对结果，成功后使用新数据；失败保持可回到原状态。对打开中的 SQLite 使用支持的备份接口，不能直接复制一个正在写入的数据库主文件就宣称一致备份。

## 5. 开放文件、局部修改与材料定位

### 5.1 修改接口建议

共同文件接口采用“基于读取内容提出修改—核对文件内容—保存”的通用策略。内部按文件串行完成短暂的核对与保存，阅读和生成可以并行；不依赖格式专属的语义冲突判断或通用自动合并。

1. 有界读取包含上下文的目标内容，取得对应文件内容的读取依据；依据的表示与保留方式在实现中确定，不要求给所有文件持续计算哈希。
2. 在该文件的内部保存协调区重读并核对整份文件内容。与读取依据一致且修改目标明确时，应用局部修改；内容已变化时返回依据失效，由 Agent 重读并重新提出修改，即使变化发生在目标之外也不自动合并。
3. 目标不明确或文件持续变化时，暂停相关修改并保留候选内容；其他工作继续，不反复争抢保存。
4. 用适合平台的安全保存方式发布已核对内容，保留必要差异和有界恢复信息。原子替换只降低半写风险，不提供与任意外部程序的互斥。
5. 返回实际保存位置及应用结果。多文件操作逐项报告成功、冲突和未执行项，保留已成功部分，不自动回滚整组文件；写成功不自动更新主张或判定交付完成。

文件监听只提示变化。未保存编辑器草稿与磁盘内容分开表达，外部改动到来时保留草稿；Agent 默认读已保存事实，用户显式附加草稿时须标明其来源。外部编辑器和获授权 shell 程序直接写入不受内部串行约束，核对与保存之间仍有竞态；安全保存、变化检测与有限历史只降低损失，不能保证捕获所有外部改动。具体能力按目标平台验证。

撤销针对实际应用范围构造反向修改，同样核对当前内容与读取依据；内容变化时重读，无法安全应用时保留现状，不能整份覆盖后续编辑。存在任务关联时记回原任务，不自动重启任务，也不统一 Git 或外部编辑器的撤销链。

失败沿共同错误分类返回：内容变化要求重读，目标不明确保留候选并澄清，目标不存在不自动重建，权限不足先处理权限，暂不可用按原因决定重试，保存效果未知先核查实际内容。错误含相关引用和必要处理信息，不设置统一自动重试；具体代码见相应接口规格。

### 5.2 共同位置契约

位置建议包含材料版本、格式类型和格式适用的定位信息：PDF 页及文本／坐标，EPUB CFI，网页 selector 与文本上下文，源码文件及行列／结构定位。它们是格式适配的联合类型，不强求一种万能 locator。

位置仅描述当次读取或对应材料版本，不承诺材料变化后的精确命中或候选重定位。按 [#44](../.scratch/scholoom-foundations/issues/44-defer-continuous-precise-source-location.md)，现阶段不设计持续精确原文定位及依赖功能。保存当时摘录、来源与分析，普通访问打开文献或文件，有可靠页码时跳转页面；需要重新核查时读取当前材料。图件只有图像时，区域标注只代表几何范围，不自动赋予曲线或数据点语义。

附件替换须保留已有批注或关键证据所依赖的材料与必要版本，旧记录保留在原材料版本上，不自动迁移到新文件位置。读取与批注模型区分原文摘录、批注作者及 Agent 解释，避免把解释呈现成原文。

旧记录显示原摘录、来源和版本依据；原材料可读时打开原版本并按可靠位置跳转。查看新版时明确记录基于旧版，不沿用旧页码；原版本缺失时保留摘录与分析并说明材料不可用。用户显式要求核查新版时形成新记录，保留旧记录，不增加跨版本位置重绑流程。

材料解析在内核可独立运行，阅读器只负责显示与交互适配。引入阅读 SDK 时把其内部标识映射到共同引用，批注内容和证据关系由领域模块保存。来源：[存储决议 #13](../.scratch/scholoom-foundations/issues/13-storage-and-change-model.md)、[工件交互 #38](../.scratch/scholoom-foundations/issues/38-workbench-artifact-interaction.md)。

## 6. 科研内容与 harness 接线

通用会话、工具执行与科研工作流共用内置 LangGraph 运行基础，模型供应商配置不等于执行后端配置。插件中的完整流程通过原生能力／图接入；MCP 工具只承诺自身已定义的调用行为。插件须提供实际支持的状态查询、取消、恢复与副作用语义，调用超时不表示操作停止，checkpoint 不保证远端工具可恢复，效果未知时先核查再重试。具体插件声明与宿主接口在相应 OpenSpec 变更中确定。

### 6.1 声明与运行入口

Agent 会话统一建模，研究任务通过工具作为业务对象交互，不以会话类型或显式任务绑定组织运行，行为以 [#43](../.scratch/scholoom-foundations/issues/43-free-agent-conversation-and-research-tasks.md)为准。本节任务／调用上下文和工作包描述覆盖任务相关工作；通用运行入口、对象操作及能力调用契约仍须据此细化，不能用自动创建任务填补接口。追加指令须区分受理与实际处理，默认在下一可处理边界调整后续工作；消息消费与唤醒沿 §6.4 初设，具体恢复接线在实现中验证。

能力声明包括身份与版本、用途、输入 Schema、所用方法与执行绑定、资源需要、产物与检查要求。Agent、程序和图使用共同职责形状 `execute(request, context) -> submission`；这是项目接口意图，不是已验证的 SDK 函数签名。

建议把上下文收敛为：任务／调用引用、获授权领域与文件工具、材料访问、取消信号、进度事件和交付通道。它不携带可绕过授权的数据库连接或任意供应商密钥。资源授权取当前有效配置，能力声明不自行扩权。

执行入口完成输入校验、创建必要调用／执行记录、调用实现和收集产物；submission 引用实际保存成果、检查发现、障碍和未完成部分。输出 Schema 合法仅表示结构正确，仍需检查实际文件／对象可读、必要产物具备及正式要求满足。

方法、角色与工作流按六类科研工作组织：发现收录、理解综合、问题方案、实施解释、写作审阅、修订交付。首批工作流包含稿件审阅改进、外部评审修订回复、稿件交付准备；内部步骤可复用，但不再建设第二套调度器或逐层注册业务调用。

Agent 可将有效做法提炼为候选 Skill、能力或工作流，保留原用途、条件、来源与验证结果，按内容管理授权启用或共享；一次任务成功不自动形成全局默认方法。

### 6.2 状态与恢复

状态建议按不同职责分别建模，避免一个总 `status` 同时代表执行与科研结论：

| 状态面 | 需要区分 | 不能据此推导 |
| --- | --- | --- |
| 执行尝试 | 排队、运行、等待、暂停、中断、取消中、已停止、失败、效果未知 | 任务已完成或结论成立 |
| 产物 | 已保存、部分可用、来源受影响、正在更新、更新失败 | 最新版本总是覆盖旧观点 |
| 正式介入 | 待答复、已决定、拒绝、条件不再适用 | 网络收到答复即完成应用 |
| 任务交付 | 尚未满足、部分满足、满足约定 | 每个内部程序都成功才允许任何成果可用 |

具体状态枚举和允许迁移在实现规格中合并精简；运行时图与领域记录各管自己的事实。

恢复先读取已保存指令、当前材料、实际产物、正式决定与必要执行记录，有关联任务时读取其目标和约束。checkpoint 可用且兼容时核对当前事实与有效授权后恢复原执行；缺失、损坏或不兼容时保留旧执行记录，从持久材料开启新的执行尝试，接续原工作，不要求还原原图节点或完整会话上下文。普通会话也可如此接续，不为恢复自动创建任务。

已受理但未处理的指令和协作消息保留可查询的处理状态，可能发生的写入、发送或迁入保留必要核查线索。效果未知时先核查，不能确认则暂停相关步骤，独立工作可继续；用户暂停或取消的工作不自动重启。临时上下文可以丢失，必要时重新分析，不默认复制全量工具历史到领域表。明确要求复现的任务额外保存其输入和环境，不把该成本强加给所有任务。

Agent 在提出方案、完成分析、改变条件或明确下一步时保存相应工件；内核核对实际保存结果及产物关联。保存内容包含有承接价值的推导、比较、理由和未决问题，后续步骤读取这些工件，不能只在任务结束时生成总结。

### 6.3 多模型与 advisor

命名模型配置由应用管理，项目与任务按需覆盖，角色未指定则继承；记录实际供应商、模型与参数。切换由用户明确触发，在当前请求结束或中止后的边界生效，并核对接收方、材料发送授权和剩余额度；目标未变时继续原能力调用，不静默路由或切换供应商。

工作包委派包含目标、初始材料、可用资源、授权和交付要求，按实际业务关系附带任务／调用引用。独立审阅首轮不接收其他审阅结论或主 Agent 的拟结论，但可读取已有证据、研究条件和作者明确约束。审阅者保存原报告与候选修改，默认不直接改稿；主 Agent 整合分歧和修订安排。工作包的初始材料不自动授权执行者读取或外发任意其他材料。

advisor 使用当前有效写作上下文及后续增量；Agent 生成文本后触发后台评审，建议携带目标、理由和改写，无建议时保持静默。写作 Agent 在可消费边界处理，并保存建议、处理理由和实际修改的关系。本轮结束有限等待已触发评审；建议导致的继续不再次触发同一轮监督。关闭或主动停止后不新增监督或自动继续，未注入建议可供查看；超时不伪装已完成。等待参数和具体 SDK hook 待实施验证。

### 6.4 多 Agent 通信与有界唤醒初设

2026-10-14，用户采纳 [#46](../.scratch/scholoom-foundations/issues/46-multi-agent-interaction.md)作为初设，具体问题在实现中探索打磨。内部 subagent、已有会话协作和 advisor 共用 harness 的授权、消息、执行与产物设施；委派关系负责子执行管理，平级通信不授予对方会话控制权。

跨会话采用持久收件箱、执行边界消费和有界唤醒，分别表达消息已受理、已消费与请求结果。运行中收件在下一可处理边界纳入；空闲且允许自动协作时合并消息并启动受现有资源上限约束的执行；用户明确暂停或停止后只保留来信，关闭／归档目标返回可诊断结果。具体恢复、去重与唤醒调度按 #46 验证，不将 UI 的瞬时状态订阅作为可靠收件通道。

上下文按工作包、独立初审或 advisor 的职责提供；当次协作可共享获授权上下文，研究依据与成果仍保存到工作区。优先评估现有 Deep Agents／LangGraph 能力，普通与异步 subagent 的实际持久化、取消和多轮交互接线需核对目标版本。

A2A 作为对外互操作候选，在明确外部调用者后映射共同能力；对外操作与持续研究任务分开，不以协议状态代替科研交付。对外 MCP 与 A2A 按需要选择，第三方 harness 执行边界沿 #07。

## 7. 文献检索、分析与更新

### 7.1 摄取与三层知识

首批检索适配 OpenAlex、Crossref、Semantic Scholar、arXiv、PubMed／Europe PMC，网页搜索供应商另选；首批不单独接 Unpaywall。全文按实际开放获取地址、OpenAlex 可用内容、arXiv／PMC 和其他仓储路径获取，记录成功与失败。各来源适配返回候选与出处，共同文献模块负责归一化、去重与入库，不让各检索入口直接建立不同身份规则。

重复合并保留附件、笔记、批注及项目引用；预印本与正式版显式关联；删除默认进回收站。已有 citekey 稳定保留，题录更正不自动改键。元数据补全可以填空，已有字段冲突按来源和实际内容核对，保留可检查的变更。

三层分别保存题录、分析产物和原文入口。Digest 包含方法及来源，区分作者主张、分析者解释与限制；通用分析和面向问题的分析可以共存。缺全文时保留题录和可用分析，并说明覆盖范围。

### 7.2 检索与读取契约

建议统一查询接受范围、对象／内容层筛选、查询文本和返回上限，融合词法与语义结果；同一来源归组，保留各命中的材料版本、层级、位置、片段及覆盖信息。原文读取按定位和限额返回实际内容，同时保留原文件访问。

索引保存派生表示与来源引用，不保存唯一研究判断。切分、融合权重、嵌入模型、索引产品和精确工具 Schema 尚未定；以典型论文、跨语言查询、缺全文、长文及来源定位质量实验选择。索引未就绪或故障时明确报告实际检索覆盖，原材料读取仍可用。

### 7.3 维护调度建议

将入库、原文补齐、分析修正等领域变化归入已决议采用的 LangGraph 原生维护流水线。保存实际依赖与发现范围：依赖表示已用材料，发现范围用于判断新增文献是否可能相关。二者不能只用文件时间戳代替。

题录展示性更正只更新展示与检索；正文、补充材料或实际使用的分析变化才检查相关依赖成果。未被分析使用的批注变化不默认重做全部分析。

合并同一对象尚未开始的重复更新，优先当前研究材料；记录本次输入依据，完成时核对期间是否有相关新变化，再决定成果可用范围和后续更新。旧成果与当前尝试分开保存，失败不覆盖最近成功结果；已知撤稿、错误来源等问题持续可见。

库知识维护可以后台执行，但受同一模型、材料发送授权及资源限制约束。对无人工作的项目只记录影响线索；不自动启动项目 Agent，不改写正式决定。任务恢复时取得提示，用户启动复核后才开展相关项目工作。

## 8. 模型、受管执行与安全边界

### 8.1 模型与数据发送

读取权限和外部发送权限分开表达。已有范围持续有效，新增供应商接收方或扩大材料范围才重新确认；worker、advisor、上下文压缩与辅助模型调用适用同一规则。

应用凭据服务优先系统凭据库，支持显式环境变量注入；系统凭据库不可用时提示，由用户选择保存方式。项目保存连接引用，执行记录记录供应商和用量，密钥与完整敏感材料不进入普通日志。首阶段运行已启用的可信程序和插件；应用工具的授权检查不等同于对任意恶意本地代码的强隔离。

模型连接具有超时、并发和限流策略；任务可设置调用次数、累计用量、总时长，不能突破应用限制。持续科研任务默认无统一硬性总时限。供应商未返回用量时记为未知，不按零处理。

可安全重试的临时模型失败默认最多额外重试两次，退避并尊重供应商等待提示；SDK 与应用共享该上限，避免叠加。参数、凭据和授权错误直接报告。效果未知的写入不因模型重试自动重放。

### 8.2 受管执行接口建议

运行请求需要明确工具或程序、参数数组、工作目录、输入资源、允许的环境配置、输出位置、时限及取消方式；返回稳定执行引用、实际状态、退出信息、日志引用和产物。敏感环境由运行时提供，不回传原始进程环境。

项目配置决定解释器、依赖和编译方式。随产品提供独立 Node、uv、Quarto／Pandoc；允许显式使用用户 Python／Conda 或 TeX。环境安装、缺包与联网准备需要已有授权；没有授权时报告缺项，不偷偷改项目锁文件。内置工具与用户工程的环境分开识别。

短命令有限时限，长计算使用受管后台执行；调用方等待超时只结束等待，不自动把计算记失败。CPU 重任务进入 Worker，用户 JS／TS、自定义图和外部工具进入受管进程。并发上限同时考虑模型连接、CPU、内存和宿主共享资源，具体初值经测量确定。

取消先停止新调度，再发协作退出请求，必要时终止拥有的执行单元和子进程。只有确认停止后标记取消完成；无法确认则保留未知及诊断。程序 PID、启动身份和实际归属需要一起核查；Windows 进程树与 Unix 进程组方案分别测试，避免终止复用 PID 的其他程序。

模型调用的本地取消不证明供应商已停止生成或计费，远端状态与用量按实际可获得信息记录。

执行记录跟随所负责的库／项目，运行时以有限日志和状态引用供查询。普通计算按实际完整程度复用输出；渲染采用最近成功产物策略。环境可执行、退出码成功、文件存在、科学结果可信分别验收。

来源：[#22](../.scratch/scholoom-foundations/issues/22-model-data-and-execution-policy.md)、[#40](../.scratch/scholoom-foundations/issues/40-research-execution-environment.md)。

## 9. 工作台、编辑器与预览

### 9.1 共享工作台接线

沿当前 `main.tsx → WorkbenchSession → Workbench` 入口演进，assistant-ui 管理 Composer 草稿并投影来源消息。真实内核接入时，在 session 来源中通过共同客户端读取领域 DTO 和事件，适配为界面模型；不将当前样例的材料名称数组或“只保留最新一轮”扩展成产品协议。

对象旁输入与 Agent 面板操作同一条待发送指令及附加材料，发送走共同事件路径；“需要你处理”只汇总确需用户判断的事项。

Agent 生成的交互式科研界面沿 [#45](../.scratch/scholoom-foundations/issues/45-interactive-research-reports.md)作为一等原生接口接入。呈现、更新及用户选择／输入回传由共同客户端与工作台承接，科研能力和迁入工作流复用；页面承载方式、资源访问、动作与等待恢复契约尚待细化，不在此预定 SDK 或封装格式。

UI 样例继续只提供数据与回调。新增持久任务、产物或审查状态必须来自共同领域接口；浏览器与 Electron 的差异留在窄启动／系统适配，测试通过同一工作台操作。

列表分页或虚拟化、消息增量合并、预览合并刷新、选中材料有界读取。高频更新需实测渲染耗时、内存和输入响应；不以全库 projection 或跨 DOM 扫描取得当前对象。工作台只展示用户需要的状态、操作和依据。

assistant-ui 与工作台能满足真实负载是待验证假设。材料列表由工作台负责，会话由相应消息组件承载，分别验证大量材料的读取与滚动、长会话的加载和内存、多 Agent 持续输出时的输入响应及重渲染范围。接入真实数据时尽早测量，交付前复验；优先利用已有组件能力，证据不支持时允许调整组件或接线，不提前自建另一套消息系统。

### 9.2 源码与可视编辑

CodeMirror 管理源码编辑和草稿；QMD／MD 的学术可视模块通过受管 Pandoc 转换及宿主资源接口连接同一稿件。源文件组及项目工程配置是保存和渲染依据。无法表示的内容保留并提供源码入口，不能在切换模式时静默丢失。

材料选区、审阅意见、Change 和 Agent 指令使用共同对象引用及位置。工具反馈回到实际对象旁及任务记录，主张、证据和正式决定只在领域服务中更新。语法补全和组件内缓存不能成为第二个文献权威。

图表修改沿可找到的生成来源调整并重新生成，关联实际数据、代码和新图件；无已知编辑结构时，图像区域标注仅提供指令定位，不假定可直接修改数据点语义。

### 9.3 预览与工程执行

已决定安全与结果边界，尚未决定实时预览的布局、刷新时机、延迟目标和完整定位体验。以下为实施建议：

- 轻量预览读取正文与已有结果；需要真实项目构建、代码单元、hook 或可执行扩展时进入受管工程执行并检查授权。
- 不能仅依靠 Quarto `--no-execute` 证明无副作用：已有实验发现它仍运行 pre-render hook。普通预览需要实际隔离项目可执行配置；不能可靠排除时提示改走授权的工程渲染。
- 将成功产物与当前渲染尝试分开。失败保留最近成功输出并标注对应稿件及状态，不能将旧 PDF／HTML 表示为新结果。编译器可能删除其输出路径，保留策略应由宿主实现并测试。
- 合并连续保存的渲染需求；当旧请求晚于新请求返回时，只把对应正确输入依据的结果展示为当前。调度不等于每次按键重编译。
- 监听正文之外的书目、图件和必要工程依赖，针对多文件 LaTeX 保留原编译链与实际位置映射；具体自动刷新路径通过代表性稿件验证。

Figma 分批提供整体空间与关键交互设计，UI harness 检查真实编辑和预览行为；设计尚未就绪时，行为明确的编辑与渲染模块可先以功能性界面接入。当前没有采纳的 Figma Frame 链接，也没有可承诺的实时预览性能指标；体验细节结合真实稿件讨论。来源：[#11](../.scratch/scholoom-foundations/issues/11-reading-writing-format.md)、[#38](../.scratch/scholoom-foundations/issues/38-workbench-artifact-interaction.md)、[#39](../.scratch/scholoom-foundations/issues/39-writing-live-preview.md)、[#40](../.scratch/scholoom-foundations/issues/40-research-execution-environment.md)。

## 10. Zotero 兼容、Connector 与迁入

### 10.1 宿主接口与权威写回

独立 Electron 宿主保留插件运行所需对象身份、同步属性、异步方法、原型、Worker／IndexedDB、SQL 和 DOM 语义。内核与宿主跨进程传 DTO；宿主内部构建兼容对象及有界缓存，两者不能混为一种对象模型。

建议每类插件变更由兼容适配转换为共同文献命令，等内核确认后更新相关宿主对象与缓存并触发适当通知。内核来源的变更反向刷新相关兼容对象，防止通知循环或旧缓存覆盖当前题录。原插件同步读和 SQL 查询所需的投影如何保持可观察一致性，需要以固定原包实际调用验证；本稿不指定未经验证的兼容数据库方案。

首批功能验收分别覆盖 BBT 引用键、BibTeX／BibLaTeX、自动导出、pull export／JSON-RPC，以及茉莉花元数据、translators／CSL、附件匹配、大纲／书签接入。宿主能初始化或导出一次，不等于这些功能全部兼容。

原型证据已覆盖 BBT 9.0.68 样本引用键与 BibTeX 导出、茉莉花 1.1.39 作者处理及合成输入下建项回退／PDF 关联；原任务 RIS 分支因 translator ID 不匹配失败，不能用整体回退成功代替该分支通过。真实在线识别、下载及独立 Reader 写回仍待验收，详见 #16 与 #41。

### 10.2 Connector 与资源版本

自有 Scholoom Connector 复用采集逻辑，使用自己的配对和本地保存适配，将结果交共同摄取。目标明确为 Scholoom，测试与官方 Zotero 扩展共存；不要占用同一默认端口后假定可以自动区分。扩展按 AGPL-3.0 开源，保留来源声明，按实际分发提供完整对应源码及必要构建脚本；第三方资源逐项核对许可。

采集会话标识用于一次保存，不能当永久文献身份。插件按已验证版本升级，宿主不直接启用插件上游自动升级；translators／CSL 可独立更新，但需保存来源与版本并验证其与当前兼容宿主的组合，保护用户自定义内容；更新失败保留上一份可用资源，更新后出现问题可回退。配对协议、端口、浏览器权限和扩展分发需单独实现调查。

### 10.3 单向迁入设计建议

1. 预检源库、附件可读性、目标空间与来源库身份；处理正在使用中的源库时采用一致读取或受支持副本方式。
2. 建立迁入计划与来源映射，覆盖选定个人库及本机可读群组材料，明确不迁账号、群组权限或在线同步关系。
3. 按可恢复批次处理集合层级、标签、题录、引用键、笔记、批注和附件关系；托管附件复制，链接附件默认保留或按选择转托管。
4. 每批保存真实成功项与失败项，验证关系和关键文件可读性；源库和源附件保持原状。
5. 续做依来源映射避免重复导入，并核对目标是否已被用户修改；不以重新迁入覆盖迁入后编辑。
6. 安全撤回只处理仍可确认由本次迁入产生且未形成需保留修改／依赖的内容；其余列出原因供处理。

迁入是需要更强恢复信息的特定高风险流程，不把批次日志扩展到所有普通文件操作。来源：[#05](../.scratch/scholoom-foundations/issues/05-zotero-compatibility-policy.md)、[#16](../.scratch/scholoom-foundations/issues/16-zotero-host-prototype.md)、[#41](../.scratch/scholoom-foundations/issues/41-zotero-ecosystem-integration.md)。

## 11. 分发、备份与运维

产品包应包含固定版本独立 Node、内核产物、两个 Electron 应用、Quarto／Pandoc、uv 和必要资源。better-sqlite3 等原生模块按独立 Node 与目标平台构建；Electron 宿主所需原生模块分别匹配其 ABI。当前 `package:dir` 的两个目录包及 `npmRebuild: false` 不证明未来原生模块可以直接加载。

每次发布锁定 Electron、Node、Zotero 宿主、插件、translators、Connector 与吸纳组件基线，并记录实际验收功能和已知限制。

首批预览版优先手动更新，分发优先 GitHub Releases。后续自动更新可采用 electron-updater，但更新需先保护未保存编辑、等待或暂停受影响任务，再协调内核与宿主停止和重新启动。Schema 迁移失败时保护数据，不能用旧程序直接打开已不兼容的新库充当回滚。

自动备份可关闭，明确包含数据库、稿件、笔记和选定重要材料，排除可重建缓存与临时编译产物。建议记录备份范围、数据库版本及缺失依赖；与开放文件同时变化时标明一致性范围，必要时在保存点协调快照，不宣称每次日常备份都是全系统事务快照。恢复到副本核对，再用于实际工作。

数据损坏或迁移失败时停止受影响数据的写入并保留现场，在副本上诊断和恢复。旧备份恢复到独立副本，保留当前数据，核对差异及缺项后选择性取回重要内容；不承诺任意两库自动合并。误合并、批量删除等高影响操作提供专门恢复路径，可安全撤销的部分先撤销，有后续冲突时由用户选择，保护新成果。诊断／只读入口、取回操作和恢复说明随实际存储能力实现并验证，不在此预定命令名称或声称完整性检查能识别业务误操作。依据 [#13](../.scratch/scholoom-foundations/issues/13-storage-and-change-model.md#损坏与误操作后的恢复)。

诊断默认记录状态、耗时、用量与必要错误，按任务／执行引用关联，内容有界并清理敏感信息。详细诊断显式开启，导出前可检查内容，默认不自动上传。密钥、未授权材料和完整项目内容不进入普通报告。

平台安装器、签名、公证、CPU 架构及更新凭据随公开分发计划确定。断网验收区分首次准备依赖与环境完整后的使用。来源：[#12](../.scratch/scholoom-foundations/issues/12-technology-stack.md)、[#13](../.scratch/scholoom-foundations/issues/13-storage-and-change-model.md)、[#15](../.scratch/scholoom-foundations/issues/15-validation-and-release-discipline.md)、[#40](../.scratch/scholoom-foundations/issues/40-research-execution-environment.md)。

## 12. 验证设计与可交付切片

测试覆盖稳定行为与失败风险，不按模块机械铺开测试，不精确断言全文提示或内部调用顺序。现有 smoke 与 UI 用例作为入口基础，后续优先扩展相关场景。下面是未来实现的验收要求，**本次文档起草没有运行这些业务验证**。

| 切片 | 必须跑通的行为 | 关键失败情境 |
| --- | --- | --- |
| 内核生命周期 | GUI／CLI／浏览器连接同一真实实例，关窗后继续，明确停机 | 并发启动、遗留发现信息、活着但不可达、认证失败、停机不明、配置隔离 |
| 状态与介入 | 快照订阅衔接，重连得当前任务与待处理项，答复仅应用一次 | 读取时发生变化、队列溢出、重复答复、请求结果未知 |
| 存储与开放文件 | 项目移动可读，局部修改保留外部编辑，撤销保护后续内容 | 文件与关系保存间中断、草稿冲突、材料缺失、备份恢复 |
| 首条科研链 | 读取真实材料、保存分析、查询实际成果、换会话继续 | 部分交付、缺全文、取消、checkpoint 不可用、产物引用失效 |
| 文献维护 | 入库／补原文／新增相关文献／分析修正正确影响相关成果 | 更新失败保留旧成果；无人项目只提示；索引重建保留正式关系 |
| 编辑与渲染 | QMD／MD 内容往返、多文件 LaTeX、正确版本预览 | 未知语法丢失、外部修改、hook 副作用、旧结果晚到、编译删除输出 |
| 模型与协作 | 授权覆盖所有调用，独立审阅，advisor 可启停并有限等待 | 外发范围越界、自动切供应商、重试叠加、关闭后自动继续 |
| 执行与取消 | 实际程序和进程树受控，长任务等待超时可查询 | 内核退出遗留进程、PID 复用、取消不明、已取消自动重启 |
| 插件与迁入 | 固定原包的每项承诺功能、真实只读源库迁入 | SQL／对象语义偏差、断点续做覆盖编辑、Connector 冲突、危险撤回 |
| 分发 | 三平台安装包启动、独立 Node／原生模块、离线准备与恢复 | 更新时活动任务、迁移失败、资源缺失、仅开发机可运行 |

确定性端到端测试使用真实内核、文件、数据库和必要兼容宿主，仅在外部模型或远程依赖边界提供受控响应；插件线上能力与科研质量另做真实验证。

中断验证先覆盖可重复的关键边界：文件已保存而关联未登记、决定已提交但执行未继续、副作用已发生但回执未知、迁移／批量操作中断、内核退出后程序仍存活。共同保存机制集中测试，高影响业务单独检查恢复；基础路径稳定后按实际风险补充随机断网、延迟或进程故障，不要求每个普通写操作重复一套测试。强制退出进程不能代替断电持久性验证，结论按实际测试范围记录。

性能门槛只针对确定性动作，如给定数据规模下的检索、分页读取、材料打开、保存和快照同步。记录硬件、版本、输入规模与缓存条件，首次测量形成基线但不等于合格，结合使用要求确定门槛并在交付前复验。Agent 运行期间，输入、浏览和取消受理等确定性响应同样验收；取消受理与外部工具实际停止分别衡量。数据库与 UI 的实现假设在开发中及交付前据此验证，证据不符时调整设计。

Agent 科研任务的总耗时、用量、调用次数、失败原因及资源消耗用于观测诊断，不按固定篇数／分钟建立端到端性能门槛。科研成果按交付要求另行验收；本地处理和模型／网络等待分别记录以定位瓶颈，不用单次算法速度或一次 Agent 运行代替系统性能证明。

真实科研验收最终以用户的一篇原创论文贯穿全流程，评价完成效果、科研质量、用户摩擦、持续工作及执行代价。具体材料、阈值、评分和重复次数由 [#21](../.scratch/scholoom-foundations/issues/21-agent-dogfooding-and-evaluation.md)后续确认；未知项不算通过，关键失败不能被平均分掩盖。

每个实施切片按 `proposal → investigation → specs/design → tasks → delivery` 留下实际结果；规划不预写完成记录。现有检查命令以根 package.json 为准，按变更影响选择类型、构建、smoke、UI 或真实业务检查，不为本次 Markdown 草稿启动服务。

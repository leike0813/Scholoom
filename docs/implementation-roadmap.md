# Scholoom 实施路线图

状态：建议稿，供选择后续 OpenSpec 变更。起草日期：2026-10-14。

本路线图安排初设规格的实施顺序、依赖和验收节点。当前 Figma 设计尚未就绪，开发可先使用已有工作台与真实模块夹具推进；视觉设计按功能分批接入。顺序可根据实施证据调整，本文不表示业务已经实现，也不一次性授权全部开发、安装依赖或发布。

行为依据见[初设规格书](initial-spec/README.md)、[PRD](prd/README.md)及相关决议；实际能力以代码、测试与[当前正式规格](../openspec/specs)为准。路线图只维护阶段、依赖和调整理由，任务勾选与交付证据集中在各 OpenSpec 变更，不再复制一份进度账本。

## 1. 推进方式：开发与界面设计并行

建议先贯通“连接真实内核 → 打开项目并安全保存笔记 → Agent 读取材料并保存成果”这条短路径，再接入文献、综合、研究执行和稿件。每一步都能在同一工作台操作，并且可以单独检查其实际结果。

这延续了 [#14](../.scratch/scholoom-foundations/issues/14-agent-development-discipline.md#按实际使用路径开发与交付) 和 [#20](../.scratch/scholoom-foundations/issues/20-ui-debugging-and-e2e-harness.md#answer) 的做法：模块按自身契约独立交付，界面尽早承接真实能力，完整路径再做整合验收。Figma 提供视觉与交互设计输入，不承担领域接口、数据权威或执行状态的定义。

### Figma 前可开展的工作

大部分核心能力可以先于 Figma 实施。近期优先沿 P1 → P2 → P3 推进，使用现有工作台持续提供可操作反馈；后续能力在各自前置就绪后接入，不必等待完整设计稿。

| 路线图部分 | 可先于 Figma 开展 | 后续结合设计收敛 |
| --- | --- | --- |
| P1 共同内核入口 | 启动、认证、连接、单实例、重连、停机与跨端状态 | 连接提示和操作入口的最终样式 |
| P2 项目与文件保护 | 项目打开、材料读取、保存、冲突检查、撤销、备份恢复 | 文件导航、差异展示和恢复选择的布局 |
| P3 单 Agent 执行 | 模型接入、授权、材料工具、成果保存、取消、恢复、最小能力调用 | 会话、材料与成果的展示组织 |
| P4 文献管理与阅读 | 收录、题录与附件管理、解析、批注存储、单篇分析；阅读器先接简单面板 | 列表、详情、阅读器与会话之间的空间关系 |
| P5 研究与知识能力 | 方法管理、研究记录、检索、综合、方案比较、正式决定、后台维护；简单比较表和选择回传可先做 | 复杂报告与研究信息的交互组织 |
| P6 受管科研执行 | 程序运行、环境准备、日志、产物、取消与进程恢复 | 运行状态与结果探索的最终界面 |
| P7 稿件能力的一部分 | 源码编辑、文件保护、格式转换、LaTeX 工程、渲染、引用、导出与研究包 | 写作空间、工具栏、预览布局及审阅交互；可视共稿按已明确的交互逐步接入 |
| P8 协作机制 | 委派、消息持久化、有界唤醒、独立审阅及 advisor 机制 | 多会话、审阅意见与修改建议的呈现方式 |
| 生态与分发 | 插件宿主、原包兼容、Connector 保存链路、迁入、平台运行与打包检查 | 插件入口、迁入向导等最终视觉设计 |
| P9 整合与发布准备 | 对已实现路径开展科研验证、恢复检查与分发准备 | 最终承诺的整体界面体验仍需完成验收 |

**设计依赖与开发依赖分别判断。** 上表表示无需等待 Figma，不表示这些工作现在都能同时开工。文献分析需要先有材料读取和共同能力调用，多 Agent 协作需要可靠的单 Agent 执行；具体前置仍按第 3、4 节安排。

**功能性 UI 随能力一起推进。** 连接状态可以先用简单提示，文献可以先用列表，恢复可以先用含义明确的选择界面。沿用已有样式并保持基本可读、键盘操作和焦点反馈，后续在同一组件上应用设计；色彩、字体、间距、图标和最终布局分批收敛，不提前投入复杂拖拽布局或动画。

没有 Figma 时，仍要明确本次动作的入口、对象、结果、失败和恢复方式。已有契约不足以决定交互时，可用工作台实操或草图讨论；涉及授权、删除、内容覆盖等含义的歧义必须先解决。无需为了普通按钮位置等待完整设计系统，也不能把未明确的业务决定埋进临时界面。

功能性界面继续在 [Workbench.tsx](../apps/desktop/src/renderer/src/workbench/Workbench.tsx) 及其实际模块中演进。模块夹具使用同一组件和事件路径，只替换声明过的依赖；后续 Figma 到位时调整这些组件，避免另写一套正式界面再搬运业务。开发态样例可以保留，但其固定回复不能冒充真实接线。

### 节奏与范围

- 一个阶段可以包含多个 OpenSpec 变更，每个变更交付一个可观察结果。不要把整章初设或整个宏观模块一次性展开成实施任务。
- 优先保持一条主路径推进；共享契约明确后，才并行做互不写同一范围的工作。生态兼容和分发风险可提前调查，不要求开多条长期实现分支。
- 近两步写到可以实施，远期保留明确成果和依赖；每次交付后据新事实调整后续顺序，不预填缺乏依据的工期、完成百分比或性能数值。
- 早期用隔离样本。允许某类真实用户数据写入前，先验证该类数据的保存、备份与恢复路径；批量迁入、合并和删除还要验证自身的中断与撤回。

## 2. 从现有基础继续

当前入口与交付依据如下；具体检查结果集中在对应变更的 delivery，本文不复制任务进度。

| 已有基础 | 可以复用 | 尚不能据此认定可用 |
| --- | --- | --- |
| 三应用入口和 pnpm workspace | 独立驻留内核、CLI、认证与生命周期、桌面及兼容宿主结构 | 插件兼容、独立 Node 产品分发 |
| 共享 React／assistant-ui 工作台 | 同一组件承接真实会话、项目文件、MiniMax 与执行控制 | 科研方法、文献阅读与完整科研业务 |
| `packages/protocol` 与 `packages/client` | Schema／类型事实源、真实 WebSocket、业务 RPC、范围订阅与重连 | 后续领域接口 |
| smoke、内核与双宿主 UI 测试 | 生命周期、文件保护与 Agent 用户路径的实际入口 | 完整科研质量和三平台成品验收 |
| 宿主及预览调查原型 | 已验证输入、兼容问题、来源代码和行为参照 | 可以直接搬入生产的完整子系统 |

正式规格包含工程基础、共同内核生命周期、工作台基础／外壳、项目文件、模型与单 Agent；契约见 [当前正式规格](../openspec/specs)，基础 harness 实际结果见 [establish-basic-agent-harness 交付](../openspec/changes/archive/2026-10-15-establish-basic-agent-harness/delivery.md)。样例“只显示最新一轮”的范围仍限于样例，真实会话采用持久分页历史。

共同内核入口沿已确认的 [#23](../.scratch/scholoom-foundations/issues/23-kernel-entry-and-lifecycle.md#answer) 已交付。按用户确认，P2 的必需文件保护与 P3a–P3c 已合为一个单 Agent 闭环，先接 MiniMax M Plan 中国区；P3d 的共同方法／能力调用由后续独立变更接入。未接入的库管理、受管计算和生态功能不因基本 harness 可用而视为已完成。

基础 Agent harness 及相应界面沿实际缺口验收。P3a–P3c 的执行反馈由 [complete-agent-execution-workbench](../openspec/changes/archive/2026-10-15-complete-agent-execution-workbench/proposal.md) 补齐；[complete-project-file-workbench](../openspec/changes/archive/2026-10-15-complete-project-file-workbench/proposal.md) 覆盖项目管理、目录与文件回收恢复、源码编辑和 Markdown 图片／公式预览；[complete-agent-conversation-workbench](../openspec/changes/archive/2026-10-15-complete-agent-conversation-workbench/proposal.md) 补齐通用会话管理与消息阅读。P3d 由 [establish-research-capability-runtime](../openspec/changes/archive/2026-10-16-establish-research-capability-runtime/proposal.md) 交付内置材料分析方法、共同调用、持久尝试及实际交付检查；完成证据集中在该 change 的 delivery。随后按 P4a 推进本地文献库，完整 Digest 沿 P4c 使用共同入口，方法管理沿 P5a 扩展。

## 3. 总体顺序与依赖

阶段编号便于讨论，不表示必须整阶段串行完成。下表中的前置均指所列能力已经可用，不要求无关部分全部结束。

| 阶段 | 可验收成果 | 主要前置 | 与 Figma 的关系 |
| --- | --- | --- | --- |
| P1 共同内核入口 | GUI、浏览器与 CLI 接入同一真实内核，正确处理断线及停机 | 现有基础 | 可直接推进，沿用工作台 |
| P2 项目与安全文件操作 | 打开隔离项目、读写笔记、重启读回、冲突保护及副本恢复 | P1 | 可直接推进，简单列表与编辑入口即可 |
| P3 单 Agent 真实工作 | 读取材料、保存成果、取消、接续与追加指令 | P1、P2 所需持久化与文件接口 | 可直接推进，先验真实交互 |
| P4 文献收录与阅读 | 本地文献渐进入库、查询、阅读与共享批注 | P1、P2；分析接入 P3 | 无需最终布局；材料交互应尽早反馈 |
| P5 从材料到研究结论 | 分层知识、检索综合、任务与正式决定、交互报告 | P3、P4；各子步骤见下文 | 可用功能性界面；报告交互需具体讨论 |
| P6 受管科研执行 | 运行真实程序、保存结果图件、安全取消及恢复 | P2、P3；任务关联使用 P5 的对应契约 | 可提前与 P4／P5 部分并行 |
| P7 稿件与修订交付 | QMD／MD／LaTeX 编辑预览、引文、导出、意见与实际修改 | P2、P3；引文接 P4／生态，工程渲染接 P6 | 编辑组件可先做，写作体验分批定案 |
| P8 多 Agent 协作 | 委派、持久通信、独立审阅与文风 advisor | P3、P5 的持久执行；文风与改稿接 P7 | 执行可先做，协作与审查体验同步收敛 |
| P9 全流程与发布 | 真实论文路径、恢复、功能界面和实际分发包验收 | 被声明为交付范围的各路径及生态能力 | 最终承诺的界面体验需完成验收 |

生态工作 E1–E4 与分发检查另列在第 5 节。它们应在需要的契约出现后进入主路径，不能全部堆到 P9。没有整套 Figma 并不阻塞 P1–P6 的能力建设，也不阻塞 P7／P8 中交互已明确的部分。

## 4. 各阶段建议拆分与完成依据

### P1：共同内核入口与生命周期

**用户能做什么：** 打开工作台接入真实内核；关窗后用 CLI 查询同一实例；再次打开可接回；明确停机后所有客户端看到实际结果。

范围沿 #23，参考初设 [K-01–K-03、K-05](initial-spec/kernel.md)。建议先形成一个有完整闭环的 OpenSpec 变更，内部按依赖实现：

| 步骤 | 实施内容 | 主要检查 |
| --- | --- | --- |
| P1.1 调查并确定接线 | 数据配置身份、发现信息、启动协调、存活判断、认证资料交付和协议错误 | 不把过期发现文件当存活，也不替换仍存活但不可达的内核；明确三平台差异 |
| P1.2 真实内核与客户端 | 本机 WebSocket／双向 JSON-RPC、运行时 Schema 校验、请求关联、CLI 启停和状态 | 并发启动同一配置只形成一个实例；查询和停止不创建实例；认证失败可辨 |
| P1.3 双宿主接入 | Electron 启动桥、浏览器开发引导、工作台连接状态和明确停止入口 | 两宿主使用共同客户端，连接失败保留草稿，浏览器不自行创建 Node 进程 |
| P1.4 故障和交付 | 有界重连、确认退出后的用户重试、明确停机、多客户端诊断 | 真实关窗续留、重新接入、停机超时不假报成功、停机后不自动拉起 |

完成时验证真实进程与连接，不构造假研究任务证明后台工作。后续业务需要订阅时再扩展状态流；P1 不一次性实现全量业务事件系统。

开发环境沿三平台同组生命周期检查推进，Linux 作为日常验证入口，其他平台结果按实际 CI／机器证据记录。独立 Node 的产品分发检查随 P1 后尽早开展。

**界面投入：** 在现有工作台展示连接、错误、重试和停机，不设计全部导航。用户此时可在 Figma 探索总体空间，开发无须等待。

### P2：打开项目并安全保存一份笔记

**用户能做什么：** 打开一个隔离项目，查看已有材料，编辑并保存 Markdown 笔记，重启后读回；外部修改时得到可处理的冲突结果。

参考初设 [D-01–D-07](initial-spec/data.md)。这是后续 Agent 获得写权限的基础，按以下小成果拆分，避免先建完整领域数据库。

| 候选变更 | 最小完整成果 | 完成依据 |
| --- | --- | --- |
| P2a 项目与材料读取 | 项目打开、稳定身份、必要本地 Schema／迁移、材料引用、有界列表与读取 | 项目移动后可打开；缺失外部依赖如实显示；GUI 与调用方读取同一文件 |
| P2b 笔记保存与保护 | 源文件权威、草稿、整份内容核对、内部按文件串行保存、错误分类及有限历史 | 外部目标外改动也拒绝旧修改；多文件逐项结果；撤销保护后续内容；重启可读 |
| P2c 恢复最小闭环 | 所选数据库与文件的备份、独立副本诊断和恢复、选择性取回入口 | 实际恢复一份样本；当前数据与备份后的成果保留；范围和缺项可说明 |

产物关联按实际文件登记并支持部分成功，文件已保存而关系未知时可核查补齐。全局库 Schema 随 P4 出现，具体研究任务表随 P5 出现，各自扩展同一存储政策。P2c 先覆盖已实现的数据，不声称能恢复尚不存在的文献合并和迁入。

有实际变化需要跨端观察时，补入 [K-04](initial-spec/kernel.md) 的快照与有界订阅：订阅衔接不漏变化，相关范围重同步，保留旧画面与本地草稿。容量依据当前场景测量，不引入全量事件回放。

**界面投入：** 现有材料列表、源码编辑组件和简单差异／恢复选择即可。保存冲突的含义必须明确，最终外观可以后续更新。真实业务路径第一次贯通后，开始维护从用户保存动作到磁盘核对的双宿主 e2e。

### P3：单 Agent 读取材料并留下可继续的成果

**用户能做什么：** 选择项目材料，向一个真实 Agent 发出指令，看到实际使用材料和产物；关闭窗口后执行继续，重新接入可查看；取消或中断后可以安全接续。

参考 [E-01–E-04、E-06](initial-spec/execution.md)、[R-01、R-03–R-05、R-07](initial-spec/research.md)、[W-01–W-03](initial-spec/workbench.md)。

1. **P3a 真实会话：** 接入内置 harness、一种明确模型配置、凭据与发送授权，建立持久会话及必要执行记录。首先开放材料读取和产物保存工具，保留实际使用引用。先落实应用默认与项目覆盖，任务与角色覆盖分别随 P5a、P8a 接入；多供应商共用机制，首轮只验一个适配不等于所有供应商可用。
2. **P3b 可控执行：** 流式输出、追加指令受理／消费、调用限制、安全重试、取消及后台状态。未确认停止不能显示已停止，来不及消费的指令不丢失。普通对话不自动建研究任务。
3. **P3c 接续与交付：** checkpoint 正常恢复和不可用时的新执行接续；保存理由、成果与下一步，未知副作用先核查，用户暂停或取消后不自启动。新会话可从材料继续，无需旧 transcript。
4. **P3d 最小方法与能力调用：** 加载一个已有方法，核对输入，记录能力调用身份、执行尝试和实际产物，进行必要交付检查。作为 P4c 单篇分析的前置，不为 Digest 另写临时执行路径；内容派生、启用管理及研究任务留到 P5a。

每个子变更都在真实工作台操作；确定性 e2e 只替换外部模型响应，不能替换内部工具、文件或数据库。真实模型可用后立即做小规模产品内试用，记录实际效果和障碍；完整科研评价细则仍沿 #21 在功能初步可用后讨论。

在这里测量长会话、持续输出、输入与取消受理，核对 assistant-ui 接线和数据库访问假设。不要等所有业务完成再发现主线程或 UI 无法承担实际负载。

**本阶段范围：** 一个 Agent 完成受控材料任务即可。通用 shell、复杂计算、自动维护和多 Agent 协作分别沿后续阶段接入。界面至少能辨接收者、附加材料、实际使用材料、草稿和待处理指令，视觉设计不影响这些契约。

### P4：文献从收录到阅读，再到单篇分析

**用户能做什么：** 收录一小批材料，逐项看到题录、附件与分析状态；直接阅读、批注，并让 Agent 使用这些内容形成已保存的分析。

参考 [L-01–L-05](initial-spec/literature.md)、[D-01、D-05、D-06](initial-spec/data.md)。建议按以下路径推进：

| 候选变更 | 交付范围 | 验收重点 |
| --- | --- | --- |
| P4a 本地文献库 | 手动／文件与题录入口、稳定条目身份、集合标签、附件管理、批次引用及逐项结果 | 题录和可读附件先用，局部失败可补；同一版本去重，不把发表版本差异抹掉 |
| P4b 共用材料阅读 | 解析与有界读取、PDF 阅读器接线、选区、书签、批注与笔记；再补 EPUB／网页 | Agent 无需可见阅读器；摘录、作者与分析可辨；替换时保留必要实际版本，缺失不跳错新版 |
| P4c 单篇科研分析 | 依赖 P3d 的共同方法／能力调用，Digest、参考文献提取、引用分析、文献评价逐项接入产物登记 | 实际保存可读，缺材料不冒充全文分析；中断保留可用结果，补齐材料后可继续 |
| P4d 管理与保护补全 | 合并、回收站、恢复、明确永久删除范围；扩展库备份恢复 | 保护批注、附件、项目引用及后续编辑；批量中断与安全撤回以副本验证 |

P4a 只需足以支撑第一条文献路径的摄取入口。在线发现和生态入口在 P5／E2 扩充，复用同一摄取服务；不另写一套临时文献库或把需要插件的功能伪装成已兼容。

P4b 的阅读器可先在共享工作台的简单面板接入。Figma 此时优先设计文献列表、详情、阅读和会话之间的关系；不必一口气画完写作、审阅与所有设置页。

### P5：从文献与材料形成可追溯的研究判断

**用户能做什么：** 发现和补充文献，组合题录、分析与原文进行检索，形成比较或综合；在交互报告中作选择，执行继续，依据、决定和成果保存下来。

本阶段包含不同职责，可分别交付，不能以一个“大知识系统”变更包揽。参考 [R-02–R-07](initial-spec/research.md)、[L-06–L-08](initial-spec/literature.md)、[W-06](initial-spec/workbench.md)。

| 候选变更 | 依赖与范围 | 可验收结果 |
| --- | --- | --- |
| P5a 方法管理与研究记录 | P3d 共同调用；扩展方法发现、派生和启用检查，任务按用户明确要求建立，问题、计划与能力交付关系持久保存 | 普通会话仍无需任务；方法同名可辨；新会话能发现并继续已有研究 |
| P5b 在线发现与补充 | P4 摄取接口；逐个接入已确认来源、标识符和网页补充，核查真实限制 | 查询覆盖、题录、全文地址及实际下载分别表达，失败保留来源和原因 |
| P5c 分层检索与综合 | P4 可读材料与分析；先调查代表样本上的解析、切分和索引，再接统一混合检索与综合方法 | 同来源跨层命中归组，可按引用读原文、核验图表；召回覆盖与缺项真实 |
| P5d 交互报告 | P3 执行／授权与 P2 产物；原生呈现、输入回传和持久报告，无需先有研究任务或正式决定 | 比较材料 → 用户选择 → 继续分析 → 保存并再次打开；普通筛选与报告交互不强制建立任务 |
| P5e 问题、方案与正式决定 | P5a 研究记录和已有可读材料；先提供问题形成、方案比较与计划方法，再接正式提案、答复和执行核对 | 从材料形成研究问题，保存备选方案、约束和计划；适用时请求正式决定，同一答复只应用一次，换会话可继续 |
| P5f 后台维护 | P4c 与 P5c 已能可靠交付；实际依赖、发现范围、变化合并和受限调度 | 旧成功成果持续可用，局部变化局部处理；闲置项目仅保存线索，用户启动复核 |

P5d 可在 P3 与必要材料读取就绪后提前实施，不等待 P5a 或混合检索完成；先用已有材料及真实 Agent 构成比较路径，再用审阅修订复核接口是否适用。P5e 可直接使用用户提供的材料，也不强制经过在线检索。报告脚本与资源访问边界在首次可执行交互前确定，避免为了快速展示赋予任意内核权限。

六组科研方法随 P4–P8 的实际业务路径逐组接入，三类稿件工作流随 P7／P8 落实；P5a 交付发现与调用机制不能代替方法内容的迁入及效果检查。旧项目方法和程序按当前契约抽取，核对许可与有价值的既有测试，不把整个旧应用作为运行依赖。

后台维护在手动路径、取消、资源限制和恢复可靠后开启。在线供应商、检索参数等影响当前路径的未知项在对应 investigation 中解决，不要求先统一研究所有检索方案。

**界面投入：** 先做可操作的比较表、报告和待决定入口，再依据真实案例设计信息层次。Figma 可以帮助收敛布局，科研判断及输入回传的契约由共同模块负责。

### P6：受管科研程序与实际结果

**用户能做什么：** 在授权范围运行研究代码，查看状态和结果图件；等待超时后仍能查询长计算，取消后知道实际停止情况；重启不重复运行结果未知的程序。

参考 [E-05–E-07](initial-spec/execution.md)、[R-04–R-07](initial-spec/research.md)、[W-07](initial-spec/workbench.md)。

建议拆为“受管运行与产物”“环境准备及工具扩展”“跨平台取消与重启核查”。先选一个真实科研样本，把 JS／TS、Python 或命令行所需路径逐项接通；声明未覆盖的运行方式，不因此改变既定支持方向。

实现前调查运行身份、工作目录、进程树、日志、资源声明和结果检查；获授权准备受管环境，保护用户已有环境。短请求等待与计算时限分别处理，实际停止与取消受理分别检查，产物完整性与程序退出码分别判断。

插件声明的 MCP 能力在此阶段或生态接入时按实际需要接入，验证配置、凭据、授权和工具实际取消／恢复能力；不预建任意外部 Agent 入口或通用插件平台。

**完成依据：** 一次真实分析产生代码、数据结果和图件，用户能查看，Agent 可继续使用；失败保留已完成成果，重启核对遗留执行，不凭旧 PID 误杀。进程与工具分发在目标平台提前验证，受管进程仍按可信代码边界说明。

P6 的基础执行可在 P3 后开始，不必等待文献全部完成；完整任务关联接 P5a。界面先提供状态、日志、产物和取消，图件来源与选区随后同 P7 整合。

### P7：稿件编辑、预览与修订交付

**用户能做什么：** 从已有材料写稿，保留开放格式和手工内容；查看实际预览及修改差异，处理审阅意见，并导出真实稿件和回复材料。

参考 [W-04–W-08](initial-spec/workbench.md)、[R-04](initial-spec/research.md)、[D-02–D-04](initial-spec/data.md) 及 [Z-03](initial-spec/ecosystem.md)。

| 候选变更 | 实施结果 | 验收重点 |
| --- | --- | --- |
| P7a 源码编辑与材料指令 | 复用 P2 保存保护，接入 QMD／MD 源码、选区与同一待发送指令 | 草稿切换不丢、Agent 写入走共同文件保护；不先造完整多面板布局引擎 |
| P7b QMD／MD 可视共稿 | 在 P7a 之后接入源码与可视编辑转换，沿同一文件保存 | 未知语法保留源码入口，真实论文样本往返不静默丢内容 |
| P7c LaTeX 工程 | 在共同文件接口上支持原生多文件、资源及工程打开，编译接 P7d | 不强转 QMD；实际修改与保存覆盖正确文件，外部工程内容保留 |
| P7d 预览与工程渲染 | 应用提供的普通排版、授权工程执行、最后成功产物及版本状态；按格式分别接入 | 普通预览不触发工程自定义脚本；失败不伪装为最新；晚到旧结果不覆盖新结果 |
| P7e 引文与交付格式 | 稳定引用键、项目映射、手工引用文件保护、DOCX／PDF／LaTeX 源交付 | 在真实稿件核对引文、公式、图表和交叉引用；来源插件导出能力沿 E1 验收 |
| P7f 审阅与修订路径 | 原意见、候选修改、实际应用、回复及版本关联；外部改稿保留原文件 | 回复中的修改声明对应实际稿件，未知转换损失明确，撤销保护后续编辑 |
| P7g 独立研究包 | 选用材料、项目事实与成果打包，标明未纳入的外部依赖；可在 P4／P5 相应事实就绪后先做 | 在缺少原文献库的环境打开包，读取已包含成果，准确列出缺项，不依赖原机器全局登记 |

编辑器基础可以在 P2 后先交付，单 Agent 修改在 P3 后接入；工程渲染依赖 P6，引用导出依赖相应库与生态功能。不必等整个 P5 或 P6 结束才接编辑组件。

此阶段恢复 [#39 预览体验](../.scratch/scholoom-foundations/issues/39-writing-live-preview.md) 的具体讨论，用真实 QMD／LaTeX 稿件确定预览布局、刷新和确定性响应目标。Figma 未完成时仍可验证编辑与渲染正确性；未确认的写作体验应作为未完成项，不凭组件接入宣布完整写作工作台交付。

### P8：多 Agent 协作、独立审阅与文风监督

**用户能做什么：** 将有界工作委派给多个执行者，取回实际成果；多个会话协作同一对象，暂停后不会被来信自动唤醒；独立审阅和文风建议有出处、有处理结果。

参考 [R-08–R-10](initial-spec/research.md) 和 [#46](../.scratch/scholoom-foundations/issues/46-multi-agent-interaction.md#answer)。顺序建议为：

1. **P8a 原生委派：** 工作包、身份、权限收紧、资源上限、角色模型配置、产物和部分失败；从并行阅读同一小组材料开始。进入多模型工作前验证实际供应商适配、显式切换、材料发送授权与用量缺失处理。
2. **P8b 跨会话通信：** 持久收件、已受理／已消费／请求结果、有界唤醒、用户暂停停止及关闭归档行为；验证中断和重复通知。
3. **P8c 独立审阅与 advisor：** 首轮互不预置意见、汇总保留分歧；文风显式开关、有限等待、当前有效上下文和建议应用，不自动修改用户自写内容。

P8a／P8b 在 P3 的单执行安全机制和 P5a 的交付关系稳定后可推进，P8c 等待相应稿件路径。不要用多 Agent 并发掩盖单执行仍会丢成果、重复副作用或无法取消的问题。

完成时安排共享文件竞争、模型限额和暂停恢复的组合场景，实际检查最终内容；审阅多数票不替代科研判断。Figma 优先解决接收者、委派结果、原意见、候选修改和待决定的辨识，不要求提前设计复杂会话关系图。

### P9：全流程整合、体验收敛与发布

将前面已交付能力组合成一篇真实论文的路径，允许研究往返；完整科研能力、生态兼容及稳定版要求保持不变。参考 [验证规格](initial-spec/validation.md)。

| 交付节点 | 核对内容 |
| --- | --- |
| 功能预览 | 明确已实现路径、平台和限制；从产品入口使用隔离样本，区分模块成功、整合成功和真实科研效果 |
| 全流程科研验收 | 按 #21 已讨论确定的样本与评价方法检查文献、方案、实际结果、图表、整稿、投稿与回复；外部 Agent 不代写预期成果 |
| 体验收敛 | 将分批采纳的 Figma 落到共同组件，核对四种布局、键盘与焦点、阅读写作及长会话负载；视觉调整后重跑受影响行为 |
| 数据与运维准备 | 实际备份恢复、选择性取回、Schema 升级、迁入撤回、损坏诊断及操作说明；独立研究包在缺少原文献库的环境打开并列明缺项；保留当前数据和升级后成果 |
| 稳定版候选 | 完整流程、目标插件功能及三平台实际分发包验收，记录版本组合、许可、签名／公证条件、已知限制和手动升级路径 |

阶段目标按真实证据判断。首个稳定版仍需 Windows、macOS、Linux 验收；源码构建、目录包生成与某一平台本地通过不互相替代。公开发布按具体授权执行。

## 5. 两类工作需要提前穿插

### Zotero 生态：尽早验证风险，按领域接口接入

不建议把所有插件工作放在文献主路径之前，也不应等稿件完成才发现原包无法接入。依 [#05](../.scratch/scholoom-foundations/issues/05-zotero-compatibility-policy.md)、[#16](../.scratch/scholoom-foundations/issues/16-zotero-host-prototype.md#answer)、[#41](../.scratch/scholoom-foundations/issues/41-zotero-ecosystem-integration.md#answer)，分成以下可并行节点：

| 节点 | 启动条件 | 交付与去向 |
| --- | --- | --- |
| E1 宿主与首批原包 | P1 后可核对既有原型；P4 文献身份及写入契约形成后接生产存储 | 固定版本未修改 BBT／茉莉花、共同数据写回、宿主故障诊断；先验一条真实路径，再扩到首批功能矩阵；引用键和导出供 P7 使用 |
| E2 Connector 与元数据 | P4 摄取、附件和部分结果可用，相应 translator／宿主能力可调用 | 独立扩展、配对、目标库、题录与附件结果、官方扩展共存；元数据填空与冲突候选、本地附件匹配、阅读辅助逐项验收 |
| E3 单向迁入 | P4 关系与删除恢复、P2 副本恢复及必要插件状态已具备 | 先小样本和真实数据副本，再扩大范围；身份映射、中断续做、后续编辑保护、安全撤回与重启读回，源库不变 |
| E4 维护及完整兼容核对 | 各功能已接通，进入预览／稳定版准备 | 原包版本升级、translators／CSL 更新与回退、用户定制保护、BBT 对外 JSON-RPC 真实调用、茉莉花在线和阅读写回，公布实际支持范围 |

E1 的调查若发现会改变文献权威或引用身份的障碍，应在依赖的生产 Schema 固化前解决；不通过改插件原包或另建平行文献库绕过。原型只保留有用证据、夹具和经审查的可复用实现。

这些工作的大部分不依赖最终 Figma。迁入预检、部分失败和撤回选择需要能被用户理解的功能性界面；扩展外观与插件入口再按分批设计收敛。

### 分发与平台：每出现一类依赖就验证一次

| 时点 | 提前验证的风险 |
| --- | --- |
| P1 | 三平台生命周期、路径与启动桥；独立 Node 随包提供及工作台关闭后独立运行，不依赖开发机已安装 Node |
| P2／P4 引入数据库及阅读器 | 原生模块 ABI、目录权限、数据库备份与迁移、Unicode／长路径、材料资源加载 |
| P6／P7 引入执行和渲染 | 进程树取消、工具发现／分发、Python／Quarto／TeX 等实际需要的环境、离线或缺依赖时的明确结果 |
| E1／E2 | 隐藏宿主、Worker、插件资源、浏览器配对与扩展构建 |
| P9 | 每个支持目标的实际安装包、升级与数据恢复、签名／公证及公开分发检查 |

早期验证可以仅覆盖当前功能的目录包或实验样本，记录局限；最终仍验证实际分发包。安全更新不能为了维持某个测试工具组合长期推迟。

## 6. Figma 可以按这个节奏准备

不用先画完整产品。每一批围绕下一条可操作路径，附正常、空、加载、失败和需要用户处理的代表状态即可；尚无真实数据时用已确认样本，随后用运行结果修正。

| 设计批次 | 建议与开发重叠的时间 | 优先回答的问题 |
| --- | --- | --- |
| F1 基础空间 | P1–P3 | 会话、材料、成果如何并排或切换；当前接收者、草稿和连接状态怎样清楚呈现；基本字体、颜色与密度 |
| F2 文献与研究 | P4–P5 | 列表、详情、阅读器与会话的关系；摄取部分失败、版本不可用、比较报告和正式决定怎样处理 |
| F3 写作与产物 | P6–P7 | 编辑、预览、图件、来源和会话的关系；选区指令、改动差异、保存冲突、旧预览如何辨认 |
| F4 审查与整体整理 | P7–P9 | 原意见、候选修改、回复与最终版本如何串联；协作结果、恢复入口及四种布局如何保持一致 |

每批可以只提供一条路径的草图或关键画面，标明哪一版已经采纳。开发在对应 OpenSpec 的 design 中引用设计来源及适用状态；交互改变行为时先更新规格，纯视觉调整沿已有契约实施。设计未完成的页面仍可用功能性界面检验业务，但不宣称视觉或整体体验已定稿。

Figma 比开发晚时，优先继续明确且稳定的模块和小交互，不预先大量实现拖拽、任意布局配置、主题编辑器或复杂动画。Figma 比开发早时，页面样例说明模拟边界，再逐项替换为真实接线；不把样例数据写成另一份领域事实。

## 7. 每个变更怎样落到 OpenSpec

沿 [scholoom-dev](../openspec/schemas/scholoom-dev/README.md) 执行，路线图中的 P／E 编号只作范围引用，不强制作为 capability 名或变更名。

1. **proposal：** 选一个具体结果，写入口、使用者、范围、前置能力及完成例子；引用初设编号和本路线图位置。说明是否需要 Figma、现有交互是否足够，避免笼统标成“等 UI”。
2. **investigation：** 核对现有实现、可复用旧代码和测试、版本及本步风险。只调查会改变该步设计的未知项，必要原型给出问题和结束依据。
3. **specs／design：** 固化可观察行为、DTO／Schema、失败和恢复；说明模块独立测试、真实接线、功能性界面及设计引用。共享协议集中维护，候选接口名经本次调查再定。
4. **tasks：** 按依赖安排实现、UI 接入和必要验证，明确整合责任。独立模块可以先交付，所依赖路径的整合验收仍须有人负责。
5. **执行后 delivery：** 记录实际接线、替身、测试结果、人工反馈、限制与接续信息。完成验证再同步／归档；对应初设正文转为正式规格链接，本文不复制任务状态。

规划到 apply 所需工件及其依赖齐备为止，不能为了 CLI 显示完整而提前填写交付结果。本轮路线图不创建整套远期变更；接下来先为 P1 建立实际变更，后续在临近实施时规划。

### 验证贯穿每一步

| 验证责任 | 从何时开始 | 应保留的证据 |
| --- | --- | --- |
| 模块行为与诊断 | 首个模块交付 | 经接口检查真实状态和失败，依赖替身明确；复用现有测试，避免文案快照 |
| 真实双宿主接线 | P1 生命周期；P2 首次文件路径 | 用户入口到内核、实际文件／数据库，浏览器与 Electron 共同组件，原生行为在 Electron 核对 |
| 数据保护与恢复 | P2 首次写入，随高影响操作扩展 | 文件保存／关系登记边界、决定提交／继续边界、未知副作用、迁移和批量中断；先可重复注入，再按风险随机化 |
| 确定性性能 | 相应动作首次可测 | 给定硬件、输入规模、缓存与并发条件下的读取、保存、检索、同步、输入及取消受理；明确目标后验收，交付前复验 |
| 真实科研质量 | P3 起小样本试用，P5／P7 扩展 | 实际材料和成果、依据正确性、限制与人工接管；#21 明确后进行完整评价 |
| 独立审查 | 关键协议、数据保护、并发与复杂整合 | 直接核对契约、改动及实际结果，修正问题再确认完成 |

Agent 任务的总耗时、用量、调用次数和失败原因只用于诊断，不以固定篇数／分钟设性能门槛。杀进程检查不等同断电持久性；初次速度测量、原型成功或旧项目结果都不能直接证明本项目验收通过。

## 8. 近期建议与范围覆盖

近期建议依次交付 P1、P2a／P2b、P2c 与 P3。先让工作台连接真实内核，再让真实材料安全地流过同一条路径，然后让 Agent 使用它；每步都可以操作和反馈。P2c 覆盖已有数据的恢复应在扩大真实数据写入前完成，不等文献库全套功能就绪。

这段时间 Figma 从 F1 开始即可。若设计暂未推进，仍可继续 P4 的文献权威、摄取和阅读接线，以及 P6 的模块调查；涉及尚未明确的复杂交互先讨论具体动作，不把整个开发暂停。

初设覆盖分布如下，便于选取变更，不能据此把某一阶段标记为已经覆盖整章。

| 初设章节 | 主要落点 |
| --- | --- |
| 内核 K-01–K-05 | P1 生命周期，P2 起真实业务订阅，P3／E1 执行及宿主故障 |
| 数据 D-01–D-07 | P2 共用保护及项目移动，P4／E3 业务恢复，P7g 独立研究包，P9 综合恢复核验 |

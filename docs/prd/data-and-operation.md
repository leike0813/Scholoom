# 数据、授权与运行

本文定义产品在数据保存、多人机编辑、科研承接和运行控制中的共同行为。产品总览见 [PRD 首页](README.md)，科研方法与执行需求见[科研工作文档](research.md)。

## 数据归属与权威

研究事实先按所属文献库或项目划分，再确定保存方式。对象叫 Evidence 或 Claim，并不决定其全局归属。

| 内容 | 权威与归属 |
| --- | --- |
| 题录、附件记录、书签、批注、文献笔记、来源自身的主张与可复用分析 | 长期文献库，随来源管理 |
| 项目采用哪些证据，以及证据怎样支持、限制或反驳项目主张 | 项目研究事实，所引用库对象保持原归属 |
| 项目数据、代码、实验记录、结果与图件 | 项目材料，可作为后续工作的来源 |
| 稿件正文 | 实际源文件或文件组；数据库、编辑器和预览不各存一份当前正文 |
| 稿件采用的主张、审稿问题、回应及正式决定 | 项目事实，与对应稿件及必要版本关联 |
| 任务、计划、决定与必要执行记录 | 跟随负责的文献库或项目 |
| 搜索索引、解析缓存、定位视图与概览 | 可派生或重建，不能覆盖正式决定、身份绑定或研究关系 |

全局文献事实保存在文献库数据库，项目结构化事实保存在项目目录的本地数据库；正文、笔记、代码、数据、图件和方法内容保留开放文件。应用全局登记项目位置与必要摘要，项目读取和恢复不依赖这一登记。

稳定内部身份与 DOI、Zotero key、citekey、路径分别表达。关键证据、重要交付与审稿轮次保留实际使用版本；普通工作按用途记录必要信息。历史快照表示曾经使用的内容，不形成另一份可自由编辑的当前库记录。

项目结论经明确整理后可以成为跨项目知识，保留最初的来源和成立条件。核对文献确实如此表述，并不等于当前项目接受该判断。

依据：[领域边界](../../.scratch/scholoom-foundations/issues/06-research-domain-boundaries.md#answer)、[存储与变更](../../.scratch/scholoom-foundations/issues/13-storage-and-change-model.md#answer)。

## 开放编辑与保护已有内容

人、Agent、外部编辑器和科研脚本可以在授权内直接读写普通文件，无需先注册全部工作文件。GUI 与 Agent 通过共同领域服务处理明确管理的结构化事实。

已保存正文以源文件为准；未保存草稿提供恢复，也可显式交给 Agent。草稿遇到外部变化时保留已知内容。Agent 修改前核对当前目标，普通变化通过重新读取、调整工作或重做补丁处理。保护范围聚焦实际修改位置，避免因整份文件发生其他变化而停止任务。

同一处内容有实质研究含义歧义、持续竞争或无法同时保留各方内容时，只暂停相关修改，其他工作继续。本次修改范围依据当前内容核对，索引过期按需刷新；不持续跟踪历史原文位置，范围见 [#44](../../.scratch/scholoom-foundations/issues/44-defer-continuous-precise-source-location.md)。

普通授权修改直接应用，提供差异、撤销和有界本地历史。用户要求先审或授权规则需要时，使用候选修改。撤销保护后续编辑，记录回到原任务，并向负责 Agent 提供变化线索；撤销不自动重启任务。

数据库使用自身事务，文件保存提供必要局部覆盖保护。日常改稿不建立通用跨文件与数据库事务，不冻结全部工程。迁移、批量破坏性操作和明确复现任务按具体风险采用更强保护。

文件监听提供变化线索，不能保证任意外部程序互斥访问。GUI、Agent 和脚本读写同一份材料的实际保护能力需要验证。

依据：[低摩擦协同](../../.scratch/scholoom-foundations/issues/13-storage-and-change-model.md#answer)、[工件交互](../../.scratch/scholoom-foundations/issues/38-workbench-artifact-interaction.md#answer)。

## 持续研究上下文

工作区概览按项目或任务显示目标、约束、相关稿件、进展、重要决定、已知问题和下一步，每项有实际来源引用。发现支持按问题、任务、稿件、材料和内容查询；读取可展开完整材料、条件与历史依据。概览从事实源形成，不能成为第二份研究记录。

科研承接必须能从持久研究材料和事实取得，不依赖旧 Agent 的 session context 或 transcript。分析、推导、方案比较、判断理由和未解决问题在形成时保存为研究工件，关联相关对象。不能只保留最终结论或一段交接摘要。

Agent 在提出方案、完成分析、改变条件或明确下一步时，通过文件或领域工具保存内容。程序核对实际保存与产物引用，后续步骤直接使用这些材料。完整可取回和每次全部送入模型是不同要求，后者按任务需要和发送授权控制。

更换 Agent 时读取目标、条件、已放弃路线、已有结果、问题与下一步，再核对当前内容。运行 checkpoint 辅助执行恢复，不能代替科研过程。实际承接质量取决于保存内容是否充分、材料是否可读及 Agent 的研究判断，需要真实任务评价。

依据：[续做与复用场景](../../.scratch/scholoom-foundations/issues/29-research-continuation-and-reuse.md#answer)、[工作区承接](../../.scratch/scholoom-foundations/issues/35-research-workspace-context.md#answer)、[harness 协作](../../.scratch/scholoom-foundations/issues/25-harness-business-integration.md#answer)。

## 项目恢复时的材料变化提示

当前无人工作的项目 A 可能受到其他项目收录的新材料或来源更正影响。系统保存相关影响线索，待 A 恢复研究时提示，由用户手动启动复核。库更新及项目恢复本身均不自动启动 A 的科研维护或复核。

提示表达相关来源变化、可能受影响的成果，以及尚未复核的情况。候选影响未经科研判断，不能直接宣称原结论已失效。用户启动后，Agent 读取当前材料，按任务授权检查论证、保存结果并处理相应修改；正式判断仍沿原授权。

该决定针对无人工作的项目。文献库基础分析与主题综合的维护继续按[文献与知识文档](literature.md#分析与综合的维护)执行。

依据：[跨模块走查](../../.scratch/scholoom-foundations/issues/42-cross-module-research-walkthrough.md#q1-已确认无人工作的项目受到库更新影响)。

## 任务授权与人的决定

任务明确范围后，Agent 可以连续进行读取、分析、计算和产物编辑，复用已有授权。正式研究决定、原始材料的破坏性修改及对外提交设置相应授权或人工节点，具体规则可以配置。工具按任务范围控制操作，普通外部程序直接访问系统资源的权限边界另行表达。

正式决定形成各入口可查询的共同事项，保存提案、依据材料及版本、条件、授权主体、实际选择与影响范围。恢复执行时核对当前适用条件。接受方案、生成正文或完成图步骤不自动满足正式研究要求。

人可追加指令、编辑材料、暂停或取消。工作台的「需要你处理」入口只汇总确需用户判断的事项；当前材料读取、索引刷新和可安全重试由系统或 Agent 处理。

依据：[Agent 产品约束](../../.scratch/scholoom-foundations/issues/02-agent-first-contract.md#answer)、[核心能力模型](../../.scratch/scholoom-foundations/issues/17-native-research-capability-model.md)、[harness 协作](../../.scratch/scholoom-foundations/issues/25-harness-business-integration.md#answer)。

## 模型配置、材料发送与凭据

应用保存供应商连接和命名模型配置，用户选择默认模型，项目、任务与角色可覆盖，未指定则继承。每次执行记录实际供应商、模型和必要参数。修改默认配置影响后续请求，正在进行的请求保持原配置。

首阶段采用明确选择，不自动路由或静默切换供应商。用户切换时在请求结束或中止后的安全边界生效，核对接收方、材料发送授权和剩余额度；研究任务及目标未变的能力调用继续沿用，读取当前材料与成果接续。

项目或文献库规定可使用连接和可发送材料范围，任务继承并可收紧。读取权限与外部发送权限分别管理；新增接收方或扩大材料范围需用户确认，已授权范围无需逐次请求。同一规则覆盖 worker、上下文压缩与其他模型调用，限制依据明确范围或标记。

凭据由应用级服务统一提供，优先使用系统凭据库并支持环境变量注入，使独立内核可以使用。项目只存连接引用，密钥不进入项目、会话或日志。系统凭据库不可用时提示，由用户选择保存方式。

日常诊断记录状态、耗时、用量和必要错误。详细诊断显式开启，导出前可检查内容，默认不自动上传。用量缺失按未知处理。

依据：[模型、数据与执行政策](../../.scratch/scholoom-foundations/issues/22-model-data-and-execution-policy.md#answer)。

## 限制、等待与重试

应用提供连接级超时、并发与限流，内核管理的模型调用共用限制，包括委派、压缩和重试。任务可以配置调用次数、累计用量和总时长上限，但不能突破应用约束；持续科研任务默认不设统一硬性总时限。

达到限制时停止相关后续调度，保留成果，说明原因、在途工作及继续条件。首阶段不提供金额预算、价格估算或金额封顶。

确认可安全重试的临时模型失败默认最多额外重试两次，采用退避并尊重供应商等待提示；SDK 与应用共用该上限。凭据、参数或授权错误直接报告。超时断线后效果未知的调用先核查或暂停相关操作，写入不盲目重放。重试耗尽保留障碍，其他独立工作继续。

程序执行时限与工具请求等待分别表达。短命令有有限默认时限，长计算按任务配置可在受管后台运行；没有日志不自动判定卡死。请求等待结束不等于后台计算失败。程序实际超时按取消路径收尾，初值随真实工具验证。

依据：[模型政策](../../.scratch/scholoom-foundations/issues/22-model-data-and-execution-policy.md#answer)、[科研执行](../../.scratch/scholoom-foundations/issues/40-research-execution-environment.md#answer)。

## 生命周期、取消与恢复

同一应用数据配置共用一个内核，可管理文献库及多个项目。GUI 与 CLI 连接已有实例或协调启动一个实例。关闭工作台或客户端断线不自动取消任务；重新接入读取当前状态、待处理事项并恢复观察。默认不要求开机自启。

工作台自动发现并连接内核，确认未运行才启动；CLI 查询状态或停止操作不会创建新内核。断线采用有界退避重连，持续失败显示原因与重试入口，认证失败或协议不兼容直接说明。内核仍存活但不可连接时，不另起实例或强制替换；确认退出后由用户重试连接启动。

工作台与 CLI 提供明确的停止内核操作，说明影响所有客户端；正常关窗只关闭界面。明确停机后客户端停止自动重连，不能重新拉起内核。停机失败或超时如实说明，连接断开不等于内核已经停止。

明确取消时先停止后续调度并请求退出，必要时终止受管执行单元及其子进程。确认停止后标记已取消；不能确认时保留未知状态和原因。已完成成果及修改保留，普通取消不回滚既有效果。模型本地中止也不能表示供应商已经停止计算或收费。

内核重启核查未正常结束的执行、可能存活的进程和实际产物。按真实支持情况重新监测、从已完成步骤或可用 checkpoint 继续，或有限重试安全部分。高代价、难重复及效果未知的操作先检查实际效果，显式取消的执行不自动重启。

共享兼容宿主故障标记所有受影响调用，其他故障聚焦实际受影响工作。重启环境与重试业务操作分别判断。首阶段不另设常驻监督守护进程，外部程序重接与断点续算按平台和工具实际支持记录。

依据：[运行架构](../../.scratch/scholoom-foundations/issues/09-electron-architecture.md#answer)、[内核生命周期目标](../../.scratch/scholoom-foundations/issues/23-kernel-entry-and-lifecycle.md)、[执行与恢复](../../.scratch/scholoom-foundations/issues/40-research-execution-environment.md#answer)。

## 材料位置、引用文件与备份

文献附件默认托管，同时支持外部链接；项目文件直接使用当前目录，大型外部材料可保留链接。材料移动或缺失支持重新定位，缺项仅影响实际依赖工作。

已有 `.bib` 与 CSL JSON 作为项目资源，保留人工内容。新增或更正文献时按项目约定更新条目，或使用用户明确选择的自动导出文件；库导出不能整份替换手工文件。项目引用键映射到稳定来源，实际冲突在相关引用处解决；普通文件编辑不自动回写全局题录。

提供可关闭的自动备份，优先保护数据库、稿件、笔记和已管理重要材料，排除缓存与临时编译产物，大型外部材料按选择纳入。备份范围明确，必要恢复应实际核对。

项目独立迁移与归档可打包选用材料，列明未包含依赖。目录移动保留项目研究事实，完整原文读取及计算复现取决于材料和环境实际可用性。完整冻结和精确复现只用于明确需要的任务，日常无需保存所有输入和执行历史。

依据：[存储与变更](../../.scratch/scholoom-foundations/issues/13-storage-and-change-model.md#answer)、[高影响变更与恢复](../../.scratch/scholoom-foundations/issues/15-validation-and-release-discipline.md#answer)。

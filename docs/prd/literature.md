# 文献与知识

长期文献库为独立阅读和项目研究提供共同材料。Agent 可以发现、收录、分析和持续取用文献，人也可以直接整理题录、阅读与批注。材料可用性、分析成果和项目判断分别表达。总览见 [PRD 首页](README.md)。

## 文献获取

| 入口 | 产品行为 |
| --- | --- |
| Agent 线上检索 | 按研究目的形成查询，获得候选文献及筛选依据，记录检索覆盖与实际收录结果 |
| Scholoom Connector | 浏览器识别页面，选择目标库与集合，收录题录、附件或快照，显示各项实际结果 |
| 标识符添加 | 通过 DOI、ISBN、PMID、arXiv 等标识发现和收录材料 |
| 文件与题录导入 | 导入已有文献文件和标准题录内容，核对关联与缺项 |
| 既有库迁入与手动管理 | 迁入选定 Zotero 内容，也可直接建立和编辑条目 |

线上检索首批使用以下来源，Agent 按研究问题选择，无需每次全部查询。

| 来源 | 已确认职责 |
| --- | --- |
| OpenAlex | 广泛发现和来源关联，利用实际可用内容 |
| Crossref | DOI 题录查询与核对 |
| Semantic Scholar | 检索及参考、被引文献扩展 |
| arXiv | 预印本发现与版本查询 |
| PubMed／Europe PMC | 生命科学题录及相关开放获取内容 |

网页搜索和页面读取补充出版商、中文及区域来源、机构仓储等，搜索供应商尚未选定，不预设各站点都有可用 API。全文使用实际开放获取地址、OpenAlex 可用内容、arXiv／PMC 和其他仓储，首批不单独接入 Unpaywall。返回候选保留来源、标识符、地址、查询覆盖及部分失败，题录、全文位置与实际下载内容分别表达。

网页 translators 负责页面识别与采集，不能据此认定跨站文献搜索已具备。实际来源覆盖、配额和下载效果需要验证。

来源：[文献管理行为](../../.scratch/scholoom-foundations/issues/32-literature-management-behavior.md#answer)、[科研方法组成](../../.scratch/scholoom-foundations/issues/36-research-business-methods-workflows.md#answer)。

## 渐进可用与日常整理

搜索候选、条目收录、附件可读和分析可用是不同进展。题录可以先收录、供查询和整理；已有附件无需等待分析即可阅读。下载失败保留原因并可补取，批量操作提供每篇实际结果。缺某一层不使其余内容一并失效。

保留集合、子集合和标签，同一文献可进入多个集合，仍是同一条目。集合用于文献分组，主题用于知识组织和综合，两者可以关联。项目采用哪些材料及怎样评价，由项目管理。

重复收录确认属于同一文献、同一发表版本时复用条目、补齐缺项和新附件。字段冲突按来源与实际内容核对，保留可检查变更。疑似重复由人或获授权 Agent 判断合并，保留附件、笔记、批注及既有引用关系。预印本与正式发表版显式关联，保留差异。

附件默认托管，也支持外部链接和文件移动后的路径重新指定。一篇文献可有正文、补充材料等多附件，明确用途。替换涉及已有批注或关键证据时保留其依赖的材料与必要版本；旧记录继续关联原版本，原版本缺失时保留摘录并说明不可用。核查新版时形成新记录，不跨版本重绑旧位置，具体边界见 [#44](../../.scratch/scholoom-foundations/issues/44-defer-continuous-precise-source-location.md#answer)；定位问题只影响相关内容。

| 操作 | 结果 |
| --- | --- |
| 移出集合 | 仅改变分组，条目仍在库中 |
| 删除文献或附件 | 默认进入可恢复的回收站，保留必要内容与关系 |
| 永久删除或清空回收站 | 明确范围与已知影响，沿破坏性操作授权执行 |
| 移除外部链接附件 | 删除库内关联，删除外部原文件作为独立操作 |

库内删除保留项目已经保存的研究事实与必要历史材料，来源当前是否可用如实显示。人、Agent 和插件管理操作提供共同的成功、失败或部分完成结果。

来源：[文献管理行为](../../.scratch/scholoom-foundations/issues/32-literature-management-behavior.md#answer)。

## 共享阅读成果

人和 Agent 共同保存、查询与编辑书签、批注及文献笔记，也可在后续分析中读取这些内容。原文摘录、批注作者和 Agent 解释保持可辨；可复用文献理解随来源保存，当前项目的证据选择与判断归项目。

Agent 经内核材料服务读取原文、位置和批注，无需打开阅读窗口。GUI 与 Agent 使用同一附件及阅读结果，阅读组件负责呈现和交互，来源、材料版本与证据关系由内核管理。

来源：[共享阅读](../../.scratch/scholoom-foundations/issues/32-literature-management-behavior.md#answer)、[阅读与定位](../../.scratch/scholoom-foundations/issues/11-reading-writing-format.md#answer)。

## 分层知识与分析产物

文献按题录／元数据、Digest、原文三层渐进取用，元数据可含论文 abstract。Digest 是 Agent 的文献分析产物，区分作者主张、分析者解释和材料限制，关键结论关联来源位置。

首批单篇成果吸纳 zotero-agents 的成熟实践：

| 产物 | 用途及内容边界 |
| --- | --- |
| Digest | 理解方法、结果、论证与限制，供后续研究决定是否深入原文 |
| 参考文献提取 | 识别文献引用的来源及必要关联 |
| 引用分析 | 分析引用关系及其内容语境，保留所依赖材料 |
| 文献评价 | 提供评价维度、依据及适用条件，缺材料的维度说明缺项 |

基础分析围绕文献自身，供不同任务复用；定向分析围绕具体研究目的，按研究语境归属。不同目的、方法或观点可以并存，新分析不因更晚生成而覆盖旧分析。可靠的来源事实更正可依授权修正基础理解，项目相关性和结论仍归项目。

旧项目的文件名、Schema 和评分规则不作为本产品的固定契约；Agent 可以沿分析中的来源关系继续读取原文。

来源：[文献场景决定](../../.scratch/scholoom-foundations/issues/26-research-scenarios-and-existing-toolchain.md)、[分层知识](../../.scratch/scholoom-foundations/issues/33-layered-literature-knowledge.md#answer)。

## 统一发现与直接读取

统一混合检索覆盖题录、各类分析、原文片段和主题综合，组合词法匹配与语义召回。Agent 选择查询、范围与所需层级，也能单独查询或读取某一层。标识符、标题和明确术语保留精确及词法匹配，自然语言问题结合语义召回。

同一文献的命中归组，同时保留层级、产物及原文位置，避免长论文以大量片段挤满结果。返回有界命中、来源引用、定位和覆盖情况，引用可直接用于继续读取。无需调用多个索引再自行拼接排名。

读取交付可以消费的内容：题录和结构化分析返回内容与引用，Digest、综合报告和笔记返回正文、来源及适用条件，原文支持局部展开与分批读取。需要视觉核验的图表、公式等提供页面或区域访问，并保留原材料关联。特殊处理仍能直接访问文件并使用其他工具。

格式解析由材料读取模块承担，解析成果可复用与维护；索引存可重建检索数据，实际内容从材料和产物取得。解析未完成或定位失效时提供真实可用情况。三层关系不要求每次逐层通过，Agent 可以直接读取需要的原文。

检索切分、融合权重、嵌入模型、索引产品与精确工具 Schema 尚待实验和具体规格，召回质量与性能未验收。

来源：[统一混合检索与读取](../../.scratch/scholoom-foundations/issues/33-layered-literature-knowledge.md#answer)。

## 分析与综合的维护

文献入库且可用材料就绪后自动生成基础分析。库中缺失或受材料实质变化影响的产物后台补齐、更新，优先处理当前研究需要的材料；缺必要材料时保留可用层级和真实缺项，补齐后继续。

主题表达目的与可发现材料范围。系统可发现初步主题，人和 Agent 可调整、合并或拆分；长期知识主题及持续研究主题按其安排维护。临时语义查询即时探索，有持续价值时再保留为维护主题。综合吸纳分类、主张、争议、研究局限、未来方向与来源关系，并反过来为选题提供线索。

实际依赖与发现范围分别保存：依赖说明既有成果用了哪些材料和分析，发现范围用于评估尚未采用的新来源。程序识别变化及候选影响，Agent 判断科研意义与补充或重做方式。题录展示性更正更新展示与检索；正文、补充材料或所用分析变化再检查依赖成果。未实际使用的批注变化不默认重做全部分析。

保留上次成功交付和当前更新过程。旧成果仍可读，同时显示采用材料、尚未纳入变化和已知来源问题；新结果满足交付要求后更新该用途的当前成果。新增文献未纳入与原证据更正、失去定位分别表达。失败、中断或缺材料保留可用成果和障碍。

| 变化 | 维护行为 |
| --- | --- |
| 文献入库 | 题录和已有附件立即可用，材料就绪后开展基础分析 |
| 补齐原文 | 补齐依赖原文的分析，检查相关综合受影响部分 |
| 新增相关文献 | 按主题目的及发现范围评估，纳入后维护综合与来源关系 |
| 更正基础分析 | 沿实际依赖检查综合及项目采用结果，按科研影响处理 |

项目论证与正式判断沿任务授权和研究语境处理。无人工作的项目保存影响线索，恢复时提示并由用户手动启动复核，详见[项目恢复规则](data-and-operation.md#项目恢复时的材料变化提示)。

维护沿共同运行时的取消、恢复、模型限制和发送授权执行，普通变化局部处理。触发、增量更新正确性、质量与性能仍待验收。

来源：[分析综合维护](../../.scratch/scholoom-foundations/issues/34-analysis-synthesis-maintenance.md#answer)、[项目复核决定](../../.scratch/scholoom-foundations/issues/42-cross-module-research-walkthrough.md#answer)。

## Scholoom Connector 与 Zotero 共存

提供独立命名、发布和维护的 Scholoom Connector，复用合适的 Zotero 页面识别、translator、附件和快照采集能力，使用自己的保存交互接入 Scholoom 库与集合。

自有扩展默认保存到 Scholoom，官方 Zotero 扩展继续保存到 Zotero。两者并用是验收情境，目标不可用时提示原因和重试机会，不静默改存其他应用或云端。条目保存和附件获取分别显示。

浏览器适配、配对、采集后的保存、扩展共存及上游维护由 Scholoom 负责。自有扩展按项目 AGPL-3.0 许可开源，保留来源声明，按实际分发提供对应源码和构建脚本，第三方内容另行核对。

来源：[Zotero 生态接入](../../.scratch/scholoom-foundations/issues/41-zotero-ecosystem-integration.md#answer)、[兼容政策](../../.scratch/scholoom-foundations/issues/05-zotero-compatibility-policy.md)。

## 首批插件功能与维护

首批支持指定版本的 Better BibTeX 和茉莉花，原发布包和代码保持不修改，由通用宿主适配。Scholoom 可用自己的 UI 呈现功能，Agent 通过共同入口调用；使用产品不要求另行安装、启动 Zotero。

| 插件 | 首批目标功能 |
| --- | --- |
| Better BibTeX | 引用键生成与保留，BibTeX／BibLaTeX 导出，自动导出、pull export 及对外 JSON-RPC |
| 茉莉花 | 中文元数据识别与补全，中文 translators 与 CSL 样式，本地附件匹配，PDF 大纲及书签 |

迁入键、用户指定键和已生成键默认稳定保留，题录更正不自动改键。新增条目按 BBT 配置生成；明确重生成时处理冲突并核对受影响的已知项目引用。项目键与库键的差异通过映射关联，项目引用文件的保护沿[数据文档](data-and-operation.md#材料位置引用文件与备份)。

发起元数据补全后在授权内自动填空并记录来源；已有标题、作者和 DOI 等冲突保留候选，由人或获授权 Agent 核对。失败不清空字段；中文作者处理等改写行为按明确配置启用，经共同文献服务保存。

茉莉花大纲与书签接入自有阅读器，支持标题、层级、位置的读写、导航与重启保存。Agent 独立使用同一附件的结果，无需可见阅读窗口。PDF 写回保护原材料、批注与证据定位，失败保留已有内容并报告实际效果。

插件只升级到 Scholoom 已验证版本，不直接启用上游自动升级。Translators 与 CSL 从明确来源独立更新，记录版本，保护用户自定义内容，失败保留可用资源并支持回退。

通用兼容层覆盖共享 Zotero 宿主契约，支持范围按版本与功能实际验收逐步扩大。加载成功、界面展示、Agent 调用和具体业务各自验证，内部桥接 RPC 不替代对外接口验收。

来源：[首批兼容目标](../../.scratch/scholoom-foundations/issues/05-zotero-compatibility-policy.md)、[宿主路线](../../.scratch/scholoom-foundations/issues/16-zotero-host-prototype.md#answer)、[生态行为](../../.scratch/scholoom-foundations/issues/41-zotero-ecosystem-integration.md#answer)。

## 单向迁入与安全续做

首阶段迁入用户选定的个人库和本机可读取的群组库内容，源库和源附件保持原状。迁入部分后续由 Scholoom 独立维护，来源后续修改通过明确再次导入或更新处理。

保留来源库区分、稳定身份映射、集合层级、标签、题录、引用键、笔记、批注和附件关系。托管附件复制，链接附件默认保留链接或按用户选择转为托管。缺失、未下载和不可读取材料逐项说明；不能完整转换的内容保留可恢复原材料并报告差异。账号、群组成员权限和 Zotero 在线同步关系不随内容迁入。

首批插件必要状态按语义迁入，包括引用键与固定状态、可映射规则和偏好。导出任务与路径先作为配置候选，核对后启用写文件行为；缓存和索引重建，不能映射配置列明差异，不承诺复制任意插件内部数据库。

迁入前检查范围、可读材料、目标差异和缺项；完成后逐项提供成功、失败及转换限制，核对关系并抽样打开附件、笔记与批注，检查引用键导出及重启读回。数量一致不能单独证明迁入成功。

失败或中断保留确认完成部分，重试核对身份映射和实际对象，保护迁入后编辑。撤回仅处理仍可安全撤销的变更，保护后续修改和项目使用关系，不能安全撤回部分明确说明。真实迁入前在副本或样本中验证中断、重试、撤回和备份恢复。

来源：[迁入范围与恢复](../../.scratch/scholoom-foundations/issues/41-zotero-ecosystem-integration.md#answer)、[高影响变更保护](../../.scratch/scholoom-foundations/issues/15-validation-and-release-discipline.md#answer)。

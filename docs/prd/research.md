# 科研工作与 Agent 协作

科研业务提供可复用方法、能力和工作流，Agent harness 负责组织执行、上下文、授权和交付。普通探索与正式流程共用科研内核。总览见 [PRD 首页](README.md)，数据和运行政策见[共同运行文档](data-and-operation.md)。

## 科研方法的组织

科研业务吸纳 zotero-agents 与 ResearchSpec 的成熟实践，按六组组织。业务流程由 LangGraph Graph／子图表达，Graph 组织 Agent、领域工具与程序节点，研究可以按需要组合及往返。

迁入的工作流与原生 Agent 共用[一等交互接口](../../.scratch/scholoom-foundations/issues/45-interactive-research-reports.md)，按需要呈现、更新交互界面，接收用户选择与输入并继续工作。文献筛选、综合比较、方案选择、结果探索及审阅处理可沿同一入口接入；具体适配与实际效果随实现验证。

| 方法组 | 工作内容 | 主要成果 |
| --- | --- | --- |
| 文献发现与收录 | 查询、网页补充、标识符识别、全文获取、筛选和整理 | 候选、筛选依据、实际收录结果和覆盖说明 |
| 文献理解与综合 | 单篇分析、阅读、比较证据、主题整理、争议和局限分析 | 文献分析、综合报告、来源关系、限制与研究线索 |
| 研究问题与方案 | 明确问题、比较路线、设计方法与分析计划 | 问题与条件、方案比较、研究计划、选取理由和待判断事项 |
| 研究实施与结果解释 | 使用或获取数据，执行分析和计算，组织实验或推导，检查结果、生成图件 | 代码、数据、实际结果、图件依据、解释、限制和未解决问题 |
| 写作与审阅 | 论证规划、文献定位、章节起草、引用核验、学术审阅及文风建议 | 实际稿件、可定位意见、论证依据和修改要求 |
| 修订与交付 | 回收反馈，安排补充验证与修改，组织回复、渲染及交付检查 | 修订稿、回复、处理记录、交付文件及未完成事项 |

主题知识整理与面向研究问题的证据综合保留不同目的，共用来源读取、证据比较、定位和交付检查基础。旧 Skill／capability 包按业务流程、节点指令、模板、程序与校验素材拆解迁入；受限第三方内容不默认内置。

项目定向综合按研究问题组织，报告及其引用的过程材料共同保存范围与材料取舍、按问题选择的比较维度、有来源支撑的发现、冲突证据、成立条件和不确定性，以及未解决问题与下一步。领域研究局限、本次材料覆盖不足与当前证据不足分别表达；研究空白需要实际依据。不同课题可采用不同章节、表格和叙述方式，不以版式或文件完整替代研究内容。具体约定见[综合内容与复核要求](../../.scratch/domain-development/issues/04-research-methods-scope.md#综合内容与复核要求)。

## Agent、业务 Graph 与能力

Agent 按角色、资源与授权开展研究，工具提供具体领域操作。科研能力表达可发现、可调用工作的输入、产物、资源及检查约定，对应的业务流程由 Graph 定义。Graph 明确步骤、依赖、分支、循环、必要检查与人工等待，节点可调用 Agent、工具、程序或子图。

节点使用的提示词、操作指导、参考资料、脚本和模板按职责组织，可复用旧 Skill 的适用内容。流程控制由 Graph 承担，不能仅把加载完整业务 Skill 的 Agent 放进通用图后视为业务 Graph 已接通。具体决定见[Graph 承载科研业务流程](../../.scratch/domain-development/issues/04-research-methods-scope.md#graph-承载科研业务流程)。

普通会话仍可使用获授权工具和辅助指导，不要求每个问题先注册业务 Graph。明确调用科研能力入口时，运行时核对输入、推进对应 Graph、记录必要调用并检查结果；单次工具使用、资源加载或内部节点不自动创建任务和新业务调用。

研究任务按独立目标、责任和交付需求划分。一个 Agent 可使用多项能力，同一能力可由不同 Agent 执行。研究计划可调整，记录备选路径及理由。

业务 Graph 内部复用节点与子图，执行步骤和结果沿共同运行机制记录；有独立科研使用或交付需求时，再建立相应调用，研究任务按既有规则创建。图步骤、科研任务、能力调用与会话身份保持各自语义。

来源：[核心能力模型](../../.scratch/scholoom-foundations/issues/17-native-research-capability-model.md)、[运行内容契约](../../.scratch/scholoom-foundations/issues/18-native-capability-runtime-and-content.md)、[简化协作契约](../../.scratch/scholoom-foundations/issues/25-harness-business-integration.md#answer)。

## 研究主题与研究任务

研究主题是长期持续维护的知识集合，由文献与知识模块掌握，随文献库持久化维护。研究任务面向一项具体产出，通常最终形成论文，由项目掌握，相关内容在项目工作区以文件形式持久化维护。

项目作为容器，允许多个研究任务，通常从一个任务开始；相关任务可共享项目内的数据、代码和材料，并保有各自的目标与成果。库中文献与主题知识在项目区仅记录指针，由 harness 在需要时通过工具读取；UI 可经内置资源协议直接在阅读器打开。任务自己的采用理由、分析、计划、过程与成果保存在工作区文件中，库知识继续由库维护。

各任务分别维护采用、排除理由和引用关系。重定向只修改明确指定的引用，跨任务修改明确范围；项目概览汇总这些事实，库维护文献和知识自身的事实。

任务内部的文献综合、实验、计算、写作和修订优先以研究计划工作项组织，支持依赖、并行、委派及调整；形成独立研究目标和最终成果时再建立关联研究任务。每项任务有一个入口文件，以少量结构化元信息和正文表达任务身份、目标、交付、当前计划及材料和成果入口；详细过程、计划和稿件可按需拆分，入口引用所属文件，各项内容一处维护。

入口及计划维护当前安排，过程文件保存完整比较、研究条件与调整理由，当前安排引用相关依据。Agent 按用户指令、明确附加的任务或相关材料定位工作，先读候选摘要及相关入口，再按需展开过程、项目材料、成果和库知识；可推进多个相关任务，候选确有歧义时才询问用户，不按最近修改猜测或绑定会话。

研究任务按动态状态持续演进：规划时可约定当前完成条件，达成后仍可扩充目标与条件，保留已有成果和当时的研究条件。

库知识引用可靠性是科研可信度红线，禁止在读取失败后以其他内容 fallback 充当所指依据。项目自行持有指针，系统不建立库材料与项目引用的反向映射表。材料创建时取得唯一标识，删除后重新入库使用新标识；回收站恢复原对象保留原标识与删除历史。删除记录保留操作者及必要语义信息，文献至少保留标题，支持明确恢复、重新入库或重定向。

材料引用异常按已确认的[材料引用行为矩阵](../../.scratch/domain-development/issues/03-project-research-assets-scope.md#材料引用行为矩阵)处理：系统访问及托管读取异常、明确删除、外链失效、权限拒绝和身份不符均由 Agent 暂停询问用户，收到明确选择后才继续。对象不存在且无删除记录时返回明确错误，由 Agent 核查处理。正常知识更新由 Agent 在已有授权内核对研究影响，正式研究决定按相应规则处理。等待用户期间不自行选择恢复方案，外链失效保持独立分类。

## Agent 会话与研究任务对象

所有 Agent 会话统一建模，可以提问、探索、讨论，也可以在已有授权内读取材料、使用工具、编辑文件、执行计算和委派协作。具体能力由 Agent 配置与授权决定；实际修改和执行保留必要记录。

会话采用通用 harness 的基本模型，用户与 Agent 自行组织话题、并行工作和对象操作，包括多个会话同时编辑同一文件。科研专门化通过工具、材料访问、领域对象与专业交互提供；额外机制须解决实际问题，不为统一工作组织方式限制会话自由度。

Agent 通过共同工具读取、创建和更新研究任务及其工作区文件。用户明确提出，或 Agent 建议并经用户确认后建立任务；工具使用、多步工作及首条指令不自动创建任务。已有材料、成果和工作记录可以关联到任务，无需另开或绑定会话。创建时明确目标与范围，计划逐步形成。

会话不设置自由对话或研究任务对话类型，不建立显式任务绑定。研究任务可以采用开放探索或正式工作流，具体能力调用及对象操作契约继续细化。

能力调用按实际用途关联文献、研究主题或项目研究任务，研究任务关联按需提供；一次调用不自动创建任务或使会话绑定任务。调用记录所用能力与业务流程、发起工作域、实际材料、执行尝试及交付，仍由科研运行模块及 harness 掌握，成果交回所属库对象或项目工作区。具体决定见[能力调用与方法域设计范围](../../.scratch/domain-development/issues/04-research-methods-scope.md#能力调用与方法域设计范围)。

系统提供固定的全局会话分类，可视为固有系统项目，容纳多个共用通用 harness 的会话。其工作区由系统管理，原则上不产生持久科研工作文件，临时工作文件按会话隔离。文献库工作可在全局会话开展，成果及接续所需分析、理由、进展和下一步保存到对应文献／主题及其分析记录；会话与必要执行记录按既有规则持久化。清理临时区不删除库成果，接续不依赖临时文件或原聊天记录。

全局会话可在目标项目信任、材料范围与模型外发授权内读取其他项目内容，不能修改目标项目。只读约束覆盖工具和程序，不在目标项目内运行会写缓存、修改环境或生成产物的脚本。全局会话只开放能实际落实访问限制的程序入口，暂不直接开放无隔离的通用 Shell／任意代码入口；临时文件可通过受控工具处理。具体决定见[全局会话与工作域](../../.scratch/domain-development/issues/04-research-methods-scope.md#全局会话与工作域)，临时区清理时机和导航操作由后续设计细化。

依据：[统一会话与研究任务对象](../../.scratch/scholoom-foundations/issues/43-free-agent-conversation-and-research-tasks.md#answer)。

## 普通持续工作与正式流程

普通持续工作可使用获授权工具、比较方案和修改产物，随实际研究调整计划。可复用科研业务流程由 Graph 表达；需要依赖、并行汇合、审查轮次或授权决定时在相应 Graph 中落实，仍由同一运行时执行。

正式待决定事项跨 GUI、CLI 与 Agent 入口共同查询，绑定提案、依据材料及版本、条件和授权主体，等待后可以恢复。步骤完成、文件生成或 checkpoint 写入不自动确认研究判断。决定返回后核对当前条件，满足适用要求才继续有关工作。

首批提供三类可复用稿件工作流：

| 工作流 | 整体目标 |
| --- | --- |
| 稿件审阅与改进 | 形成可定位意见，安排实际修改和必要复核，保留未处理事项 |
| 外部评审修订与回复 | 保留原评审，补充验证、修订稿件并形成有实际依据的回复 |
| 稿件交付准备 | 按原生格式与目标配置渲染、组织文件和检查交付 |

上述流程以业务 Graph 实现，节点与子图按实际需要复用，有独立用途时提供相应能力入口。程序检查结构、资源和保存结果，科研 Agent 判断证据及研究要求是否满足。执行成功、材料完整与学术充分性分别表达，局部缺项只影响实际依赖工作。

首条文献综合路径允许单个 Agent 完成取材、综合和依据核查，不以多 Agent 作为必需前置。科研 Agent 核查论据是否支撑结论、冲突如何处理及结论是否超出材料范围；用户或能力明确要求独立复核时，须实际完成，缺少对应能力则报告未完成，不能用自查替代。正式研究决定继续沿相应授权规则。

## 内容发现与科研工作包

共同发现体系提供已注册科研能力、对应业务 Graph 的描述、实际来源和版本，纯文献库工作无需项目研究任务。同名或同身份候选可辨并由配置或本次调用明确选择，目录顺序不静默覆盖。GUI、CLI 与内置 Agent 使用相同定义与版本。

先提供当前工作与可见范围相关的能力摘要、输入及交付约定，再按需取得必要指导与资源，支持主动搜索和精确查询。首批业务 Graph／子图由 Scholoom 的 TypeScript 源码定义并注册，节点指令、模板和检查素材随实现维护；用户／项目通过已开放参数配置目标、材料范围、模型／角色及复核要求，配置不绕过必要检查或扩大授权。首批不提供用户／项目自定义 Graph 功能。具体业务流程的节点、顺序和回路另行设计，当前校准与交接要求不代表这些结构已定案。

有效做法按流程、节点指导、模板、程序和检查素材分别沉淀，保留用途、条件、来源与验证结果。Graph 与配套节点资源作为整体实现追溯版本，不另建独立方法／提示词版本和发布体系；调用记录实际 Graph／实现版本、模型配置、采用材料及成果引用。普通执行保留必要信息，明确复现要求时留存所需实现、资源和环境，不默认归档每次执行的全部源码和环境；一次成功不自动成为默认流程。具体版本标识可结合应用构建，由实施规格核对。

当前先设计共同科研 Graph 运行基础，覆盖内建注册与配置、可信执行上下文与生命周期、材料及成果交接、记录检查与诊断。固定夹具 Graph 接入真实科研运行模块与共同调用路径，明确模型及未就绪领域端口的替身边界；该验证不能代替实际业务 Graph 经产品入口的科研验收。范围与分工见[科研业务 Graph 与工作流决定](../../.scratch/domain-development/issues/04-research-methods-scope.md#answer)。

Graph 中的 Agent 节点在职责范围内自主工作；需要并行、独立审阅或独立上下文时委派 worker，提供科研工作包：目标、相关任务、初始材料、可用资源、授权范围、交付要求和检查标准。执行者可在范围内继续发现材料，其权限同时受调用方与工作包限制。

主 Agent 与 worker 共用内置 LangGraph harness，可选择不同模型供应商，流程控制、暂停与恢复沿同一机制。更换 Agent、会话或执行尝试从持续研究事实和产物续做，不要求精确重放全部历史。插件 MCP 提供受管理的工具能力，不作为外部 Agent 执行接入；对外 MCP 的查询与有限工作请求同样不改变内部执行权威，公共范围沿[外部接口决议](../../.scratch/runtime-architecture/issues/07-external-interfaces-and-extensions.md#answer)，接线仍待实施。

## 主动跨会话协作

Agent 可以按工作需要定向联系获授权的其他会话，提问、请求处理、转交工作或通知成果。已有会话各自保持交流与执行上下文，通信本身不取得对方会话控制权，也不要求创建或绑定研究任务。

收件后有界唤醒处理：运行中的会话在下一可处理边界消费来信；空闲且允许自动协作时，在已有资源上限内处理；用户明确暂停或停止后保留来信并显示待处理。界面区分消息已受理、Agent 已消费和请求的实际结果，不能把收到通知显示成工作完成。

后台或子执行结果交给负责的 Agent，由其结合目标、当前结果及有效授权判断后续；系统负责保存、投递和有界唤醒，不以结果到达直接判定业务应推进，沿[结果处理决议](../../.scratch/runtime-architecture/issues/04-execution-persistence-and-recovery.md#q8结果到达交给-agent-判断)。

协作中的分析依据、决定与成果保存到工作区，回复可以引用这些材料；当前协作上下文不成为跨会话科研承接的唯一来源。subagent 委派与 advisor 沿各自管理和上下文约定，共用原生运行基础。

来源：[多 Agent 交互初设 #46](../../.scratch/scholoom-foundations/issues/46-multi-agent-interaction.md)。用户于 2026-10-14 采纳初设，具体交互、字段和执行机制在实现中打磨。

## 多模型分工与学术审阅

角色配置引用共同方法和命名模型配置，可以由用户或项目派生、任务覆盖，不固定模型品牌，也不要求每次全部启用。

| 角色 | 职责 |
| --- | --- |
| 主 Agent | 组织工作、分派、汇总意见、安排修改，按实际成果核对交付 |
| 执行者 | 起草、分析、补充验证或修订，交付实际结果 |
| 学术审阅者 | 按研究设计、论证与证据、文献与引用等视角审查，提供定位、依据和限制 |
| 文风 advisor | 针对 Agent 生成文本提供去 AI 化建议，由写作 Agent 处理 |

学术分工审稿默认独立初审。各审阅者读取稿件、研究材料和标准，首轮不预先接收其他审阅意见或主 Agent 拟结论；已有证据、条件和作者明确约束仍可读取。后续讨论或复核再共享保存意见。

审阅者默认保存报告和候选修改，不直接修改被审稿件。主 Agent 汇总，安排获授权执行者修订并按需要复核；工作包可明确赋予修订职责。原意见保留角色、模型、实际材料、当时摘录及可用位置，处理记录关联理由及实际修改，汇总不替代原意见，多数票不确认科研结论。意见与 advisor 建议不随编辑持续跟踪精确位置；需要复核时读取当前稿件，沿[定位范围约束](../../.scratch/scholoom-foundations/issues/44-defer-continuous-precise-source-location.md)处理。

用户在审阅期间修改目标时，应用前读取当前内容并协调相关部分。意见处理、实际修订与整体交付分别核对，普通授权修改不增加逐项人工审批。

## 可开关的文风 advisor

用户显式开启或关闭文风监督。advisor 取得当前有效写作上下文和约束，接收新增生成文本、材料读取结果及相关变化；上下文可包含用户材料，建议目标限定为 Agent 生成文本。用户自写或修改文本不因保存而自动进入文风处理，作者身份不能靠检测文风猜测。

在 Agent 完成一段生成文本的执行边界后台评审，提供独立建议消息，包含定位、理由和可用改写，默认使用读取及建议提交权限。写作 Agent 结合研究依据决定怎样处理并实际修改，对事实、引用、数值、条件和结论强度负责。建议、处理理由与修改关联持久保存，无建议时静默。

写作 Agent 结束本轮前有限等待已触发评审。收到具体建议后可在原任务继续修改，这次继续默认不重复触发同一轮监督。超时或模型失败保留状态与成果，说明监督未完成；关闭或主动停止后停止新增监督与自动继续，未注入建议保留可查看。

持续参与和对阶段性生成成果集中审阅均在需求范围内，沿同一对象范围和方法组织。建议时机、含义保持、停止效果及延迟需要真实模型验收。

来源：[advisor 行为](../../.scratch/scholoom-foundations/issues/37-multi-model-research-collaboration.md#answer)、[运行协作](../../.scratch/scholoom-foundations/issues/25-harness-business-integration.md#answer)。

## 科研程序执行与环境

支持 Agent 使用已有数据、代码和结果，也可执行分析脚本、计算及外部工具生成新材料。默认按项目配置确定工作目录，代码、输入、报告和图件直接保存在工作区，纯中间文件与缓存放受管临时位置。

在配置或任务已经授权的范围内，运行时自动准备并复用所需解释器、依赖和 TeX 宏包。准备失败说明具体缺项与已采取操作，独立工作继续；扩大依赖范围或改动用户已有环境需相应授权。用户工程沿自身环境声明，已有解释器或 Conda 可按明确配置使用。

执行记录提供实际状态、错误、必要日志和产物引用，GUI 与 Agent 读取共同结果。普通计算只复用已完整且满足用途的部分，未完成文件可查看但标明状态；不能仅按退出码或文件存在确认科研交付。渲染预览另保留最后成功产物，其授权和失败表现见[工作台文档](workbench.md#预览与工程渲染)。

短命令时限、长后台计算、取消和恢复沿[共同运行政策](data-and-operation.md#限制等待与重试)。强安全隔离不在首阶段承诺，资源限制和安全边界分别说明。

来源：[科研执行环境](../../.scratch/scholoom-foundations/issues/40-research-execution-environment.md#answer)。

## 交付、分批成果与接续

科研工作形成时实际保存分析、方案比较、理由、结果和下一步，关联任务、能力调用或步骤。工具返回保存结果和可读取引用，程序核对必要产物，Agent 自述不能代替保存。

每批成果与问题随执行保存并局部检查，已满足用途的部分可以使用；整体完成按整体要求判断。声明独立复核的任务将实际产物、必要材料和标准交给检查者，发现分歧或不足交回负责 Agent 补充或修订。

更换 Agent 或会话从工作区材料接续，取消保留已保存成果，高代价或效果未知操作先核对实际结果。修订与回复的完成声明须对应成果及稿件版本，证据不足也可以作为完成评估的结果，但不能作为未完成实验的完成声明。

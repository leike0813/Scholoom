# 验证与分发 Specification

初设参考；适用方式见 [总入口](README.md)。

## Purpose

规定本初设转为实际交付时需要的验证证据，区分确定性行为、真实科研质量和平台分发范围，以真实数据及接线核对恢复和升级，避免原型、构建成功或局部测试被误认为完整产品已经通过验收。

依据：[质量与发布 PRD](../prd/constraints-and-validation.md)、[开发纪律 #14](../../.scratch/scholoom-foundations/issues/14-agent-development-discipline.md)、[验证发布 #15](../../.scratch/scholoom-foundations/issues/15-validation-and-release-discipline.md#answer)、[双宿主 e2e #20](../../.scratch/scholoom-foundations/issues/20-ui-debugging-and-e2e-harness.md#answer)、[科研评价 #21](../../.scratch/scholoom-foundations/issues/21-agent-dogfooding-and-evaluation.md)。

## Requirements

### Requirement: V-01 真实接线与独立模块验收

模块 SHALL 按自身契约独立验证，提供状态、失败原因及必要诊断入口；跨模块验收使用真实内部接线。确定性 e2e SHALL 使用真实内核、文件、数据库及必要兼容宿主，受控响应仅放在外部模型或远程依赖边界，并检查实际持久化或产物。每轮使用隔离的配置、库、项目及输出，明确进程归属。

#### Scenario: 界面显示动作完成
- **WHEN** e2e 通过用户入口提交保存或科研动作
- **THEN** 同时核对真实文件或领域状态，不能只凭界面文本认定成功

#### Scenario: 模块先于完整路径交付
- **WHEN** 模块依赖以替身参与独立验收
- **THEN** 记录替身与实际验证范围；完整路径整合后再核对真实接线，不把独立验收要求解释为独立进程或包

### Requirement: V-02 双宿主与测试工具维护

浏览器和 Electron SHALL 复用真实工作台组件、session 及事件路径；preload、IPC、原生能力和生命周期在真实 Electron 验证。Playwright 为当前共同测试路线，接入障碍按证据选择修复、暂缓非必要升级或迁移，不为测试便利长期拖延必要安全升级。

#### Scenario: Electron 自动化 API 因升级不可用
- **WHEN** 新版本破坏当前自动化接入
- **THEN** 记录障碍和受影响验证，选择并核实可行处理；浏览器通过不替代 Electron 验收，WebdriverIO 仅作为待评估备选

### Requirement: V-03 故障与数据保护验证

恢复验证 SHALL 先在关键提交边界进行可重复故障注入，核对实际文件、关联、正式决定和副作用；共同机制集中验证，高影响业务增加对应恢复场景，再按风险补充随机故障。测试 SHALL 区分杀进程与断电持久性，未知效果不能算通过。

#### Scenario: 文件已保存但关联状态未确认时中断
- **WHEN** 注入故障并重新启动
- **THEN** 核对实际文件和数据库关系，验证缺项可补、已完成不重复，未知效果先核查

#### Scenario: 外部编辑与保存持续竞争
- **WHEN** 外部编辑器连续保存或 Git 切换文件内容，同时 Agent 尝试修改
- **THEN** 验证内容变化时拒绝旧修改并重读、局部暂停和后续内容保护，记录外部竞态限制，不宣称获得外部互斥

### Requirement: V-04 确定性动作性能门槛

性能门槛 SHALL 仅用于确定性动作，记录硬件、版本、输入规模、并发和缓存条件，结合使用要求确定目标，开发中检查回归并在交付前复验。检索、读取、保存、快照同步以及 Agent 运行期间的输入、浏览、取消受理均在适用范围；取消受理与外部执行实际停止分别衡量。

#### Scenario: 首次性能测量
- **WHEN** 在给定环境测得确定性动作耗时
- **THEN** 结果作为现状基线，对照使用要求确定门槛，不仅因为已有测量就判定合格

#### Scenario: 并行负载暴露数据库或 UI 瓶颈
- **WHEN** 真实规模的数据库操作、长会话或持续输出使交互不满足目标
- **THEN** 按证据调整查询、线程、访问方式或 UI 接线并复验，不把同步数据库调用或组件负载假设当成不可修改原则

### Requirement: V-05 真实科研质量与执行诊断

真实科研验收 SHALL 经产品入口运行，覆盖文献、方法结果、图表、整稿、投稿及修订回复，检查独立运行、后续接入和跨会话承接。Agent 整体耗时、用量、调用次数与失败原因用于诊断，不设置固定篇数／分钟的端到端性能基线；成果按科研要求另验。

#### Scenario: 外部 Agent 协助验收
- **WHEN** 外部 Agent 驱动或评价 Scholoom
- **THEN** 科研成果仍由产品内执行产生，外部 Agent 代写产物不能算作产品通过

#### Scenario: 汇总科研评价
- **WHEN** 展示多个科研任务的评价结果
- **THEN** 分开呈现客观结果、独立模型评分与人工判断，区分首次、重试和基础设施失败，未知不算通过，关键失败不被平均分掩盖

样本、评分尺度与重复次数仍沿 #21 在功能初步可用后确定。

### Requirement: V-06 备份恢复及用户处置说明

迁入、Schema 升级和高影响批量变更 SHALL 先在副本或样本验证结果及恢复，检查后续编辑和引用关系。发布 SHALL 提供与实际能力一致的损坏诊断、停止受影响写入、现场保留、备份核对和选择性取回说明；备份必须实际恢复核验，单纯生成备份不算恢复通过。

#### Scenario: 怀疑数据库损坏
- **WHEN** 用户按恢复说明处理受影响数据
- **THEN** 可在保留现场和当前成果的前提下诊断，先在独立副本核对恢复内容与缺项；不能安全恢复的部分明确列出，不自动对原数据进行破坏性修复

### Requirement: V-07 分发包与支持范围

预览版 SHALL 明确已验功能、平台及限制；首个稳定版须完成完整科研流程、真实科研效果与 Windows、macOS、Linux 实际分发包验收。每个声称支持的平台 SHALL 检查安装启动、独立 Node、原生模块、兼容宿主、路径、阅读渲染与生命周期，记录版本组合及第三方许可要求。

#### Scenario: Linux 开发测试通过
- **WHEN** 准备发布支持三个平台的版本
- **THEN** 分别核对各目标平台实际分发包，构建成功和 Linux 本地测试不代替其他平台验收

### Requirement: V-08 更新与数据恢复分离

早期预览版 SHALL 提供手动下载安装及支持范围说明，保留研究数据。更新在用户选择时机保存编辑，等待或暂停受影响任务，并协调内核与宿主停止。应用回退与数据恢复 SHALL 分别处理，保护升级后的成果；自动更新是否接入沿后续实际需要确定。

#### Scenario: 关闭窗口后开始升级
- **WHEN** 人类工作台已经关闭但后台任务仍存在
- **THEN** 升级流程核查并协调相关进程，不能仅凭窗口关闭判定后台已停止或数据可直接替换

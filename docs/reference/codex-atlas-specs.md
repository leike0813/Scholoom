# Codex 图册实测规格

本文把 `references/Codex-UI-Reference-Atlas.pdf`（Codex UI 设计参考图册，18 页，内嵌 16 张官方公开截图）
逐张量测成可落地的数值参考，供实现型 agent 直接取用。

## 如何使用本文

图册每页只有「画面观察 / 可借鉴的设计 / 实现时关注」三类散文，缺色值、尺寸、间距、层级与状态矩阵。
本文补的就是这些数。但要先说清楚三条边界：

1. **本文是参考素材的实测，不是官方规范。** 图册素材来自不同发布条目，构建号多数未知，
   不能据此确认当前产品的完整功能或默认参数。
2. **实现时以现有事实源为准。** 结构决策看 [`docs/ui-design/README.md`](../ui-design/README.md)，
   颜色事实源是 [`apps/desktop/src/renderer/src/styles.css`](../../apps/desktop/src/renderer/src/styles.css)
   的 `:root`（浅色 7-53 行）与深色映射（136-165、167-195 行）。本文只提供实测值与状态线索，
   不改任何 token、不改任何组件。
3. **素材证明不了的，一律不写成规范。** 真实展开的 diff 审阅面板、独立 Skills 管理页、权限弹窗、
   运行失败态、悬停、键盘、真实设备像素比，一律进各节「不可推断」栏，文末 D 表汇总为缺口清单。

### 各节的栏目读法

六栏固定；颜色表是「实测规格表」拆出的子表，只是单独成表便于查色值。

| 栏位 | 用途 |
|---|---|
| 素材 | 页码、抽取文件名、原生尺寸、**校准比例与依据**——比例栏决定了该节 CSS 值怎么读 |
| 画面结构 | 元素层级，从上到下、从左到右；成对素材（浅/深两页）只写差异，不重复 |
| 实测规格表 | `元素 \| 实测 px \| 推算 CSS \| 取值来源`。**实测 px 是硬事实，推算 CSS 依赖比例假设** |
| 颜色表 | 同结构，`元素 \| 实测 hex \| 取值来源`。文字色同时给峰谷与笔画众数，抗锯齿使单像素不可靠 |
| 状态与交互线索 | 每条注明「静态图可见」或「需原型验证」 |
| 不可推断 | 本图证明不了的行为与参数 |
| 对本项目的落地建议 | 指到 `styles.css` 的 token 名或行号；已实现 / 未实现分别写明 |

### 比例约定

比例是本文全部 CSS 值的唯一前提，每张图单独校准，判据写在各节「素材」栏：

- **@1x**：CSS 值 = 实测 px。第 2–5 页（Windows 工作区、侧栏、执行记录）与第 12–13 页（自动化创建对话框）属此类。
- **@2x**：CSS 值 = 实测 / 2。第 6–11 页与第 14–17 页属此类。
- **未校准**：找不到可用的 1px 参照线，该节只给像素事实，所有 CSS 值前加 `≈`。全文只有第 11 页
  （批注，裁切图）落在这一档；单张图内的局部元素（如被切掉一半的 tooltip）不可测时，
  写在该行「取值来源」里而不是整节降级。

校准方法统一为：沿垂直或水平方向取一条像素序列，找最细的 UI 描边（不用图表网格线、
不用抗锯齿过渡带），数出厚度。2px 判 @2x，1px 判 @1x；落在半像素上的 1px 线（两行等值）判 @1x。
第 4、5 页本身无参照线，比例由「与第 2 页逐像素 1:1 裁切」外部推定，判据与比对脚本见该节与附录。
命令见文末附录。

## 图册自述的边界

图册第 18 页给出四条取舍，本项目已在 `docs/ui-design/README.md` 里落为设计原则，本文沿用同一纪律，
不重复论证：

1. 先搭稳定骨架——侧栏负责项目与任务，正文负责当前工作；有实际产物时再增加预览区。
2. 让状态和对象相邻——等待审批、未读、运行状态贴近对应任务；变更摘要与文件入口贴近结果。
3. 把输入与上下文一起设计——输入器保留文本、发送和当前环境；次要配置按使用频率折叠。
4. 统一主题的语义角色——一套组件结构覆盖浅色与深色，分别验证正文、次级文字、焦点和状态色可读性。

图册第 18 页同时声明「本册未收录」四类界面：真实展开的 diff 审阅面板、独立 Skills 管理页、
权限审批弹窗、运行失败状态；并声明公开静态图片无法验证悬停、键盘操作、动态刷新性能与真实尺寸。
本文沿用这条清单，逐节把这些内容归入「不可推断」，文末 D 表把它们登记为待设计项。

另有三处素材本身的限定，容易被误当规范，逐节已重复标注：

- **窗口外的桌面壁纸不是产品界面**（第 6、7、9、10 页）。第 7 页深色截图里壁纸仍是亮的，只有窗口内变暗。
- **嵌入预览的网页内容不是 Codex 组件**（第 9、10 页的 TEAM PLAN / USAGE PREVIEW 卡片）。参考时要区分宿主层与被预览层。
- **合成图不是真实窗口**（第 14 页四宫格、第 15 页其浅色象限裁切）。第 14 页交通灯直径 34 px 与 macOS 常规量级不符，说明该图非原生 Retina 截图。

图册第 18 页提到的 `sources.json`（原图链接与像素尺寸）未随图册提供，本文不复述任何原图链接。

### A 组（p2–p5）比例校准说明


- 侧栏与正文之间的竖直分隔线在 x=556、557 两行都取到非背景色（`#F1F1F1`、`#EFEFEF`），
  在 y=610、611 两行取到 `#EFEFEFEF`、`#F0F0F0`。两行数值几乎相同，且都等于「1px 实线色 `#DFDFDF`
  以 50% 覆盖率摊在两行」与白底的混合值（0.5×223 + 0.5×255 ≈ 239）。这是**落在半像素位置上的
  1 CSS px 发丝线**，不是 2px 线。
- 用字形反证：侧栏任务名一字高 10–13px，正文行内字高 14px。若按 @2x 解释，字体只有 7px、
  侧栏宽 297/2 ≈ 148 CSS px、行高 15px，与窗口整体 1381×1039 的实测量级（对应一个正常的
  桌面窗口）严重冲突。按 @1x 解释，全部数值落在常见 UI 量级（侧栏 297px、行高 31px、正文 14px 字号）。
- 故本组统一记 @1x，**CSS 值 = 实测 px**。下文「实测 px」与「CSS」两列数值相同，不是复制错误。

第 4、5 页是第 2 页的**局部裁切**，但裁切是逐像素 1:1 的（不是缩放）：已用 200 个随机采样点
逐点比对 `shot-003.png(x,y)` 与 `shot-001.png(x+267, y+105)`、`shot-004.png(x,y)` 与
`shot-001.png(x+716, y+266)`，**差异像素 0 个**。因此它们沿用 @1x 判定，且本文给出的坐标都可
直接平移回整图坐标。文末复核命令里带 `-seed` 的一次比对可重跑这一步。

### 状态与交互线索

- 选中态：侧栏选中行用**整行底色块**（`#E8E8E8`）+ 左侧内缩 7px，不是左侧色条（静态图可见）。
- 徽章「Awaiting approval」是**绿色药丸**，紧跟任务名右侧、截断文字之外，占据行内独立位置（静态图可见）。
- 任务行右侧同时容纳「变更计数 + 右对齐时间」两段元信息（静态图可见）。
- 蓝色实心圆点（9px）表示某任务的进行/异常态，同列表其他行为线性图标（静态图可见）。
- 工具记录是**等宽、浅灰、无图标**的独立行块，与正文自然段在灰度和行距上都分开（静态图可见）。
- 工具记录首行比后续行更淡（同色更浅一档），疑似「正在执行 / 未完成」态（静态图可见，是否为状态而非压缩差异需原型验证）。
- 变更卡片头行与文件行底色不同（`#F6F6F6` vs `#F3F3F3`），折叠态无展开箭头（静态图可见）。
- 发送按钮是灰底圆钮（`#878787`），非强调色（静态图可见；hover/按下态不可见）。

### 不可推断

- 悬停、按下、焦点环、键盘 focus-visible：静态图完全不可见。
- 滚动条、滚动容器边界、可滚动区域的滚动反馈。
- `+889 -0` 与卡片内 `+1 -9` 的语义差别（是否工作区累计 vs 单文件）需原型验证。
- 首个工具记录行变淡是「运行中」还是截图压缩差异，不能断定。
- 真实 DPR、是否系统缩放 125%/150%；本文只按像素比推断 @1x。
- 断点、响应式行为、窗口尺寸下限。

### 对本项目的落地建议

- 侧栏行高 30px、选中行底色块左右内缩 7/11px：本项目已有 `--surface-active` 可承接选中底，
  行高需在 `apps/desktop/src/renderer/src/workbench/` 侧栏行样式上按 30px 统一（当前无统一行高 token，
  建议新增 `--row-h` 之类，避免散落裸值）。
- 选中行底色：现有 `--surface-active` 浅色值应与实测 `#E8E8E8` 对齐评估（`styles.css:7-53`）。
- 侧栏底 `#F3F3F3` 与正文底 `#FFFFFF`：`--surface` / `--bg` 的浅色取值可直接对照（`styles.css:7-53`）。
- 1px 发丝线 `#EFEFEF`：`--border` 浅色实测吻合度需核对（`styles.css:7-53`）。
- 三级文字灰阶（主文字 ≈`#1E1E1E`–`#383838`、次级 ≈`#878787`、分组标题 ≈`#232323`）已由
  `--text-primary/--text-secondary/--text-tertiary` 覆盖，但本项目未把「工具记录灰阶」单列；
  若要与图册一致，建议在 agent 流里复用 `--text-tertiary` 而非新增 token。
- 状态点直径 9px：本项目无对应元素（现有 `.icon-btn` 30×30，`styles.css:343-351`），
  属新增表达，落点建议放在侧栏行组件内的状态指示符。
- 徽章（`--await-bg` / `--await-text`）已存在（`styles.css:7-53`），图册实测底 `#C1E2CE`、字 `#30955A`

### C 层级与可读性

只写从像素能直接读出的**相对亮暗关系**，不给无依据的 WCAG 数字。

| 层级 | 浅色实测 | 深色实测 | 结论 |
|---|---|---|---|
| 正文底 → 侧栏底 | `#FFFFFF` → `#F3F3F3`，差 12/255 | `#181818` → `#1A2037`，差约 2–8/255（渐变） | 浅色层级靠约 4% 明度差即可分辨；深色侧栏与正文几乎同明度，靠色相与渐变区分，本项目用中性灰阶梯（`#181818` → `#1f1f1f`）反而更稳 |
| 侧栏底 → 选中行 | `#F3F3F3` → `#E8E8E8`，差 11/255 | `#1A2037` → `#262A3D`，差约 12/255 | 两套主题的选中态抬升幅度接近（≈4% 明度），可作为「选中不得弱于 4% 明度差」的底线 |
| 主文字 → 次文字 | 峰谷 `#1E1E1E` → `#878787` | `#FFFFFF` → `#828699` | 深色下次文字比浅色更亮一档（`#828699` 对 `#878787`），说明两侧不是同一值换算 |

| 正文 → 占位文案 | `#1E1E1E` → `#C3C3C3` | `#FFFFFF` → `#5C5C5C` | 占位与工具记录同档，说明占位不是最弱一级，而是与次要信息同权 |
| 底色 → 链接 | `#FFFFFF` → `#2C77C0` 峰谷 | `#181818` → `#B7CFE7` 笔画峰 | 浅色链接靠降明度，深色链接靠升明度加去饱和；同一角色两侧明度方向相反 |

一句话结论：图册的层级主要靠 **背景明度 2–4% 的小步抬升 + 文字明度降 2–3 档** 建立，不靠描边也不靠阴影；

### 1:1 裁切校验（第 4、5 页比例判定的前提）

```bash
uv run --project "/home/joshua/.ar" --locked -- python - <<'PY'
from PIL import Image
import random

a = Image.open('/tmp/atlas-specs/shot-001.png').convert('RGB')

    b = Image.open('/tmp/atlas-specs/' + name).convert('RGB')
```

### 取色

只采大面积平涂区域内部像素，避开文字与抗锯齿边缘：


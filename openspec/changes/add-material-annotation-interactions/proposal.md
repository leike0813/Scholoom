# 变更提议

## Why

共同资源打开、阅读记录、显式 ContextItem、共同输入框和条件保存已经交付，但真实格式视图尚未共同完成“选择—批注—发送—检查实际修改”的闭环。现有基础不能证明 PDF 或可视预览的选择已进入指令，也不能把库批注保存解释为正文写回。本变更补齐材料交互与修改核查，复用所属领域权威，避免重复发送通道、隐式改写附件及跨版本自动定位。

## What Changes

- 在真实格式视图中贡献有版本依据的文字、已有结构对象及图片区域，复用共同输入框检查、编辑批注、发送与草稿保护。
- 增加实际修改及依据的差异查看；项目正文复用现有条件保存。主线已确认本批库正文继续只读，排除附件正文写回和sidecar转正文，阅读记录不冒充正文修订；未来写回须另有正式提供者及授权。
- 保留原阅读记录的身份、修订、作者及权限；当次指令批注与持久阅读记录分别表达。
- 报告运行及更新由独立的 `add-interactive-research-reports` 承接，不成为本变更前置。

## 完成判据

1. 浏览器和 Electron 从共同资源入口完成固定材料的选取、批注、共同发送，真实 harness 取得原版本及摘录；模型允许受控。
2. 实际项目修改经所属保存权威落盘，差异反映读取依据与实际保存结果；并发变化、撤权、迟到回执不覆盖草稿。
3. 无正文／记录写入能力时如实显示限制；库正文写回在调查与契约未闭合前不得宣称完成。
4. 诊断能分辨选择、草稿、发送受理、执行、保存和刷新。CI 既有写作 PDF 预览失败有明确调查入口，不凭增加超时消解。

## Capabilities

### Modified Capabilities

- `workbench-agent-context`：补充真实格式视图选择和批注的贡献行为，沿原显式项与可靠发送契约。
- `workbench-resources`：补充修改依据、差异及刷新保护，保持所属正文及阅读记录权威。

# 变更提议

## Why

项目已有稳定文件身份、条件保存、资源首次创建和执行成果关联，但尚无可供人和 Agent 共同发现的持续研究任务。右侧任务面板目前只有展示模型，能力尝试仍按会话查询。换会话后，研究目标、采用理由、障碍与下一步只能依赖调用者自行组织普通文件。依据项目与研究资产决议，本变更为任务入口及其关联提供文件契约、有界发现、共同操作和工作台入口，使新会话能逐步读取真实材料继续工作，同时保留项目文件与文献库各自的权威。

## What Changes

2026-10-26恢复范围：HEAD77cd078已包含公共0519904／b838402。用户已选择任务详情单一“运行科研图”动作；本轮实施任务侧编排及注入科研端口验收，真实科研启动适配仍由科研线提供，不能以替身关闭I1。细节见design第8节。

- 在 `packages/projects` 增加文件任务 Module：开放 Markdown 入口保存少量结构化身份、名称、研究状态、工作项及引用，正文保存目标、约束、当前安排和接续线索；长过程及成果独立成文。
- 人和 Agent 共用有界任务发现、明确引用读取、受保护创建与更新。过程材料和成果继续经共同资源接口保存，任务关联写回入口文件，不新增任务正文数据库或反向项目引用表。
- 通过任务专属组件接入右侧任务导航与中间详情；使用共同资源视图、上下文贡献和 composer，任务选择不绑定会话。
- 分别返回实际文件保存、入口关联与尚未核查的来源状态，覆盖冲突、人工改动、重复身份及部分保存。复用已有操作收据，不制造跨文件事务。
- 为科研、委派、计算提供可选 `TaskRef`／工作项引用及材料导航；本 change 不规定其调用 DTO，不注册业务 Graph，也不因一次调用自动创建任务。

首个有界交付覆盖当前可读项目文件与库附件。主题／分析知识指针、库身份／删除历史和恢复提供者的未交付部分保留明确前置，详见 investigation 的等待输入表；不以附件 missing 冒充删除证据。阅读批注与交互报告仍由阅读交互线分别规划。

## 完成判据

1. 隔离项目在无 harness／模型的人工组合中创建任务、保存多份过程文件和成果并关联；重新打开从磁盘取得相同目标、计划与引用。
2. 文件编辑、应用内重命名及外部变更后重新发现／读取；旧依据无法覆盖新内容，损坏或重复入口有明确诊断，不按修改时间选任务。
3. 成果已保存而入口更新失败时文件保留，可用原文件／创建操作依据核查并只补关联；来源取用失败保留项目记录，遵循材料引用行为矩阵。
4. 新项目会话从任务摘要、入口、过程和实际成果找到目标、依据、障碍与下一步。受控模型只证明真实工具／文件接线，不认定科研质量。
5. 双宿主从右侧任务打开中间详情、编辑入口并打开关联资源；跨项目、迟到回执及刷新保留各自草稿。定向验证先核对已知项目 UI 基线失败，不放宽超时或用 `.first()` 掩盖身份歧义。
6. I1 固定图整合由本线负责，等待文献实际取材及科研线提供者；在前置未收到时保留未完成，不将替身独立验收称为真实整合。

## Capabilities

### New Capabilities

- `research-tasks`：以项目文件承载持续任务及工作项导航，提供共同发现、创建、读取、条件更新、材料关联、失败诊断和任务视图。

### Modified Capabilities

无。沿用 `project-files`、`workbench-resources`、`workbench-agent-context`、`execution-work-domains`、`domain-execution-handoffs` 和 `module-runtime` 的现有保护；新增任务行为集中在本 change 的 `research-tasks` delta，不复制或削弱这些规格。

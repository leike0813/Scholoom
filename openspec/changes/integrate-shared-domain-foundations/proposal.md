# 变更提议

## Why

七条开发线已交回独立成果，但共同 dev 仍停留在 e3d58fc。各线继续等待公共代码，会反复核对同一批设计；直接合并整树则会引入两份 v5 迁移、共享符号冲突及尚未审定的领域行为。本变更接收已实现的公共切片，将资源声明、命令观察、项目迁移、材料位置和集合查询组合为可验证基线，供后续领域接线消费。执行历史沿独立的 add-harness-execution-history 交付，不复制其契约。

## What Changes

- 抽取资源 schema 叶模块并保留原导出；合并按项目身份建会话与真实双窗口 UI 夹具。
- 接入有界受管命令观察、持久确认前启动保护、完整停止收据及长时限分段计时。
- 使用 v4→v5 delegations→v6 program_runs 单一迁移链，保留各步保护副本和失败重试。
- 接入材料位置／区域坐标基准／草稿对象的同源声明、编码及回归；保持旧消息可读。
- 接入集合直接父范围查询和原生 CSL 编辑声明；不收紧开放 metadata。
- 不启用图片格式、新题录选择、库原值／键／事务、产物引用、报告或生态生产接线；不复制七域私有业务。

## 完成判据

公共切片在同一实际宿主组合构建，命令、迁移、资源、上下文及库回归通过；执行历史与 Agent 切片另做兼容核对。保留未完成平台和科研范围，给出消费者同步基线与下一轮入口。

## Capabilities

### Modified Capabilities

- `platform-access`：有界命令观察、确认背压、停止收据及长时限。
- `project-files`：统一迁移顺序及保护副本。
- `workbench-agent-context`：当次位置、区域基准与草稿对象保真。
- `literature-catalog`：集合直接父范围及开放 CSL 编辑声明。

## 决策与授权依据

沿七域分工 #09／#10 的公共补充先实现、dev 接入验证后同步约定。用户请求本轮验收与调度，沿此前提交授权执行已交回公共成果的接入；不扩大依赖安装、真实用户数据或后置科研流程范围。来源副本与引用键冲突政策已由用户确认，进入文献／生态后续实施，不扩大本公共切片。

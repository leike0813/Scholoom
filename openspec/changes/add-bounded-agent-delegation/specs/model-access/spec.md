# Model access delta

## ADDED Requirements

### Requirement: 命名模型配置与委派钉入

系统 SHALL 提供当前供应商目录内的命名模型配置，包含稳定配置身份、显示名、修订及模型／支持的推理参数；配置与凭据分离，保存复用私有配置保护。配置保存 SHALL 核对预期修订，冲突保留原配置及调用方草稿。角色可引用命名配置，调用方可显式选择另一命名配置；未指定时继承父执行已钉入的实际配置，不重取最新默认。委派受理 SHALL 保存配置来源和实际解析值，之后改名、修改或移除配置不改变已有执行。缺失、非法模型或不支持参数 SHALL 明确拒绝，不静默回退，不扩大供应商和数据接收方范围。只读配置状态不含密钥。

#### Scenario: 父子选择不同命名模型
- **WHEN** 父委派明确引用一个合法命名模型配置，随后用户修改该配置或应用默认
- **THEN** 子使用受理时钉入的模型及参数，查询可核对原配置身份和修订；父执行继续其原配置

#### Scenario: 未指定与失效配置
- **WHEN** 工作包未指定模型且角色没有模型引用，或显式引用的配置不存在
- **THEN** 前者继承父实际配置，后者在执行前明确失败，不能把失效引用当作未指定

#### Scenario: 并发更改命名配置
- **WHEN** 两个设置入口根据同一旧修订保存不同模型
- **THEN** 首次保存推进修订，后到保存返回冲突且不覆盖已保存配置，正在运行的委派均保持原解析值

### Requirement: 不同子模型共享根推进额度

父执行、通用委派及现有能力子执行 SHALL 共用宿主持有的同一根推进请求预算，包括实际模型调用、压缩和安全重试；更换子模型描述不得生成新预算。各执行仍使用自己的实际模型描述、取消信号及有效授权，所有执行继续共享全应用并发上限1和现有请求期限。已消耗次数不因子完成、失败或取消返还；子取消不得释放父仍持有的租约。等待子执行结果不占模型名额。模型请求在排队前后及最终准入复查对应有效授权，先前已读取／附加材料不能绕过后续外发检查。

#### Scenario: 跨模型耗尽根预算
- **WHEN** 父与不同模型的子执行以及压缩／重试合计达到现有32次预算
- **THEN** 下一请求在发送前返回 resourceLimit，已有成果保留，不能通过新建模型对象或新委派绕过预算

#### Scenario: 子取消与其他请求并行
- **WHEN** 一个子执行等待或持有模型租约时被取消，另一父／无关会话仍在运行
- **THEN** 仅终止对应子请求并按真实流结束释放其名额，其他租约和全局计数保持正确，不额外返还已用预算

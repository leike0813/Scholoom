# 变更提议

## Why

现有 harness 可启动科研能力专用子执行，但工作说明、输出检查和进展均绑定科研 attempt；子执行共享父模型对象和会话临时区，没有通用委派身份、角色配置、独立上下文及可查询成果。因此不能将已有子进程隔离视为通用协作已交付。本变更沿已归档的执行、资源和上下文基础，补齐一次有界委派，使父 Agent 和用户能核对实际子执行、材料依据、保存结果及未完成项，并在取消或重启后保留真实状态。

## What Changes

- harness 提供工作包受理、角色解析、独立受管子执行、状态／有限等待、所属取消和结构化结果；复用 broker、RemoteAgent、进程准入、模型租约及资源保存，不开启 SDK 默认 task 或另建执行系统。
- models 增加当前供应商内的命名模型配置；子模型可明确选择或继承父执行钉入配置，父子共用根请求预算。开发环境的 Codex / gpt-6.1-sol / high 不转为产品模型配置。
- 子输入仅含角色指导和明确工作包，临时区独立，工具与资源范围由宿主求有效交集。初审不自动注入父历史或其他审阅结论。
- 在现有会话工具记录下展示委派、障碍、实际资源及取消状态；保持 dock／overlay 和共同 composer。科研角色内容、任务正文和材料修订权威仍归各自领域。
- 实施范围为委派同源契约、harness 深层模块、必要模型配置及宿主接线、现有会话组件和定向验证；正式规格同步另行处理。跨会话通信、advisor、递归委派、后台移交及新供应商另行规划。

## 完成判据

2026-10-30用户确认采用Linux阶段收口并授权按计划修订工件：以下通用委派判据验收Linux Browser＋真实Electron，macOS沿既定人工能力／受管执行不可用；Windows目标未交付，Windows与旧CI唯一因果调查沿本change的[tasks后续责任](tasks.md#后续责任不计本阶段复选框)保留，未被证明已修。4.3的Linux最终核对及6.2真实科研四项核查仍未完成；6.2保留原失败、真实保存→父按ref/basis读回→按最新任务依据关联及独立质量评价，新真实模型执行仍须另获次数／预算／数据外发授权。权限交集、隔离、共享预算、截断零派发、unknown及完整停止保证不变。

以下验收目标按实际结果逐项核对，当前状态见 [delivery](delivery.md)：

1. 真实父子受管执行通过受控模型完成明确工作包，子实际保存新文件，父按稳定引用及 basis 读回；执行完成、资源保存、关联及科研验收分别表达。
2. 独立上下文和 scratch、角色／命名模型钉入、宿主强制工具交集可核对；材料变化、撤权、容量不足和模型共享预算均有行为证据。
3. 等待超时不取消子执行；子失败／父退出／用户取消／重启查询不丢产物、不自动重放未知保存、不提前释放未确认归属。
4. 浏览器和 Electron 共用会话路径查询、查看资源和取消所属子执行；诊断能区分发送、受理、worker、模型、工具、停止及刷新。
5. I3 由本线负责：先独立验证无任务依赖的真实资源交接，再等待项目提供者完成实际任务关联整合；后者不以替身通过抵充。

## Capabilities

### New Capabilities

- `agent-delegation`：工作包与角色、权限与上下文、执行和结果、等待取消恢复及会话内观察。

### Modified Capabilities

- `model-access`：新增命名模型配置以及不同实际模型共享根推进预算的约束；保留当前模型目录、接收方及授权政策。

# 变更提议

## Why

当前基础单 Agent 已能读写材料、追加指令、取消和接续，三区外壳也已交付，但工具消息只有“执行中／已返回”，dock 将未结束工具显示为完成，成果缺少直接打开入口，输入器也未呈现实际项目、模型和权限。用户难以从工作台判断 Agent 做了什么、失败在哪里、结果保存到何处。本次先补齐现有执行的可观察与可操作闭环，为完整基础 harness 阶段和下一步 P3d 提供可靠入口。

## What Changes

- 持久工具记录包含调用名、有界输入／结果摘要及真实状态；工具返回错误、异常、取消和中断均不冒充成功。
- dock 与 overlay 使用共同工具投影；overlay 可展开调用详情，dock 区分运行、失败、未知和完成。
- 两种输入器显示当前会话的项目、MiniMax 模型与有效权限；成果经已有文件 tab 打开，保留输入草稿和接收会话。
- 修正路线图与 UI 设计中过时的活动 change 链接，记录本阶段的后续 P3d。

## 完成判据

1. 真实图读写工具经过协议、数据库和共同客户端返回可识别调用，刷新后仍可查看；失败或中断无虚假成功状态。
2. 同一工作台的 dock／overlay 展示一致，输入上下文可辨，成果点击后打开实际文件且不丢草稿。
3. 现有内核与双宿主 e2e 扩展覆盖成功、工具错误及取消；静态检查和相关回归通过。

## Capabilities

### Modified Capabilities

- `agent-harness`：增加持久、有界、可诊断的工具调用记录。
- `ui-workbench-shell`：增加执行上下文、工具详情与成果打开行为。

## 决策与授权依据

用户本轮要求以完整基础 Agent harness 及界面为阶段目标，起草并实现下一 change，授权本次方案及实现。沿 #14、#15、#20、#25 与既有 P3a–P3c 契约；不安装依赖、不提交、不操作已有运行实例、不调用付费模型。测试使用隔离模型 HTTP 夹具和既有双宿主自动化入口。

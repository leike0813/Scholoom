# 变更提议

## Why

当前内核只有一次性 CLI，工作台尚未连接真实后台。路线图 P1 和已确认的 #23 要求人类工作台与 CLI 共用驻留内核，关闭窗口后仍能查询，并可靠地区分断线、不可达、退出和明确停机。本变更建立这条真实生命周期路径，为后续项目文件与 Agent 执行提供共同入口，不用模拟研究任务证明后台运行。

## What Changes

- 建立同一数据配置的单实例 Node 服务、本机 WebSocket、认证及双向 JSON-RPC 消息处理。
- CLI 提供启动、状态和停止；Electron 与浏览器开发入口复用启动协调和共同客户端。
- 工作台显示真实状态、重试与停止入口，连接变化保留草稿；发送研究指令仍不可用。
- 增加隔离的真实进程与双宿主检查，同步开发说明。

## 完成判据

- 并发启动同一配置返回同一实例，不同配置互不干扰。
- GUI 关闭后 CLI 仍能查询，重新打开接回同一实例。
- 认证、协议错误可辨；短暂断线有界重连，存活但不可达不替换；退出后用户重试才重新启动。
- 明确停机通知所有客户端，确认退出后才报告停止；结果未知不伪装成功，不自动拉起。
- 本机必要检查与独立审查完成，三平台使用相同检查入口，未运行平台不宣称通过。

## Capabilities

### New Capabilities

- `kernel-lifecycle`：真实内核发现、启动、认证、连接恢复、状态查询与明确停机。

### Modified Capabilities

- `ui-workbench-foundation`：默认工作台显示实际连接状态；生产样例参数仍不启用模拟结果。

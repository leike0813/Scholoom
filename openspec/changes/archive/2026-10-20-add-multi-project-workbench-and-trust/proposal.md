# 多项目工作台与项目信任

## Why

当前内核已按项目保存会话和文件事实，但工作台左栏只显示当前项目，切换其他项目需要进入最近项目菜单，无法同时观察多个项目的会话。项目读取、写入、外发又分别配置，增加日常使用成本。本变更提供多个项目常驻的导航，明确会话与项目内容的联动，并将 Agent 的项目权限统一为一次信任决定，同时保留未信任项目的人工使用能力。

## What Changes

- 最近项目作为左栏驻留列表，各自展开、分页及管理会话；选择会话同时切换所属项目。
- 项目文件标签组和右栏随项目切换，草稿独立保留；共同文献和设置跨项目保留。
- 将三项项目授权合并为信任状态，新建、添加及旧项目首次进入时询问，可选择受限模式。
- 内核区分人工与 Agent 调用，信任在实际执行和材料访问入口生效；后台会话元数据独立通知。
- 新建会话收口到项目行菜单右侧的独立按钮，普通会话同样提供；移除顶部、折叠侧栏和空态的全局新建入口。项目菜单改为紧凑图标菜单，仅保留打开项目和确认移除。
- 项目名称始终为目录末级名，移除独立别名及重命名接口；文件系统改名后重新添加，名称更新且身份与记录保留。

## 完成判据

两个项目可同时驻留并持续执行，切换不混入其他项目的消息、材料或文件状态；受限项目可人工编辑，但不能启动 Agent 工作。旧项目全部重新确认，撤销信任阻止后续动作而不主动取消在途调用。浏览器与真实 Electron 经同一内部接线验证。

补充完成判据：非当前项目行的新建动作归属该项目，迟到回执不覆盖后续选择；扩展菜单不包含新建和名称表单。旧别名不覆盖文件夹名，重新添加改名目录保留原项目记录。

## Capabilities

### Modified Capabilities

- `ui-workbench-shell`: 多项目会话树、项目内容切换和信任交互。
- `project-files`: 单一项目信任、人工访问及旧授权转换。
- `agent-harness`: Agent 访问的信任检查和撤销语义。
- `model-access`: 模型、压缩与重试共用项目信任。
- `research-capabilities`: 科研能力使用同一信任契约。
- `literature-attachments`: 项目材料摄取保留调用来源并检查信任。

## 决策与授权依据

用户在本会话明确选择：未信任仍允许人工浏览编辑；项目文件标签组随项目切换，全局内容保留；旧项目全部重新询问；撤信任只阻止后续操作；项目行只展开折叠。用户已批准实施方案及既有测试夹具启动和回收隔离服务。未授权安装依赖、提交、切换分支或操作真实用户数据。模块规则沿运行时架构 #01，实施与验证沿工程纪律 #14/#15。

后续用户要求收口新建入口、取消项目重命名并重做项目菜单，在方案列明文件与行为后回复“继续”，授权在同一 change 实施本轮调整。

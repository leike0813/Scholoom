# 变更提议

## Why

工作台目前把执行状态、归档恢复、待核查指令及错误堆叠在中间区顶部，展开 Agent 后又移入消息区。这些反馈随形态改变位置并占用内容空间。需要稳定的底部状态栏，与左下内核状态区对齐，同时提供统一的条目贡献接口，让后续组件及插件适配能够接入同一呈现与生命周期管理。

## What Changes

- 新增中间至右侧贯通的状态栏，与内核状态区共享 40px 高度；Agent 双形态均保留底栏。
- 执行状态常驻，全局通知集中为摘要、数量与向上详情层，保留原有操作及失败反馈。
- 项目信任继续使用现有居中弹窗，状态栏仅提供待确认／受限状态和重新打开入口，不计入通知。
- 提供实例级、贡献者隔离的标准条目服务及 React 接入，内置功能使用同一接口。
- 局部表单、编辑器、阅读器反馈保留各自上下文；成果入口归入所属执行的 Agent 结果消息，保存和登记反馈进入状态栏，移除 tab 上方及消息流末尾的独立成果汇总；不新增依赖或实现插件加载器。

## 完成判据

- 浏览器与 Electron 的状态栏同高对齐、单行稳定，折叠侧栏或展开 Agent 不遮挡。
- 通知操作保持实际接线，切换项目／会话不留下旧操作，失败可重试且草稿保留。
- 标准接口可注册、更新、显隐、释放及按贡献者清理，实例与贡献者互不覆盖。
- 信任决定在弹窗完成，明确受限项目普通重开不重复询问。

## Capabilities

### Modified Capabilities

- `ui-workbench-shell`：底栏布局、标准贡献接口、通知及信任入口，更新原消息区恢复提示位置。

## 决策与授权依据

用户本会话确认中间至右侧贯通、摘要与详情弹层、统一条目接口，并补充项目信任应使用弹窗；随后明确要求“Implement the plan”。实施及既有隔离测试 harness 的运行沿该方案授权，不涉及依赖安装、Git 提交或分支操作。布局事实源为 `docs/ui-design/README.md`，模块与验证纪律沿项目 AGENTS 及 #14、#15。

用户随后指出顶部成果区域不属于其设计，并明确回复“是的，请这么做吧”，批准将成果入口放回对应 Agent 结果消息、保存与登记反馈归入 statusbar。

# 变更提议

## Why

文献库重设计保留了列表和附件详情，却移除了已有授权、建项、导入、集合、批次和备份恢复入口，元数据编辑也未接到共同库接口。用户无法从界面完成已确认的基本操作，现有双宿主用例及开发模式冒烟持续失败。需要恢复真实用户路径并保留当前列表／详情布局，不能用测试直调 API 代替产品入口。

## What Changes

- 沿原 LibraryPanel 的共同客户端调用和草稿保护，恢复授权、手动建项、JSON／本地材料导入、批次查询与显式接续、集合及备份独立恢复。
- 将修订核对、草稿保存、迟到回执保护接回现有列表与详情；修正分页和范围通知刷新。
- 更新现有 UI 用例至当前 option 列表语义；业务操作仍经可见入口完成，不增加后端权威或依赖。

## 完成判据

浏览器与 Electron 均可授权、建项、导入部分非法批次、修改与分组、保留草稿、拒绝过期覆盖、备份并恢复至独立目录。现有附件入口及隔离开发冒烟可用；当前会话与未发送指令保留。

## Capabilities

### Modified Capabilities

- `literature-catalog`：明确共同工作台的人工管理入口及草稿、独立恢复行为。

## 决策与授权依据

沿 [UI 设计](../../../../docs/ui-design/README.md#本地题录库)及正式题录／附件规格。用户在本轮“可以，那继续推进吧”批准 Windows 定向诊断、库 UI 独立变更、Electron 加载诊断和 macOS 可行性验证方案。仅在隔离测试数据中验证恢复，不修改用户库或安装依赖。

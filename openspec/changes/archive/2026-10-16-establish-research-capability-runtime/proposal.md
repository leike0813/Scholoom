# 变更提议

## Why

基础 Agent 已能安全读写项目，但方法内容、明确能力调用与普通工具调用尚未分开。当前无法查询一次科研使用采用的方法、输入、执行尝试和交付检查，后续单篇分析容易另建专用执行路径。本变更落实路线图 P3d：在共同 harness 中加载一个材料分析方法，以声明驱动的共同能力入口执行，并把实际成果与科研充分性分开表达，为 P4c 提供可复用接线。

## What Changes

- 提供一个内置材料分析 Skill 及独立能力声明，摘要发现、按需加载；首次只支持内置内容。
- 提供共同能力执行模块：检查输入与有效权限，复用当前模型、调度和安全文件工具，自动保存调用与执行尝试、实际材料与产物及交付检查。
- Agent 经单个明确能力工具完成工作，不要求手工登记或结项；允许以原调用身份重试，取消与重启保留已保存成果。
- 共同协议提供有界方法与执行查询；现有工作台工具详情、成果打开和取消入口承接真实结果，不新增管理页。
- 更新开发入口与路线图中的会话归档链接。本步不提前实现 P4c 完整 Digest、方法管理、研究任务、插件、shell 或多 Agent。

## 完成判据

- 从工作台发送材料分析指令，真实内核加载方法、执行文件工具并保存可打开报告，工具详情可读调用身份及检查结果；浏览器和 Electron 均验证。
- 非法输入、缺少授权不触发能力模型执行；执行结束但缺少实际产物显示交付不完整，不能因模型自述而通过。
- 原调用重试保留身份、增加尝试；重复工具恢复不盲目执行；取消、内核重启保留记录及实际文件，查询不启动模型。
- 模块行为、真实客户端接线和双宿主用户路径有受控模型边界验证，科研充分性始终另行判断。

## Capabilities

### New Capabilities

- `research-capabilities`：内置方法发现、按需读取、声明驱动能力执行、持久尝试、交付检查与安全重试。

## 决策与授权依据

用户本轮持续目标明确授权按路线图创建、实现、归档 change 并提交；据此继续实施与 Git 提交，不切换分支、不安装依赖、不发布。契约依据 R-03/R-04 的 P3d 子集及决议 #18、#25、#36。首次方法采用已核对的材料分析原则重组为 Scholoom 原生 Skill，不迁入旧 Python runtime；完整文献业务沿 P4c。现有工具及成果交互已足够，无 Figma 阻塞。测试仅使用隔离合成材料与外部 HTTP 模型替身，真实供应商效果另记。

# 变更提议

## Why

单 Agent、项目管理、文件编辑及预览已交付，但会话仍默认同名，无法整理归档，回复只按纯文本显示。现有列表先取 100 条再排序，当前会话还隐含依赖自己出现在列表中；超过列表范围或加入筛选后会影响发送与执行控制。当前阶段先改善通用 harness 的日常使用体验，交付可辨认、可查找、可恢复的会话以及可阅读、可复制、可打开材料的消息界面。

## What Changes

- 首条受理指令生成短标题，支持手动改名、活动／归档切换和项目内标题查找、有界分页。
- 停止后的会话可归档及恢复，保留历史、成果、未处理指令和草稿，恢复不自动执行。
- 当前会话独立于列表读取，项目级会话变化可跨客户端刷新，流式文本不触发列表查询。
- Agent 正文支持 Markdown、代码、表格和公式，正文及代码可复制；材料和相对链接复用文件入口，外链显式打开，消息图片不加载。
- 复用现有 Markdown 渲染链与 Worker，控制可见消息的解析、合并和过期响应。

## 完成判据

通过真实客户端和双宿主工作台完成命名、查找、归档、恢复、阅读、复制及打开材料；超过 100 个会话时仍能访问和操作当前会话。归档不丢内容、不自动继续；异步响应不串会话。共享协议、内核、文件保护、生命周期与双宿主回归通过，并完成必要独立审查。

## Capabilities

### Modified Capabilities

- `agent-harness`：会话命名、项目内分页发现、归档与恢复、独立当前会话及列表变化通知。
- `ui-workbench-shell`：会话整理入口、可阅读消息、复制与材料打开、有界流式渲染。

## 决策与授权依据

用户本轮选择通用 harness 使用体验，确认首条指令命名且可手动修改、停止后归档、仅查当前项目标题，以及 Markdown／复制／文件入口、消息图片不加载；随后明确要求 Implement the plan。沿 #13、#14、#15、#20、#43 与当前正式规格。允许实现与隔离自动测试，不提交、归档、安装依赖、运行付费模型或操作日常内核。P3d、更多模型、shell、MCP、多 Agent、全文检索及消息修改重发后置。

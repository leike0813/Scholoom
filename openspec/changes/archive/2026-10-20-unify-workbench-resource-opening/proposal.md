# 统一工作台资源打开

## Why

项目文件和文献库附件目前使用分立的资源类型、打开回调和读取接线。它们虽然共享 tab 容器，编辑器与阅读器仍需要知道资源来自哪一个业务入口。继续在这两条路径上补文献界面，会重复实现格式选择、身份核对和视图生命周期，也无法兑现用户明确要求的共同编辑阅读接口。本变更先统一资源引用、访问端口和打开路径，为后续完整文献管理界面提供可复用基础，保留所属领域的授权、材料版本与保存保护。

## What Changes

- 在 protocol 声明项目文件／库附件的共同资源引用、描述、有界读取和文档解析契约；由现有 editor 包中的资源访问模块消费窄端口，宿主绑定项目与文献提供者。
- 工作台改为一个资源打开入口与格式选择机制，文件树、文献附件和已有资源链接都进入它；复用 SourceEditor、VisualEditor、PdfReader、DocumentReader 及既有草稿和阅读记录。
- 补齐项目二进制材料的有界读取接线，复用现有受管解析计算，使项目内 PDF／EPUB／HTML 与库内同格式附件进入共同阅读实现。库内 UTF-8 文本可进入共同文本视图，按所属能力呈现可写或只读状态。
- 保留资源身份、版本、所属权限及范围。打开库附件不复制材料到项目，不切换 harness 工作域；项目正文继续沿原条件保存，库附件在已有不可变材料约定下读取。
- 本变更不重做文献主界面，不实现 UI 选择工具、库附件原字节编辑、OCR、完整主题分析、外部 Office 插件或新格式支持；这些在全域实施计划中分别安排。

## 完成判据

1. 项目文件与库附件经同一打开入口和共同资源端口进入视图，调用方不再分别提供文件／附件渲染入口。
2. 两类来源的 PDF／EPUB／HTML 使用共同阅读实现；项目文本保持源码、可视编辑及保存能力，库文本按已有资源权限打开，不能将不支持的保存报告为成功。
3. 稳定资源在重复打开、分屏、路径变化及项目切换时不串身份、草稿或旧材料版本；库资源跨项目保留，打开动作不切换会话或执行项目。
4. 库撤权、材料变化、项目保存冲突、解析失败及关闭视图有可核查结果；复用既有文件保护和材料解析边界。
5. 必要类型、架构、内核与浏览器／真实 Electron 定向验证通过。只读规划不作为上述验证通过的证据。

## Capabilities

### New Capabilities

- `workbench-resources`：跨项目文件与库附件的共同资源访问、格式视图与打开生命周期。

## 决策与授权依据

- 用户在[文献域职责票](../../../../.scratch/domain-development/issues/02-literature-knowledge-scope.md)明确要求同一套编辑器与阅读器接口，保持现有工作台骨架及 harness 项目工作域。
- 用户已确认完整计划并同意开始 A 批实施。依赖安装、服务启动、真实模型与用户数据操作继续按各自授权范围处理；本批使用隔离夹具验证，无需真实模型或用户材料。
- 契约与守卫沿[模块依赖决议](../../../../.scratch/runtime-architecture/issues/01-module-dependencies-and-authority.md)、正式 module-runtime、project-files、workspace-editor、literature-attachments／reading 规格。

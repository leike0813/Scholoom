# 变更提议

## Why

题录及原始附件已能共同摄取、备份和取用，但工作台阅读器仍是占位，Agent 也只能读取附件原字节，无法按页取得 PDF 正文或接续用户的阅读成果。本变更沿路线图 P4b 和已确认的 EmbedPDF v2 选型，交付一条真实的 PDF 阅读与共享记录路径。材料版本仍是定位依据，书签、批注与笔记保存在内核共同库，原 PDF 不因阅读或批注被覆盖。EPUB／网页阅读在后续连续变更中推进，不以本变更代表整个 P4b 完成。

## What Changes

- 新增不依赖可见阅读窗口的 PDF 检查与有界按页文本读取，重计算在受管 Worker 中执行。
- 从题录附件打开已有 reader tab，接入 EmbedPDF 2.15.1 的翻页、缩放、搜索、文字选区与批注交互；所需 WASM／字体随应用打包。
- GUI 与 Agent 通过同一内核 interface 查询、保存和更正材料版本所属的书签、批注与文献笔记，分别保存摘录、作者与解释；并发编辑核对修订号。
- 阅读成果纳入现有数据库备份／独立副本恢复；材料失效时仍可读取已保存摘录及记录。
- 补齐实际工作台入口、双宿主验收和开发／架构文档中的当前实现描述。

## 完成判据

1. 从工作台文献附件打开合成 PDF，可翻页、搜索独立已知文字并建立选区；浏览器与 Electron 共用同一实现。
2. 保存书签、带摘录的高亮批注和独立笔记，重启读回；Agent 在没有阅读窗口时读取同一材料页与阅读记录，并能在授权范围内保存自己的记录。
3. 旧修订号更正被拒绝；失效外链不破坏旧摘录，新附件不会继承旧材料的页码；撤权拒绝后续读取／保存／外发。
4. 独立恢复副本可读回相同记录及托管材料；原始 PDF 字节保持原状。
5. 相关内核、真实 RPC／Agent、双宿主 UI、静态检查及必要独立审查通过，实际范围记录在 delivery。

## Capabilities

### New Capabilities

- `literature-reading`：有界 PDF 正文取用、版本定位、共同阅读记录、授权、并发与恢复。

### Modified Capabilities

- `ui-workbench-shell`：在既有 tab 骨架中提供实际 PDF 阅读及共享记录入口，保留会话与草稿。

## 决策与授权依据

- 路线图 P4b；PRD「共享阅读成果」；初设 L-03／L-04；#11 阅读与定位、#12 Answer Q7（EmbedPDF v2）及 Q14（后续 Zotero DOM EPUB／网页）、#44 不做跨版本持续定位。
- 用户持续目标授权按路线图创建／实施／归档 OpenSpec change 并提交；沿用既有实现和 Git 提交授权，不切换分支。
- 用户已明确批准 `artifacts/pdf-reading-dependencies.md` 所列新增依赖安装。固定版本、资源处理及执行命令沿该清单；本轮按最新要求完成此变更、归档提交后停止。
- 不调用真实模型或启动手动开发服务；验收采用隔离合成材料和既有测试 fixture。

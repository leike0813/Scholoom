# 变更提议

## Why

当前工作台已有项目文件与科研能力入口，但文献库仍为占位，跨项目题录没有独立权威。路线图 P4a 先交付题录可用的闭环：手动建项和标准 CSL JSON 批次摄取，保留稳定身份、发表版本、集合标签、来源与字段冲突，使人和 Agent 可查询整理同一库。附件与阅读在接续变更实现，本次如实表达题录已收录而材料与分析尚不可用。

## What Changes

- 新增独立全局文献题录模块与共享 Schema，提供有界查询、手动建项/更正、版本关联、集合/子集合和标签分组。
- 同一规范化 DOI 及明确发表版本复用身份、填补空字段并保留冲突；无确定标识时保留独立候选，不猜测合并。
- 以 CSL JSON 为首项标准题录格式，批次受理返回持久引用、逐项处理并保留来源及失败，重复受理不重复摄取；重启可查中断并显式接续。
- 真实工作台文献库 tab、Agent 工具及共同客户端接同一模块；库写入与发送采用明确授权，题录备份与独立副本核查覆盖首条写入路径。
- 后续 P4a 附件变更继续托管/外链和文件摄取，P4b 阅读、P4c 分析、P4d 合并/删除不提前加入。

## 完成判据

浏览器和 Electron 可手动建项、导入含逐项失败的 CSL JSON、查询题录并整理集合/标签；数据重启可读。重复同版本复用身份但预印本/正式版保留差异及显式关联；冲突不覆盖新内容。Agent 通过同一模块查询/摄取，输入/权限失败有结构化结果。备份实际在独立副本读回，当前库与后续编辑保留。

## Capabilities

### New Capabilities

- `literature-catalog`：库题录、同版本身份、集合标签、渐进批次、授权与恢复。

### Modified Capabilities

- `ui-workbench-shell`：正式接入文献库 tab，保留既有布局、会话与项目草稿。

## 决策与授权依据

用户持续目标授权沿路线图逐步创建/apply-ready、实施、归档及提交。依据初设 L-01/L-02 的题录子集、D-01/D-06、#13/#32；P4a 按可观察结果拆分，完整范围保留。沿现有 Node/SQLite/React/协议，不安装依赖、不发布、不接触真实用户库。UI 沿设计文档补充本功能交互后实施，确定性测试使用隔离合成数据与本地模型响应。

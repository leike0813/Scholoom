# 变更提议

## Why

基础 Agent 已能安全读写项目材料，但项目只能打开已有目录，工作台缺少目录管理、回收恢复和真实预览。现有成果、撤销和草稿以路径定位，目录改名后可能失效，路径复用还可能指向另一文件。本次沿完整基础 harness 的阶段目标，先交付可日常操作的项目与文件工作台闭环，再推进路线图 P3d。

## What Changes

- 项目新建、打开、显示名重命名、切换和移出最近列表，保留后台执行。
- 人与 Agent 共用目录创建、文件及非空目录重命名、回收、恢复和可查询的操作结果。
- 按需登记稳定文件引用，保护成果、撤销、当前材料和草稿；结构操作与相关保存协调。
- 普通写授权扩展到文件结构操作，已有项目重新确认；迁移前备份。
- 共享源码／预览／并排工作台，Markdown 表格、图片与公式在 Worker 解析，安全读取本地图片。
- 同步备份范围、设计与开发入口；P3d、工程编译、永久删除与交互报告后续承接。

## 完成判据

1. 用户从共同工作台新建项目、授权、管理文件，Agent 保存实际成果，源码和预览显示同一草稿。
2. 非空目录改名与回收后引用不误认；恢复不覆盖已有内容；并发、断线和中断结果可核查。
3. 双宿主真实内部接线与数据保护检查通过，预览期间输入和本地取消受理在代表样本下一秒内响应。

## Capabilities

### Modified Capabilities

- `project-files`：项目管理、稳定引用、结构操作及回收恢复、图片读取与备份。
- `ui-workbench-shell`：项目入口、真实文件树、共享文件文档与 Markdown 预览。
- `agent-harness`：共同文件管理工具及结构操作后的重读适应。

## 决策与授权依据

用户在本会话选择项目与编辑预览优先，确认显示名／最近列表管理、非空目录操作、图片与公式、运行中结构操作，以及将新操作纳入写授权并重新确认已有授权。用户明确授权必要依赖安装并要求 Implement the plan。沿 #13、#14、#15、#20 和已有文件保护契约。不提交、不启动日常开发服务器、不操作用户已有内核或真实研究数据；自动测试使用隔离配置及外部模型夹具。

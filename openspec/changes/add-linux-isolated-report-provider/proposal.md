# 变更提议

## Why

交互报告的iframe候选已被真实STUN外发与CPU阻塞反例否定。随后普通用户scope、namespace、配额及文件／句柄门的有限原生校准提供了机制依据，但临时控制器没有生产恢复权威、完整策略或浏览器保证。主线已决定先交独立Linux platform能力。需要把批准字节交付、预执行隔离、实际资源上限和完整归属收尾组织为一个可独立测试的深模块，沿既有ProcessAdmission保留未知占用，避免将临时样本或根PID退出误作可用报告承载。

## What Changes

- 新增宿主内部的Linux隔离提供者：接收领域已批准的有界字节、宿主登记的可信程序／隔离策略及原instanceId；提供能力核查、启动、查询、停止和遗留核查。
- 在不可信程序进入前完成namespace、私有只读字节交付、FD／stdio门、系统调用策略和独立scope实际限额核对。依赖普通用户已有bwrap／user manager／委托条件，不能兑现即unavailable。
- 沿唯一ProcessAdmission预留与保留占用；完整范围及身份核查才结清停止，控制器丢失或重启不确定保留unknown，不自动重放。
- 在design提交最小公共签名、同源schema位置、所有权和有限独立验收，供主线审查；本轮不写生产源码或注册操作，不复制三轮临时C程序。
- ReportResources继续拥有ref／basis、来源read/send和内容版本。提供者不接ResourceRef、用户路径、任意argv、通用socket代理或工作台认证。

## 完成判据

本轮规划：proposal、investigation、适用specs、design、tasks满足scholoom-dev的apply.requires依赖；没有新change delivery。代码事实、已有原生证据、未证明保证及最小下一校准分别清楚，原报告change以链接保留前置，不勾2.1b／I5。

未来提供者交付：主线审公共契约后，固定原生输入经真实Linux机制证明预执行保护、冻结字节只读、资源上限及故障／恢复不提前释放容量；所有必要保证均满足的已登记程序策略才可声明可用。程序／策略或OS条件不足明确不可用。浏览器完整进程图尚无目标校准，不以native模块结果开放活动页面。

## Capabilities

### New Capabilities

- `linux-isolated-report-provider`：领域无关的有界字节隔离执行、预执行策略、能力诊断、统一准入及完整停止／恢复契约。

已有`platform-access`的范围授权、原生适配及未知停止要求保持；新capability补充独立能力，不改原managedExecution可用性、macOS降级或普通命令契约。

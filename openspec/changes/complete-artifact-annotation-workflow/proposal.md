# 变更提议

## Why

现有材料选择已经能经共同指令进入真实执行并产生可核查修改，但批注只能在附加项检查器中填写，正文为空时不能发送；完整排版 HTML 也没有选区入口。用户要求按 Codex 式材料交互补齐现有格式，并确认有批注即可发送。本变更复用已有资源、草稿、可靠指令和文件历史权威，使材料旁输入与共同输入框操作同一批注，补齐 HTML 产物依据与双宿主完整验证。

## What Changes

- 现有源码、可视编辑、Markdown、PDF、EPUB／HTML 和图片选择提供就地批注，共同检查器可继续编辑、移除。
- 有非空批注而正文为空时允许共同发送，仍沿原 session.send 及可靠受理。
- 只读 render 资源支持 HTML；静态排版预览贡献真实文字选区并保护原版本和草稿。
- 扩展现有对象与区域用例到真实发送、项目修改和历史核查。

## 完成判据

浏览器和 Electron 实际入口均可就地批注、检查及仅批注发送；文字、对象和区域按原身份／版本进入真实 worker；HTML 产物可选字、读取、重开并在源稿修改后更新，有草稿时保留旧预览。差异、撤销及授权沿既有能力，记录缺失的科研理由保持未知。

## Capabilities

### Modified Capabilities

- `workbench-agent-context`：就地编辑共同批注和仅批注发送。
- `workbench-resources`：HTML 产物的只读资源、静态选择及更新保护。

## 决策与授权依据

- 沿研究交互职责票 #07 和工件交互票 #38；2026-10-29 用户选择先补齐现有格式、有批注即可发送，并明确要求 Implement the plan。
- Office 原生支持另立变更；执行 HTML 自身脚本的交互报告继续由 add-interactive-research-reports 承接。
- 使用已安装依赖、隔离测试和受控模型；不提交代码、不操作真实用户库、不发起付费模型请求。

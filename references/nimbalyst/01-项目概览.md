# 01 项目概览

> 事实来源：仓库根 `README.md`、`AGENTS.md`、`docs/FEATURE_INVENTORY.md`、`.ua/wiki/README.md`、各 `packages/*/package.json`。
> 调研快照见 [README](README.md#调研快照)。

## 一句话

Nimbalyst 是一个 **MIT 开源的、可视化的 coding agent 工作台**：把 Codex、Claude Code、OpenCode、GitHub Copilot 等编码 agent 的会话、worktree、任务、文档、图表、提交和代码收进同一个界面，**人和 agent 编辑同一批磁盘上的普通文件**。

它不是又一个 IDE，也不是聊天壳。README 的定位句是「open-source visual workspace for building with coding agents」，副标题强调「Visually editable. Deeply linked.」

## 它在解决什么问题

| 问题 | Nimbalyst 的答案 |
| --- | --- |
| agent 的改动是一坨文本 diff，人看不懂也不敢合 | WYSIWYG 编辑器 + 红/绿 diff 逐条审阅，接受或拒绝每一条 |
| agent 在自己的环境里改文件，人看不见 | 人和 agent 操作同一批磁盘文件，编辑器即现场 |
| 多个 agent 并行会互相踩踏 | 每个会话一个独立 git worktree |
| 任务、计划、bug 散在 agent 的上下文里 | tracker 系统，agent 与人读写同一份 |
| MCP 工具结果是原始 JSON | 渲染成可视 widget |
| 换编辑器类型要离开这个工作台 | 所有编辑器（含内置的）走同一个 `EditorHost` 契约，自建编辑器是一等公民 |

最关键的一条立场在 README「Plain files on disk」：内容与状态存在 markdown 里，工作流在 slash command 里，一切都在 git 仓库里，**没有需要迁出的专有存储**。

## 产品能力全景

### 可视化编辑器

内置 WYSIWYG 编辑器，人和 agent 协作编辑同一批文件，agent 改动以红/绿 diff 呈现供逐条审批：Markdown、Mockups（带批注）、Mermaid、Excalidraw、CSV、Data Models、Monaco 代码。

### 会话管理

会话与文件双向链接（session ↔ file）、在会话中打开文件、按 session 分组被触碰的文件、并行会话、搜索与恢复、Kanban 看板。

### 任务跟踪

plan、bug、feature、todo 都在 tracker 里，agent 可以编辑、新增、移动、执行；人也能查看与编辑同一份。

### 面向开发者

git 状态管理、AI 辅助 commit、内嵌 ghostty 终端、worktree 利用。

### 移动端

iOS 伴侣应用：会话仪表盘（看哪些 agent 在等你、哪些还在干活）、文字或语音回复（agent 立即恢复）、滑动审阅 diff、排队下一个任务、推送通知。

### 扩展系统

可插拔编辑器覆盖任意文件类型。现有扩展包括 Astro 网站编辑器、可视化 git log、mindmap、slides、3D object 编辑器。

### 遥测与自动更新

匿名使用分析发往 PostHog，明确不收集用户名/邮箱/IP、文件内容或路径、API key 或 token、文档/会话/聊天内容。随机匿名 ID 用于关联同一安装的事件，可随时在 Settings → Advanced → Analytics 关闭。完整事件表在 `docs/POSTHOG_EVENTS.md`，隐私规则在 `docs/ANALYTICS_GUIDE.md`。

自动更新默认走 **stable** 渠道；早期版本可在 Settings → Advanced → Release Channel 切到 **alpha**。

## 平台矩阵

| 平台 | 形态 | 说明 |
| --- | --- | --- |
| macOS | 桌面 .dmg | Apple Silicon 与 Intel 双架构，均需 macOS 12+ |
| Windows | 桌面 .exe | Windows 10+，x64 与 arm64 架构专属包 |
| Linux | .deb / AppImage | Debian、Ubuntu 及其衍生版；其他发行版用 AppImage |
| iOS | 伴侣应用 | SwiftUI 原生壳（`packages/ios`） |
| Android | 原生壳 | `packages/android`，有独立构建与单测脚本 |
| 浏览器 | 浏览器扩展 | `packages/browser-extension`，做 web clipping 与 AI 抽取（唯一依赖 `turndown`） |
| 浏览器/WebView | 预构建协作包 | `packages/collab-bundle` 供无编辑器宿主使用 |
| CLI | `nim` 命令 | `packages/cli`，不开桌面应用也能驱动 tracker 并与 agent 互操作 |
| Node | `nimbalyst-node` | `packages/node`，在纯 Node 进程跑 agent session |
| 编辑器内 | 扩展 | `packages/extension-sdk` + marketplace |

**协作同步服务器（`wss://sync.nimbalyst.com`）是独立项目**，客户端按 `packages/collab-protocol/` 的线格式与之通信。

## 十四步阅读路径

`.ua/wiki/tour.md` 给出按依赖顺序组织的 14 步导览，这是理解全局最有效的入口：

1. **项目概览** — README 弄清楚 Nimbalyst 是什么
2. **主进程引导** — `bootstrap.ts` 抢在 electron-store 之前设 userData 与 V8 上限
3. **Preload 安全桥** — `window.electronAPI` 是主/渲染唯一通道，暴露数百个方法
4. **渲染进程挂载** — 初始化顺序被刻意固定（性能监控 → Monaco → Jotai/PostHog → App）
5. **IPC 处理器组织** — 「一个领域一个 Handler」
6. **本地数据库双后端** — Worker Thread + 门面 + 后端选择器
7. **数据模型与迁移** — 0001 建 19 表 71 索引，0002–0023 顺序追加
8. **共享 runtime 层** — 理解「哪些能力属于产品、哪些属于宿主」
9. **扩展系统与编辑器契约** — EditorHost 是一等公民的根据
10. **编辑器内核与 diff 审阅** — DiffPlugin 是最有特色的能力
11. **AI 会话与 agent 编排** — AIService 是主进程 AI 总控
12. **Git 与 worktree 并行** — 破坏性路径一律串行化
13. **协作同步** — 44 个通道的 DocumentSyncHandlers，outbox 模式
14. **内置 MCP 服务** — 本机自建五个 MCP HTTP 服务供外部 CLI 使用

## 定位判断

Nimbalyst 与常见同类工具的差别值得记清楚：

- 不是 IDE —— 它不接管编译、断点、语言服务，核心是**审阅 agent 产出的文档与代码改动**。
- 不是聊天壳 —— agent 的每一步都落到磁盘文件上，有 diff、有 worktree、有 git。
- 不是笔记应用 —— 文档本身就是 agent 的工作介质，不是给人记的备忘录。

一句话概括：**它把「agent 在暗处改文件」变成了「人和 agent 在同一张桌子上改同一份文件」。**

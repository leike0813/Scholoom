# 03 功能地图与用户模型

> 事实来源：仓库根 `README.md`、`docs/FEATURE_INVENTORY.md`、`.ua/wiki/tour.md`、各 docs 摘要。
> 用途：回答「Nimbalyst 有哪些能力、每项能力落在代码的哪里」。

## 一句话架构

> **用户写文档 → agent 改同一批磁盘文件 → 改动以红/绿 diff 呈现 → 人逐条接受或拒绝 → 产物在 git 仓库里。**

中间的每一个环节都对应一个子系统。

## 功能域清单

### 1. 可视化编辑器

七类内置编辑器，全部 WYSIWYG：Markdown、Mockups（带批注）、Mermaid、Excalidraw、CSV、Data Models、Monaco 代码。

**共同点**：走同一个 `EditorHost` 契约，自定义编辑器是一等公民。实现见 [05 编辑器与 AI 与扩展](05-编辑器与AI与扩展.md)。

### 2. diff 审阅（Nimbalyst 最有特色的能力）

agent 提出的改动以红/绿 diff 呈现，人在**渲染后的文档中**逐条接受或拒绝，而不是看原始文本 diff。

- 编辑器侧：`editor/plugins/DiffPlugin/`（`core/` 22 + `handlers/` 13）
- 审批 UI：`plugins/DiffApprovalBar/` + `UnifiedDiffHeader`
- 会话状态：`services/document-model/DiffSession.ts`
- 基线快照：`file/FileSnapshotCache.ts`（优先用 `git cat-file --batch` 批量读取）
- 已知写入排除：`file/knownFileWrites.ts`（避免自家写入被当成 agent 改动）
- 移动端：滑动审阅、点按批准

`DiffErgonomicsFixture.ts` 与 `diffErgonomicsFixtureContent.ts` 是**diff 人机工程测试夹具**：在用户已打开的工作区里真实写文件、建 pending tag、覆盖内容并开 tab，复现一次 AI 编辑的完整链路。

**并行隔离**：每个会话一个 git worktree，由 `GitWorktreeService`（2499 行）编排。

### 4. Tracker 任务跟踪

agent 与人读写**同一份** tracker。

| 方面 | 实现 |
| --- | --- |
| 纯语义层 | `@nimbalyst/tracker-core`（记录、生命周期、key、发布、就绪） |
| schema 层 | `@nimbalyst/tracker-schema`（模型、YAML 解析、**schema 变更分类**） |
| 同步层 | `@nimbalyst/tracker-engine`（同步引擎、协议、持久化） |
| 引擎内 | `main/services/tracker/`（48 文件） |
| 编辑器插件 | `runtime/src/plugins/TrackerPlugin/`（82 文件，schema 驱动） |
| 引用节点 | `runtime/src/plugins/TrackerLinkPlugin/`（13 文件） |
| 本地键分配 | `main/services/tracker/localKeyAllocator.ts` |
| MCP 工具 | `mcp/tools/trackerToolHandlers.ts` |

**tracker 引用在正文中**表现为 chip，序列化为可移植的 `nimbalyst://KEY` markdown 链接——**内容仍是纯 markdown**。

### 5. Git 内置

- 跨仓库完整操作：`ipc/GitHandlers.ts`
- 跨仓库提交分组：`GitCommitService`
- AI 起草提交：`runtime/src/store/atoms/gitCommitProposals.ts`
- 引用追踪：`.ua/wiki` 标签中 `git` 268 次
- 内嵌终端：ghostty
- 批量读取 blob：`GitCatFileBatch`（长驻 `git cat-file --batch`）

### 6. 协作同步

见 [07 数据持久化与协作](07-数据持久化与协作.md)。要点：个人 JWT 与团队 JWT 严格区分、outbox 模式、44 个同步通道、本机自建五个 MCP 服务。

### 7. MCP 客户端与服务端

**双向**：

- 作为**客户端**连接外部 MCP server，**工具结果渲染成可视 widget**而非原始 JSON（`runtime/src/ui/AgentTranscript/components/CustomToolWidgets/`，21 文件 + feedback 10 + gitCommit 5 + shared 2）；
- 作为**服务端**在本机自建五个 MCP HTTP 服务，供外部 CLI 调用（`main/mcp/`）。

`toolBudgetService.ts` 管理工具预算——**工具调用有配额，不是无限的**。

### 8. 扩展系统

- SDK：`@nimbalyst/extension-sdk@0.6.0`（零运行时依赖，9 个 exports 子路径）
- 加载：`runtime/src/extensions/ExtensionLoader.ts`
- 特权宿主：`main/extensions/PrivilegedExtensionHost.ts`
- 权限：`PERMISSION_CATALOG`（扩展只能引用不能注册）
- 市场：`packages/marketplace`（Cloudflare Worker，26 个官方扩展）
- 面板扩展点：`FixedTabHeaderRegistry`、`DocumentHeaderRegistry`（按优先级注册）
- 现有扩展：Astro 网站编辑器、可视化 git log、mindmap、slides、3D object 编辑器

### 9. 语音模式

`main/services/voice/`（29 文件，含 `engine/live/` 5）+ 渲染侧 `store/listeners/voiceModeListeners.ts`。移动端支持**语音回复**。

### 10. 用量与统计

- 上下文窗口使用追踪（`docs/CONTEXT_WINDOW_USAGE_TRACKING.md`）
- 用量统计（AI 层定位中提到）
- `shared/toolUsage.ts`——工具使用统计的共享类型与纯函数
- `store/atoms/gitCommitProposals.ts`——提交提案
- `docs/codex-costs.mjs` 脚本

### 11. 遥测

PostHog 匿名分析。`AnalyticsService`（入边 4）统一事件发送：设置存储、客户端生命周期、会话序号、日活心跳、**发布渠道归因**。

**不收集**：用户名/邮箱/IP、文件内容或路径、API key 或 token、文档/会话/聊天内容。完整事件表在 `docs/POSTHOG_EVENTS.md`。

`check-analytics-allowlist.mjs` 强制每个事件名必须分类进 `INGESTED_ALWAYS`/`INGESTED_SAMPLED`/`INTENTIONALLY_DROPPED`——**因为 PostHog 侧有服务端丢弃逻辑，不在名单上的事件会被静默吞掉**。

- `services/tutorial/`（6）——教程项目模板

| 角色 | 入口 | 能做什么 |
| --- | --- | --- |
| **写文档的人** | 编辑器 tab | 可视化编辑、批注、评论、frontmatter、查找替换 |

## 关键交互原则

从代码摘要能反推出的几条：

1. **纯文件优先**——内容在 markdown，状态在 git 仓库，深链用 `nimbalyst://` scheme。
2. **只读降级必须存在**——`TrackerReferenceReadOnlyChip`（无 store 的宿主）、`TrackerReferenceNode.tsx`（未注册渲染器时降级为纯 key 文本）、`createReadOnlyHost`（SDK 提供）。
3. **按 tab 隔离状态**——`SearchReplaceStateManager` 按 tab 维护，同一文件的不同 tab 互不干扰；store 的 key 是 `editorKey = 文件 + 位置`。
4. **降级与自愈**——`RecoveringFileWatcher` 自动重建句柄；`useColdPaintFallback` 处理首屏。
5. **多窗口归属明确**——`permissionPromptTargeting` 修正「只按 activeWorkspace 匹配」的漂移；`workspaceWindowMatch` 决定复用哪个窗口。
6. **高频更新要合并**——`transcriptStreamAccumulator` 每帧每会话一次更新。

## 移动端的定位

iOS 伴侣应用不是「桌面端的缩小版」，而是**只做四件事**：

1. 会话仪表盘——看哪些 agent 在等你、哪些还在干活；
2. 回复提问——文字或语音，**agent 立即恢复**；
3. diff 审阅——滑动浏览、点按批准；
4. 排队下一个任务——保持流水线不断。

配套的主进程设施：`MobilePromptDelivery.ts`（**四阶段独立投递**：先落库，再分别唤醒进程内 provider 与 MCP 等待者）、`main/services/sync/`（8 文件）、`ios-transcript-tests.yml`（CI 中独立的 transcript 测试）。

**这个取舍很值得学**：移动端只保留「决策」路径，不重复实现「编辑」路径。

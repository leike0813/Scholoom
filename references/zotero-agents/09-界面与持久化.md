### `regionEquality.ts`：渲染稳定性的原语

`src/shared/regionEquality.ts` 只有 42 行，因为它只提供原语：

```ts
export function safeText(value: unknown): string
export function stableRegionSignature(value: unknown): string   // JSON.stringify(value ?? null)
export function equalBySignature(previous: unknown, next: unknown): boolean
```

`equalBySignature` 的三级快路径（每个分支都与"比较 `JSON.stringify` 输出"精确等价）：

1. `previous === next` → true
2. 任一为 `null`/`undefined` → `both == null`
3. 同为 `string` 或同为 `boolean` 且 `!==` → **必然 false**
4. 兜底比较两个签名

**`number` 被刻意排除在快路径外**——`NaN`/`Infinity` stringify 成 `"null"`，必须走字符串比较。

### 签名的设计约束（文件头注释）

> A selection contains only the region's user-visible content and open/collapsed state — high-frequency updates owned by other regions (revisions, streaming chunks, counts) must **never** enter a selection.

**这是整个 UI 稳定性设计的核心一句话。** AGENTS.md 把同一条约束写成了硬约束：transcript revision / page signature / streaming chunk / item count / prompting event tail / log tail **一律不得进入整面板 chrome render key**。

`src/sidebar/components/regionEquality.ts`（200 行）是同一机制在 sidebar 的落地，**两层级**的写法值得学：

- `replyStructuralSignature` + `replyRegionEqualityInput` — `structure` 变化重建 composer 外壳，`live` 变化只 patch 保留的 textarea
- 注释解释 `live.payload` 的加入**修复了一个真实 bug**：连续两次 `waiting_user` 轮次若只变 payload，旧代码会复用上一次渲染捕获的过期闭包
- `detailsDrawerEqualityInput` — open 状态**故意排除**（由子节点在容器上切换，永不重建内容）
- `permissionDrawerEqualityInput` — open 标志**在边界内**

**同一份函数被「命令式守卫」和「Preact `memo`」共用**，注释强调 "the equality boundary cannot drift between them"。

### 迁移方式：无 version 表

```ts

// 缺列时：
"ALTER TABLE ... ADD COLUMN title TEXT NOT NULL DEFAULT ''"
```

即 **`CREATE TABLE IF NOT EXISTS` + `PRAGMA table_info` 按列探测补列**，向前迁移，无 schema version 号。写入统一用 `INSERT OR REPLACE`。

### `guardedSqlite.ts` 的五层保护

`GuardedSqliteConnection`：`createStatement` / `execute` / `executeSimpleSQL` / `transaction` / `release`。

1. **按路径单例 + 引用计数** — 多调用方共享连接，`ownerCount` 归零才真关；路径归一化时 Windows 盘符转小写
2. **嵌套事务计数** — `transactionDepth > 0` 时内层直接执行 fn 不再 BEGIN；最外层用 `BEGIN IMMEDIATE`（抢占写锁），失败 `ROLLBACK` 但**吞掉 ROLLBACK 自身异常以保留原始错误**
3. **busy 重试** — `busy_timeout = 2500ms`、`DEFAULT_BUSY_RETRY_ATTEMPTS = 3`
4. **释出前强制检查点** — `transactionDepth > 0` 时抛 `guarded_sqlite_transaction_active` 并**回滚 `released` 标记以允许重试**；正常释放先 `PRAGMA wal_checkpoint(TRUNCATE)` 再 `asyncClose`
5. **测试复位** — `resetGuardedSqliteForTests()`

第 2、4 条都是**"在错误路径上保护原始错误"**的写法，值得抄。

**generation 机制**（`workerGeneration`）值得学：`shutdownRuntimeFileRangeReader()` 使当前 generation 失效并 `worker.terminate()`；`ensure` 时比对代标记——**所有 in-flight 请求通过代标记自动判定结果作废**，避免关停时挂起。

响应校验严格：拒绝长度不符、拒绝非法字节数据、拒绝尾随字节。`workerFactoryForTests` 可注入。

### `zipStore.ts`（160 行）

手写的**只存储不压缩** ZIP writer：

- CRC-32 自实现，标准多项式 `0xedb88320`，表在模块加载时构建
- 本地文件头 magic `0x04034b50`，通用标志 `0x0800`（UTF-8 文件名）
- **压缩方法写 0（store）** —— 不引入 deflate，因为用途是打包可流式读取的数据
- 路径穿越防护 `normalizeEntryName`：反斜杠转正斜杠、去前导 `/`、压缩连续 `/`，并拒绝 `..`、`../` 开头、含 `/../`、以 `/..` 结尾的条目

## 主题与本地化

### 本地化

11 个 locale 目录，每个 2 个 `.ftl`（`addon.ftl` + `preferences.ftl`）。

**key parity 实测**（`grep -c "^[a-zA-Z0-9][a-zA-Z0-9-]* *="`）：en-US / zh-CN / ru-RU 的 `addon.ftl` 均为 **1880** key，完全一致。en-US 两文件合计 **2144** key。

`scripts/check-localization-governance.ts`（443 行）的三类校验：

1. **key parity** — 与 base locale 做**双向差集**，任何一侧多出都失败
2. **helper 契约** — 集中式 helper 必须导出托管后端的 display/toast 解析器，防止各处自建翻译逻辑
3. **managed 文件形态检查** — 导出结构符合规范

### 主题：两套不同机制

⚠ **这是一个需要点明的认知偏差**。README 声称 Markdown Reader「自动适配 Zotero 明暗主题」，但**两处用的机制不同**：

**(a) 插件主体**（`addon/content/shared/theme.css` + `theme.js`）—— `--zs-*` CSS 变量 + `@media (prefers-color-scheme: dark)` 覆盖，运行时由 `theme.js` 补一层宿主主题同步。

**(b) Markdown Reader**（`addon/content/markdown-reader/index.html`）—— **不加载 `theme.js`、不引用 `theme.css`、不使用任何 `--zs-*` 变量**，只用：

```css
:root { color-scheme: light dark; --reader-border: color-mix(in srgb, CanvasText 16%, Canvas); ... }
body { background: Canvas; color: CanvasText; }
```

即 **CSS 系统颜色关键字 + `color-scheme: light dark`**，跟随**操作系统/浏览器**配色方案。

**后果**：该页在独立 tab document 中打开（`markdownAttachmentTab.ts` 经 `Zotero_Tabs`），不继承 Zotero 主界面的主题文档。**用户在 Zotero 内切主题但系统主题不变（或反之）时，Markdown Reader 会与插件其余 UI 表现不一致。**

`markdown-renderer.css` 中 grep 不到 `prefers-color-scheme` / `--zs-` / `:root` / `data-zs-theme`，确认它不做任何主题处理。

## 对 Scholoom 的启示

1. **跨容器挂载不复制组件**。`standaloneTopicApp` 与 `synthesisWorkbenchApp` 共用组件树，只换 root。这条规则能省掉大量重复。
2. **渲染稳定性靠"selection 里只放用户可见内容"**。一句话约束（`regionEquality.ts` 文件头注释）比一堆性能建议更有效。
3. **签名随快照下发，不让前端自行推导**。省掉一整类"推导逻辑不一致"的 bug。
4. **比较函数被命令式守卫和声明式 memo 共用**。两套判断必然漂移，共用是唯一解。
5. **原语文件要小**。`regionEquality.ts` 只有 42 行，复杂逻辑在各自的 `*EqualityInput` 里——这让"共用"这件事没有心理负担。
6. **shutting down 用 generation 标记作废 in-flight 结果**，比逐个取消更简单也更可靠。
7. **偏好迁移要有单向收敛点**：读新源 → 空则回落旧源 → 迁移标记 → **清空旧源**。不留双源。
8. **错误路径要保护原始错误**。`guardedSqlite` 的嵌套 ROLLBACK 与 released 回滚都是这个模式。
9. **"跟随系统主题"和"跟随宿主主题"是两件事**。写文档时要分清，别笼统说"自动主题"。

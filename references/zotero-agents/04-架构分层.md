## 依赖结构：四条主干

层间依赖极密（47 条有向关系、22 对双向依赖），逐条读意义不大。真正有信息量的是主干：

```
                    页面与交互界面 (162)
                            ↕
Agent 协议与后端运行时 (155) ←→ 工作流引擎与执行 (86)
                            ↕                    ↕
                    插件外壳与核心运行时 (65) ←→ Zotero 宿主与 Bridge (94)
                                               ↕
                                  Synthesis 领域与侧车 (357)
```

- **「插件外壳与核心运行时」是所有主干层的汇聚点**：它被 4 个层单向依赖（155→65、86→65、94→65、162→65），同时自己也依赖其中 3 个。改这一层等于改全项目。
- **「工作流引擎与执行」是第二枢纽**：它被 agent-runtime、ui-surface、zotero-host 三层依赖，同时依赖全部其他主干层。业务能力的入口在这里。
- **Synthesis 领域被单向依赖**：它依赖 plugin-core（53 条）与 zotero-host（12 条），但反向依赖很少（ui-surface→synthesis 12、build-tooling→synthesis 51）。说明它是**叶子域**，可以被整体替换而不影响其他层——这与 README 中「Rust 是唯一生产所有者」的迁移状态一致。
- **构建层对 Zotero 宿主有 21 条 `defines_schema` 关系**，是唯一非 imports/configures 的跨层关系类型：构建脚本定义 `contracts/` 下的 JSON Schema。

## 关系类型口径

| 关系 | 含义 |
| --- | --- |
| `imports` | 文件之间的 import 关系 |
| `calls` | 符号之间的调用关系 |
| `depends_on` | 显式记录的依赖 |
| `configures` | 配置作用于目标 |
| `defines_schema` | 定义目标的结构约束 |
| `implements` | 实现目标声明的接口 |

归属类关系（`contains`、`exports`、`documents`）不计入层间依赖，它们只表示内容归属。

**注意：这个项目几乎没有 `implements` 边**。也就是说它不依赖接口/实现分离来表达扩展点，扩展点是通过 manifest 合约与后端 Provider 契约在运行时表达的，不是通过 TypeScript 接口层次表达的。排查「谁实现了某接口」时不要指望图谱，要看 `backends/types.ts` 与 `providers/types.ts`。

## 三个必须理解的架构决定

导览里点出的三个要点，是这个项目区别于普通 Zotero 插件的地方。

**一、插件运行在 Gecko 沙箱里，没有 Node 的 `fs` / `child_process`。** 因此 `IOUtils`、`OS.File`、`Components` 流与 `platform/subprocess` 适配层是手写的最小可移植层，而不是 npm 包。这是「同一份代码同时跑在 Zotero 7/9/10」的前提。AGENTS.md 把它写成硬约束：**切勿将 Node.js 环境中才能使用的代码用于插件环境**。

**二、跨领域通信全部经过 wire 契约。** `src/shared/` 下的 `dashboardWireContract.ts`、`assistantWireContract.ts`、`synthesisWorkbenchWireContract.ts` 定义页面与宿主之间的 DTO，**重构时不得改变**。配合同治文档反复出现的 `*_ssot.md` 命名（SSOT = Single Source of Truth），这个项目把「哪些东西是边界、哪些是实现」写进了文件命名里。

**三、工作流包的代码不在插件进程内执行。** `workflows_builtin/` 下是纯 `.mjs` 模块，运行在沙箱里；产物先过 JSON Schema 校验再写入 Zotero 笔记。因此 `skills_src/topic-synthesis/contracts/db-schema.sql` 与 `payload-schemas/*.schema.json` 就是 **Agent 输出质量的第一道闸门**。

# 12 扩展指南与已知坑

这一篇面向"我要在这个项目上加东西"的人。前半是操作手册，后半是陷阱清单。

## 扩展一：新增一个工作流包

以最简单的 `workflows_builtin/mineru/` 为样板，**7 个文件、1224 行**：

```
workflows_builtin/mineru/
├── workflow-package.json     5 行
├── workflow.json             ~150 行，声明式 manifest
├── README.md                 面向用户的前置准备（注册 token、配置后端）
├── hooks/preflight.mjs       102 行
├── hooks/buildRequest.mjs    117 行
├── hooks/applyResult.mjs     601 行
└── lib/pdfSplitPlan.mjs      404 行，纯函数，hooks 共享
```

### 建议写序

1. **`workflow-package.json`** — 最简形态 `{id, version, workflows: ["workflow.json"]}`
2. **`workflow.json`** — 参照 `src/schemas/workflow.schema.json`（唯一 SSOT，`schemaVersion: 2`）
3. **`lib/*.mjs`** — 可复用**纯函数**，相对路径 import
4. **`hooks/*.mjs`** — 三个具名导出
5. **`README.md`** — 用户前置准备
6. **校验**：`npm run check:builtin-workflow-manifest`

### hooks 契约

签名统一为：

```js
export async function <hookName>({ selectionContext, runtime }) {}
```

`preflight` 返回 `{kind: "continue", context: {...}}`。

**hooks 只拿到闭合的 `runtime.hostApi` 投影 + 声明的执行上下文。** 明确**不提供**：`runtime.helpers`、`runtime.handlers`、`runtime.zotero`、`IOUtils`、`Components`、addon 对象。

`runtime` 字段全集（`docs/components/workflow-hook-helpers.md`）：

| 组 | 字段 |
| --- | --- |
| 能力 | `hostApi`（v12 投影）、`hostApiVersion: "12"` |
| 执行上下文 | `invocationMode`、`debugMode`、`workflowId`、`packageId`、`workflowRootDir`、`packageRootDir`、`workflowSourceKind`、`hookName`、`locale` |
| 取消 | `signal` |
| Web 全局 | `fetch`、`Buffer`、`btoa`、`atob`、`TextEncoder`、`TextDecoder`、`FileReader` |

⚠ **后三类 Web 全局全部标注为"可能为 `null`"** —— hook 里不能假定它们存在。

`runtime.signal` 是 host 无关的运行时自有 `CancellationSignal`，**只承诺** `aborted` / `addEventListener("abort")` / `removeEventListener("abort")`；**不承诺** `reason`、`onabort`、`throwIfAborted()`、`dispatchEvent()`，也**不保证能当原生 `fetch` signal 用**。

### `workflow.json` 关键字段（mineru 实例）

```json
{
  "schemaVersion": 2,
  "id": "...",
  "label": "...", "description": "...",
  "version": "...",
  "executionModes": ["auto"],
  "provider": "generic-http",
  "display": { "core": ..., "emoji": ... },
  "i18n": { "defaultLocale": ..., "messages": {...} },
  "trigger": { "requiresSelection": true },
  "inputs": { "member": { "kind": ..., "accepts": { "mime": ... } },
              "grouping": { "mode": ... } },
  "validateSelection": { "select": ..., "filters": ... },
  "execution": { "poll_interval_ms": ..., "timeout_ms": ... },
  "request": { "kind": "generic-http.steps.v1", "steps": [...] },
  "hooks": { "preflight": "...", "buildRequest": "...", "applyResult": "..." }
}
```

`request.steps[]` 支持 `extract`（JSONPath）、`repeat_until`、`fail_when`、`binary_from`、`response_type: "bytes"`。

### 已废弃字段（出现即非法）

顶层 `backend`、`defaults`、`request.result`、`request.create.engine/model/parameter/runtime_options`。

## 扩展三：新增一个 Skill

### 有效性判定

**一个 skill 进入 registry 的条件是同时具备 `SKILL.md` 和 `assets/runner.json`。**

registry entry 字段：`skillId`、`sourceKind`（`official`/`dev-local`/`user`）、`sourceDir`、`skillMdPath`、`runnerJsonPath`、`checksum`、`diagnostics`。

### 来源优先级

1. `official`：`content/official/skills`（订阅安装）
2. `dev-local`
3. `user`：`skills/`

**同 id 时 user 覆盖 official。** debug mode 只控制 debug-only 条目的可见性。

**registry 职责边界**：只发现插件侧 skill 并记录 diagnostics；**不执行 skill、不 patch `SKILL.md`、不创建 run workspace**。

### Host Bridge 七个保留 ID

只来自 XPI 内的 `content/host-bridge-skills/`：`zotero-bridge-cli`、`zotero-library-agent`、`zotero-library-query`、`zotero-literature-acquisition`、`zotero-literature-analysis`、`zotero-research-synthesis`、`zotero-library-curation`。

### ACP 兼容 runner 行为

workflow 继续发 `skillrunner.job.v1`；**ACP 兼容是 provider/backend 的实现细节，不是 workflow 编写的关注点**。

流程：解析插件侧 skill 资产 → 物化到 run-local agent skill root → 注入最小 SkillRunner 兼容 run contract 到物化的 `SKILL.md` → 校验 `resultJsonPath` 里 runner 拥有的 result JSON envelope → 返回正常 `ProviderExecutionResult` 供现有 `applyResult()` hook 用。

**业务脚本可以写 package fallback 文件，但不得手写 runner 拥有的 result envelope。**

runtime options 合成顺序（后者覆盖前者）：

```
runner.json.runtime.default_options
  → request payload 的 runtime_options
    → 提交时的 providerOptions
```

`hard_timeout_seconds` 只接受正整数；三源都无有效值时回落 **1200 秒**。它是**本地可恢复连接守卫**：从 ACP prompt-ready 边界起算，到期本地断连，排空 transcript 后追加 timeout status item，**远端 session 保持可恢复**；**不得**把 run 标记为 `failed` 或 `canceled`。

现状：`skills_builtin/` 26 个 skill 目录（其中 3 个是 submodule）；`skills_src/` 只有 2 个模板源码：`topic-synthesis/`、`literature-deep-reading/`。

## 已知坑：十二项

### 1. 命名不一致：zotero-skills vs Zotero Agents

- 仓库/package 名是 **`zotero-agents`**（`package.json:2`）
- 但生成的 help-docs 资源根仍是 **`chrome://zotero-skills/content/help-docs/assets/img/`**（`scripts/build-help-docs.ts:47`）——**改名前遗留的运行时 chrome 前缀**
- 历史目录名 `.zotero-skills-runtime/` 与 `.zotero-agents/` 并存
- `zotero-plugin.config.ts` 写数据目录时用 `zotero-agents/data/...`
- `src/` 下搜 `zotero-skills` 命中 `helpCenterTab.ts`、`workspaceTab.ts`、`synthesisWorkbenchTab.ts`、`bundleIO.ts`、`messageFormatter.ts` 等

**运行时命名与仓库命名长期不同源，按仓库名推断运行时路径会错。**

### 2. 四处版本号不一致

| 位置 | 值 | 性质 |
| --- | --- | --- |
| `package.json` | `0.9.0` | 真实版本 |
| `content-package.version.json` | `0.8.7` | **设计意图**（内容包独立版本线） |
| `content_api` | `3.0.0` | **设计意图** |
| `README.md:13` badge | `v0.5.0` | **真实漂移，差 4 个 minor** |
| README badge 的 TypeScript | `4.0+` | 实际 `typescript: ^5.9.3` |

`addon/manifest.json` 的 `version` 是占位符 `__buildVersion__`，构建时注入——**读 manifest 看不到真实版本**。

前三处不同是解耦设计，第四处是漂移。

### 3. 四份 tsconfig 的边界容易踩错

主配置 include `["src","typings","packages/*/src"]`，但 **exclude** 掉 `src/sidebar/components`、`src/sidebar/**/*.tsx`、`src/shared/**/*.tsx`、`src/dashboard`、`src/synthesis`、`src/synthesisWorkbenchApp.ts`。

| 配置 | 覆盖 | tsx |
| --- | --- | --- |
| `tsconfig.json` | 主体 | 不带 `jsx` |
| `tsconfig.sidebar.json` | `src/sidebar/**` + `src/shared/**/*.ts` | **不含 tsx** |
| `tsconfig.dashboard.json` | `src/dashboard/**` + `src/shared/**/*.ts` | 含 tsx |
| `tsconfig.synthesis.json` | `src/synthesis/**` + `src/synthesisWorkbenchApp.ts` + `src/shared/**` | 含 tsx |

**后果**：`src/shared/` 下的 `.tsx` **只被 dashboard / synthesis 检查**。sidebar 引用的 shared `.tsx` 不在 sidebar 投影里，改 shared 组件可能只在部分配置中报错。

**教训**：`npm run build` 会跑全部 4 次 tsc；**只跑 `tsc --noEmit` 会漏掉页面层错误。**

另：共享 i18n 文件 `src/synthesisWorkbenchI18n.ts` 被三份子配置都 include（侧栏也在用），改一处要三处都过。

### 4. ESLint `no-restricted-imports` 会拦什么

**三处页面 import 边界**（作用于 `src/sidebar/**`、`src/dashboard/**`、`src/synthesis/**`）：

- 允许：同目录相对路径、`../shared/` 形式、`src/shared/**`、Preact 入口（`preact`、`preact/hooks`、`preact/compat`、`@preact/signals`）
- **拦截其余一切 import**

**第四处更严**（`src/synthesis/components/**`）：允许 `./`、`../`（**但 `../../` 双重否定被排除**）、`{2,}/shared/`、Preact。

**另有一条 global 限制**：`src/**/*.ts`（排除 `src/sidebar/**`）**禁用全局 `AbortController`**，必须用 `createCancellationController()` 或 `resolveNativeAbortControllerConstructor()`。

### 5. Gecko 沙箱没有 Node API

`src/workflows/archive.ts` 有 `resolveGeckoArchiveWriterRuntime()` / `writeZipInGecko()`——归档在 Gecko 侧有独立运行时。`runtimePersistence.ts:1044` 注释处理 Windows 无 POSIX mode 的 `nsIFile` 权限位映射。

对应硬约束：AGENTS.md:147 + `runtimePersistence` 唯一事实源。

### 6. `content-package.version.json` 与插件版本解耦

三套版本号并存：插件 `0.9.0` / 内容包 `0.8.7` / `content_api 3.0.0`。

**规则**：插件版本变了**不需要**提升 content 版本；**内容变了必须提**（AGENTS.md:291：内容不同必须提升 content package 版本）。命令：`bump:content-package`、`check:content-package-release`。

### 7. `addon/content/help-docs/` 自动生成不能手改

AGENTS.md:36 明确标注"**自动生成，不要直接修改！**"。`build-help-docs.ts` 内有 `rm`——**重新生成会清空重建**，手改必丢。

真正的编辑点：`site/docs/`（en）与 `site/i18n/<loc>/docusaurus-plugin-content-docs/current`（其余 locale）。

### 8. `addon/content/harness/prototype-*.html` 被构建排除

`zotero-plugin.config.ts:334-335` 明确排除：

```
"!addon/content/harness/prototype-*.html"
"!addon/content/harness/prototype-*.bundle.js"
```

**源码留在仓库但不进 XPI**。改动在本地能看，打包后 404。目录里还有 `index.html`、`harness-host.js`、`styles.css`、`prototype-source-switching.html`、`prototype-workspace.html`。

### 9. `builtinWorkflowSync.ts` 已无生产调用点

`src/modules/workflow/catalog/builtinWorkflowSync.ts` 存在，但在 `src/` 内**除自身外零引用**，只被两处测试引用（导出 `__builtinWorkflowSyncTestOnly`）。

**陷阱**：它仍被测试覆盖，容易误判为"在跑的启动同步逻辑"。实际内置工作流的分发走 content package。

### 10. `.invariants.yaml` 只覆盖 skillrunner

全仓仅 3 个 `*.invariants.yaml`，全在 `docs/components/`，全部是 skillrunner。`check-skillrunner-ssot-invariants.ts` 恰好硬编码这三条路径。

即 **`npm run check:ssot-invariants` 只覆盖 skillrunner 状态机**，不覆盖 ACP / Synthesis / Citation Graph。`docs/acp-skills-state-machine-ssot.md`（37 KB）虽有 SSOT 文档但**无 invariants 文件**。

### 11. debug-only 模块在 release 被 esbuild 擦除

`__synthesis_sidecar_diagnostics_enabled__` 等为 `"false"` 时相关代码被**整块 tree-shake**。

**陷阱**：在 debug 模式下测通的行为在 release 包里可能**根本不存在**。用 `check:runtime-diagnostics-release-elision` 验证（它编译真实入口，要求 exclusive input 贡献 0 字节）。

### 12. AGENTS.md 自身的数字漂移

| 位置 | 声明 | 实际 |
| --- | --- | --- |
| `AGENTS.md:117` | 365 个 capability | **366** |
| `AGENTS.md:90` | ~326 个 `*.test.ts` | **330** |
| `AGENTS.md:59` | ~342 个 `src/modules` 文件 | 未逐一核对 |
| README badge | v0.5.0 / TS 4.0+ | 0.9.0 / TS 5.9.3 |
| `docs/synthesis-layer/README.md` | R9/Stage 1 未完成 | **已完成**（见 08 篇 D-2） |
| Synthesis README | foundation **v5** | **v6** |
| `registry.json` | `expected.crossProcessCapabilities = 120` | **130**（检查脚本硬断言 120，冻结在过期值） |
| `AGENTS.md:278/286` | "发布流程硬约束" | **标题重复两次**，内容不同 |

⚠ **最后一项最值得警惕**：一个"检查脚本"硬编码了过期的期望值（120 vs 130），于是检查永远通过、漂移永远发现不了。**机器校验的期望值本身也需要被 review。**

另外：实机二进制当前是 7.0.32 / 9.0.6 / **10.0.2**，而兼容矩阵 `zotero-10-*` 仍固定 10.0.1——AGENTS.md 明确说"**差异是有意保留的，不得据此改矩阵**"。

## 对 Scholoom 的启示

1. **扩展点要配"模板仓库"**。`workflows_builtin/mineru/` 就是一个 7 文件的最小完整样板，新人照着抄就能起步。
2. **"唯一来源"字段要在文档里点名**。兼容性由 `provider` 字段唯一决定——这种规则如果不写清楚，开发者一定会去用 `requestKind` 推断。
3. **废弃字段要显式列为"出现即非法"**。靠"不再支持"是不够的，必须写进 schema 让它报错。
4. **生成的 help-docs 要在目录内和文档内双重标注**。AGENTS.md 写一句"不要改"，脚本里还有 `rm`——两道防线。
5. **机器校验的期望值要有人 review**。过期期望值 + 严格比较 = 永久绿灯。
6. **能力投影的兼容性边界要写进 API 文档**。`signal` 只承诺三个方法、不承诺 `reason`/`onabort`/可当 fetch signal——这种"只承诺 X" 的写法比列全部 API 更能防 bug。

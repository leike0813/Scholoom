# 01 项目概览

## 定位

Zotero Agents 是一个 **Zotero 桌面端插件**，把外部 AI Agent（Codex、OpenCode、Claude Code 等 CLI 工具）接到用户的 Zotero 文献库上，让 Agent 直接在库内执行文献分析、检索入库、标签治理、深度精读、主题综述等任务。

它的自我表述是「all-in-one agentic workbench for your Zotero library」，并明确区分自己与市面常见的 Zotero AI 插件：不是聊天框，而是把 PDF 变成可探索、可审计、可累积的研究知识网络。

- 官方仓库：`https://github.com/leike0813/zotero-agents`（Gitee 镜像同步）
- 用户文档站：`https://leike0813.github.io/zotero-agents/`（Docusaurus，源码在 `site/`，56 个页面）
- 作者：Joshua Reed（包配置中的 author 字段）

## 核心设计立场

`AGENTS.md` 把项目定位讲得非常直接，值得完整引用其设计意图：

> 插件采用模块化、工作流可插拔的设计理念。插件本体提供通用的 UI 界面及菜单。内部通过统一的工作流协议，由各组件分别按流程执行任务。**插件本身不包含任何具体的业务逻辑。**

这一条决定了整个仓库的组织方式：`src/` 里没有任何「怎么分析论文」的知识，只有一层执行外壳；所有业务能力都在 `workflows_builtin/` 的工作流包和 `skills_builtin/` 的 Skill 资产里。README 的说法是「插件是一个 execution shell，声明要做什么，插件负责怎么执行」。

作者在 AGENTS.md 里给团队的提醒同样直白：**「如无必要，勿增实体！」**

## 命名与历史

项目有两个名字，文档里混用时需要注意：

| 名称 | 时期 | 说明 |
| --- | --- | --- |
| Zotero Skills | v0.4.x 及以前 | 旧名，旧仓库 `leike0813/Zotero-Skills` 保留历史发布与迁移记录 |
| Zotero Agents | v0.5.0 起 | v0.5.0 是改名后的第一个大版本 |

包配置里还留着一批旧标识符作为内部兼容锚点：`config.addonRef` 为 `zotero-skills`，`config.addonInstance` 为 `ZoteroSkills`，`config.prefsPrefix` 为 `extensions.zotero.zotero-skills`。改这些会影响用户的首选项数据迁移，**不要按名字推断它们是笔误**。

## 与 Scholoom 的关系

这是一个**可以完整参考的同类项目**：Scholoom 若也要做文献智能体工具，Zotero Agents 提供了三层可直接借鉴的范式。

1. **执行外壳与业务资产分离**。把「Agent 怎么调用、结果怎么落库、权限怎么管」做成固定外壳，把「做什么」全部推给可插拔的声明式工作流包。这一层的边界设计（manifest 合约、hook 契约、Host API 版本化）是这个项目最值得抄的部分，详见 [05-构建与工程化.md](05-构建与工程化.md) 与 [06-工作流引擎与执行.md](06-工作流引擎与执行.md)。

2. **Agent 变更必须经审批的写权限模型**。`zoteroHostCapabilityBroker` 强制的「写前无副作用预检 → 等待审批 → 重新准备 → 摘要变化需重新审批」四步，是任何「让 LLM 直接改用户数据」场景的通用模式，详见 [10-宿主能力与Bridge.md](10-宿主能力与Bridge.md)。

3. **派生知识与源材料严格分离**。Zotero Agents 花大力气做的是「分析产物不是笔记正文，而是渲染自后端数据」，以及 WebDAV 同步只同步结构化知识而不碰附件。这条边界避免了 AI 生成的不可编辑文本污染用户的原始记录，详见 [03-功能地图.md](03-功能地图.md) 与 [09-界面与持久化.md](09-界面与持久化.md)。

## 已知局限（官方自述）

README 的 Known Limitations 列出三条，其中第一条对架构理解很关键：

> **Native Synthesis retirement acceptance is not final** — Rust 是应用、持久化、canonical store 与计算的**唯一**生产所有者。插件侧旧 owner 与外部 Node service/worker 栈已从开发源码树中移除。

也就是说，Synthesis 子系统经历过一次从「TypeScript/Node 实现」到「Rust sidecar 独占」的迁移，迁移尚未完成最终验收。**读这个仓库的 Synthesis 相关代码时，不要假设还有 Node 侧实现存在。**

另两条：WebDAV 同步未经充分测试，建议尽量手动同步；大规模文献库性能未充分测试。

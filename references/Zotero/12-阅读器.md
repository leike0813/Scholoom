# 12 阅读器子模块（reader）

`reader/` 是 Zotero 主仓库的 Git 子模块，独立克隆、独立构建，负责 PDF、EPUB 与网页快照三种文档的渲染、批注、高亮与朗读。本文基于子模块自身的知识图谱（223 个文件节点、531 节点、1287 边、10 个分层）撰写，调研时子模块 commit 为 `692c2898`。

**先记住一条边界**：reader 不碰存储。所有批注的读写都通过宿主（Zotero 客户端或 web-library）回调完成，「渲染 + 交互，存储外置」是读后续所有代码的前提。批注数据本身由主仓的 `xpcom/annotations.js` 与 `xpcom/reader.js` 负责。

## 一、两种渲染链路

reader 的核心结构不是「一个页面读三种格式」，而是**两条互不相通的渲染链路 + 一层格式无关的外壳**：

| 链路 | 覆盖格式 | 基类 | 核心文件 |
| --- | --- | --- | --- |
| DOM 链路 | EPUB、HTML 快照、SDT | `DOMView` | `src/dom/common/dom-view.tsx` |
| PDF 链路 | PDF | 无基类，独立实现 | `src/pdf/pdf-view.js` |
| 格式无关外壳 | 全部 | 无 | `src/common/reader.js`、`src/common/view.js` |

DOM 链路的意义在于 `DOMView` 把「在 iframe 中渲染 XHTML 文档」这件事抽象掉了：选区、批注创建与渲染、查找、缩放、主题、朗读、外部链接、拖放全部定义在基类上，EPUB / SDT / snapshot 三个视图只实现各自的少量钩子。新增一种 DOM 格式的成本因此被压得很低。

PDF 走不了这条路——pdf.js 的文本层不是稳定的 DOM 结构——所以它是完全平行的一条链路。`pdf-view.js` 与 `reader.js` 并列为全库扇出最高的两个文件（各 25 / 24 条出边），两者地位相当而非主从。

## 二、格式无关核心

`src/common/reader.js`（约 3000 行）是整个子模块的架构中心。它只面向抽象的「文档视图」工作：视图生命周期、状态派生与变更广播、批注编排、朗读、查找、缩放导航、打印，以及宿主回调桥接。

`src/common/view.js` 是第二道门面，按 `type` 延迟创建 PDF / EPUB / Snapshot / SDT 基础视图，把搜索、缩放、翻页、主题、朗读、SDT 阅读模式等能力聚合起来。**宿主与移动端只调 `View`，不直接碰 `Reader` 或各格式视图**。

两个单点事实源值得记住：`src/common/types.ts`（跨模块类型契约，扇入 24）与 `src/common/defines.js`（批注颜色、朗读颜色、debounce 时长等常量，扇入 18）。要改任何枚举都应从这两处出发。

## 三、SDT 与位置映射

批注要存成与具体文件无关的稳定标识，就必须能在各格式的原生坐标之间来回转换。SDT（Structured Document Tag）就是这套换算的中枢，它同时是 document-worker 的产物格式（见 [14-文档处理Worker.md](14-文档处理Worker.md)）。

- `src/common/sdt/position-mapper.ts` 定义 `SDTPositionMapper` 接口，并提供按 ref 查 block、展开 text node span 等各格式复用的公共能力。
- `src/pdf/pdf-position-mapper.ts` 换算成页码加 rect，并缓存解码出的 run data。
- `src/dom/epub/lib/` 侧的 mapper 在 text node 位置与源文档 CFI 之间双向换算，还要处理多子路径与 NFC 偏移。
- `src/common/sdt/document-session.mjs` 持有 pack 读取器与物化后的结构文本，负责版本校验、进度上报与 AbortController 中断。

EPUB 侧的位置换算分散在几个文件里，`cfi.ts` 处理 CFI 定位、`lib/page-mapping.ts` 对候选页码映射打分（有效数量、单调性、覆盖度）。

## 四、批注体系

三个文件分工明确，且刻意做了「宁漏勿误」的取舍：

| 文件 | 职责 |
| --- | --- |
| `annotation-manager.js` | 所有批注增删改查的**唯一写入口**：批注集合、过滤条件、防抖保存、撤销/重做历史、图片变更 |
| `annotation-selection-handler.mjs` | 把「视图内选中」与「向宿主通知选中」解耦；移动端内联编辑场景延迟通知以免打断输入 |
| `annotation-cleanup.mjs` | 只筛掉可安全删除的空文本批注，**宁可漏删也不误删用户数据** |

批注的**呈现**不走这条链路，由 `selection-popup.js` 在选区后浮出触发。读写与呈现分离是这里的设计要点。

主仓侧的对接是 `xpcom/annotations.js`：批注缓存图片读写、JSON 序列化与反序列化，位置数据超长时自动拆分批注。

## 五、PDF 选区

`src/pdf/selection.js` 是 PDF 侧真正的难点：把 PDF 的字符模型与 DOM 选区互相换算，支持单词/行选区、修饰键扩展、跨页连续选区与 flow 隔离。跨页连续选区意味着一个高亮要同时落在两个页面的文本层上，而 flow 隔离要保证双栏排版里的选区不会跨栏跳跃。

`src/pdf/lib/renderer.js` 负责把页面坐标经 viewport 变换到像素坐标，以 4 倍缩放绘制批注与区域裁剪图并导出 PNG——这是图片类批注的数据来源。

## 六、共享组件库

格式无关的外壳 UI 全部收在 `src/common/components/`，与两条渲染链路解耦。

- `reader-ui.js`（扇出 22）是 React 根界面，装配工具栏、侧边栏、各类弹窗与 popup 容器，把 Reader 状态与回调桥接为 UI 事件。经过这一步之后的状态都是无渲染的纯 JS 对象。
- `toolbar.js` 汇集页面跳转、缩放、批注工具、查找、朗读与进度条。
- `sidebar.js` 在 thumbnails / outline / annotations 三个视图间切换。
- 弹层分两类：随内容定位的 `view-popup`（如 `selection-popup.js`），与 `view-popup/overlay-popup/index.js` 按 `params.type` 路由的六种 overlay——internal-link、external-link、footnote、citation、reference、image。后者是这一体系的**单一事实源**，新增弹层类型只需在此登记。

## 七、read-aloud 朗读层

朗读是结构上解耦最彻底的功能，刻意做了三层：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 编排 | `manager.ts` | controller 创建销毁、语音目录加载、按 tier/language 选音回退、额度轮询，订阅事件驱动 React 刷新；**刻意不感知 React 与 DOM** |
| 播放状态机 | `controller.ts` | 与语音后端无关，以 EventTarget 承载段落推进、暂停恢复、句子与段落跳转 |
| 语音提供方 | `browser/` 与 `remote/` 两套 | 统一 `voice.ts` 的 id、label、score、tier 属性；`remote/provider.ts` 把嵌套响应展开成扁平语音配置列表 |

段落切分（`segment-split.ts`）依赖 SDT 位置映射，所以朗读是这条链路的消费者而非独立子系统。`read-aloud-links.js` 按操作系统给出系统语音设置页的深链。

## 八、样式与主题

样式是全项目被引用最多的资源（`main.scss` 扇入 21），按 SCSS partial 严格分层。`main.scss` 按 abstracts → themes → base → components 的固定顺序聚合，是打包样式的根。主题走 `_light.scss` 与 `_dark.scss` 两条色板，把 accent、fill、text 等语义色映射为 CSS 自定义属性，因此切主题不需要重新加载样式。

**与内容文档相关的样式必须分两处注入**，这是个容易踩的细节：`view.scss` 约束移动端外壳与 iframe 尺寸，`dom/common/stylesheets/annotations.scss` 注入文档 iframe 内部，负责批注层的绝对定位、指针事件穿透与层级。只有前者能在宿主文档里覆盖 EPUB 自带样式。

## 九、构建与运行形态

同一份核心代码要跑在桌面端、web-library、移动端和浏览器调试环境，差异全部收敛到「HTML 模板 + 入口脚本」：`index.reader.html` 提供 `#reader-ui`、`#split-view` 双栏与打印容器，`index.view.html` 精简为移动端单视图；`src/index.zotero.js`、`src/index.web.js`、`src/index.dev.js` 各自注入不同的宿主回调桥接后创建同一个 Reader 单例。

`webpack.config.js` 导出六份构建：zotero / web / dev 三个 reader 入口，加上 ios / android / view-dev 三个 UMD 形式的 view 入口，正好对应这套运行形态划分。`tsconfig.json` 启用 strict 但**只覆盖 `./src`**，并显式排除仍是 JavaScript 的 `src/common` 与 `src/pdf`——TypeScript 化只完成了 EPUB/快照那一侧。

CI（`.github/workflows/ci.yml`）在 push 与 pull_request 上跑 build + test，Node 22 缓存 node_modules；master、`x.y` 版本号、`*-hotfix` 或 `ci-test` 分支还会把 build 目录打包上传 S3 供预览。

## 十、给 Scholoom 的启示

1. **格式无关外壳 + 格式专属链路**。`Reader` / `View` 两层门面之下，DOM 系格式共享一个基类，PDF 独立成链。新增格式时，先问它能不能落成 DOM——能就继承 `DOMView`，不能才写独立链路。
2. **批注位置与结构化文本位置需区分**。PDF 批注保存页索引及页面坐标，如 `pageIndex`、`rects`、`paths` 和 `nextPageRects`；SDT mapper 另外提供结构化文本范围与格式内位置的转换。位置转换不自动绑定材料版本，也不保证文档改版后批注仍能正确定位。跨版本恢复需由宿主保存版本关联并核验位置。
3. **单点事实源用小文件扛**。`defines.js` 18 个扇入、`overlay-popup/index.js` 一个文件路由六种弹层，都比散落在各处的常量表和 switch 更难用错。
4. **批注清理宁漏勿误**。`annotation-cleanup.mjs` 的取舍是显式写出来的。这类不可逆操作值得在代码里留下意图说明。
5. **「不感知 React 与 DOM」的编排层**。`read-aloud/manager.ts` 把状态编排与渲染分开，使得朗读既能被 React 界面订阅，也能在无界面的移动端工作。

# 03 功能地图

按用户能力域组织，每个域给出承载它的核心模块。文件路径均在 `chrome/content/zotero/` 下，除注明处。

## 1. 收集：从网页到条目

| 能力 | 核心模块 | 说明 |
| --- | --- | --- |
| 浏览器连接器 | `xpcom/server/server_connector.js` | 浏览器扩展把网页数据 POST 到本地服务，检测可用 translator 并保存条目/附件/快照 |
| 翻译器框架 | `xpcom/translate/`（子模块）、`xpcom/translation/`、`RemoteTranslate.mjs`、`actors/TranslationParent.mjs`、`actors/TranslationChild.mjs` | 749 个 translator 定义在独立仓库，主进程只做调度，内容进程执行 |
| 隐藏浏览器 | `HiddenBrowser.mjs` | 加载页面、等待就绪、序列化 DOM、生成快照 |
| 反爬处理 | `xpcom/browserRequest.js`、`captcha.js` | 识别验证码 / Cloudflare 拦截，必要时开可见窗口让用户过验证 |
| 拖放与附加链接 | `xpcom/fileDragDataProvider.js`、`attachLink.js` | 拖条目或文件进窗口；给独立附件附加链接 |
| 识别文档 | `xpcom/recognizeDocument.js` | 从 PDF/EPUB 抽文本，识别 DOI、ISBN、arXiv 号，交给 translator 补全，并可撤回 |
| 按标识符查找 | `createParentDialog.js`、`xpcom/locateManager.js` | 用标识符添加条目；「检索」功能管理外部学术搜索引擎列表（`resource/schema/engines.json`） |
| 快速复制 | `xpcom/quickCopy.js` | 按站点定制复制格式（引文、书目、笔记、DOI 等） |
| RSS 订阅 | `xpcom/feedReader.js`、`data/feed*.js`、`resource/feeds/` | 解析订阅源为条目，处理 enclosures 附件与富文本摘要，支持 OPML 导入与定时更新 |

**翻译器框架的内部实现**（`xpcom/translate/` 子模块，现已可查）：

| 关注点 | 实现 |
| --- | --- |
| 消费方契约 | 宿主必须自备 `Zotero.Translators` / `Zotero.HTTP` / `Zotero.Translate.ItemSaver`；`src/http.js` 是纯契约层不含实现 |
| 权威装配示例 | `example/index.html` 的顺序敏感 `<script>` 序列——读它比读文档快 |
| 运行时底座 | `src/promise.js` 补 `Promise.method` / `defer` / `delay`（translator 代码大量用 `Promise.method` 包同步函数），`src/debug.js` 提供带级别过滤与栈帧过滤的日志 |
| RDF 子系统 | `src/rdf/`：内嵌 rdflib 栈，`init.js` 是 `$rdf` 命名空间的唯一装配点，term/uri/identity/n3parser/rdfparser/serialize 各自负责术语、地址归一化、索引化存储与两侧编解码 |
| 自测夹具 | `testTranslators/` 随包发布，translator 作者拿到 npm 包即可自测 |

宿主侧的实现正是主仓这几个文件，细节见 [15-翻译框架与共享工具库.md](15-翻译框架与共享工具库.md)。

## 2. 组织：文库、分类、标签、检索

| 能力 | 核心模块 |
| --- | --- |
| 资料库 | `xpcom/data/library.js`、`libraries.js`、`group.js`、`groups.js`；个人库、群组库、订阅库共用同一抽象 |
| 分类 | `xpcom/data/collection.js`、`collections.js` |
| 条目 | `xpcom/data/item.js`（全项目最核心数据模型）、`items.js` |
| 标签 | `xpcom/data/tags.js`：创建、重命名、颜色分配、删除、条目列表开关状态 |
| 高级搜索 | `xpcom/data/search.js`（把条件编译成临时表 + SQL）、`searchConditions.js`（全部可用条件与操作符）、`searches.js`（保存的检索） |
| 快速搜索语法 | `xpcom/searchQuery.js`：把 `by:smith after:2020 tag:"to read"` 解析成条件树，附带补全与本地化词表 |
| 关系 | `xpcom/data/relations.js`：维护 `dc:relation` 等谓词化的条目关联图谱 |
| 作者 | `xpcom/data/creators.js`：去重作者记录、按 ID 或姓名查找、数据清洗、孤儿清理 |
| 回收站 | `data/item.js`、`data/collection.js` 中的 trash 语义，配合 `deletedItems` / `deletedCollections` 表 |
| 重复项 | `xpcom/duplicates.js`：按 ISBN、DOI、标题、作者聚类，并用查集维护分组；`elements/duplicatesMergePane.js`、`mergeGroup.js` 做字段级合并 UI |
| 出版物 | `publicationsDialog.js`、`data/` 下的 `publicationsItems` 表、`elements/publicationsLicenseInfo.js` | 创建群组出版物并选择 CC 许可 |
| 撤稿告警 | `xpcom/retractions.js`：按 DOI/PMID 维护映射，用 Crossref 前缀缓存批量发现撤稿条目，在条目上打标 |
| 笔记 | `data/notes.js` + `elements/noteEditor.js` + `note-editor/` 子模块（ProseMirror schema 版本 10，`src/core/schema/index.js` 是唯一入口） |
| 附件 | `xpcom/attachments.js`：导入 / 链接 / 快照、URL 附件、可用文件自动发现与下载、存储目录管理、重命名模板 |
| 批注 | `xpcom/annotations.js`：PDF / 图片批注的缓存图片读写、JSON 序列化，超长位置数据自动拆分批注 |

## 3. 引用与引文

| 能力 | 核心模块 |
| --- | --- |
| 样式与 locale | `xpcom/style.js`（`Zotero.Styles` 管理样式与 locale 列表的加载/安装/校验，`Zotero.Style` 构建并缓存 citeproc 引擎），`styles/` 与 `chrome/content/zotero/locale/csl/` 子模块 |
| 引文引擎 | `xpcom/cite.js` + 内嵌的 `xpcom/citeproc.js`（vendored citeproc-js），`resource/schema/abbreviations.json` |
| Word / LibreOffice 集成 | `xpcom/integration.js`（3830 行，引文域的插入/更新/删除、参考文献维护、citeproc 状态同步）、`integration/` 目录的引用与参考文献对话框 |
| 远程文档代理 | `xpcom/httpIntegrationClient.js`：把插入引文、编辑字段、刷新文档等命令以 JSON POST 到外部服务 |
| 从文档反向导入 | `rtfScan.js` + `modules/rtf.mjs`：解析 RTF 中的引文，按作者-年份、标题等规则在库中检索候选，写回 `citationItemIDs` |
| 参考文献生成 | `bibliography.js`：输出 RTF / HTML / 剪贴板 / 打印 |
| CSL 升级 | `updateCSL.xsl`：XSLT 把旧版 CSL 0.8 就地升级到 CSL 1.0 |
| 时间轴 | `xpcom/timeline.js`：按天/周/月/季/年/十年分桶，产出 Obsidian 兼容的时间线 XML |

## 4. 阅读

| 能力 | 核心模块 |
| --- | --- |
| 阅读器控制器 | `xpcom/reader.js`：以 ES class 体系管理阅读标签页、独立窗口、阅读预览面板，以及全局 `Zotero.Reader` 单例（打开、状态存取、事件注册、朗读支持） |
| 实际阅读器 | `reader/` 子模块：架构中心 `src/common/reader.js`，门面 `src/common/view.js`，见 [12-阅读器.md](12-阅读器.md) |
| PDF 处理 | `document-worker/` 子模块 + `xpcom/pdfWorker/manager.js`：主进程端管理器，启动 worker、用消息队列串行调度任务，提供导入导出、页操作、全文提取、批注处理。见 [14-文档处理Worker.md](14-文档处理Worker.md) |
| 结构化文本 | `xpcom/sdt.js`：调用 document-worker 抽取结构化文本，按源文件哈希缓存到磁盘（靠 `versions.js` 的版本号判断缓存失效） |
| 全文索引 | `xpcom/fulltext.js`：PDF/EPUB/笔记的文本提取、分词索引、队列调度与全文检索 SQL 生成 |
| 笔记编辑器 | `xpcom/editorInstance.js` 桥接 `note-editor/` 子模块，管理编辑器生命周期、保存、引文插入与批注序列化。见 [13-笔记编辑器.md](13-笔记编辑器.md) |
| 模板与词典 | `modules/templates.mjs`（笔记编辑器的轻量模板语言）、`xpcom/dictionaries.js`（下载安装 Hunspell 词典，为笔记挑最佳词典） |
| 朗读 | `readAloudFirstRunDialog.js`、`readAloudVoicesDialog.js`：通过 iframe 承载 reader 侧 UI，回调桥接开通/选声/购买额度。reader 侧实现在 `src/common/read-aloud/`（manager / controller / provider / voice / segment-split，browser 与 remote 两套语音后端） |
| 阅读进度 | `xpcom/attachmentReadObserver.js`：监听 reader 的 open/close/pageChange，把最后阅读时间写回 item |

**批注的完整链路**（跨主仓与两个子模块）值得单独看，因为它横跨三处：

| 阶段 | 位置 |
| --- | --- |
| 选区与批注创建 | reader `src/pdf/selection.js`（PDF 字符模型 ↔ DOM 选区换算）/ `src/dom/common/dom-view.tsx`（DOM 路径） |
| 批注状态管理 | reader `src/common/annotation-manager.js`——所有批注增删改查的**唯一写入口** |
| 位置稳定性 | SDT 位置映射（reader `src/common/sdt/position-mapper.ts` 各格式实现），批注存结构引用而非坐标 |
| 抽取与结构化 | document-worker `src/pdf/structure/`（大纲、引用、参考文献、flow 分类） |
| PDF 字节读写 | document-worker `src/pdf/annotations/{read,write,delete}.js` + `pdfassembler.js` |
| 存储与序列化 | 主仓 `xpcom/annotations.js`（缓存图片读写、JSON 序列化、位置超长时自动拆批注） |

## 5. 同步

见 [07-同步与存储.md](07-同步与存储.md)。入口是 `xpcom/sync/syncRunner.js`，附件走 `xpcom/storage/`，库级设置走 `xpcom/syncedSettings.js`，服务端推送走 `xpcom/streamer.mjs`（WebSocket 订阅同步、样式与翻译器更新主题，驱动自动同步与自动更新）。

## 6. 扩展与第三方接入

见 [09-集成与扩展.md](09-集成与扩展.md)。要点：插件系统 `xpcom/plugins.js` + 三个声明式扩展点 `xpcom/pluginAPI/`；本地 HTTP 服务 `xpcom/server/`；翻译器脚手架 `chrome/content/scaffold/`。

## 7. 导入、导出与报告

| 能力 | 核心模块 |
| --- | --- |
| 导入导出总入口 | `fileInterface.js`（挂载为 `Zotero_File_Interface`），`exportOptions.js` 按所选 translator 动态生成选项界面 |
| Mendeley 迁移 | `import/mendeley/mendeleyImport.mjs`：校验数据库、选择本地或 API 数据源、保存集合与条目、下载附件与批注并汇报进度 |
| 翻译器导入导出 | `xpcom/translate/`（子模块） |
| 报告 | `reportInterface.js` + `xpcom/report.js`：把选中条目及笔记、子条目渲染为内嵌 CSS 的静态 HTML，在内置阅读器中以禁用 JS 打开 |

## 8. 横切基础设施

这些模块不属于任何单一功能域，但每个功能都依赖它们：

| 模块 | 职责 |
| --- | --- |
| `xpcom/db.js` | SQLite 访问：异步查询、事务调度、WAL 降级、完整性校验与损坏恢复 |
| `xpcom/notifier.js` | 全局事件中心，以「事件名 + 类型 + ID 集合」三元组描述事件，支持优先级观察者、事件合并（queue）、事务化批量派发（begin/commit） |
| `xpcom/prefs.js` | 偏好读写、类型转换、旧版分支迁移、观察者、虚拟收藏状态持久化 |
| `xpcom/id.js` | 自增 ID 发号器：内存计数 + 数据库取偏移量 |
| `xpcom/undoHistory.js` | 字段级 undo/redo 栈，与事务生命周期挂钩，按库隔离，支持分批暂存以合并高频编辑 |
| `xpcom/uri.js` | `zotero.org` 标识 URI 的生成与解析（用户、群组、条目、分类、标签、检索），可反向还原对象或转换为 API URL |
| `xpcom/http.js` | HTTP 客户端（重试、代理、Cookie 上下文） |
| `xpcom/file.js` | 文件系统工具库 |
| `xpcom/debug.js`、`debugViewer.js` | 带级别过滤的日志与可视化回放窗口，可把报告提交到 Zotero 服务器换取 Debug ID |
| `xpcom/error.js` | 统一错误码与带用户提示对话框的异常体系 |
| `xpcom/progressWindow.js`、`progressQueue.js`、`progressQueueDialog.jsx` | 浮动进度窗格与后台任务队列的模型和渲染 |
| `xpcom/dataDirectory.js`、`profile.js` | 数据目录选择/校验/迁移、profile 探测与占用检测 |
| `xpcom/session.js` | 窗口与标签状态的持久化，重启后恢复布局 |
| `xpcom/commandLineHandler.js`、`modules/commandLineOptions.mjs` | 命令行参数（`-url` / `-file` / `-Zotero_debugText` 等）与运行期 XPCOM 组件 |
| `runJS.js`、`dictionaryManager.js`、`reportInterface.js` | 开发者窗口（Ace 求值）、词典管理、报告入口 |

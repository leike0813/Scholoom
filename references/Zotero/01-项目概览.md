# 01 项目概览

## 定位

Zotero 是一个**运行在 Firefox/Mozilla 平台上的桌面文献管理软件**，用于收集、整理、引用与共享研究资料。它不是 Electron 应用，也不是 Web 应用，官方对源码的表述是「XUL/XHTML application on a Mozilla platform」（见 `CLAUDE.md`）。

- 官方仓库：`https://github.com/zotero/zotero`
- 官网与帮助：`https://www.zotero.org/`，源码说明在 `/support/dev/source_code`
- 用户论坛：`https://forums.zotero.org/`

## 版本与许可

| 项 | 值 | 说明 |
| --- | --- | --- |
| 版本事实源 | `version` 文件内容 `11.0.SOURCE` | 构建与打包流程读取此文件 |
| `package.json` 版本 | `7.0.0` | 该字段是 `private: true` 的 npm 私有清单，与产品版本不同步，不代表产品版本 |
| 许可 | AGPL-3.0（`COPYING`） | 源码头部逐文件带 AGPL 许可块 |
| 扩展打包 | `update.rdf` 声明扩展 ID 与 `Firefox 45.*` 应用目标，更新地址指向 `download.zotero.org` 上的 `zotero.xpi` | `update.rdf` 属于 Firefox 扩展清单 |

需要注意的版本语义：`package.json` 里的 `7.0.0` 对应的是「Zotero 7 系列」的产品线命名，而 `version` 文件里的 `11.0.SOURCE` 是真实构建版本号。读版本时以 `version` 为准。

## 应用形态

- **主窗口**：`chrome/content/zotero/zoteroPane.xhtml` + `zoteroPane.js`（单文件约 7700 行、186 个方法）。
- **阅读器窗口**：`reader.xhtml` 作为外壳，实际 PDF/EPUB/快照阅读与批注由 `reader/` 子模块承载（`src/common/reader.js` 为架构中心）。
- **笔记窗口**：`note.xhtml`（windowtype `zotero:note`），实际编辑器由 `note-editor/` 子模块承载（`src/core/editor-core.js` 为装配点，ProseMirror schema 版本 10）。
- **大量独立对话框**：导入、导出、参考文献、重复项合并、批注列表、词典管理、验证码、重命名预览等，各自 `.xhtml` + 控制器脚本配对。
- **协议处理器**：`zotero://` 自定义协议，`ZoteroProtocolHandler.mjs` 分派 attachment、data、report、select、debug、pdf.js、open 等子路径。
- **本地 HTTP 服务**：Zotero 在本机监听端口，供浏览器连接器与本地 API 使用（见 [09-集成与扩展.md](09-集成与扩展.md)）。

**主仓与子模块的连接方式是构建期 + 运行期消息传递，不是 import。** 构建期由 `js-build/` 下三个任务脚本把子模块产物复制进 `build/`；运行期 document-worker 走 postMessage RPC，reader 走宿主回调，translate/utilities 靠全局命名空间注入。因此主仓代码里找不到 `import` 指向子模块，这不是遗漏。

## 技术栈快照

| 领域 | 技术 |
| --- | --- |
| 宿主平台 | Firefox / Gecko（XUL、XPCOM、Actors、Web Components） |
| 业务语言 | JavaScript（`.js` / `.jsx` / `.mjs`），Babel 转译，CommonJS + 少量 ESM |
| UI 形态 | XUL/XHTML 文档 + XUL 自定义元素（`XULElementBase`）+ React 18 组件 |
| 样式 | SCSS → Dart Sass 编译 |
| 本地化 | Fluent（`.ftl`），源语言 `chrome/locale/en-US/zotero/` |
| 存储 | SQLite（mozStorage API）+ 文件系统（附件、快照、图片缓存） |
| 依赖管理 | npm，依赖直接嵌入 XUL 环境（部分包经 Browserify 打成 UMD） |
| 测试 | Mocha + Chai（assert 风格）+ Sinon，运行在构建后的 Zotero 实例内 |

**子域各有独立的技术栈与工具链**，与主仓不共享 `node_modules`：

| 子域 | 打包 | 语言 | 测试 | Node |
| --- | --- | --- | --- | --- |
| reader | Webpack（6 份配置） | JS + 部分 TS（strict，仅覆盖 `src`） | `node:test` | 22 |
| document-worker | Webpack（单 UMD worker，`dynamicImportMode: eager`） | JS + TS | 自建分运行时测试链 | 24 |
| note-editor | Webpack（5 份配置）+ Babel/SCSS/SVG/字体 | JS | Mocha | 20（另需 Ruby 3.3 编译 Fluent） |
| utilities | 无构建（直接发布源码） | JS | Mocha + Chai + jsdom | 14 |
| translate | 无构建（顺序 `<script>` 加载） | JS | 自建 `testTranslators/` 夹具 | — |

## 贡献流程

`CONTRIBUTING.md` 明确：**Zotero 不使用 GitHub Issues**。缺陷与功能请求一律发往官方论坛，开发者确认后才会创建 issue。

这条规则对 Scholoom 有直接参考价值——它意味着上游项目的 issue 区不是可靠的需求来源，真正的讨论发生在论坛与 PR 评审中。

# 09 外部集成与扩展体系

Zotero 对外开放能力的方式有三套：本地 HTTP 服务（给浏览器连接器与脚本）、引文文档集成（给 Word/LibreOffice）、插件 API（给第三方插件）。三者互相独立，但都建立在「核心对象 + Notifier」之上。

## 一、本地 HTTP 服务

Zotero 在本机监听一个端口，暴露两组接口。

### 框架层

| 文件 | 符号 | 职责 |
| --- | --- | --- |
| `xpcom/server/server.js` | 9 | 启动 `nsIServerSocket` 监听端口、解析请求、匹配 `Zotero.Server.Endpoints` 中的端点实现，生成响应，处理 CORS、书签脚本等通用能力 |
| `xpcom/router.js` | — | 路由辅助：把 controller 参数映射为对象类型，定义无效路径异常 |
| `xpcom/api.js` | 2 | 请求参数解析层：把 URL query 与路径解析成对象类型、library 前缀和分页信息 |
| `xpcom/server/saveSession.js` | 8 | 「保存会话」管理：创建带 TTL 的临时会话，在多次请求之间暂存待保存的条目、快照与附件 |

### 浏览器连接器

`xpcom/server/server_connector.js`（14 符号）实现浏览器扩展的全部端点：translator 检测、条目/附件/快照保存、样式安装、客户端主机名与代理查询，并处理保存目标与版本兼容性。

配套 `server_connectorIntegration.js`：在编辑器与 Zotero 之间转发命令执行、文档内容回传与窗口置底请求。

**会话模式是这里的关键设计**：一次「保存网页」涉及 translator detect → 翻译 → 保存条目 → 下载多个附件 → 保存快照，是跨多次 HTTP 请求的长流程。`saveSession` 用带 TTL 的临时会话把这几步串起来，避免客户端重复传数据。

### 本地 REST API（Zotero 7 内置）

`xpcom/server/server_localAPI.js`（22 符号）提供面向脚本与第三方工具的 REST 接口：

- 条目 / 分类 / 标签 / 库的 CRUD 端点
- API key 授权与限流
- 批量读写与 **PATCH 合并语义**
- 全文索引上传
- CSL 引文格式化输出

`server_integration.js` 是更早的书签脚本兼容层，为 Word/LibreOffice 书签脚本提供命令执行入口。

### 配套的 URI 层

`xpcom/uri.js`（29 符号）生成与解析 `zotero.org` 标识 URI（用户、群组、条目、分类、标签、检索），可反向从 URI 还原对象、libraryKey 或数据库 ID，并转换为 API URL 与网页 URL。`ZoteroProtocolHandler.mjs` 注册 `zotero://` 协议并把这些子路径分派给各自的处理函数。

## 二、引文文档集成

`xpcom/integration.js` 是这一层的核心，**单文件 3830 行、18 个符号**。图谱标注其中两个最重的类：

| 类 | 行范围 | 职责 |
| --- | --- | --- |
| `Session` | 1027–1783 | 单个文档的引文会话：跟踪 `citationsByIndex`、参考文献域与引文样式缓存，协调 citeproc 引擎刷新、样式切换、RTF/HTML 延迟引文高亮 |
| `Citation` | 3203–3471 | 单条引文的领域模型：持有 `citationItems` 与 `properties`，懒加载条目数据、合并重复引文、处理已删除条目，输出 citeproc 所需的 JSON |

模块整体负责在 Word/LibreOffice/Google Docs 等文档中插入、更新、删除引文域和参考文献，维护引文状态与 citeproc 引擎同步，并提供字段/文档的序列化与反序列化。

配套：

- `integration/` 目录：引用与参考文献对话框（`citationDialog/`）
- `xpcom/modules/rtf.mjs`：RTF 编解码与引文处理，把富文本 RTF 与纯 Unicode 互转，并提供从笔记中解析、匹配、替换引文的完整链路
- `xpcom/httpIntegrationClient.js`：把插入引文、编辑字段、刷新文档等命令以 JSON POST 到外部服务，充当 `Zotero.Integration` 与远程处理器（桌面、移动端或自建服务）之间的传输层
- `xpcom/cite.js` + `xpcom/citeproc.js`：内嵌 citeproc-js 引擎，负责 CSL 样式解析、变量渲染与参考文献格式化
- `xpcom/style.js`：`Zotero.Styles` 管理样式与 locale 列表的加载、安装、校验；`Zotero.Style` 表示单个 CSL 样式并构建、缓存 citeproc 引擎
- `app/modules/zotero-word-for-{mac,windows}-integration`、`zotero-libreoffice-integration`：三个平台的引用插件（Git 子模块），由 `resource/word-processor-plugin-installer.mjs` 统一编排安装

## 三、插件系统

### 加载

`xpcom/plugins.js` 负责加载第三方插件的 XPCOM 作用域，把插件的 `_global` 对象注入 Zotero 命名空间——插件因此可以像内部代码一样调用 Zotero 的 API。同时管理默认偏好项与本地化资源，并在插件安装/更新/卸载时同步 UI。

`xpcom/preferencePanes.js` 是首选项窗格注册表，除 Zotero 内置分区外也允许插件注册自定义窗格，注册时启动偏好观察者以便内容随设置变化刷新。

### 三个声明式扩展点

统一基类 `pluginAPI/pluginAPIBase.mjs` 用声明式选项定义（`optionTypeDefinition`、`mainKeyName`、`notifyType`）统一实现注册、注销、参数校验与变更通知。

| 扩展点 | 文件 | 开放了什么 |
| --- | --- | --- |
| `Zotero.ItemPaneManager` | `itemPaneManager.js` | 允许插件向条目信息面板注册自定义区块（section）与信息行（info row），并提供渲染、切换、条目变更等生命周期回调 |
| `Zotero.ItemTreeManager` | `itemTreeManager.js` | 允许插件注册自定义列并提供数据提供器与单元格渲染器——社区插件最常使用的扩展面 |
| `Zotero.MenuManager` | `menuManager.js` | 向主窗口、阅读器、条目窗格等约 20 种目标菜单注入菜单项、分隔符与分组，支持上下文相关的显示条件与点击钩子 |

`menuManager.js` 内部的 `MenuManagerInternal`（112–814 行）核心是 `updateMenuPopup`：把注册数据投影到真实 XUL 弹层元素上，处理分组、可见性、图标、事件与可用数量计算。**这是「声明式注册」到「命令式 DOM」的转换点**，写扩展时若菜单不显示，先查这里的投影逻辑。

读这三个文件能清楚看出 Zotero 打算把哪些界面能力开放出去。

## 四、翻译器生态

- 翻译器定义在独立仓库 `zotero/translators`（主仓库内为 `xpcom/translate/` 子模块），749 个 `.js` 文件。
- 框架代码在主仓库：`xpcom/translation/`（3 文件）、`actors/TranslationParent.mjs` / `TranslationChild.mjs`、`RemoteTranslate.mjs`（主进程句柄，把 detect/translate/runTest 转发到内容进程并管理完成回调）、`actors/translation/{http.js,translate_item.js}`（内容进程侧执行沙箱）。
- 开发者工具是 `chrome/content/scaffold/`。
- **硬约束**：绝不手写生成 translator，绝不生成 UUID，绝不手写测试用例——都通过 Scaffold。

## 五、CSL 样式生态

- 样式定义在 `zotero/bundled-styles`（主仓库内 `styles/`），locale 在 `citation-style-language/locales`（主仓库内 `chrome/content/zotero/locale/csl/`）。
- `updateCSL.xsl` 用 XSLT 1.0 把旧版 CSL 0.8 就地升级到 CSL 1.0：处理 `cs:link` 的 `rel` 取值重命名、`cs:category` 的 `term` 到 `citation-format`/`field` 转换、`cs:option` 上移为 `cs:citation`/`cs:bibliography` 属性，以及条目类型原型（article/book/chapter）回退语义的展开。
- `resource/schema/renamed-styles.json` 记录样式改名。

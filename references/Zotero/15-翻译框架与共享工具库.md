# 15 翻译框架与共享工具库（translate / utilities）

`chrome/content/zotero/xpcom/translate/` 与 `chrome/content/zotero/xpcom/utilities/` 既是 Git 子模块（`zotero/translate`、`zotero/utilities`），又是两个独立分发的 npm 包。本文把两者放在一起，因为它们是**同一族「无自举入口、由宿主装配」的库**——理解了这个模式，两者的设计就都通了。

调研时的子模块 commit：`translate` 为 `dd524aea`，`utilities` 为 `4051881d`。图谱口径：translate 20 个文件节点 / 74 节点 / 157 边 / 5 层；utilities 9 个文件节点 / 74 节点 / 96 边 / 4 层。

**旧版调研中这两处是空目录**，此前关于它们的描述全部来自主仓调用侧（如 `browserWindowShim.js` 让 translators 子模块在现代 Gecko 上继续工作）。现在可以给出内部实现。

## 一、核心模式：框架不自带能力

translate 明确划定了边界：宿主必须自行实现

- `Zotero.Translators` — translator 元数据与源码的获取
- `Zotero.HTTP` — translator 沙箱里的网络请求
- `Zotero.Translate.ItemSaver` — 抓取结果落库

并在启动时调用 `Zotero.Schema.init`、`Zotero.Date.init` 与 `cachedTypes.setTypeSchema` 灌入 schema 与日期格式数据。`Zotero.Debug` 属于可替换的扩展点。

`src/http.js` 是这套设计的样板：**它是契约层而非实现层**——只声明 `Zotero.HTTP` 单例、`StatusError` / `TimeoutError` 异常类型，并给出 translator 沙箱中 `request` 与 `processDocuments` 的默认骨架，真正的网络栈由宿主注入。

`utilities` 走的是同一模式，只是没有 `package.json` 之外的装配负担：它是一组挂载到 Zotero 全局命名空间的工具模块，调用方必须自己完成前置条件——`Zotero.Schema.init(schema.json)`、`Zotero.Date.init(resource/dateFormats.json)`、先加载 `resource/zoteroTypeSchemaData.js` 再加载 `cachedTypes.js`，并自行实现 `Zotero.localeCompare()`（通常用 `Intl.Collator`）。

**读这两个库之前先读 README 与 package.json 的入口声明**，否则会误以为存在自举式的初始化流程。

## 二、example 目录即装配清单

`translate/example/` 是对上述契约的最小可运行实现，也是本框架的**权威加载顺序参考**。`index.html` 用一串顺序敏感的 `<script>` 标签依次载入 `src/` 下的运行时与 `src/rdf/`，最后再挂上 `example/` 下的覆盖层——**顺序错了命名空间就会缺失**。

五个文件连起来读一遍，宿主契约就落地了：

| 文件 | 示范的宿主责任 |
| --- | --- |
| `index.html` | 加载顺序 |
| `index.js` | 主流程：构造 `Zotero.Translate.Web` 实例、注册 select 与 error 处理器、调用 `getTranslators` 与 `translate` |
| `translators.js` | 用 `Object.assign` 扩展框架单例，把 translator 元数据与源码**预置进内存缓存**，替代真实仓库的下载 |
| `http.js` | 以 `XMLHttpRequest` 覆写 HTTP 单例 |
| `translate_item.js` | ItemSaver 的最简实现，把条目以 JSON 回传而不写入真实数据库 |

## 三、RDF 子系统

`src/rdf/` 是内嵌的 RDF 栈（来自 rdflib），**24 条内部依赖边集中在这一层**，对外只被 example 引用，属于自包含的底层设施。

`init.js` 是它唯一的装配入口：创建全局 `$rdf` 命名空间，挂载 `Util` 与 `log`，在 CommonJS 环境下依次 require 其余六个模块，浏览器环境则挂到 `Zotero.RDF.AJAW`。图中七个 rdf 文件与 `init.js` 之间**都存在双向边**——其余模块既被 init.js 装载，又回头引用它导出的命名空间。单独读 `term.js` 或 `n3parser.js` 会因为拿不到 `$rdf` 上下文而卡住，理解这条「环」是读懂整个子系统的前提。

| 文件 | 职责 |
| --- | --- |
| `term.js`（扇出 18） | 术语类型系统：Symbol、BlankNode、Literal、Collection、Formula、Statement、Variable、Namespace，是整个 RDF 栈的类型词汇表 |
| `uri.js` | RFC 3986 风格的 URI 工具集：`join` 拼接、`refTo` 相对化，以及 hostpart / docpart / document / protocol 等分解函数 |
| `identity.js` | 索引化三元组存储 `IndexedFormula`，维护 subject / predicate / object 三级哈希索引，支持 OWL `sameAs` 等价合并 |
| `n3parser.js` | N3/Turtle 流式解析器 `__SinkParser`：手写词法分析与递归下降语法分析 |
| `rdfparser.js` | RDF/XML 解析，遍历 DOM 逐元素构造三元组 |
| `serialize.js` | 反向输出 N-Triples、N3 或 RDF/XML |

`uri.js` 存在的理由值得记一笔：RDF 里同一个资源常有多种写法（末尾斜杠、片段标识符、base 相对形式），**地址归一化不掉就无法判断两条三元组说的是不是同一件事**。

解析与序列化构成闭环——translator 既能读取网页里的内嵌 RDF，也能把自己的输出序列化成标准格式交还宿主。

## 四、Translator 测试夹具

`testTranslators/` 是发布包自带的测试夹具，图中是独立于 example 的另一棵依赖树，只借用 `src/` 层的 `http.js` 与 `promise.js` 驱动执行。

- `translatorTester.mjs`（扇出 15，**全仓库唯一零入度节点**）解析 translator 代码中内嵌的 `TEST CASES`，驱动 web / import / search 三类翻译；把环境抽象成 web 与 non-web 两套，使同一份用例既能在 Node 下跑静态快照、也能在浏览器里打真实网页。
- `test.mjs` 定义 Test 用例数据模型，提供条目清洗与深比较逻辑。
- `diff.mjs` 是配套的纯文本 diff 生成器，递归比较两个 JSON 结构并用空格标记差异，用于定位测试数据不匹配的具体位置。

这套夹具随包发布，意味着 translator 作者拿到 npm 包就能自测，不需要拉主仓库。

## 五、utilities：类型缓存与 schema 映射

整套库的数据底座由两个静态资源加一个轻量查询层组成：

- `resource/zoteroTypeSchemaData.js` 是 Zotero 客户端 `build_typeSchemaData.html` 生成的扁平数组表（itemTypes / creatorTypes / fields），`resource/README.md` 记录了来路。
- `cachedTypes.js` 只模拟 connector 需要的**极小部分 API**，把它展开成以 ID 和名称双向可查的结构并挂到 `Zotero.ItemTypes` / `CreatorTypes` / `ItemFields`。
- `schema.js` 是另一条线：从 zotero-schema 仓库的 `schema.json` 构建 **CSL 类型与字段的正反向映射表**并挂载为 `Zotero.Schema`，供条目转换 O(1) 查表。

两份数据都由 `.gitmodules` 指向的子模块提供，README 明确要求**随仓库打包而不要远程加载**。这与主仓的 `resource/` 第三方资源策略一致：XUL 环境下远程加载不可靠，能内嵌就内嵌。

## 六、utilities：日期中枢

`date.js`（扇出 13）是全库最复杂的单个模块，也是条目转换与翻译框架的日期基础设施。它在 **SQL / ISO / HTTP / EDTF / multipart 五套表示**之间互转。

核心是 `strToDate` 这个启发式解析入口：先用斜杠正则判断年月日端序（大端、小端、端序混排），再回退到月份名、序数与纯数字规则。EDTF 解析由 `parseEDTF` 处理并产出 begin / end / uncertain 限定信息；`strToMultipart` 给出 Zotero 内部的区间表示。

`init()` 需要预生成多语言月份匹配表，这张表来自 `resource/dateFormats.json`——按语言与区域组织的静态数据，是全库最大的资源文件之一，也是 `strToDate` 能识别非英文日期的前提。

## 七、utilities：条目转换与 OpenURL

`utilities_item.js`（`Zotero.Utilities.Item`，扇出 13）是数据模型层，负责 Zotero 条目与 **CSL JSON / API JSON / 旧版导出格式**之间的双向转换，外加 Extra 字段解析、姓名粒子（particles）与后缀拆分、笔记标题生成、call number 比较。

它**自身不含 import**，重度依赖 `Zotero.Schema` 映射表与 `Zotero.ItemTypes` / `ItemFields`，也调用 `date.js` 的 `parseEDTF` 处理日期字段——所以它只能在 `schema.js`、`cachedTypes.js`、`date.js` 全部装配完成后工作。这个严格的初始化顺序是设计选择，不是偶然。

`openurl.js`（`Zotero.OpenURL`）实现 OpenURL ContextObject 的双向转换：生成方向调用 `Date.strToISO` 归一化日期；解析方向用 `Utilities.cleanAuthor` 清洗作者，并在 Firefox 环境下用 `cloneInto` 处理跨 compartment 安全问题。

`utilities.js`（扇出 23，全库最高）是 npm 侧的主入口，承载字符串清洗、DOI / ISBN / ISSN 抽取与校验、HTML 转义与自动链接、XPath 查询、编辑距离、变音符号还原以及调试输出。文件末尾用 `movedToUtilitiesInternal()` 为一批已迁移到 `Utilities.Item` 的函数批量生成带 deprecation 警告的转发桩——**读到警告不要以为是 bug**。字符串密集的匹配依赖随库内置的 `xregexp-all.js` 与 Zotero 专用的 `xregexp-unicode-zotero.js`，这样在 CommonJS 环境下也能拿到浏览器里才有的 XRegExp 能力。

## 八、utilities 的 CI 印证了什么

`.github/workflows/ci.yml` 在 push 与 pull_request 时于 ubuntu-latest 上**递归检出子模块**、安装 Node 14，以 `package-lock.json` 的哈希为 key 缓存 node_modules，命中缓存就跳过 `npm install`，最后执行 `npm test`。

这条流水线顺带印证了前面提到的子模块依赖——**不递归检出，schema 与类型数据就是缺失的**。图谱把这条流水线拆成了 5 个 step 节点（checkout / install-node / cache-node-modules / install-node-modules / run-tests），是全仓库唯二有 step 拆解的 pipeline。

## 九、给 Scholoom 的启示

1. **「契约层 vs 实现层」是框架库的通用手法**。`translate/src/http.js` 只声明单例、异常类型与方法骨架，宿主注入真实实现。框架因此不绑定任何网络栈，测试夹具与 example 也都能替换它。
2. **装配顺序即文档**。`translate/example/index.html` 的顺序敏感 script 序列是理解整个框架最快的方式。这类「加载顺序敏感」的架构，一份可运行的 example 胜过十页说明。
3. **双向依赖的装配点是必要的恶**。RDF 子系统的七个文件与 `init.js` 互相引用，读单个文件会卡住。这是全局命名空间模式的必然代价——用单一收敛点换取模块独立性。
4. **静态数据随包分发，不远程加载**。`zoteroTypeSchemaData.js` 与 `dateFormats.json` 都是生成产物随仓库走。多语言日期解析依赖这张表，远程加载会让离线场景直接失效。
5. **严格初始化顺序要写进 README**。`utilities` 的「必须先 init schema 与 date」写在 README 而非代码里。这类前置条件用文档传递比用运行期断言更轻。

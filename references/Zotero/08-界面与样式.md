# 08 界面、组件、样式与本地化

## 一、主窗口

| 文件 | 规模 | 职责 |
| --- | --- | --- |
| `zoteroPane.xhtml` | — | 声明菜单栏、工具栏、标签选择器容器、分类树与条目树等界面骨架，引用 `zoteroPane.js` 与平台样式表 |
| `zoteroPane.js` | 约 7700 行 / 186 方法 | 控制器：初始化条目树与分类树、标签选择器、检索与分类选择状态、菜单构建、拖放导入、条目增删改等全部主界面交互 |

配套的顶层文件：

- `tabs.js`：`Zotero_Tabs` 单例，管理资料库、阅读器、笔记三类标签的生命周期、钩子（`tabHooks`）、焦点切换、侧栏状态与内存回收，**按物理内存决定同时保留的标签上限**。
- `contextPane.js` / `elements/contextPane.js`：右侧上下文面板的全局控制器与元素实现。
- `customElements.js`：自定义元素注册中心（见下）。
- `include.js`：各类独立对话框窗口的通用引导脚本。
- `commonDialog.js`：为所有对话框提供统一 ESC 关闭行为。
- `platformKeys.js`、`titlebar.js`：平台相关的快捷键与自定义标题栏行为。
- `editMenuOverlay.js`：编辑菜单（复制/剪切/粘贴/撤销）的全局 overlay 控制器。

## 二、XUL 自定义元素

`elements/` 目录 54 个文件、210 个符号。全部继承 `elements/base.js` 中的 `XULElementBase`（通过 `XULElementMixin` 混入到继承 `XULElement` 的类上）：

- 提供 `init()` / `destroy()` 生命周期钩子
- `content` getter 指向内部 `<template>`，`connectedCallback` 时 `document.importNode` 后挂载，让渲染逻辑能用原生模板语法而不必手写 DOM
- 自动 `MozXULElement.insertFTLIfNeeded("branding/brand.ftl")` 与 `zotero.ftl`，并对 shadow root 连接 `document.l10n`

`XULElementMixin` 注释里直接引用了 Mozilla 的 `XULElement`，说明这条路径是继承 XUL 元素基类以支持 `customElements.define`，与浏览器里继承 `HTMLElement` 的标准路径不同。`attributeChangedCallback` 的属性反射与节点生命周期由基类串起来。

条目信息面板是最好的学习样本，自外向内四层：

| 元素 | 职责 |
| --- | --- |
| `itemPane.js`（注册名 `<item-pane>`） | 面板主容器，用一个 `deck` 在条目详情、笔记编辑器、重复项合并、批注列表、批量编辑提示之间切换，按选中项状态更新顶部操作按钮 |
| `itemDetails.js` | 整体容器，串联 info / abstract / attachments / notes / tags / related 等区块，按可见性与滚动做同步和异步分级渲染，提供区块固定、拖拽排序、插件自定义区块与侧边栏联动 |
| `itemBox.js`（注册名 `<info-box>`） | 核心实现，3000 余行：按条目类型渲染全部元数据行，支持行内编辑、字段增删与排序、作者行的单/双栏与拖拽排序、跨条目批量编辑、类型切换、撤稿横幅、插件注入的自定义行 |
| `collapsibleSection.js` | 所有分区共用的折叠容器 |

其他常用元素：`editableText.js`（行内可编辑文本，按属性选 input/textarea，支持 Esc 回滚、Enter 提交）、`tagsBox.js`（多行标签编辑）、`notesBox.js` / `noteBox.js` / `contextNotesList.js`（笔记相关）、`attachmentBox.js`、`relatedBox.js`、`librariesCollectionsBox.js`、`colorPicker.js`、`advancedSearchPane.js`、`annotationItemsPane.js` / `annotationRow.js`（批注列表）、`duplicatesMergePane.js` / `mergeGroup.js`（重复项合并）、`itemPaneSidenav.js`（分区侧边导航，支持固定与拖拽排序并持久化顺序）、`itemPaneCustomSection.js`（插件分区）、`styleConfigurator.js`（引文样式配置）、`searchTextbox.js` / `queryTextbox.js` / `quickSearchTextbox.js`（搜索输入框系列）、`splitMenuButton.js`、`tabsMenuPanel.js`、`guidancePanel.js`（首次运行引导气泡，全局互斥）。

## 三、React 组件与虚拟化

数据量最大的两个视图用 React 实现，且**没有直接依赖 react-window，而是自研虚拟化**。

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 树模型（XUL 侧） | `libraryTree.js` | 条目树与资料库树共用的基类，负责层级行的访问、展开折叠模型、排序与选择模型 |
| 行数据 | `itemTreeRow.js` | 按行类型（普通条目、附件、批注、分类、检索）提供字段取值 |
| 列定义 | `itemTreeColumns.jsx` | 全部可用列的唯一事实源 |
| 条目树 | `itemTree.jsx`、`collectionViewItemTree.jsx` | 分别实现不同数据源；`collectionViewItemTree.jsx` 是体量最大的 React 组件，同时含行数据提供器与树本身 |
| 分类树 | `collectionTree.jsx` | 继承 `libraryTree.js` 的 `LibraryTree`，实现分类、行、RSS 源、检索式的层级渲染、过滤、展开折叠、拖放移动/复制、重命名与删除 |
| 虚拟渲染 | `components/virtualized-table.jsx`、`components/windowed-list.js` | 只挂载可见行，随滚动卸载并缓存行高 |
| 标签选择器 | `components/tagSelector.jsx`、`tagSelectorList.jsx` | 另一套虚拟化实现，手工计算气泡位置；`tagSelectorList.jsx` 在 `componentDidUpdate` 中重算单元格尺寸与位置、按需回滚滚动 |
| 表单 | `components/form/*`、`components/input.jsx` | 文本输入等 class 组件，`Input` 串起 cancel/commit/focus 三个公开命令与 change、blur、focus、keyDown、paste 事件，按 `autoComplete` 决定渲染 Autosuggest 还是裸 input |
| 其他 | `tabBar.jsx`、`tooltip.js`、`draggable.jsx`、`annotation.jsx`、`button.jsx`、`icons.jsx`、`search.jsx`、`progressQueueTable.jsx`、`editable*` | 标签栏、提示、拖拽源、批注渲染等 |

**职责边界很清楚**：展开状态、排序、选择模型全留在 XUL 侧的 `libraryTree.js`，React 只负责渲染。`progressQueueDialog.jsx` 是「XUL 窗口 + React 挂载点」的范式：`.xhtml` 提供 `#progress-container`，`.jsx` 把数据交给 `VirtualizedTable`。

## 四、样式体系

SCSS 侧把 `@use` / `@forward` 当作模块系统：partial 文件以下划线开头且不直接产出 CSS，由入口文件统一引入。

```
scss/
├── abstracts/     变量与 mixin（_variables.scss、_mixins.scss 等，8 文件）
├── themes/        明暗调色板（_light.scss 等）
├── base/          全局基础样式
├── components/    53 个组件样式
├── elements/      38 个自定义元素样式
├── xulElementPatches/ 8 个原生 XUL 控件补丁
├── mac/ win/ linux/    平台覆盖
└── _zotero.scss   主入口清单
```

`scss/_zotero.scss` 本身**不产生任何 CSS 规则**，只按 abstracts → themes → base → components → elements 的顺序聚合全部 partial。平台差异由三个平级入口叠加：

| 入口 | 引入 |
| --- | --- |
| `zotero-mac.scss` | `_zotero.scss` + `mac/` 下的 createParent、editable、menuBar、tabBar、titleBar、输入控件、引文浏览器 |
| `zotero-win.scss` | `_zotero.scss` + `win/` 平台 mixin，覆盖 createParent、tabBar、titleBar、citationExplorer、infoBox 及各类控件 |
| `zotero-unix.scss` | `_zotero.scss` + `linux/` 下的 createParent、editable、feedSettings、menu、menupopup、tabBar、titleBar、infoBox |

设置窗口另有一套入口：`preferences.scss`（含左侧导航、搜索框、提示气泡、隐藏结果布局）+ `preferences-mac.scss` / `preferences-win.scss`。其他独立入口：`about.scss`、`bibliography.scss`、`errorReport.scss`、`feedAbstract.scss`、`merge.scss`、`progressQueueDialog.scss`、`progressWindow.scss`、`scaffold.scss`。

平台目录映射由 `chrome.manifest` 的 `os=` 分支完成，**换平台外观只需看这三个入口文件**。

另有 `chrome/content/zotero-platform/{mac,win,unix,default-version}/` 下的纯 CSS 覆盖（`integration.css`、`overlay.css`、`tab.css`、`tagselector.css`、`preferences.css`、`itemPane.css`、`publicationsDialog.css`、`style.css`）与 `chrome/skin/default/zotero/` 下的皮肤 XHTML。

`chrome/content/zotero/xpcom/uiProperties.js` 负责把用户偏好的字号与界面密度应用到已注册的 UI root，处理最小值边界与 RTL 语言下的镜像取值。

## 五、本地化

- 源语言：`chrome/locale/en-US/zotero/`（另有 `en-US/scaffold/`）
- 格式：Fluent（`.ftl`），在 XUL 文档中通过 `<link rel="localization">` 引入，或元素上用 `data-l10n-id`
- 访问方式：XUL 侧 `Zotero.getString()`（旧 `.properties` 遗留），代码侧 `Zotero.Intl`（按名取串、按前缀批量取串、以 locale 为键的排序比较）
- 语言数量：`chrome.manifest` 声明数十种（af-ZA 到 zh-TW，含 ar、fa、he-IL 注释掉的等），实际目录数与之对应
- `js-build/config.js` 的 `ftlFileBaseNames` 列出源文件：`zotero`、`preferences`、`scaffold`、`reader`、`integration`、`note-editor`、`schema`、`fileRenaming`
- `xpcom/locale.js` 导出支持的 locale 列表与书写方向判断

**硬约束**（`CLAUDE.md`）：所有新字符串必须加到 `.ftl`，**不得**再往 `.properties` 或 `.dtd` 添加新字符串。

## 七、给 Scholoom 的启示

1. **大数据量列表自研虚拟化**是有代价的选择：Zotero 明确写明没依赖 react-window，改用 `windowed-list.js` + `virtualized-table.jsx`。若 Scholoom 也要处理万级行，需要提前决定虚拟化归属（框架库 vs 自研），并把行高缓存、滚动锚点、卸载时机作为一等设计项。
2. **条目面板的分级渲染**值得抄：`itemDetails.js` 的 `render` 会刷新自定义区块与固定区块，向所有区块下发 `item`/`editable`/`tabID` 属性，对隐藏区块调用 `discard`，然后按滚动锚点依次执行 `asyncRender` 并逐帧让出主线程——目的是让 `isPaneVisible` 判断准确。**高频更新的 DOM 必须专门处理可见性，否则会做大量无用渲染。**
3. **平台差异集中到入口文件**。Zotero 让三个入口文件承担全部平台差异，组件样式保持平台无关。这让「加一个平台」的代价可控。

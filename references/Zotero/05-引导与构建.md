# 05 应用引导、构建系统与测试

## 一、应用引导：zotero.mjs

Zotero 不是打包式 Web 应用，没有模块 bundler，文件之间也不通过 ES import 互相引用。全部真相在 `chrome/content/zotero/zotero.mjs`：

- `makeZoteroContext()`（约 221–339 行，标记为复杂）创建或重建 Zotero sandbox 上下文，注入全局属性与 `Date` 本地化覆写，然后把各 xpcom 脚本**按固定顺序逐个载入该沙箱**。
- 载入 `resource://zotero/require.js`，注册 `zotero:` 自定义协议处理器。
- 把 `dateOverrides.js` 注入每个新建窗口（它打补丁覆盖 `Date.prototype.toLocaleString` / `toLocaleDateString`，在调用方未传 locale 时回退到 `Services.locale.requestedLocales`）。
- 导出 `ZoteroContext`，供 reinit 时重建整套上下文；同时提供平台判断与初始化回调注册。

**载入顺序即依赖顺序**。想加一个新的核心模块，要先决定它在 `zotero.mjs` 的哪一行被载入，而不是 import 进来。`CLAUDE.md` 描述的对偶事实：模块靠共享同一全局对象协作，`loadSubScript(url, scope)` 是 XUL 时代的经典做法。

## 二、构建系统 js-build/

自研 Node.js 构建系统，**不走 Webpack**。`js-build/config.js` 是唯一事实源，以数组形式声明构建目标。

### npm 脚本

| 脚本 | 实际执行 |
| --- | --- |
| `npm run build` | `node js-build/build.js` |
| `npm start` | `build.js` + `watch.js` |
| `npm run clean-build` | `clean.js` + `build.js` |
| `npm run sass` / `npm run js` / `npm run clean` | 单独触发 SCSS 编译 / JS 转译 / 清理 |
| `npm run ftl-to-json` | Fluent → JSON，供 Transifex 上传 |
| `npm run localize-ftl` | 扫描 `chrome/locale` 全部语言目录，与 Transifex 下载的 `zotero.json` 双向转换，CJK 语言补写标注 |

### config.js 声明了什么

| 数组 | 内容 |
| --- | --- |
| `dirs` | 需要编译 JS 且符号链接非 JS 资源的目录：`chrome`、`components`、`defaults`、`test`、`test/resource/chai`、`test/resource/mocha` |
| `symlinkDirs` | 直接符号链接的目录：`xpcom/rdf`、`xpcom/translate/src`、`styles`、`translators` |
| `copyDirs` | 需要真实复制的目录：`test/tests/data`（注释说明原因：浏览器加载测试数据时会跟随符号链接，导致 URI 不匹配引发假失败） |
| `symlinkFiles` | 根目录逐文件的链接规则，含大量 `!` 排除：`resource/**/*` 但排除 `react-virtualized.js`、`SingleFile/**/*`（只留 `lib/**/*`）、`ace/**/*`（只留少量需要的文件）、`monacopilot.mjs`、`vs/language/typescript/tsWorker.js`、以及 `chrome/skin/**/*.scss`；`SingleFile`、`react-virtualized`、Monaco TypeScript worker 这些文件被排除是因为要由 `babel-worker.js` 补丁后再用 |
| `browserifyConfigs` | 打成 UMD 的 npm 包：`react-select` → `resource/react-select.js`、`url` → `resource/url.js`、`sinon` → `test/resource/sinon.js` |
| `jsFiles` | JS/JSX glob 掩码 + 上述需特殊处理的单文件 |
| `scssFiles` | `scss/**/*.scss` 与 `chrome/skin/default/zotero/**/*.scss` |
| `ignoreMask` | 所有任务共享的排除掩码（`#*` 备份、schema 仓库的 README/压缩包/脚本、translate 示例与 README、utilities 的 node_modules 与 test） |
| `ftlFileBaseNames` | `zotero`、`preferences`、`scaffold`、`reader`、`integration`、`note-editor`、`schema`、`fileRenaming` |

### 各构建任务

| 脚本 | 职责 |
| --- | --- |
| `build.js` | 一次性完整构建入口：加载签名、清理失效产物，并行触发 browserify / copy / js / sass / symlinks 以及 reader、document-worker、note-editor 三个子模块构建，最后写回签名并打印总耗时 |
| `js.js` | 按 glob 找出待编译文件，用文件签名跳过未变更者，用 Node `cluster` 按 CPU 数量 fork worker 并行转译，通过 IPC 汇总 |
| `babel-worker.js` | worker 进程：对源文件做**文本级改写**——修正 XUL/XHTML 中的 `createElement`、剥离 `globalThis`、屏蔽 `Set` 等——再调 `babel.transformAsync` 输出到 `build/`，并回传耗时与错误 |
| `sass.js` | Dart Sass 编译 `scss/` 与 `chrome/skin/`，按平台（win/mac/unix）拆分 partial 文件，按 mtime 签名增量跳过 |
| `symlinks.js` | 把源码、子模块（reader、note-editor、translators、styles、utilities 等）与 node_modules 产物链接进 `build/`，支持 copy 模式处理必须真实拷贝的文件 |
| `copy.js` | 按 glob 复制需原样复制的资源，基于文件签名增量判断 |
| `browserify.js` | 执行 `browserifyConfigs` |
| `utils.js` | 构建系统公共库（14 个符号）：文件签名读写与比较、失效产物清理、彩色日志、glob 掩码格式化、路径比较、debounce |
| `watch.js` | chokidar 监视 chrome、components、scss、test、styles、translators，变更按类型分派到 js/sass/copy/symlinks，配互斥锁与防抖做批量构建，可自动执行 omni 脚本更新 |
| `clean.js` | 删除构建产物目录 |
| `reader.js` / `note-editor.js` / `document-worker.js` | 子模块构建：子进程执行其自身构建脚本拿产物列表，重建 `build/` 目标目录并复制；`reader.js` 对 git-lfs 未拉取等特定错误做降级处理 |
| `ftl-to-json.mjs` / `localize-ftl.mjs` | Fluent 本地化维护 |

### 转译配置

仓库根 `.babelrc` 启用 React JSX preset 与 `babel-plugin-transform-es2015-modules-commonjs`，并显式排除 `citeproc.js`、ace、scaffold 模板等无需转译的文件。

**应用实际读取的是 `build/` 下的产物，不是源码**。改完源码看不到效果，先确认构建是否跑过。

### 值得借鉴的两个技巧

1. **文件签名做增量构建**。`utils.js` 给每个产物算签名，签名未变就跳过编译。这比时间戳比较更可靠——内容一致就不重编。
2. **针对 XUL 环境做源码改写**。`babel-worker.js` 在转译前对文本动手，修正 XUL/XHTML 里的 `createElement`、剥离 `globalThis`、屏蔽 `Set`。这类补丁是普通 Babel 流程里见不到的，但它说明「宿主环境不是标准浏览器」这件事会一路渗到构建层。

## 三、翻译器脚手架 Scaffold

`chrome/content/scaffold/` 是开发翻译器的图形工具，主窗口 `scaffold.xhtml` 由工具条、元数据表单、内嵌浏览器、三个 Monaco iframe 容器与底部输出/测试面板组成；`templates/` 下是 `newWeb.js`、`scrapeBibTeX.js`、`scrapeEM.js`、`scrapeMARC.js`、`scrapeRIS.js` 五个脚手架模板。

`CLAUDE.md` 里有硬约束：**绝不手写生成 translator，绝不生成 UUID，绝不手写测试用例**——三者都必须通过 Scaffold 完成。

## 四、测试

测试跑在**构建后的 Zotero 应用实例内**。

```bash
test/runtests.sh                     # 全部
test/runtests.sh item                # 单个文件（省略 Test 后缀与 .js）
test/runtests.sh item collections    # 多个文件
test/runtests.sh -g "pattern"        # 按 grep 模式过滤
test/runtests.sh -f                  # 首次失败即停
test/runtests.sh -s item -e item     # 指定起止文件
test/runtests.sh -c                  # 完成后打开 JS 控制台
test/runtests.sh -b                  # 跳过内置 translator/style 安装，加快启动
test/runtests.sh -d 5                # 调试日志级别 1–5（默认 3）
```

- 技术栈：Mocha + Chai（assert 风格）+ Sinon。
- 测试文件在 `test/tests/`，命名 `<module>Test.js`；辅助代码在 `test/content/support.js`。
- `test/runtests.sh` 会在 watch 进程未运行时自动触发 `npm run build`，不需要手动先构建。
- 实用提示：flag 要写在测试名之前；几乎总该用 `-f`，因为一次失败会引发后续一堆假失败；多测试联跑时想看某一项的调试输出，在测试开头加 `Zotero.Debug.init(1)` 再配 `-d 5`。

## 五、Lint 与 CI

- `npx eslint <file>`；配置在 `eslint.config.mjs`，ESLint v9 flat config，继承 `@zotero/eslint-config`，用 Babel parser，声明浏览器与 Mozilla XPCOM 全局变量，启用 React 插件。
- `CLAUDE.md` 明确：**代码库并未完全被 lint 覆盖**，只需关注新增或改动行。
- CI 由 `.github/workflows/ci.yml` 驱动构建与测试，并在发布分支上打包上传；`config.js` 里的 `buildsURL` 指向 `https://zotero-download.s3.amazonaws.com/ci/`。

## Question

首批设计的共同输入见[首条文献综合路径与最小跨域契约](01-literature-synthesis-path.md#answer)。

科研业务与工作流域怎样用 LangGraph Graph 承接首条文献综合路径，复用现有材料读取、能力调用与交付检查，并保持与通用执行及领域权威的分工？

- 以一项实际综合工作划定业务 Graph、能力入口与交付要求；明确 Graph 的流程控制、节点内 Agent 指令与配套资源，以及通用 harness 的职责。
- Graph 组织科研步骤和检查，文献及项目模块负责所属成果和事实：确定材料读取、交付、成果引用与部分失败的交接职责。
- 旧项目 Skill／capability 包拆为 Graph 流程、节点指导、模板、程序和校验素材；确定内建注册、发现与版本边界，用户／项目自定义 Graph 功能后置，不继承旧包的管理流程。
- 明确首批是否依赖尚未具备的检索、多 Agent、程序执行或交互报告；区分必需前置与后续增强，列出可独立测试及检查实际成果的入口。

本票确定科研业务 Graph 的设计包与依赖，不编写全部科研内容或把工作流步骤转换为新的业务任务体系。

## Graph 承载科研业务流程

本节记录用户本轮明确修正的架构方向，是相关旧决议中流程承载约定的当前依据。

- **业务流程由 LangGraph Graph／子图表达。** 需要保证的科研步骤、依赖、条件分支、循环、并行汇合、交付检查与人工等待进入 Graph 定义及执行；流程推进不能继续仅由 Skill 正文指示 Agent 自行完成。
- **节点完成具体工作。** 节点可调用 Agent、领域工具、程序或其他子图。Agent 节点的提示词、操作指导、参考资料、模板和校验素材服务该节点；旧 Skill 的适用内容可拆解复用，但 Skill 包不再作为科研业务流程的权威载体。不要求另设独立 Method 对象或先建立一套方法包生命周期。
- **通用 harness 与业务 Graph 分工。** harness 提供模型调用、受管执行、工具访问、取消、等待及恢复等共同基础；科研模块提供业务 Graph、节点实现和科研交付要求。只有通用 Agent 循环、再以 Skill 指挥完整业务步骤的接线，仍需迁移到实际业务 Graph。
- **能力保留调用契约。** 科研能力继续表达可发现、可调用工作的输入、交付与检查约定；其业务流程绑定相应 Graph。能力入口与业务 Graph 各有职责，既有能力声明只提供元信息及 Graph 引用，不把 capability 包或 YAML 描述重新变成第二套流程定义。具体注册和字段由实施规格核对。
- **Graph 执行状态与领域事实分开。** Graph 记录流程执行位置、必要控制状态和所属成果引用；文献／主题知识仍归库，研究任务、分析理由与产物仍沿项目文件规则保存。checkpoint 不替代研究事实，不复制库知识为项目依据；材料异常继续沿共同矩阵处理。
- **保留自主研究与通用会话。** Graph 可包含自主 Agent 节点和按研究结果调整的循环；不要求把每次思考、工具调用或普通问答另建业务图、任务或调用。会话不绑定研究任务，节点数也不决定任务或子调用数量。
- **旧内容按职责迁入。** 从旧 Skill／capability 包中提取实际流程、节点指令、模板、纯规则、程序及校验素材，按本项目 Graph、领域接口及授权重新接线。六组科研业务、综合内容、分批交付和独立复核要求保留；旧包的目录、宿主及流程推进方式不作为兼容要求。

原 Q5／Q6 以“用户／项目方法包”为主要管理对象，已撤下，未形成决定。首批定义与配置采用下文 Q8：Graph 由 Scholoom 源码维护并注册，用户／项目自定义 Graph 功能后置，首批不提供。节点指导资源的具体格式仍可在实施中核对，不引入旧方法包生命周期。

当前正式规格和代码反映既有材料分析交付；本节修正后续设计方向。具体业务 Graph 接线及迁移需后续 OpenSpec 和真实运行验收，本轮不据此宣称已实现。

## 全局会话与工作域

用户已明确以下归属方向，作为科研业务调用语境与后续 harness 设计的输入。

- 系统提供一个内建、固定的全局会话分类，可理解为固有的系统项目；它容纳多个通用会话，继续共用既有 harness。此处区分会话归属，不重设自由对话／研究任务对话类型。
- 全局工作区由系统管理，原则上不产生持久文件；可使用临时工作文件，不同会话的临时工作区隔离。
- 文献库相关工作可以在全局会话进行，文献及研究主题的成果继续由库掌握，不要求创建用户项目研究任务。
- 全局会话可以读取其他项目中的内容，不能修改目标项目。读取仍沿目标项目信任、材料范围与模型外发授权，全局归属不自动扩大资源权限。

### 已确认的持久化与程序边界

- **Q1.1：临时文件与长期科研事实分开保存。** 全局临时工作区不承载长期科研事实；需要接续的库内分析、理由、进展和下一步保存到对应文献／主题及其分析记录。会话与必要执行数据由 harness 按既有规则保存。工作区清理不删除库成果，科研承接不依赖聊天记录或临时文件。中断后核对实际库成果、必要运行记录与当前授权，沿既有恢复规则继续，不假定临时文件仍在。
- **Q1.2：只读约束覆盖工具与程序。** 跨项目工具仅取得目标项目的读取能力；全局会话仅开放能实际落实访问限制的程序入口，暂不直接开放无隔离的通用 Shell／任意代码入口。不在目标项目里运行会生成缓存、修改环境或写入产物的脚本。临时文件仍可由受控工具处理，工作目录或提示语不作为访问限制的保证。普通项目的可信代码执行决定继续适用，全局会话沿本段的更窄能力范围。

以上两项经用户回复“接受”确认。临时文件保留与清理时机、全局会话的导航和管理操作，以及具体接口与目录由后续设计承接；这些细节不改变临时区与库成果的权威边界。

旧文献域决定中的 harness 项目工作域表述需结合系统固有工作域核对；当前正式规格和实现尚不表示这套全局会话能力已接通。

### Q1.3：按实际用途关联业务对象

能力调用记录所用能力与业务流程、发起工作域、实际材料、执行尝试与交付，按用途关联文献、研究主题或项目研究任务；研究任务关联按需提供，不因调用自动创建任务或使会话绑定任务。

| 工作 | 业务关联 | 成果归属 |
| --- | --- | --- |
| 全局会话分析一篇文献 | 文献及其分析记录 | 文献库 |
| 全局会话维护研究主题 | 主题及所用材料 | 文献与知识库 |
| 项目会话推进论文研究 | 所服务的研究任务及相关材料 | 项目工作区文件 |

调用与执行记录仍由科研运行模块及 harness 掌握，不转移输入与成果的领域归属。全局会话读取其他项目材料时，来源仍指向原项目，读取不授予修改该项目或其研究任务的权限。

### Q2：完整目录、共同契约与首条交接校准

本票形成三项设计结果：

1. 六组科研业务的完整职责目录，逐项明确适用目的、输入、成果归属、Graph／子图与节点职责、能力入口、旧内容复用依据及外部依赖。
2. 业务 Graph、能力调用、节点 Agent 与通用 harness 的共同契约，以及材料读取、成果保存、部分失败、程序检查和科研判断之间的交接。

## 共同契约的已确认基础

以下整理[内容与执行契约](../../scholoom-foundations/issues/18-native-capability-runtime-and-content.md#answer)、[harness 简化接线](../../scholoom-foundations/issues/25-harness-business-integration.md#answer)、[首条路径](01-literature-synthesis-path.md#answer)及本票已确认决定，不新增通用调用台账或业务任务层级。

- **发现与执行。** 共同目录提供已注册科研能力、对应业务 Graph 及输入交付约定；运行时随调用处理必要记录并执行 Graph。节点及子图沿步骤和结果记录，不逐层自动创建业务调用，业务流程不以 Skill 正文承载。
- **流程选择与资源。** 能力与 Graph 候选保留实际来源和版本，同名不按目录顺序静默覆盖。节点指导与资源依其职责取得；资源需求不授予权限，全局会话的程序限制同样适用。首批 Graph 随 Scholoom 源码定义并注册，用户／项目通过已开放参数配置，自定义 Graph 功能后置。
- **输入与范围。** 工作目的、材料引用、实际交付目标、所选能力／业务流程及必要参数由调用约定表达；按用途关联业务对象，研究任务关联可选。初始材料允许在授权内继续发现，不把初始清单当作全部实际采用来源。
- **读取与依据。** 库知识由工具按指针读取；项目材料通过所属项目的有范围能力读取。实际采用的来源、必要版本与材料深度可辨；已知材料条件与读取异常分别表达，异常策略只引用[材料引用行为矩阵](03-project-research-assets-scope.md#材料引用行为矩阵)，不在方法内另设替代来源的静默路径。
- **成果与过程。** 由 Agent 经所属领域工具或项目文件操作在形成时保存成果、比较、理由和下一步，取得实际可读引用。库知识不复制为项目事实源；项目自己的解释与采用判断保存到项目文件。运行时核对实际保存及声明要求，提示语或自述不替代保存。
- **交付与部分结果。** 实际执行、必要产物可用与科研判断分别表达。分批保存并保留已成功成果，关联失败不删除文件，逐项说明未完成、未关联或结果未知；局部成功不自动满足整体交付。
- **恢复与授权。** 中断或新会话从所属研究事实、实际产物、必要运行记录与当前授权接续，checkpoint 不替代研究事实。全局临时文件不承担接续权威，项目状态不因库更新自动改写；正式决定及未处理操作沿既有恢复规则核查。

## 综合内容与复核要求

以下 Q3 与 Q4 经用户回复“采纳”确认。

### Q3：按研究问题组织综合内容

报告及其引用的过程材料共同提供：

- 本次研究问题、范围和材料纳入／排除理由。
- 围绕问题选择的比较维度，例如方法假设、数据条件、评价方式或适用范围。
- 有来源支撑的综合发现，以及冲突证据、成立条件和不确定性。
- 分别说明领域研究局限、本次材料覆盖不足及当前证据不足。
- 未解决问题与下一步。

相互矛盾的文献结论需分析能够确认的条件差异，并保留尚无法解释的分歧。研究空白的判断需要依据，不能由本次材料未覆盖直接推出。不同课题可采用不同章节、表格和叙述方式；内容要求由报告与实际可取回的过程共同满足，不要求每篇文献填满固定表格。程序文件检查和版式完整不构成科研充分性判据。

### Q4：单 Agent 基础路径与按需独立复核

基础路径允许单个 Agent 完成取材、综合和依据核查。程序检查实际保存、材料可读性与来源引用；科研 Agent 核查论据能否支撑结论、冲突是否妥善处理，以及结论是否超出实际材料范围。正式研究决定继续沿既有授权规则。

独立审阅可由用户或能力声明要求；一旦要求独立复核，须实际完成，缺少对应能力时明确报告未完成，不能用自查替代或声称已通过。独立审阅沿既定协作规则取得实际材料、形成意见并保留分歧。多 Agent 协作不是基础路径的必需前置，但相关专用方法仍声明其实际依赖。

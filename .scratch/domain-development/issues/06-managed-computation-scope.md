## Question

科研计算与执行环境域应在现有平台进程能力、PDF 处理和编辑排版之外提供哪些程序运行能力，首批设计需要它到什么程度？

- 区分平台进程机制、程序运行、环境准备、编辑排版和 Agent 执行监督，明确可复用职责及接口归属。
- 围绕首批或后续真实科研工作，识别程序输入、环境、日志、结果与图件、取消及重启核查的设计入口。
- 保持人工基础操作独立于 harness；明确运行结果与科研交付判断的交接，避免为脚本执行强制建立会话或能力调用。
- 给出对方法域、项目域和成果交互域的最小依赖，以及独立诊断、目标平台验证和后续接入的启动条件。

本票不选择全部解释器或环境工具，不安装依赖，也不扩大可信代码执行的安全承诺。

## Answer

2026-10-21，用户分两轮采纳 Q1–Q4，确定科研计算与执行环境域的职责、首批设计范围、运行依据、基本操作及独立验收。以下为后续设计输入，不表示程序运行能力已交付或授权业务实施。

### Q1：程序运行、平台与编辑器的分工

程序运行能力指人和 Agent 共用的程序运行管理，包括指定环境与参数、启动、状态与日志、实际输出、取消及重启核查。功能域及其职责不预定新增包、进程或接口。

| 责任方 | 负责内容 |
| --- | --- |
| 平台 | 启动、输出读取、进程树控制、停止确认等系统机制 |
| 程序运行能力 | 环境准备与选择、运行记录、状态与有界日志、输入输出引用、取消及重启核查 |
| 编辑器 | 稿件转换、编译流程、依赖识别、最后成功预览与导出 |
| 科研业务 Graph／Agent | 选择计算方法、组织代码与参数、判断结果是否满足科研要求 |
| 宿主 | 装配提供者、统一资源准入与生命周期 |

人和 Agent 使用同一套程序运行能力；人工运行无需建立会话或能力调用。现有排版优先复用共同进程能力，进一步提取程序运行职责时保留已有保护，不强行统一排版与科研计算的业务状态。Agent 执行监督仍归 harness，科研解释和交付判断归负责 Agent 与科研业务，文件及成果权威仍归所属领域。

### Q2：首批设计包与校准路径

先形成“项目内程序执行与环境供给”设计包，用项目中的数据、代码和参数，经准备或复用获授权环境、实际运行、保存结果表或图件，校准人和 Agent 查询同一运行事实及实际文件的路径。

设计覆盖缺依赖、部分输出、长时间无日志、取消及重启核查，用固定样例独立验证程序运行能力。具体科研方法和结果解释由后续业务 Graph 承接，不等待完整科研流程才能设计本域。

基础文献综合不依赖通用程序运行；需要计算或工程渲染的工作声明实际依赖。环境准备、实际产物保护、工具等待与程序时限、取消和恢复、可信代码范围继续沿[科研程序执行决定](../../scholoom-foundations/issues/40-research-execution-environment.md#answer)，全局会话继续受[全局工作域的程序边界](04-research-methods-scope.md#已确认的持久化与程序边界)约束。

### Q3：运行依据与科研材料归属

一次运行保留足以核查的已知事实：

- 实际启动命令、参数、工作目录、解释器及可确认的环境版本。
- 已声明的代码与输入材料引用，以及可取得的版本依据。
- 运行状态、退出结果、有界日志和实际输出引用。

程序可能自行读取其他文件，系统不能据此声称已掌握全部依赖；无法确认的部分如实标明，不默认复制整个项目，也不承诺任意程序都能完整复现。

运行事实由运行记录维护。方法选择、结果解释及有研究价值的判断保存为项目材料，并关联相应运行和成果。输入、代码和结果仍沿所属领域的身份与版本规则核对；退出成功或输出文件存在不代替科研判断。

### Q4：基本操作入口与独立验证

首批提供运行、查看状态与有界日志、取消及打开结果的基本操作。人工入口从项目文件或明确运行配置发起；Agent 经工具使用同一能力。界面接入既有工作台，终端、Notebook 等交互的具体设计另行讨论。

独立验证采用小型固定程序，核对以下可观察行为：

- 人工路径无需会话或模型，Agent 路径取得相同的运行事实。
- 环境准备、缺依赖诊断、实际输出和部分失败。
- 输出过量、长等待、取消、进程后代收尾及重启核查。

模型可以使用受控响应，程序和文件操作走真实接线。先取得本机验证证据，目标平台仍按实际分发环境分别验收；科研质量由相应真实业务路径验收，固定程序通过不代表科研结论正确。

### 后续交接与启动条件

本域可依据既有平台进程机制、项目文件契约和本票范围开展“项目内程序执行与环境供给”的详细设计，不等待完整科研流程。跨域接口、宿主装配及统一准入由[共同工程主线](09-shared-engineering-responsibility.md)统筹；编辑器保留排版保护，项目域提供材料和成果的身份及读写，科研方法域声明所需程序、环境、输入输出及科研检查，成果交互域承接操作与查看。

[并行设计与交付安排](10-parallel-design-and-delivery.md)据此核对实际依赖。具体工具支持、环境准备机制、运行记录契约、复用提取范围和实施任务由相应 OpenSpec 调查与设计确定。人工与 Agent 的共同入口、真实环境及跨模块结果接线在实施验收中落实，不以单模块或受控响应通过代替真实整合。

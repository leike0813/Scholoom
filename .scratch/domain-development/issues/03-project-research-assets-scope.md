### 当前领域模型

术语见 [CONTEXT.md](../../../CONTEXT.md)。

| 概念 | 含义 | 领域 owner | 持久化 |
| --- | --- | --- | --- |
| 研究主题 | 长期持续维护的知识集合 | 文献与知识模块 | 随文献库持久化维护 |
| 研究任务 | 面向一项具体产出的研究工作，通常最终落实到论文 | 项目 | 相关内容在项目工作区以文件形式持久化维护 |

库知识以文献与知识模块为唯一事实源。项目区仅保存文献或研究主题相关知识的指针，harness 需要使用时通过工具读取；UI 可以经内置资源协议直接在阅读器中打开。任务在工作区文件中保存自己的目标、约束、计划、进展、分析、判断、成果及指针的采用语境。概览从所属事实源生成，库知识内容继续随库维护。此前提取并保存库知识内容的建议未获采纳。

项目是研究任务的容器，允许容纳多个任务，常见情况从一个任务开始。相关任务可以共享项目中的数据、代码和材料，各自保持目标与成果。例如同一批数据形成实证论文和方法论文，可以分别组织为同一项目中的两个研究任务。

各任务分别保存自己的采用、排除理由及引用关系。同一篇文献可以在任务 A 中因样本不符而排除，在任务 B 中采用；库维护文献及知识事实，项目概览汇总各任务情况。重定向只修改当前明确指定的引用，需要修改多个任务时明确范围；其他任务的研究判断与引用保留，由其后续读取按矩阵处理。

面向论文等具体成果的研究任务，其内部文献综合、实验设计、计算分析、写作及修订优先作为研究计划工作项组织。工作项按需要记录目标、输入、预期产物、进展和下一步，支持依赖、并行及调整，执行与委派可引用相应工作项。单次方法调用保留实际执行记录；部分工作形成需要独立维护的研究目标和最终成果时，再建立关联研究任务。

研究任务是动态演进的研究状态。规划时可约定当前完成条件，达成后仍可继续扩充目标、范围和完成条件；当前状态随研究工作更新。已有成果及其当时满足的条件继续保留，扩充后的交付依据当前约定判断。

每项研究任务有一个明确入口文件，例如 task.md。入口包含必要的身份、名称及状态等少量结构化元信息，以及目标与交付要求、当前研究计划、库知识指针、项目材料及过程和成果文件入口。较长分析、方案比较、实验记录和稿件按需独立成文，由入口引用；计划较大时可拆成独立文件，入口保留引用，各项内容只在所属文件维护。人、harness 和 UI 从同一任务入口发现当前工作并逐步读取依据。实际文件名、目录及字段在后续设计中明确。

入口及计划维护当前安排，过程文件保留完整比较、研究条件及调整理由，当前安排引用其依据。例如由方法 A 改为 B 时，当前计划使用 B，原 A 的分析及放弃理由保留，并表达与当前选择的关系。入口承担当前工作导航，完整历史论证由关联材料承载。

研究内容在形成时由实际开展该段工作的 Agent 通过共同文件或领域工具保存，关联对应工作项、任务和产物；组织本次工作的 Agent 核对实际交付并整合当前安排。工具返回实际保存结果和可读取引用，不能仅凭自述登记完成。人和其他获授权 Agent 可共同编辑，文件保护沿按文件串行、内容变化即重读的既有契约，不引入任务或会话独占。

新 Agent 依据用户指令、明确附加的任务或相关材料定位工作，先读候选摘要，再读相关任务入口以确定目标、交付、当前计划及障碍。随后按本次工作展开过程记录、项目材料和成果，库知识通过指针及工具取得，核对当前材料后继续并写回所属文件。指令涉及多个任务时可分别推进；候选确有歧义才询问用户，不按最近修改猜测任务，不建立会话与任务绑定。

此前决议中允许主题成果归项目、研究任务属于库或项目，以及将任务结构化事实存入项目数据库的表述，与本轮定义存在差异。当前结论和术语采用本轮定义，相关旧票作为历史依据；仍适用的会话独立、开放文件、来源关联及共同视图方向继续保留。工作区文件格式、目录和具体共同接口由后续详细设计明确，当前代码尚未实现这套任务模型。

### 库引用完整性红线

用户明确库知识引用可靠性属于科研可信度红线，系统应维护引用完整性，禁止 fallback。库知识读取失败必须如实报告，不得改用缓存副本、模型记忆或其他来源充当该指针所指的科研依据。任务自己的研究记录与成果仍以工作区文件为事实源。

项目区自行持有库知识指针，系统不建立“库内材料—项目引用”的反向映射表。库管理自身对象及其读取状态；不依赖遍历全部项目来发现引用或判断删除影响。

材料自创建即具有唯一标识；删除后再入库创建新标识，即使是同一篇文献也不复用旧身份。库保留已删除对象的标识、操作者及必要语义信息，文献至少保存标题。操作者须来自实际调用身份，不能由 Agent 猜测或编造。删除记录只描述库对象自身，不记录引用它的项目。

回收站中原对象及原材料仍在时，恢复原对象保留原标识，删除历史继续保留；原指针在恢复后可重新读取。重新搜索或取得材料并入库创建的是新对象，使用新标识，需要明确重定向，不能冒充恢复原对象。

重新入库得到新身份，重定向改变引用目标；这些操作须在有效授权内明确进行，不能伪装为旧目标读取成功。具体重定向操作和关联变更记录在后续接口设计中明确。库知识本身依然只有库这一处事实源，项目只保存指针及自己的研究语境。

外链材料继续保留，失效作为独立情况表达；不要求全部库材料改为托管。路径缺失本身不能判定用户删除，外链与托管材料必须能在诊断中区分。[当前附件规格](../../../openspec/specs/literature-attachments/spec.md)和实际实现作为后续调查输入，本票不直接修改正式规格或实现。

### 材料引用行为矩阵

本矩阵统一保存材料引用的行为策略，适用于 harness 工具及 UI 资源读取。用户已确认各行策略；它是后续契约与验证的输入，不表示这些分类与行为均已实现。

“暂停询问”指当前 Agent 暂停推进工作，向用户说明目标对象、已知事实、具体错误及可选处理，收到用户明确答复后才继续。等待期间不自行选择忽略、重定向、重新入库或其他恢复方案，未答复不视为同意。

| 情况 | 可依据的事实与分类 | Agent 策略 | 处理路径 |
| --- | --- | --- | --- |
| 所指对象存在且材料可读 | 库实际取得所指权威内容 | 正常读取，按研究目的使用 | 沿原指针继续 |
| 对象有明确删除记录 | 已删除，返回操作者及必要语义，文献至少有标题 | 暂停询问，不自行认定应撤销删除 | 用户可选择恢复原对象（若可恢复）、忽略、重定向或重新搜索入库 |
| 对象不存在且无删除记录 | 目标不存在；不能据此认定用户删除或系统损坏，也可能是 Agent 生成错误 | 返回明确错误，由 Agent 核查并决定处理，无法判断时可询问用户 | 核查指针与库身份、重新查找；实际采用新对象时明确变更引用 |
| 库无法连接或服务不可访问 | 系统访问异常，目标状态可能无法取得 | 暂停询问 | 由用户决定恢复后重试、忽略或其他明确处理 |
| 库托管材料读取报错 | 库读取异常，保留实际错误 | 暂停询问 | 由用户决定诊断修复、重试、忽略、重定向或重新搜索入库 |
| 库托管对象记录存在，实际内容缺失 | 库数据完整性异常，不推定用户已删除该对象 | 暂停询问 | 由用户决定修复或恢复库、忽略、重定向或重新搜索入库 |
| 外链材料失效或不可读 | 外部依赖不可用，区别于库托管材料缺失；仅凭缺失不能确定谁删除或移动 | 暂停询问 | 用户可重新定位同一材料、忽略、重定向或重新搜索入库 |
| 明确的权限拒绝或读取授权撤回 | 无当前有效访问权，不等同对象删除 | 暂停询问，遵守有效授权 | 用户决定是否调整授权、忽略或终止相关工作 |
| 返回材料与所指身份或既定材料条件不符 | 完整性不符，不能当成原引用读取成功 | 暂停询问 | 由用户决定核查、恢复或明确采用新对象 |
| 库明确声明文献分析或主题知识发生正常修订，当前内容可读 | 正常知识维护，区别于材料读取异常 | 在已有授权内读取权威内容并由 Agent 核对任务影响，库更新不自动改写已有判断或稿件 | 相关研究保存核对依据、影响与后续安排；正式判断按相应授权处理 |

用户选择后的处理必须保留实际含义：

- **忽略**：记录用户选择及被跳过的引用或工作，按剩余条件继续；被跳过的材料不成为已读、已核验的依据。影响原完成条件时，明确记录缺项或用户调整后的条件。
- **重试或修复后继续**：重新读取原指针，实际取得可靠内容后才继续依赖它的工作；再次失败仍按矩阵处理。
- **恢复原对象**：回收站中的原对象及材料仍可恢复时，保留原标识恢复，保留删除历史，再实际读取原指针。
- **重新定位外链**：沿共同材料契约核对是否为同一材料，保留原身份所指的实际含义。
- **重定向**：明确采用另一个库对象，只更新明确指定的引用并保存变更理由；跨任务修改明确范围，不将新对象冒充旧对象。
- **重新搜索入库**：在有效授权内执行查找及收录，新建对象取得新标识，再明确更新任务引用。

以上矩阵、暂停语义及处理原则已由用户确认。具体错误码、载荷、交互组件及恢复操作由后续详细设计承接。

### 职责与首批交付边界

首批设计以 ResearchSpec 的工作区承接为参考，并按上述本项目模型组织；以下职责、共同操作和验收范围作为后续设计输入。

### 完整职责与首批范围

本域沿既有领域边界管理项目研究语境、持续任务、项目材料与成果，以及所属证据和主张关系、稿件、审稿问题和正式研究决定。文献自身的事实与可复用分析仍归文献库。

首批围绕[首条文献综合路径](01-literature-synthesis-path.md#answer)，优先明确持续研究任务、项目来源与成果关联、研究过程材料的发现读取及派生概览，使补充材料后更换会话或 Agent 可以继续研究。研究问题、证据与主张、正式决定、稿件及审稿问题保留完整职责和后续设计入口，按实际需要推进专门对象管理；首批不一次性建立全部对象模型。

研究问题表达研究希望弄清的内容，研究任务组织具有持续目标和交付的工作；计划表达可调整的工作安排，普通过程材料保存研究论证。正式决定、稿件及证据关系继续沿各自既定语义与权威，不能以普通笔记或执行状态代替。任务按用户明确要求或建议经确认后创建，会话与任务沿既有独立约定。

### 参考 ResearchSpec 的材料组织

| 部分 | 保存与读取责任 |
| --- | --- |
| 研究任务记录文件 | 在工作区保存目标、约束、进展及材料、过程文件和成果的关联，可独立于原会话查询。 |
| 开放的研究过程文件 | 保存计划、完整分析、方案比较、采用与放弃的理由、限制、未决问题及下一步；较长专题按需单独成文并相互引用。 |
| 实际成果 | 任务形成的综合报告、证据比较表等保留实际文件，所用库文献、主题与分析成果以指针关联。 |
| 工作区概览 | 从上述事实源生成入口，沿引用展开完整材料；不另存一份可编辑的当前正文或研究事实。 |

任务笔记承担导航和当前工作安排，关联材料保存完整论证。任务内容以工作区文件为持久事实源，目标、约束和进展引用各自所属文件中的记录，避免维护两份当前状态。概览与摘要不能替代接续所需依据。

研究内容在形成时持续保存，后续步骤读取已保存材料，沿[工作区承接决定](../../scholoom-foundations/issues/35-research-workspace-context.md#answer)及[harness 协作决定](../../scholoom-foundations/issues/25-harness-business-integration.md#answer)落实保存与交付接线。ResearchSpec 提供工作组织和恢复入口的参考，其方法要求与程序实现分别核对；具体目录、字段及可复用源码在后续设计中选择。

### 共同操作、视图与跨域交接

人和 Agent 共用任务查询、创建与更新，材料和成果关联，以及概览、发现和内容读取能力。接口沿共同 protocol、client 与 broker 接入，复用现有文件身份、保存保护和资源打开能力。普通工作文件可直接操作，按研究需要关联。

任务从现有右侧任务面板导航，详情接入中间 tab，报告及过程文件继续使用共同编辑阅读入口；设计依据见[工作台设计文档](../../../docs/ui-design/README.md#右区)。概览、任务列表和关联读取保持有界，具体字段、操作名和内页布局留给详细设计。

| 责任方 | 首批交接 |
| --- | --- |
| 研究项目与研究资产 | 管理任务、项目研究语境、过程材料及成果关联，提供持久化、发现读取和相关失败诊断。 |
| 文献与知识管理 | 提供稳定库来源、材料版本、可读内容及可复用分析；项目保留自己的采用理由与研究判断。 |
| 科研方法与工作流 | 组织分析与综合，定义和检查实际交付，通过所属领域保存成果和关系。 |
| harness | 提供通用执行及必要记录，保留与任务、能力调用和实际产物的关联；研究进展与执行状态分别表达。 |
| 阅读写作与成果交互 | 提供共同编辑、阅读及资源打开入口；本域承担自己的任务视图。 |

首批共同约定包括来源和材料版本引用、过程与成果的保存读取、任务及能力调用关联和部分失败表达。共享契约由主 Agent 统筹，方法执行与界面不另建领域权威。

### 材料变化、复用与独立验证

接续时读取当前过程文件，通过指针取得所需库内容，并核对已有采用条件。库来源不可用时保留项目自己的过程记录、判断和成果，说明依赖缺项；库知识的可读性由库读取结果确定。补充材料后的影响核对及闲置项目手动启动复核，沿[首条综合路径决定](01-literature-synthesis-path.md#补充材料与新会话续做)继续细化。项目成果跨会话继续使用；跨项目复用保留来源和成立条件，主动整理为库资产沿既有授权办理。

保存或关联部分失败时保留实际成果及已确认的关联，说明未保存、未关联或结果未知的部分。材料引用错误按上面的行为矩阵处理；需要用户决策时当前 Agent 暂停等待答复。其他保存失败继续沿所属工具契约核对。读取、保存、关联和结果刷新分别提供可诊断结果；执行成功、文件存在及 Agent 自述不代替研究交付判断。

| 验证层次 | 首批范围 |
| --- | --- |
| 模块独立验证 | 经共同接口检查任务持久化与查询、来源和成果关联、过程材料读取及局部失败；可替换文献和执行依赖，检查实际保存结果。 |
| 共同工作台 | 浏览器与 Electron 共用任务操作、详情和资源入口，核对当前事实及失败反馈。 |
| 跨域研究接续 | 首次综合后补充材料，由新会话从项目记录与当前材料找到目标、理由、成果和下一步，判断影响并保存后续成果。 |
| 变化与失败情境 | 核对来源不可用、用户修改过程文件、保存或关联部分失败时的实际可用内容、成果保护及后续可做工作。 |

实施时优先复用现有测试，补充稳定行为的必要验证。受控模型可核对保存与读取接线，真实科研接续另核对依据使用、材料变化识别及实际后续成果；能打开报告或读取摘要本身不证明承接质量。主 Agent 负责跨域整合验收。

### 完整情境走查

下表将已确认规则串成可检查的情境，只做设计语义走查，不作为运行或科研质量验收证据。

| 情境 | 应有行为及事实源 |
| --- | --- |
| 从库主题开始一篇论文研究 | 项目建立面向具体成果的任务，入口保存目标、当前完成条件及计划，工作区只记录所用库知识指针，harness 通过工具读取。 |
| 同项目并行实证论文与方法论文 | 两个任务共享项目数据和代码，各自维护采用理由、计划与成果；同一库材料的排除或采用判断不会互相覆盖。 |
| 更换 Agent，项目内有多个任务 | 按指令和相关材料定位候选，先读入口再展开当前计划、过程和成果；歧义才询问，不按最近修改猜测，库知识沿指针读取。 |
| 由方法 A 改为 B | 当前计划更新为 B，完整比较及放弃 A 的理由保留在所属过程文件，入口引用依据，后续工作能分清当前安排和历史探索。 |
| 达成当前完成条件后加入新研究要求 | 保留已有交付及其条件，任务可扩充目标与完成条件，当前状态随工作更新；形成独立研究成果时可建立关联任务。 |
| 库主题或分析正常修订 | 库继续维护知识权威，Agent 在已有授权内核对任务影响，保存本任务的判断理由和安排；正式决定按相应规则处理。 |
| 引用对象进入回收站 | 返回对象标识、操作者和必要语义，Agent 暂停询问。用户选择恢复原对象时保留原身份及删除历史，实际读取成功后继续。 |
| 用户选择重新搜索入库并重定向 | 新对象取得新标识，只修改明确指定的引用并保存理由；其他任务后续读取原引用时独立按矩阵处理，不维护反向引用映射。 |
| 库不可达、托管材料缺失或外链失效 | 区分矩阵中的具体类别，Agent 暂停询问并等待用户选择，保留已保存成果，不使用 fallback。 |
| Agent 生成不存在的对象标识 | 工具明确返回对象不存在且无删除记录，Agent 核查并决定处理；不能谎称已读，也不能推定用户删除。 |
| 用户选择忽略某引用 | 保存用户选择和跳过范围，按剩余条件继续；被跳过材料不成为已核验依据，完成声明对应当前明确条件。 |
| 人与多个 Agent 修改同一任务文件 | 使用共同文件工具，内容变化即重读，保留实际成果与冲突信息，不以会话或任务独占替代写入保护。 |
| 过程或成果已保存，但入口关联失败 | 如实保留已保存文件与未完成关联，不能将其误报为完整交付；按实际结果核查并补齐记录，避免删除成果或凭自述推进。 |

### 详细设计与实施的输入

- 项目域细化任务入口及工作项的文件契约、身份、目录与共同操作，复用现有文件身份和保存保护，提供有界列表、发现与内容读取。
- 文献域细化材料身份、删除记录、回收站恢复、知识修订及外链诊断；删除记录保存可信操作者和必要对象语义，库不维护项目引用反向表。
- 共同工程主线统筹引用、错误及操作 Schema、broker/client 接入和资源协议；harness 复用工具结果、询问与接续机制，按矩阵返回错误或暂停等候，方法域按实际研究组织计划及交付检查。
- 工作台接入任务入口、详情和材料资源，明确实际读取失败、Agent 等待选择及引用变更结果；运行状态与研究状态分别表达。
- 按上表与矩阵选择有稳定行为边界的必要测试，核对真实保存及共同接线；跨会话真实科研承接质量由主 Agent 组织整合验收。具体参数和实际结果记录在所属 OpenSpec tasks／delivery。

## Answer

2026-10-22，用户明确本阶段多工作树、无统一协调 Agent 的开发模式，并分轮确认 Q1–Q5：公共基础先行、并行启动条件、公共补充经 dev 同步、独立提交边界和分阶段验证责任。以下为后续规划输入，不表示公共基础已完成或授权业务实施。

### Q1：先规划并完成公共基础，再并行开发

先规划各域之间需要的共享契约与接线，由公共基础线完成涉及多域接线的共同部分，再转入多个工作树并行开发。并行阶段没有统一协调 Agent。

本决定确定推进顺序，公共基础完成标准见 Q2，并行期间的公共基础补充路径和提交边界见 Q3／Q4，整合验收责任见 Q5。不据此启动实施，也不预设所有领域功能均由公共基础线实现。

### Q2：公共基础完成与并行启动条件

公共基础的范围限定为本批计划并行功能实际需要的共同部分，启动并行开发前满足以下标准：

1. **接口明确。** 各域提供与接收的内容、权限及失败表达有明确契约和调用示例。
2. **接入口可用。** 协议、宿主注册、工作台挂载等所需共同位置准备好，各域能够按约定接入自己的实现。
3. **小样例实际跑通。** 用固定输入及必要依赖替身，验证跨域调用、结果返回、保存和界面刷新；明确尚未接入的业务实现，不能将替身结果视为真实业务整合通过。
4. **可独立开发和检查。** 每个工作树具备运行、测试及诊断入口，能够替换尚未完成的依赖，验证自身模块。

公共基础的现有实现、缺口、具体文件与任务清单在后续调查和规划中确定，复用已有调用、注册、守卫及 UI harness。各工作树从完成上述验证的共同基础开始；具体工作树划分与整合安排由[并行设计与交付票](10-parallel-design-and-delivery.md)承接。

### Q3：公共基础补充先在当前工作树实现，再经 dev 同步

并行开发中发现公共基础缺口时，先在发现问题的工作树实现，然后在主工作树当前 `dev` 分支 cherry-pick 对应改动，再同步到其他工作树。公共基础改进及时回到共同基础，减少各工作树长期保留私有补丁及重复实现。

该路径保留 Q1 的“初始公共基础先完成，再并行开发”顺序，并行阶段无需统一协调 Agent。提交范围、依赖处理及接入验证见 Q4；本票讨论不自动执行 Git 操作。

### Q4：公共补充提交的独立性与接入验证

公共补充拆成能够独立使用和验证的提交，包含契约、实现、必要调用方调整及验证，不依赖仅存在于原工作树、尚未进入 dev 的业务代码。原工作树中尚未完成的业务功能继续独立开发。

cherry-pick 到 dev 后运行受影响的必要检查，通过后再同步。接收更新的其他工作树验证自身相关调用及功能。具体检查沿变更影响选择，不要求每次同步都重复全量验收；公共补充检查通过不代替最终真实跨域路径验证。

### Q5：工作树、dev 接入与跨域整合的验证责任

| 阶段 | 验证责任 |
| --- | --- |
| 工作树内开发 | 该工作树负责验证自己的模块，说明真实接线、依赖替身及未完成依赖 |
| 改动进入 dev | 本次接入的执行者负责检查合并后的相关行为 |
| 跨域路径具备运行条件 | 单独安排一次整合任务，明确负责人，验证真实内部接线及实际保存结果 |

各域独立通过、dev 接入检查通过、完整科研路径通过分别记录。整合任务有自身范围和负责人，不要求常驻统一协调 Agent。验证沿既有 OpenSpec tasks／delivery 记录，不另建进度账本；真实科研效果仍沿各业务域及既有科研验收约定核对。

### 共同工程与领域职责的衔接

下列归属沿[模块依赖决议](../../runtime-architecture/issues/01-module-dependencies-and-authority.md#answer)、[模块运行规格](../../../openspec/specs/module-runtime/spec.md)及各域决定承接，由 Q1–Q5 组织本阶段交付，不改变领域权威：

- 共同工程维护共享协议的承载、类型与校验传播、broker、平台机制、宿主注册和生命周期，以及共同工作台骨架、分发及跨域接线。领域操作的含义、schema、规则、授权和所属记录仍由提供该能力的领域维护，共享目录不改变语义归属。
- 领域负责自身迁移、数据保护及业务诊断，宿主承接物理容器与跨模块升级装配；工作台和宿主不另存领域权威。实际迁移、权限、性能及双宿主检查随所属变更验证，跨域影响沿 Q5 整合验证，继续复用已有守卫和测试入口。
- 文献及项目提供所属资源与授权，阅读编辑域提供共同视图和选区交互，harness 承接通用输入与执行，科研 Graph 负责业务判断；上下文工具接入真实提供者，隐含对象由 Agent 通过工具理解，无法确定时询问用户。

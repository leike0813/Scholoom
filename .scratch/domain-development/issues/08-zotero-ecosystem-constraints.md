## Question

Zotero 生态接入域怎样划分宿主兼容、Connector、translators、引用键、插件资源和迁入职责，哪些风险需要在首批文献与项目设计固化前调查？

- 复用既有宿主原型、兼容决议及当前题录／附件接口，识别可能影响稳定身份、版本、引用关系、共同数据权威及写入保护的具体问题。
- 区分文献获取的业务结果与生态协议、插件宿主要求；明确文献域与生态域分别掌握什么，避免另建平行文献库。
- 确定 BBT、茉莉花、Connector 和单向迁入各自的后续设计入口及前置；核对原包兼容与旧项目方法复用两类要求。
- 只把尚无可靠证据且会影响当前取舍的问题转为范围明确的 research 或 prototype 票，说明其阻塞的决定、需要的证据与停止条件。

本票通过与用户讨论确定调查优先级及接入边界，不安装插件、启动兼容实验或执行真实迁入。当前没有预设外部 research 票，发现具体知识缺口后再创建。

依据：[生态决议](../../scholoom-foundations/issues/41-zotero-ecosystem-integration.md)、[兼容宿主原型决议](../../scholoom-foundations/issues/16-zotero-host-prototype.md)、[生态初设](../../../docs/initial-spec/ecosystem.md)、[现有宿主骨架](../../../apps/zotero-host/src/main/index.ts)。

## Answer

2026-10-22，用户分两轮确认 Q1–Q5，确定生态域职责、提前调查的优先级、迁入撤回原则及四个后续设计入口。本票收束为 resolved；以下是详细设计输入，不表示相关能力已实现、调查已完成或授权业务实施。

### Q1：引用键与插件状态归属

文献域掌握正式引用键及其固定状态；生态域承接未修改 BBT 原包的生成逻辑、配置和兼容存取，项目域掌握项目自己的引用映射。同一正式引用键只有一处事实源，插件缓存重建或升级不能使已采用的键丢失或变化。具体存储与原包读写适配在详细设计中核对，不另存一套可独立修改的正式引用键。

已有键稳定、明确重生成、导出文件保护及必要插件状态迁入继续沿[生态行为决定](../../scholoom-foundations/issues/41-zotero-ecosystem-integration.md#answer)。已知项目引用的核对受[项目引用约定](03-project-research-assets-scope.md#库引用完整性红线)约束，不建立库材料到项目引用的反向表，也不遍历全部项目来宣称影响范围完整。

同库正式键的大小写冲突沿[文献域决定](02-literature-knowledge-scope.md#正式引用键冲突)，由共同文献权威执行。

### Q2：提前调查的范围与优先级

对象身份与去重条件分别表达。当前题录、附件及材料版本使用独立 UUID；DOI 与版本参与题录去重，内容哈希参与附件去重和完整性核对。Zotero 来源身份映射不能仅凭 DOI、文件内容或引用键判断为原对象。

2026-10-26，用户确认来源副本政策：恢复或复制Zotero源库后，默认视为新的来源实例，只有用户显式确认后才允许重绑定。该规则只决定外部来源映射，不改变Scholoom已有材料身份；相同文件内容、条目key或源库副本不能自动证明仍属原实例。实现及恢复路径由文献共同权威与生态适配在所属OpenSpec核对。

| 调查 | 所阻塞的设计决定 | 所需证据与停止条件 |
| --- | --- | --- |
| 来源库及条目身份、类型与字段映射 | 题录及组织关系契约定案 | 核对固定 Zotero 基线的库／条目 ID、key、类型、字段和关系，与共同文献身份及来源映射逐项对照；说明重复迁入、删除后重新入库和回收站恢复如何区分。能列出映射、保留信息及未解差异后结束，不扩展为完整迁入实现。 |
| 插件保存与引用键保护 | 共同写入、修订冲突与删除恢复契约定案 | 核对 BBT／茉莉花原包实际消费的对象保存、SQL、通知、缓存及固定键行为，对照共同授权、修订和提交结果；说明哪些可复用、哪些适配缺失。不能从已有样本证明的语义明确列出，只有确实影响当前选择且静态材料无法回答时才另提有界原型。 |
| 阅读写回与材料版本 | 共同阅读及材料修订契约定案 | 核对茉莉花大纲／书签的实际 Reader 和 PDF 写回依赖，对照共同阅读记录、材料版本、批注及研究依据保护；明确读取、编辑和原文件变化各自归属与待验证链路，不以完整 Zotero 参考环境代替独立宿主证据。 |

优先开展前两项，阅读写回在对应详细设计定案前闭合。先利用固定源码和已有证据；本轮只确定调查范围与前置，不将讨论确认写成调查完成。具体调查进入所属详细设计的 investigation；只有会影响本地图当前取舍、且已有材料不能回答的问题，才另建 research 或 prototype 票。

Connector 配对与共存、真实在线识别、各类导出服务及目标平台分发随各自接入变更验收；其尚未通过不阻塞无关基础能力，也不能据此省略对应支持目标。

### CSL 更正与原值导出的明确选择

2026-10-27，用户确认：普通 CSL 保存不自动覆盖 Zotero 原值。CSL 与原值不一致或无法比较时，导出前须明确选择采用原值；Agent 可依用户明确指令作此选择，无法确定时询问用户，不要求每次由用户人工点击。更正原值采用独立“更正所选原值”动作。

下一实施切片限于已有唯一 schema 44 期刊原值的题名更正；日期、作者、多来源、CSL 表达导出和自动同步不由该选择授权。具体 DTO、修订核对、事务和验证沿 [connect-zotero-host-bbt](../../../openspec/changes/connect-zotero-host-bbt/design.md)。

### Q3：迁入撤回采用保留原则

沿[项目引用约定](03-project-research-assets-scope.md#库引用完整性红线)，系统不维护库材料到项目引用的反向表，也不遍历全部项目。没有查到项目引用不能作为安全删除的证据。

无法证明安全的已入库对象继续保留，明确报告不能自动撤回的部分。取消尚未完成的迁入、撤销仍可核对且安全的变更、删除已入库材料分别处理；不能只凭本次迁入标记删除对象，也不将新增材料视为尚未被研究采用。后续明确删除或引用重定向继续遵循共同文献操作、授权及材料引用行为矩阵。

该原则细化[原迁入检查与恢复决定](../../scholoom-foundations/issues/41-zotero-ecosystem-integration.md#q8检查迁入结果支持失败中断后的续做与安全撤回)的安全撤回要求；源库、源附件及迁入后的编辑保护继续有效，不承诺整批迁入可无条件回滚。

### Q4：插件及资源维护分工

| 责任方 | 负责内容 |
| --- | --- |
| 生态域 | 通用兼容宿主、原包装载与适配；插件、translators／CSL 的来源、版本、更新和回退 |
| 文献域 | 题录、附件、正式引用键及阅读记录的共同权威，摄取与修改规则；线上来源查询、标识符解析与全文获取的业务结果 |
| 编辑阅读域 | 自有阅读器、引文和书目呈现，消费共同数据及资源 |
| 共同工程主线 | 宿主装配、进程监督、协议接线及产品分发 |

translators 执行、插件宿主和资源维护逻辑集中复用；插件结果通过共同领域入口供人和 Agent 使用。文献获取的身份、冲突与逐项保存结果仍归文献域，生态域提供相应协议、运行环境及来源适配，不另立文献库或阅读事实。

固定 Zotero 10 基线的通用兼容层、指定版本原包不修改和已验收功能支持范围沿[兼容宿主决定](../../scholoom-foundations/issues/16-zotero-host-prototype.md#answer)。插件按已验证版本升级、translators／CSL 独立更新及用户定制保护沿[生态更新决定](../../scholoom-foundations/issues/41-zotero-ecosystem-integration.md#q5插件按已验证版本升级translatorscsl-独立更新)执行；本票确定维护责任，不另建更新机制。

原包兼容与旧项目方法复用是两类要求。BBT／茉莉花原发布包及代码保持不修改；zotero-agents／ResearchSpec 的方法、内容和实现按 Scholoom 契约抽取或重组，不要求旧包、API 或 CLI 兼容。科研流程、能力入口与节点资源的迁入归科研业务域，采用[Graph 承载决定](04-research-methods-scope.md#graph-承载科研业务流程)，不由生态域建设旧工作流兼容层。

### Q5：四个设计入口及独立验证

先闭合 Q2 中身份映射、插件保存与引用键保护两项调查，再据此细化以下四部分；阅读写回调查在对应阅读与材料修订契约定案前闭合。设计入口共享兼容宿主及共同文献接口，不预定新增四个包或进程。

| 设计入口 | 共同前置与交接 | 独立验证重点 |
| --- | --- | --- |
| 兼容宿主与 BBT | 固定基线、共同身份、题录读写及正式引用键契约；共同工程主线装配和监督宿主 | 原包装载与生命周期、共同数据读写、已有键稳定、BibTeX／BibLaTeX 与各类导出、失败诊断；对外 JSON-RPC 和 pull export 经真实外部入口核对，内部桥接成功不能替代。 |
| 茉莉花与阅读适配 | 复用共享宿主；文献域的元数据候选、附件关系及材料修订，编辑阅读域的共同阅读接口 | 中文元数据识别及字段冲突、附件匹配、大纲书签生成编辑与导航、Agent 不依赖可见阅读器访问同一结果、重启读回及材料版本和批注保护。 |
| Connector 与采集 | 复用 translator 运行和资源维护逻辑；文献域的库／集合选择、摄取与附件逐项结果 | 自有扩展独立运行与配对、与官方扩展共存、页面识别和采集、题录与附件部分成功、失联及重试；目标不可用时保持明确失败，不改投其他应用或云端。 |
| Zotero 单向迁入 | 来源库及条目身份映射、共同组织关系与回收恢复、必要插件状态映射 | 内容和关系保留、源库及源附件保持、中断续做及重复迁入核对、后续编辑保护、安全撤回；抽样实际打开材料、检查引用键导出和重启读回。 |

各入口可独立设计和验证，无需等待生态域全部完成；生产写入不能越过所属身份、授权、修订和恢复前置。现有原型及旧项目测试可作有范围的参考，不能替代产品真实接线。真实网络、原包执行、外部接口、浏览器／Electron 及目标平台分发各自记录实际验证范围，替身与受控响应明确标出。

各入口提供所属配置、操作、结果和失败原因，接入既有工作台与共同 Agent 工具，不另建工作台。诊断复用接口、日志或测试，区分请求发送、受理、实际执行与结果刷新，能够核对部分成果、冲突及未完成项。具体界面沿设计事实源，完整跨域路径由主 Agent 负责整合验收，各入口独立通过不代替真实科研与分发验收。

### 后续交接与设计启动条件

后续详细设计按项目 OpenSpec 阶段约定，将 Q2 的调查证据、共同契约和复用职责落实到各自 investigation、规格及设计；具体 Schema、SQL 适配、原包调用、进程封装和实施任务在所属变更明确。四个入口延续[文献基础工具实施计划](../library-foundation-plan.md)的生态交付位置，提前调查仍须在相应基础契约定案前闭合。

[共同工程主线](09-shared-engineering-responsibility.md)据 Q4 统筹共享协议、提供者装配、生命周期和分发；[并行设计与交付安排](10-parallel-design-and-delivery.md)据 Q2、Q5 区分调查、设计定案、生产写入及真实整合的前置。调查发现影响已确认职责或共同权威的新冲突时，带证据回到所属决定讨论。

当前没有尚需独立 research 或 prototype 票才能决定的全局职责问题，未新增这两类票；已能明确的调查范围、证据与停止条件集中在 Q2，交所属详细设计承接，不将未完成调查藏入地图的模糊事项。用户确认本票不等于执行兼容实验、真实迁入或启动业务开发。

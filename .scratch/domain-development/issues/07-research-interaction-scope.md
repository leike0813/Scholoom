## Question

阅读写作与成果交互域负责哪些可复用能力，各业务域自行接入哪些视图，首批综合路径需要怎样的真实反馈与人工介入？

- 以已交付阅读器、文件编辑、稿件转换和排版为基础，区分领域记录、界面交互、开放文件及公共执行职责。
- 沿用户在[文献域讨论](02-literature-knowledge-scope.md)明确的约束：项目文件与库附件使用同一套资源打开、编辑器和阅读器接口，由共同能力选择格式视图，资源归属及授权由领域保持。明确现有文件 tab 与 reader tab 如何衔接到该契约，并核对同格式两类来源的真实接线。
- 划定编辑阅读组件、对象指令、交互式报告、成果查看与修改审查的共同能力，避免业务域各建一套交互桥或本域集中承包所有业务界面。
- 确定首批所需的材料选择、来源核查、综合结果与下一步呈现；哪些交互可复用当前工作台，哪些应进入后续专门设计。
- 说明报告持久保存、动作回传、授权及资源访问的设计归属和依赖；核对双宿主、草稿保护及有界刷新等既有约束。
- 明确当前条目、附件及阅读选择如何通过工具供 Agent 查询；界面导航与 harness 的项目工作域独立，切换文献库或打开附件不改变会话接收者。上下文工具的具体载荷与作用范围在相应设计中确定。

本票只划定责任与接入条件。具体界面设计沿设计事实源推进，不重新设计工作台布局或承诺持续精确原文定位。

依据：[UI 设计](../../../docs/ui-design/README.md)、[交互式科研界面决议](../../scholoom-foundations/issues/45-interactive-research-reports.md)、[工件交互决议](../../scholoom-foundations/issues/38-workbench-artifact-interaction.md)、[工作台初设](../../../docs/initial-spec/workbench.md)。

## Answer

2026-10-22，用户分轮确认 Q1–Q6，确定共同阅读写作与成果交互职责、Codex 式交互目标、浏览与指令路径、刷新保护以及两个设计包的独立验收范围。以下为后续设计输入，不表示交互链路已交付或授权业务实施。

### Q1：共同阅读编辑与业务交互的分工

| 责任方 | 负责内容 |
| --- | --- |
| 阅读写作与成果交互域 | 共同资源视图、阅读编辑组件、选区与对象指令入口、差异查看、交互式科研界面的承载与动作回传 |
| 文献、项目等业务域 | 对象身份、版本、权限、保存规则，以及各自的列表、详情和业务操作 |
| harness 与科研业务 Graph | 接收指令或交互输入、推进执行及等待，判断科研交付；harness 提供通用执行，Graph 与负责 Agent 掌握业务判断 |
| 程序运行能力 | 新计算、工程渲染和图件重新生成 |
| 共同工程主线 | 共享协议、宿主装配和工作台骨架 |

例如审阅意见由所属领域保存，本域提供查看意见、比较修改及向 Agent 提要求的交互，是否解决意见由负责 Agent／科研业务判断。各业务域复用共同能力，不因此将所有业务界面集中交给本域。

### Q2：两条可分别推进的设计线

1. **围绕现有材料和成果工作。** 补齐当次选区／对象附加、共用指令、来源打开、修改差异与依据、撤销及变化通知。首条文献综合以已有报告视图承接，核对实际来源、结果和下一步。
2. **交互式科研界面。** 细化共同呈现、更新、用户输入回传、资源访问和运行边界，以材料比较或结果探索的小场景校准，供 Agent 与业务 Graph 共用。

交互式科研界面现在即可开展设计，基础综合不等待它完成。两条线沿通用会话约定：对象导航不切换接收会话、不强制绑定研究任务；隐含对象由 Agent 通过工具理解，无法确定时询问用户，沿[Agent 运行协作决定](05-agent-collaboration-scope.md#answer)。

既有对象交互中的任务绑定表述以[统一会话决定](../../scholoom-foundations/issues/43-free-agent-conversation-and-research-tasks.md#answer)为准；当次选区、差异和独立审阅记录沿[定位范围约束](../../scholoom-foundations/issues/44-defer-continuous-precise-source-location.md#answer)，不承诺内容变化后的持续精确定位。具体界面结构与视觉仍以项目 UI 设计为事实源，本票不另设布局。

### Q3：以 Codex 的交互模式为设计目标

以[Codex 交互调研](../research/desktop-ade-codex.md)所记录的体验为参照：用户在预览中选择对象、文字或区域，添加批注，随指令发送给 Agent，再查看处理后的结果。沿 Q1／Q2 的共同阅读编辑与交互界面职责设计，具体界面仍归项目 UI 设计维护。

本决定确认交互目标；页面按钮请求 Agent 工作的默认路径见 Q4，两个设计包与独立验收范围见 Q6。本票不预定先只做文字和图片、再做 HTML 图表的实施顺序。隐含对象理解、会话接收者及定位范围继续沿已确认边界。

### Q4：报告浏览与向 Agent 提要求的操作路径

筛选、排序、展开等浏览操作在报告内直接完成。点击“进一步分析所选论文”等需要 Agent 处理的动作，默认将所选对象和要求加入当前会话的共同输入框，由用户检查、增删、补充后发送，可与其他批注一起提交。

页面按钮与选区批注共用同一条待发送指令，打开和操作报告不切换会话接收者。需要一步执行的固定操作，后续按实际需求逐项明确行为。

### Q5：报告更新、浏览状态与草稿保护

没有未提交的编辑或批注时，预览自动显示新结果；报告仍支持的筛选、排序等浏览状态尽量保留。有未完成的编辑或批注时，保留当前页面和草稿，提示报告已更新，由用户选择何时查看新版。

已附加到输入框的选区保留当时的摘录和版本依据，不随报告更新替换成新版内容。Agent 修改前核对当前材料；选区不承诺跨版本自动重定位，沿既有定位范围约束。

### Q6：详细设计包与独立验收

沿 Q2 的两条设计线，分别形成可独立推进的设计包，各自覆盖完整操作链路：

| 设计包 | 校准与验收链路 |
| --- | --- |
| 材料批注与修改 | 打开材料 → 选择文字、图表对象或图片区域 → 添加批注 → 进入共同输入框并发送 → 查看修改、差异和依据 |
| 交互报告 | 打开文献对比报告 → 筛选、排序、展开 → 将所选条目交给 Agent → 更新报告 → 关闭后重新打开 |

详细设计同时明确报告资源访问与运行隔离、保存方式，以及关闭工作台后的等待与接续行为。这些具体契约在设计阶段闭合，不从本票推定任意文件、网络或内核访问权限。图表对象选择以已有结构信息为依据，普通图片区域只提供指令定位，沿既有[对象选择决定](../../scholoom-foundations/issues/38-workbench-artifact-interaction.md#q2对象选择与图片区域标注)。

独立验证接入真实阅读器、共同输入框、harness 和文件保存；模型可使用受控响应，核对对象传递、实际修改、刷新和草稿保护。失败时能查清选择、发送、执行或结果刷新环节。浏览器与 Electron 均验证；科研分析质量另由真实业务路径验收，受控响应和独立链路通过不代表科研质量通过。

### 后续交接与启动条件

两个设计包基于已交付共同资源与阅读编辑基础开展详细设计，不等待完整科研流程，也不要求交互报告先完成才能开展基础综合。文献及项目域提供所属资源身份、版本、读写授权与保存；harness 承接共同指令、执行与等待；科研业务 Graph／Agent 负责分析和交付判断，需要新计算或工程渲染时衔接程序运行能力。

共享协议、宿主装配及共同工作台接线由[共同工程主线](09-shared-engineering-responsibility.md)统筹，[并行设计与交付安排](10-parallel-design-and-delivery.md)据此核对实际依赖。具体界面结构和状态呈现先落实到 UI 设计事实源，再由后续 OpenSpec 承接实施；本票不另选布局、前端框架或报告 SDK。

### 会话交互边界

用户管理的是持续存在的 Agent session，通过发送消息推进工作。正常一轮回复结束后，下一条消息沿用同一会话的有效上下文；取消、崩溃或宿主重启后，发送新消息也使用这一入口，由系统完成必要恢复和核查，再按最新指令开展工作。

会话是可用完即弃的交互与临时工作上下文，不是重要科研资产，也不是工作推进的必要依赖。同一会话保持连贯是交互能力；工作目标、约束、分析依据、进展、决定、成果及下一步在形成时保存到所属工作区、文献库或领域记录，后续工作从这些持久事实取得所需内容，沿[会话独立的承接约束](../../scholoom-foundations/issues/35-research-workspace-context.md#会话独立的承接约束)。会话丢弃或上下文丢失不应造成业务事实、必要依据与已完成工作无法接续。

执行尝试、运行实例、checkpoint 和 resume 是内部运行机制，不成为用户必须管理的对象或独立恢复操作。此前“重启后显式接续”的产品含义是重启本身不自动开工，用户发送新消息即可重新驱动该会话；不要求重新点击继续按钮、重复原指令或学习后端的发送／恢复接口区别。

新消息不等于无条件重放上次尚未完成的动作：先纳入当前指令，用户改变方向或撤回旧要求时据此调整；未知副作用按既有规则核查，不绕过授权和数据保护。会话身份与有效上下文不因一次回复结束、执行尝试变化或进程替换自动丢弃。正常跨轮与异常后的上下文行为沿 Q6–Q7，不据此承诺任意故障下完整恢复所有临时状态。

当前实现中 session.send 在空闲时新建执行并带入有限历史，session.resume 单独尝试恢复旧 checkpoint；UI 已以发送新消息作为接续入口。这些内部路径尚未按上述统一会话行为整合，本轮不修改业务实现或恢复 UI 按钮。

### Q1：按模块保持唯一持久化权威

| 内容 | 保存责任 |
| --- | --- |
| 会话、指令、消息、执行状态、工具调用事实、协作收件与消费记录 | harness 的持久记录部分，部署在宿主侧 |
| 模型默认配置与凭据 | 模型、凭据模块；执行记录保存本次实际配置 |
| 题录、项目事实、能力调用与交付关联 | 各自所属模块 |
| 正文、代码、报告等科研工件 | 实际文件，经共同文件能力或获授权程序保存 |
| checkpoint | harness 的内部恢复资料，按 Q3 使用每执行尝试的私有存储 |

执行进程经 broker 提交运行事实、查询记录和调用领域能力，不直接打开库或项目业务数据库。它可持有当前执行所需临时状态，不另存一份对外权威。应用宿主负责装配，broker 负责传递，二者不接管所属模块的记录规则。运行记录的逻辑归属不预定物理数据库文件数量或存放目录。

### Q2：会话、执行尝试与运行实例身份分开

会话身份承载保留中的交互上下文。执行尝试身份在兼容 checkpoint 接续时保留；无法恢复而重新组织执行时建立新尝试，关联仍保留的旧记录。运行实例身份在每次启动执行进程时重新分配，绑定所属宿主实例及实际进程身份，不用 PID 代替。

只有当前有效实例可推进状态、申请模型和发起操作；替换前撤销旧实例资格，迟到结果按原操作归档核查，不覆盖新实例。指令、工具调用与委派身份保留，不因换 PID 自动重新执行。具体身份字段、存储与校验方式由后续契约细化。

### Q3：每尝试独立的私有 checkpoint 存储

每个执行尝试使用独立私有 checkpoint 存储，由当前有效运行实例独占访问。框架在执行进程完成序列化和保存，宿主侧记录归属、位置及必要恢复信息；与库或项目业务数据库分开，不借此直接访问业务表。该私有存储及 SQLite 原生接入继续沿平台资源范围与受控适配契约，不扩大执行的业务权限。

兼容接续沿用该尝试的 checkpoint，但必须先排除旧实例继续写入；新尝试使用新存储。复用已有 SQLite saver，避免单个执行损坏或修复共享 checkpoint 文件时影响其他执行。代价是更多私有文件，具体目录、保留与清理规则随实现确定。

### Q4：可靠受理与可恢复的消费确认

宿主侧保存指令及稳定身份，提交后才返回已受理。运行实例将指令纳入可恢复上下文并完成 checkpoint 保存后，再确认已消费；不能只凭进程内注入或更新布尔标记宣称该消费可以恢复。

checkpoint 已保存而消费确认丢失时，按原指令身份核对，避免重复注入；两个存储不承诺原子提交。已消费不等于工作完成；checkpoint 不可用时，未完成推进涉及的全部指令继续参与新尝试，不能只取最近几条消息，也不要求用户重新提交已受理指令。

上述受理与消费保证是行为契约，优先复用既有框架的持久化和恢复能力，harness 负责宿主记录与 checkpoint 的确认衔接。当前实施变更已选择同步 durability、saver 保存后幂等确认及确认丢失后的核对补确认，具体接线见[实施设计](../../../openspec/changes/migrate-runtime-architecture/design.md#7-私有-checkpoint指令确认和正常跨轮)。[调查记录](../../../openspec/changes/migrate-runtime-architecture/investigation.md#checkpoint-保存后确认消费能否使用现有框架)中的局部实验验证了保存后确认顺序及失败时阻止后继模型步骤；真实磁盘、IPC、进程中断和完整产品图的保证仍须通过该变更的故障验证。

### Q5：工具收据先保存，未知副作用先核查

复用 harness 已有工具收据机制：工具执行前，宿主侧先保存调用身份、所属执行尝试和必要核查参数；保存失败则不开始操作。工具返回后，先持久保存实际结果或结果引用，再交给执行图继续。具体结果内容、有界预览和大结果引用沿共同工具契约，不把界面预览截断内容当作完整恢复结果。该顺序保障当前执行及其内部恢复，不要求复制为独立业务台账或永久留存，沿 Q10。

恢复遇到同一调用时，已有确认结果可复用，实际效果未知则先查所属模块或产物，不直接重放。文件已保存而关联未完成时只补关联，保留文件及已确认部分；工具收据不替代领域事实，也不承诺外部副作用恰好执行一次。

历史读取结果可用于还原经过，后续修改仍须重读当前材料。恢复执行不凭旧读取结果覆盖当前内容，不把图恢复成功或工具函数返回等同于科研交付成立。

### Q6：正常跨轮保留会话有效上下文

正常一轮回复结束后，再发送消息保留该 session 的有效工作上下文，包括对话、工具结果、已形成摘要及必要工作状态。不能仅因一轮回复结束就只取最近几条聊天记录重新开始；关闭界面后再打开同样如此。

在会话仍保留时，上下文过长允许压缩，保留的原始历史可查询；交互中当前目标、用户约束和未完成事项需要保留，其业务内容同时沿各自事实源保存。正常跨轮接续与异常资料缺失后的回退分别处理；Q3 的每尝试私有 checkpoint 不能成为丢弃有效上下文的理由，也不将保留会话升级为工作推进的前提。

### Q7：异常后在原会话说明缺失并接续

保留中的会话异常后优先恢复已有交互上下文，确实无法恢复时说明缺失。工作推进及接续从工作区、材料和所属领域／运行记录取得必要事实；仍可用的会话消息和摘要可以帮助恢复交流，但不能成为业务续做的唯一依据。会话丢失或主动丢弃后，其他会话也应能从同一事实源开展工作，不要求用户恢复旧会话或操作恢复按钮。

某次写入是否完成无法确认时，系统先核查；无法核查则说明具体障碍，只暂停依赖它的部分。用户新发消息始终决定当前方向，不在纳入新要求前无条件重放旧工作。该回退允许部分临时上下文丢失，不能把同一会话身份当作完整恢复全部状态的证明。

### Q8：结果到达交给 Agent 判断

后台计算或子执行的结果作为输入交给负责的 Agent，由 Agent 结合当前目标、结果、最新指令和有效授权判断继续、调整、等待或结束，不由系统仅凭结果到达就决定业务推进。harness 负责结果保存、投递及有界唤醒，沿已有资源限制和用户停止意图；用户明确停止后不因迟到结果自动重新开工。关闭界面与停止会话工作分别表达。

### Q9：会话随项目保存，工作独立于会话

用户同意项目会话随项目保存，同时明确会话可用完即弃，不作为重要资产或工作推进的必要条件。不能把会话历史、会话摘要或 checkpoint 的长期保存设为成果留存、换会话工作或研究接续的前提，也不要求用户为保住工作先备份或导出旧会话。

备份与保护的重点继续是持久工作材料、领域事实、成果及必要执行记录；会话留存本身不代替这些事实源。未知操作效果、已受理的独立工作等优先查询所属模块已有状态与实际结果，范围沿 Q10；本轮没有授权删除任何实际数据或新增会话删除功能。

### Q10：复用已有状态与实际结果，不建通用工具调用台账

工作接续直接使用所属模块已有事实和实际成果：读取材料可以重读；文件或题录修改核对当前内容及所属模块已有结果；后台计算查询已有受管执行状态和产物。不为海量 tool call 另建一套通用操作台账。

Q5 的 harness 工具收据继续服务交互、诊断及内部恢复，不复制为另一套业务账本，也不要求永久保存才能续做。会话丢弃后允许失去逐步还原旧执行的能力，后续工作从持久材料、所属模块状态和实际成果接上；业务必需内容在形成时保存，不能等到丢弃会话才补录。

所属模块已有状态和实际结果不足以核实某次操作的效果时，报告未知并暂停依赖它的重试，不盲目重新执行；独立工作仍可继续。此限制不推导为所有工具新增永久日志的要求。

### Q11：上下文丢失与必要存储故障分别处理

会话上下文或内部快照不可用时，必要工作事实完整则由 Agent 从工作区重新取得材料，判断如何接上工作。必要工作记录或操作安全记录无法保存时，停止依赖它的新操作，报告实际障碍，不能继续产生无法核查的修改。

某个范围受影响时，其他独立工作仍可继续，不将局部故障扩大为整个应用不可用。内部机制给出真实状态，Agent 据此判断后续；用户仍通过会话交流，不需要操作恢复接口。该规则不要求为全部工具调用另建台账，必要状态沿所属模块已有职责与契约保存。

## Question

模块调用、执行进程与宿主通信、平台能力调用、兼容宿主通信，以及工作台／CLI 到应用入口的协议如何组织，才能共用领域契约而不混淆权限、进程生命周期或客户端职责？

遵守[模块依赖票](01-module-dependencies-and-authority.md)确定的统一 broker 约束：跨模块动作由 broker 管理与路由。明确 broker 的接口、契约注册和宿主接入方式，以及未来提取独立产品时需要保留或替换的部分；不默认把统一逻辑入口实现为独立服务。

契约 SSOT、依赖守卫、类型化注册和实现符合性沿[已确认约束](01-module-dependencies-and-authority.md#架构策略与依赖守卫q8)。本票细化同一契约如何跨传输承载、发现能力及报告版本不兼容；不为每种传输再建领域 DTO 或另立校验事实源。

运行时违约沿[局部处置规则](01-module-dependencies-and-authority.md#运行时违约处置q12)：隔离相关注册、能力或调用的失败，保留其他独立能力；效果未知先核查。本票据此细化连接与传输行为，不将不合约回包等同于操作未发生。

对已确认拓扑中的每条连线，明确调用方、提供方、可信身份、允许操作、传输与 schema 归属。比较 broker 适配使用直接函数调用、Node IPC／消息通道、stdio 和既有 WebSocket 的位置；进程内调用是否需要序列化，以实际用途决定。明确内部接口与跨端 DTO 的关系，复用现有 packages/protocol、packages/client 的适当职责。

讨论请求与稳定执行身份、受理／消费／结果、取消与超时、流式更新与持久消息、积压与背压、重连、错误、版本协商及诊断。执行进程不能通过自报权限获得领域能力。跨会话业务通信与底层 IPC、客户端通知缓冲分别表达，避免将传输可靠性当作副作用恰好执行一次。

## Answer

2026-10-18，用户确认 Q1–Q8，覆盖通信承载、入口职责、数据、调度、积压及兼容与操作语义。以下为目标契约，broker 和公共双向 RPC 尚未实施，不能以本文或静态检查代替运行验证。

### Q1：按调用位置选择承载，共用领域契约与跨进程 RPC 机制

同一进程内的跨模块操作经 broker 直接调用受契约约束的类型化异步接口，不要求先编码为 JSON 或绕行网络，授权与领域检查仍按既有职责执行。模块内部函数和普通共享库依赖继续沿原边界处理。

跨进程复用已有 JSON-RPC 请求、响应与通知结构，形成共享的双向调用机制，由实际传输适配接入同一 broker。工作台／CLI 到内核继续使用 JSON-RPC 与 WebSocket，远端由 SSH 隧道承载；内部通道位置沿 Q3。

领域参数、结果、事件、错误和交互语义沿提供方维护的同源契约，传输适配不另写一套业务 DTO 或改写副作用语义。共享机制是待实施目标，不能把当前客户端及服务端的局部处理当作已完成内部 RPC。

### Q2：共用机制，按入口角色分别注册操作

共同通信机制不表示全部连接都能调用相同方法。宿主按接入角色注册操作与范围：工作台／CLI 使用产品入口；内部执行通道承载执行控制及获准能力调用。入口绑定可信角色、执行实例和可用范围，不接受调用者通过自报字段取得内部控制权。

同一领域操作继续由所属模块核对有效授权；内部心跳、上下文注入等控制不因共用 JSON-RPC 就成为工作台或普通插件的可调用业务接口。用户仍管理 Agent session，通过发送消息推进工作，不新增必须管理的进程或恢复对象。

### Q3：Node 子进程使用 IPC，Zotero 插件兼容宿主复用回环 WebSocket

| 路径 | 承载方式 |
| --- | --- |
| 应用宿主与自有 Node Agent／计算子进程 | 独立 Node IPC 通道，协议与标准输出／错误日志分开 |
| 应用宿主与 Zotero 插件兼容宿主 | 受认证的回环 WebSocket，绑定内部角色、宿主及实例范围 |
| Zotero 插件兼容宿主的主进程与内部页面 | Electron 窄 IPC／MessagePort 适配，共用相应契约与调用机制 |

这里的 Zotero 插件兼容宿主是此前确定的独立 Electron 应用，为原包插件提供 Node 与 Chromium 环境；表中第二条由其 Electron main 接入应用宿主，第三条才是其内部页面桥。不能把 ipcRenderer 或 utilityProcess 当作独立 Node 应用宿主的入口。

普通 Python、编译器等外部程序仍由公共受管执行能力管理输入、输出及实际状态，不强制实现 RPC。本轮不增加通用 stdio RPC 入口；插件自身 MCP 传输继续沿既有插件契约，不由本选择改写。Node 消息发送、WebSocket 接入及 Electron 桥的真实三平台行为仍须实施验证。

### Q4：跨进程传契约数据与受控资源引用

跨进程参数、结果和事件使用受 schema 约束的数据及有范围、归属与生命周期的资源引用，数据库连接、SDK 实例、进程内函数等留在所属进程。可信上下文在入口重建，不把整个进程内 CallContext 序列化给对端，也不凭引用字符串授予访问权。

小结果可在大小限制内随 RPC 返回；大文件、二进制和长内容通过所属模块已有的有界读取／传输接口取得，不将完整材料塞入每条控制消息或另建全量文件复制总线。传输适配可按实际能力优化字节承载，但不能改变领域权威、访问范围与对象身份；具体大小、分块及资源失效行为由相应实施规格验证。

### Q5：双向调用交错处理，等待不阻塞必要回调

连接可以同时关联多个请求、响应及反向请求，不等一个请求全部完成才接收或调度下一条消息。例如应用宿主等待 Zotero 插件兼容宿主导出时，兼容宿主请求读取文献的调用仍可到达所属模块并取得结果。

等待对端时，不占住对方回调所需的锁、事务或调度名额，避免循环等待；并发仍有界。会话内串行、单文件保存及领域事务保护继续沿各自契约，不将通道可并发等同于任意业务动作可并行修改同一对象。必要控制与响应不排在长业务调用完成之后才处理。

### Q6：消息与在途工作有界，超载在新工作受理前处置

限制每连接的消息大小、在途请求数及待发送队列，结合应用级资源控制约束总负载；容量不足时，在新工作受理前返回可诊断的繁忙或资源限制。普通业务流量不能耗尽响应、取消及健康检查所需的处理能力，不能用无界排队换取表面受理。

进度合并与订阅重新同步沿已有有界投影规则，追加内容不能无说明地丢失。已受理指令、实际结果及正式待处理事项沿所属持久状态查询，不以消息送达作为唯一事实源；无法确认实际效果时保留未知。单个慢连接或受影响能力局部处置，不扩大为整个 broker 的无界等待或全局重启。

请求超时只结束本次等待，不等于取消业务工作或证明副作用未发生；明确取消、停止确认、旧实例及迟到结果沿进程与持久化决议。并发上限、队列容量、处理优先级及实际资源保护在实施中验证，不在本票猜测参数。

### Q7：按协议版本与角色可用接口判断兼容

连接接入核对可信身份、目标实例与协议版本，按角色报告由同源契约及实际注册产生的可用接口。应用版本号不必完全相同；首阶段支持当前协议版本，不承诺任意跨协议版本兼容，也不通过试探性业务写入判断是否兼容。

缺少可选接口只限制依赖它的功能，不扩大为无关能力不可用。协议不兼容时明确拒绝该连接，显示实际原因，不反复认证或自动替换已有实例；升级时机继续沿远端部署决议。可用接口信息只用于接入与发现，不取代调用时的有效授权检查；具体握手字段、版本策略及发现入口由实施规格确定。

### Q8：副作用、返回模式与等待策略沿同源契约

接口契约同时描述操作是否可能产生业务副作用、返回实际结果还是已受理的稳定引用，以及相应等待策略。客户端与内部 RPC 从同一声明取得处理规则，不各自维护只读方法名单与业务特殊分支。具体时长和限额按配置及验证结果确定，不能仅凭方法名或超时推定操作未发生。

短操作等待实际结果；长工作受理后返回稳定引用，再经查询或订阅取得状态。RPC 请求编号只关联本次往返，不能替代指令、执行、协作请求或领域操作的稳定身份；发送成功、消息被读取、消费确认及科研完成仍分别表达。错误保留结构化类别、相关引用与实际可核查状态，效果未知先核查，不从可重试提示推导副作用可盲目重放。

这些是接口定义上的规则，不为逐次调用另建通用台账。已受理指令、工具结果、协作收件与领域工作仍按所属模块现有职责保存；会话可丢弃、工作沿持久材料接续的边界不变。

### 代表路径语义核对

| 路径 | 调用与结果规则 |
| --- | --- |
| Agent 工具保存文件 | 当前有效执行实例经 Node IPC 接入受限 broker，由所属文件能力核对授权和当前内容后保存。结果先按已有工具收据及领域职责保存，再回到执行；断线或超时后查询实际结果，文件成功但关联失败时只补关联，旧实例迟到结果不覆盖新状态 |

| SSH 远端重连 | 工作台重建 SSH 承载和 WebSocket 后核对身份、实例、协议及可用接口，查询实际状态并恢复范围订阅。未知请求按原稳定身份核查，草稿保留，新业务指令不自动补发；不因重连启动重复写者或强停共享内核 |

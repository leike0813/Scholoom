## Question

工作台位于客户机、科研内核位于远程工作机时，文献库、项目、Agent 执行、平台能力、模型凭据、Zotero 兼容宿主和插件分别运行或保存在何处？SSH 只承载连接还是也负责发现、启动与部署，断线及重连如何处理？

比较明确的部署情境：全部本机；远端同时持有库与项目；本机库和远端项目分布。每种候选核对路径含义、目录选择、材料读取与外发、附件传输、编辑与预览、凭据驻留与授权、兼容宿主显示条件及离线行为。是否支持各情境由用户选择，不把纳入讨论视作全部承诺。

需要区分远端真实资源、本机缓存或投影与复制材料；如果出现复制，明确归属与更新语义。保持现有本机运行目录的文件系统约束，不能将 SSH 连接等同于直接把锁文件或 SQLite 放在网络挂载上。

## Answer

2026-10-18，用户确认 Q1–Q9；以下为已定的部署目标与限制，具体 SSH、分发、资源及恢复接线由后续 OpenSpec 变更落实，不代表已实现或实跑验证。

### Q1：支持全部本机与远端完整运行环境

支持两种部署情境：A 为工作台、文献库、项目及 Agent 全部本机运行；B 为工作台位于客户机，通过 SSH 接入工作机，文献库、项目与 Agent 执行均在工作机，断开客户端连接后已受理的远端工作仍可继续。

本机库与远端项目同时协作，以及仅将计算程序交给远端执行，本轮后置，不纳入当前支持契约。每套运行环境继续保持自己的共同数据权威，不为远程连接额外引入跨机同步与分布式工作组织。SSH 准备及模型凭据沿 Q2–Q3，兼容宿主运行条件沿 Q4。

### Q2：工作台负责远端准备、内核接入与 SSH 隧道

用户选择 SSH 主机，工作台检查并准备匹配的远端运行组件，发现或启动所选配置的内核并建立隧道，不要求用户手工维持端口转发。内核只监听工作机回环地址，远程连接经 SSH 承载。

同一远端配置沿已有单实例规则复用，不能因连接失败就强行替换已有内核。版本不兼容、活动工作与升级时机沿 Q7，安装范围沿 Q8，组件下载与准备沿 Q9；具体分发方式在实施中验证，不据此授权当前会话安装或升级任何组件。

### Q3：模型配置、凭据与调用随运行环境

远端运行环境的模型配置与 API Key 保存在远端，模型请求也从远端发出。用户可通过工作台设置，经已认证的连接提交配置；远端秘密按凭据模块的保护与不回读规则处理，不成为客户端显示或普通诊断内容。

本机与远端模型配置独立，不自动复制 Key；SSH 登录凭据继续留在客户机。配置入口不改变领域与材料授权，跨机传输材料及发送到模型的行为仍按各自授权处理。

### Q4：远端核心支持无桌面服务器，插件按能力检查条件

远端核心无需先打开远程桌面即可运行。远端兼容目标为 Windows／macOS／Linux，优先验证 Linux；三平台及各平台的具体运行条件以真实分发与验收结果为准，不能用本机通过代替远端验证。

Zotero 兼容宿主和插件也部署在远端，按所需运行依赖与显示条件检查、按需启用。不满足条件时明确报告该能力不可用，其他工作照常进行，不将插件移到客户机以绕过部署约定。“无需打开工作台”与“不需要任何图形运行依赖”分别核对，现有原型证据不构成无桌面下全部插件可用的承诺。

### Q5：远端保存、本机交互，材料明确传入传出

远端项目通过远端目录浏览选择，路径在资源所属端解释，不能将客户机系统选择器返回的路径直接用作远端路径。编辑、阅读及预览展示在本机工作台进行，文件保存与工程编译发生在远端；工作台按需取得展示内容，远端文件与所属模块记录继续掌握权威。本机缓存服务展示，不成为另一份当前事实。

本机材料经明确上传／导入成为远端副本，成果经下载／导出取得本机副本；不自动同步两端目录，不因连接远端就自动转移本机库。传输、领域写入及模型外发分别遵守既有授权，副本保留所属材料与来源关系，不暗中宣称与原文件持续同步。

沿已有本机文件系统约束，运行配置、锁及 SQLite 由工作机本机文件系统承载；SSH 提供连接与受控传输，不将网络挂载等同于本机存储，也不改变既有文件并发与保存保护。

### Q6：断线保留草稿，重连先核查实际状态

断线期间保留已打开内容与本机草稿，允许继续编辑草稿，但不能显示为远端已保存。新指令暂留草稿，不自动排队新的业务指令或修改等待重连后执行；该规则不阻止 SSH 连接自身的有界重试。

重连成功后先查询远端实际状态、结果及待处理事项，不以本机旧画面推定当前事实。发送结果未知的请求按原稳定身份查询与核查，不另造身份盲目重发；文件保存重新核对当前内容，冲突时保留草稿并沿现有重读规则处理。

远端已受理工作继续沿 Q1，网络断线不等同于取消或停机成功；用户明确停止后不因重连自动启动工作。系统确认远端内核退出、无法确认退出、认证或版本错误时，分别沿既有生命周期与恢复契约处理，不因重连另起重复写者。草稿和未确认输入按所选环境及对象隔离，不跨本机与远端误投。

### Q7：兼容时复用，升级由用户选择时机

与当前工作台兼容时直接复用已有远端内核，不因存在更新就强制升级。不兼容时说明原因，由用户选择升级时机；沿已有发布规则保存编辑，等待受影响工作结束，或由用户选择停止后再升级，不能为了当前工作台接入强停共享内核或静默迁移数据。

更新影响同一内核的其他客户端与工作，不将关闭单个工作台等同于后台已停止。数据迁移、恢复副本及保护后续成果沿既有存储和发布约束；具体安装切换与兼容版本范围由后续实施规格核实。

### Q8：复用既有 SSH 接入，组件限定到远端用户目录

复用客户机既有 SSH 配置、密钥与认证代理，沿用标准主机身份校验，不另建一套登录凭据管理，也不将客户机登录凭据转交远端。具体 SSH 适配、支持选项与诊断在实施时核对。

Scholoom 组件安装到远端当前用户的受管目录，不自动提权或改动系统环境；系统依赖不足时明确报告缺项，已有环境与新增工程依赖继续沿既有环境授权规则处理。当前票只记录产品契约，不执行实际安装。

### Q9：复用兼容组件，远端下载失败后本机传包

先复用远端已有的兼容组件；缺失时默认由远端下载，下载失败后由客户机下载目标平台的运行包并经 SSH 上传。允许按主机强制本机传包，以免受限网络反复尝试远端下载。参考依据见[VS Code 与 Zed 调查](../research/ssh-server-bootstrap-reference.md)，选择其引导方式，不照搬其版本号、安装目录或自动更新策略。

运行包匹配工作机的平台、架构与所需兼容版本，不把客户机可执行文件直接用作远端产物。升级及迁移时机继续沿 Q7；切换下载路径不解决权限、平台不支持、解压及启动失败等其他问题，应报告实际原因，不以回退成功宣称运行环境已全部就绪。

本机可取得组件时，远端无需能够直接访问组件下载站；双方均无法取得缺失组件时如实报告缺包。组件安装与后续运行的网络条件分别核对：模型、插件与额外科研依赖仍取决于各自实际网络及环境准备，不承诺所有科研工作完全离线。具体包拆分、缓存、下载和上传机制在实施规格中验证，不另设新的包管理权威。

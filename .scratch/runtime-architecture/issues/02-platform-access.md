## Question

如何让自有代码的 OS／文件系统访问统一经过平台模块，隐藏跨平台差异，同时保留领域模块对保存规则、授权和数据归属的控制？第三方依赖通过什么适配获得和使用本机资源？

模块调用遵守[模块依赖票](01-module-dependencies-and-authority.md)中的统一 broker 约束。用户已明确文献管理、人工编辑、预览和编译可在没有 harness 时使用；本票需要据此界定可独立使用的文件、渲染和程序执行基础能力，避免平台模块反向依赖 harness。

需要确定能力分组与契约：路径与文件身份、读取和枚举、受保护保存与权限、锁、监视、临时目录、进程与进程树、运行时发现、桌面系统集成，以及这些能力在 Node、Electron 和浏览器中的可用位置。统一模块的逻辑入口不预设为一个大对象或同一物理实现。

区分平台提供的机制和领域定义的行为，例如原子保存机制与“内容已变化应重读”的业务规则。核对 SQLite、LangGraph checkpoint、PDF 解析器、插件与受管程序的直接访问范围，明确适配器职责、错误、取消和诊断；受管程序的系统访问与应用代码的入口规则分别说明。SSH 场景由远程部署票确定资源所在主机，本票提供可承接的能力边界。

## Answer

用户已确认 Q1–Q8，覆盖平台机制、资源范围、条件保存、第三方原生适配、宿主能力、资源生命周期、保证与错误及系统访问范围。以下是设计结论；平台模块、broker 接线和对应守卫尚未实现或实跑验证。具体进程拓扑、SSH 部署和传输细节继续由后续票决定。

### 平台机制与业务规则（Q1）

平台提供 OS／文件系统访问机制，按文件与目录、受保护保存、权限与锁、进程及进程树、环境与系统目录、宿主系统集成等能力分组；统一入口不要求一个包揽业务的大对象。

文献的存储规则、编辑冲突含义、Quarto／TeX 编译流程与 PDF 解析归各自模块或适配器，跨模块经 broker 使用平台机制。人工预览与编译所需能力独立于 harness，科研运行时使用同一基础能力。复用已有成熟机制，领域授权和平台的系统范围检查分别执行。

### 有明确范围的文件能力（Q2）

普通模块使用宿主已绑定的资源范围和范围内位置访问文件，平台核对真实路径、符号链接与访问范围；领域模块继续决定业务授权和保存规则。路径本身不授予权限。本机绝对路径用于可信的选择、导入、启动配置等接入，不能直接成为普通模块或 Agent 任意访问本机资源的通道。

资源引用在其实际所在执行端解释；不将未来远端路径当作工作台本机路径。资源绑定与领域身份分别表达，文献身份、项目身份和 fileId 仍由所属领域维护。本票不提前确定 SSH 部署或精确 DTO。

### 有界条件保存（Q3）

平台提供在实际资源执行端完成的有界条件保存与串行协调：重新定位、核对条件和写入作为一个受保护操作完成，避免经 broker 拆成独立的读取、核对和写入后引入新的竞态。领域模块决定提交什么依据、冲突的业务含义及历史留存。

协调仅覆盖应用经该入口发起的操作，不锁住外部编辑器或获授权程序，也不承诺文件与数据库的通用事务。保留现有内容变化重读、目标身份核对与结果未知核查等行为，不通过抽取退化既有保护。

### 第三方原生资源适配（Q4）

能接收文件接口或字节的依赖复用平台能力；必须使用原生路径或句柄的依赖放入受控适配器，明确资源范围、读写方式及释放责任。SQL、事务和解析规则仍归所属模块，不因为原生访问需求而集中进平台业务层。对外不暴露数据库连接或原生句柄。

SQLite 当前的原生文件路径与 PDF 文档的内存输入分别适配；运行资源如 WASM 的加载同样有明确范围。不要求拦截第三方库的每次系统调用，不以适配器声明承诺任意本机代码的强隔离。

### 宿主适配（Q5）

通过共同契约注册实际可用的宿主适配：Node 提供文件和进程能力，Electron 提供原生目录选择等桌面能力，浏览器提供自身可用能力。普通业务模块不导入 Electron 或自行判断操作系统。

能力缺失明确报告，由上层选择替代路径，例如浏览器使用内核目录浏览。实际动作在能力及资源所在执行端解释，不按工作台所在宿主猜测文件位置；本机／远程部署的具体选择仍沿远程票。

### 资源生命周期与取消（Q6）

临时文件句柄随操作结束释放，成功和失败路径都履行收尾；监听、流、数据库适配和受管进程明确归属到持有它们的模块或执行，由对应生命周期关闭、取消或回收。作用域、原生适配及资源的释放责任必须能从契约与注册关系中查明，不能依赖调用者猜测。

工作台连接与后台工作生命周期分别表达，断线不自动取消后台任务。取消按实际完成情况报告，不表示已经撤销写入；无法确认效果时保留结果未知，核查实际内容再继续。取消和进程树收尾的具体执行单元及监督方式沿[进程票](03-session-execution-processes.md)，不将关闭一个网络请求直接等同于已停止所有相关执行。

### 跨平台保证与错误（Q7）

共同契约明确能力必须满足的保证，例如不覆盖已有文件、条件保存、确认进程退出。提供者按其实际能力履行保证；不能提供必要保证时明确报告不支持或不可用，由上层选择替代路径，不静默降低保证。

错误使用共同语义分类，并保留有界的平台诊断。文件不存在、权限不足、目标变化、资源暂不可用、不支持及实际效果未知分别表达，不把系统错误全部归为冲突或统一自动重试。精确错误码沿共同契约确定，不在平台另建平行错误类型事实源。

原子替换、持久落盘、内部互斥、外部进程退出是不同保证；某项成功不替代其他项。文件监听沿既有开放编辑契约作为变化线索，不宣称观察到每次修改或排除外部写入。

### 系统访问覆盖范围（Q8）

自有代码的网络连接、环境读取、系统目录、私有存储／系统凭据和桌面／浏览器宿主能力也通过平台或受控宿主适配收口。模型接收方政策、密钥选择及领域授权仍由所属模块维护，系统设施不取得这些业务规则的权威。

纯路径计算、编码、JSON、哈希等普通计算继续使用共享库，无需 broker。真实路径解析、文件元数据读取及其他系统资源操作仍通过平台能力；不能借纯计算工具包装新的系统访问绕行。

| 能力族 | 平台或宿主适配提供 | 保留在所属模块的职责 |
| --- | --- | --- |
| 文件、目录及变更线索 | 有界读取与枚举、路径范围检查、条件保存、临时资源、监听与权限机制 | 文献／项目身份、编辑依据、历史、材料版本与保存规则 |
| 锁与私有资源 | OS 权限、排他机制和受保护保存，明确实际保证 | 哪个库、运行配置或业务操作需要持有何种保护 |
| 程序、Worker 与进程 | 系统启动、状态、输出与终止所需机制 | 编译及解析流程、Agent 调度、执行单元和监督决策 |
| 网络与环境 | 连接、运行环境、系统目录及宿主资源访问机制 | 模型接收方、联网授权、请求业务语义和配置选择 |
| 私有存储与系统凭据 | 对应宿主的受保护存储及系统凭据设施 | 凭据选择、模型配置和材料外发规则 |
| 桌面与浏览器能力 | 原生选择框、外链等系统集成，以及实际可用的浏览器宿主能力 | 用户交互、草稿归属和缺失能力后的显式替代流程 |

表中能力族是接口组织，不预定一个包对应一个进程，也不要求增加未使用的 OS 操作。各操作的请求、结果、事件及必要保证归其同源契约；读取量、队列和输出有界，实际限制沿调用需求与验证确定。

### 初始化、凭据与适配边界核对

初始化沿前票已确认的宿主装配职责：宿主创建平台适配和 broker，完成资源及能力绑定，普通模块的运行时跨模块操作随后经 broker。初始化阶段所需系统访问收在明确的宿主／平台适配职责内，不据此放开业务模块直接调用 OS；具体初始化顺序由实际依赖落实，避免以 broker 路由请求创建 broker 自身的循环。

凭据的系统存储、权限和环境访问由受控适配执行，凭据与模型模块继续选择所需配置。结合前票的消费范围控制，普通模块不因能调用平台就获得全部环境、凭据或任意路径；对外保留当前不回读密钥、不通过普通诊断暴露秘密的契约。此处核对已有授权及适配职责，不改变原凭据保存政策。

原生适配内部的路径／句柄只服务其已登记资源。第三方原生访问可能在平台的文件协调之外，不能因此把应用内串行保存描述为覆盖数据库驱动、外部编辑器和任意程序的全局互斥。数据库并发和文件／数据库恢复继续沿所属契约及[持久化票](04-execution-persistence-and-recovery.md)。

### 依赖守卫与独立验证

沿[模块依赖决议](01-module-dependencies-and-authority.md#架构策略与依赖守卫q8)，统一架构策略限定哪些平台／宿主／原生适配可以直接使用文件、进程、网络、环境和宿主系统接口，以及它们提供、消费的能力。普通模块只依赖所需契约和 broker 接入；检查静态、类型及可分析动态引用，防止引入直接系统访问、越界原生适配或反向依赖。允许原生访问的位置、用途和资源范围需明确，不以整包豁免替代受控适配。

新边界即时启用守卫，旧代码按已确认的分批迁入及受限例外规则处理；守卫以真实越界样例验证，不用精确文案或源文件片段匹配证明架构符合。具体工具与规则实现进入 OpenSpec，不在此承诺现有 lint 已经覆盖。

优先复用现有项目文件、文献附件、PDF、凭据和生命周期测试，只补未覆盖的稳定行为边界。替身可用于错误注入与模块独立验证，OS 权限、文件替换及进程退出等保证须在真实目标环境核对。Linux 通过、模拟 Windows 分支或代码阅读不表示三平台通过。

| 代表路径 | 契约与职责核对 | 实施时需要的证据 |
| --- | --- | --- |
| 人与 Agent 竞争保存文件 | 同一领域规则提交条件，由资源端完成串行核对和写入；内容变化重读，未知效果先核查 | 实际临时文件系统上的竞争、路径／身份变化、不覆盖新目标和写入结果核查 |
| 读取或保存凭据 | 平台／宿主设施处理权限和系统访问，凭据模块决定选择，调用受范围与授权约束 | 目标 OS 的私有权限／ACL、损坏保护和受限诊断 |
| 停止受管程序 | 持有资源的模块／执行发起停止，平台报告实际状态，不把请求结束当作进程退出 | 自有进程及进程树的真实退出、超时和状态未知；具体监督由进程票确定 |
| SQLite 与 PDF 原生适配 | SQLite 通过受控原生路径适配，PDF 可使用材料字节，依赖资源在适配内持有和释放 | 实际驱动／解析器的打开、失败与关闭，以及受控路径和运行资源读取 |
| 浏览器与 Electron 使用同一业务 | 各宿主只注册真实能力，不可用明确报告；人和 Agent 共用领域操作 | 双宿主真实接线及目录选择／替代浏览的差异验证 |

### 本票边界与后续

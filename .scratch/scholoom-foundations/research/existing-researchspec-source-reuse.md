## 跨候选的三条横向事实

**存在多种局部写入机制，没有据此证明全项目崩溃安全。** `write-plan.ts` 以预检、临时文件、备份及异常回滚处理一组文件；评审源复制使用 `wx`，Python 文稿管线使用自己的 `os.replace`。它们可以提供实现和测试素材，但不能直接充当 Scholoom 统一 Change、应用事实与恢复机制的已完成实现。来源哈希用于定位或冲突检测，也不构成授权或操作系统隔离。

**可复用模块与 CLI 之间是干净的单向依赖，但与工作区布局不是。** 第 1、3、4、5、6、8 项所涉模块对 `src/cli/**` 零 import（已 grep 确认）；而第 7 项 `graph-run.ts` 通过 `GraphWorkspaceIndex` 与 `researchspec/` 目录结构强绑定，`STABLE_SPEC_PATHS`（`capabilities/registry.ts:214-219`）更是把四个稳定规格路径硬编码为 `researchspec/specs/*`。这两类不能用同一种方式取用。

**能力校验器接口与实现语言解耦，这是最省成本的一处。** `runCapabilityValidators` 只要求 manifest 声明 `argv0` 与参数模板，实际执行体可以是 Python、Node 或任何可执行程序。Scholoom 的 Skill + YAML 声明 JSONSchema 若要保留「交付检查可执行」这一属性，接入点是这个接口形状，而不是那些 Python 脚本。

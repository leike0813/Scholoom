# Scholoom 原插件宿主：验证范围与收敛记录

关联票：[16](../issues/16-zotero-host-prototype.md)。2026-10-04 用户结束原型并确认 Node＋Chromium 通用兼容层，从固定 Zotero 10 基线开始，开发时以重要插件推动适配，不承诺全部插件无缝运行。正式决定集中保存在票的 Answer 中，本票已 resolved。本文保留已有证据和范围约束，未执行项目不构成兼容结论，也不作为继续本原型的待办。

[第四轮实验](zotero-host-boundary-results.md)已执行“兼容宿主维护库、共同接口供两端使用”的代表性链路，结果为 9 项主链路与 5 项第二客户端检查通过；其他候选和正式工作台仍待取证。

[第五轮实验](zotero-host-reader-results.md)已执行自己的 PDF 阅读视图与书签写回：真实页面导航、界面改名、能力侧重读和原 Reader 重开通过；原插件保存仍需原 Reader DOM。该证据支持分开呈现，并明确保留内部写入 UI 的成本，不构成正式阅读组件或独立分发选择。

[第六轮实验](zotero-host-restart-results.md)已执行真实 Electron 接入与正常重启，但后台始终是完整 Zotero。它证明外部调用与工作台接入，不证明 Scholoom 已建立独立兼容宿主；前六轮证据不足以选择独立宿主路线。用户明确指出该套壳方向偏离目标。

[独立最小宿主实验](zotero-host-minimal-results.md)随后完成：Node 执行未修改的 BBT 原 bootstrap／主包，独立 SQLite 题录提供对象和只读 SQL 视图；原 Worker 使用 Chromium 原生 IndexedDB，引用键生成／保留和实际 BibTeX 导出通过。纯 Node 对照在 IndexedDB 初始化失败。这是限定 BBT 业务的独立兼容证据，尚不覆盖茉莉花或整体路线。

[独立宿主变更实验](zotero-host-mutation-results.md)进一步完成：题录保存后的 modify 通知经原 BBT 监听器更新缓存，导出当前标题／DOI／作者；屏蔽通知的对照确实导出旧数据。茉莉花原主包在工具包构造的 Prompt DOM 初始化失败，未进入 onStartup 或元数据业务。未运行完整 Zotero。

[原生 DOM 实验](zotero-host-native-dom-results.md)随后通过：原茉莉花在 Chromium 页面完成 Prompt 初始化和 onStartup，新增通知触发原作者拆分并保存到同一 SQLite，BBT 实际导出新作者；关闭偏好的对照保持原样。在线元数据、附件和 Reader 尚未覆盖。

[元数据任务实验](zotero-host-metadata-results.md)进一步通过：合成 HTTP 输入下，原茉莉花实际搜索／筛选，原 RIS 请求 ID 未注册后由原插件回退建项，并关联原 PDF；原 BBT 导出同一题录及附件路径。无结果对照不建项，正确注册 ID 的官方 RIS 独立导入对照通过。未验收真实在线服务、下载或 Reader。

## 已确认的选择与产品前提

选择 Node＋Chromium，建设固定 Zotero 10 基线的通用宿主契约，适配接入 Scholoom 的文献权威。重要插件作为开发优先次序及验收样本；完整 Zotero 保留为功能对照，参考宿主中通过的检查数量不作独立路线的兼容承诺。

已确认目标来自[产品定位](../issues/01-first-product-loop.md)、[兼容策略](../issues/05-zotero-compatibility-policy.md)和[存储职责](../issues/13-storage-and-change-model.md)：

- 用户使用独立 Scholoom，无需另行安装或启动 Zotero；科研内核可以在工作台未打开时执行，工作台随后接入。
- 指定版本 BBT、茉莉花原包及代码保持不变，Scholoom 承担宿主适配，可以用自己的界面呈现功能、配置和结果。
- Agent 与工作台通过共同领域服务处理结构化事实。文献拥有稳定内部身份，兼容标识通过映射关联；同一题录只有一个当前权威。
- 文献获取、管理、阅读和写作最终均需贯通；#16 只用代表性功能帮助选择宿主，其他功能明确列为待验收。

“未打开工作台”指人类工作台与科研执行可以分开。兼容环境所需的内部窗口、DOM 或进程应记录其产品和维护代价；这些实现条件不能自行升级为产品禁止事项。原包兼容、工作台呈现和独立分发分别取证。

## 原型结束时的验证边界

已实现的独立链路：**实验能力脚本 → Node 宿主兼容接口 → 原 BBT → 独立题录权威 → 原 Worker／translator → 实际产物。** 主包在 Node VM 中执行，Worker 在 Chromium 中执行；没有启动 Zotero 应用。复用一份静态日期资源，接受未实现 UI／事件投递的注册，因此不能承诺整个插件兼容。

题录修改后的通知／缓存更新、茉莉花原生 DOM 初始化、中文作者保存及固定协议输入的元数据建项／PDF 关联已通过。用户依据这些局部证据和 Electron 适配方向选择 Node＋Chromium，不将选择视为全部契约已实现。真实网络、独立 Reader 等缺口转入正式功能实现与验收；本原型不再安排下一轮实验。

| 实验 | 可观察结果 | 对选择的意义 |
| --- | --- | --- |
| BBT 数据变更与缓存（已执行） | modify 通知驱动原包更新，导出新字段；无通知对照保留旧数据。批量／并发／删除仍未验证 | 普通题录的数据变更兼容已有事实，不再把首次导出当作唯一依据 |
| 茉莉花非 Reader 业务（固定输入元数据／PDF 关联已执行） | 原生 DOM、作者处理及原任务回退建项／关联通过；真实在线识别和下载仍未覆盖，RIS ID 差异单独记录 | 判断第二个插件其他承诺功能所需服务及维护代价；现有成功不等于整包兼容 |
| Gecko 辅助宿主（未实施） | 没有裁剪 Gecko 接入独立权威的运行证据 | 曾作为平台／窗口语义复用的候选比较，本次未采用 |

复用现有真实样本和已通过的原插件入口。每次以业务读写与产物帮助决策，直接设置字段或模拟结果不能充当原插件实际更新。工作台展示和完整 Zotero 的正常重启不再是本票下一项默认实验。

## 比较候选边界

| 候选 | 需要补的证据 |
| --- | --- |
| 纯 Node 兼容服务 | 原主包／Worker 已实际执行；缓存缺 IndexedDB，业务失败。进一步实施前需要明确缓存运行时，有限失败不能证明不可行 |
| Node 主宿主加 Chromium Worker／内部 DOM 页面 | 原 BBT 引用键／导出／通知更新，以及原茉莉花 DOM／作者保存、固定 HTTP 输入下原建项回退／PDF 关联通过；真实在线识别、下载、Reader、Electron 嵌入和运行时封装未验证 |
| Gecko 辅助宿主 | 仍未实现裁剪宿主。需要列出实际必须保留的服务并接入独立文献权威，完整 Zotero 实验仅作对照 |
| 独立题录权威与兼容 SQL／对象视图 | 本轮两条题录已经实跑。其他字段、类型、关系、直接 SQL 写入和并发未覆盖，不能扩大为完整 Schema 兼容 |

上表保留选型时的证据边界，宿主路线已选定 Node＋Chromium，正式数据库、Schema 和进程部署仍由后续票落实。比较区分实跑事实、源码推断与未知项；维护代价用已识别的服务、映射及适配工作说明，没有实现的部分不编造量化估算。

## 已执行实验的范围约束

开始前用几句话说明：验证哪个 Scholoom 使用情境、比较哪个候选边界、观察什么结果、该结果会影响哪项选择。结束后先报告这个问题的答案，再链接原始证据。

原插件启动或生命周期错误，只有阻断本次目标链路，或可能改变候选路线判断时才继续隔离。已经能说明依赖或代价的失败应记录并进入比较，不连续扩展为完整 Zotero 启动、无显示环境或卸载修复工程。

只有一次运行才需要的临时对象保留在原型中；不提前建立正式业务架构。依赖安装、Git 操作及环境变更仍遵守用户授权边界。需要 Electron 实机或分发证据时明确列出对应实验，不能由普通 Node 消费者或完整 Zotero 参考环境代替。

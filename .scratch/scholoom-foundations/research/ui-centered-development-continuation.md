# UI 为中心的开发协作：讨论记录与 Windows 续接

记录日期：2026-10-11。用户要求先保存当前讨论，由用户将项目迁到 Windows 后再继续。本记录保存开发协作方向、实验结果及待验证事项，不替代产品决策票或业务实现规格。

## 已确认的方向

- 继续采用 TypeScript／React／Electron，暂不考虑 Rust 路线。Agent Core 维持 LangGraph／LangChain／Deep Agents 原方案，不直接移植 Codex harness；[Codex harness 复用调查](codex-harness-core-reuse.md)保留为参考。
- 这是个人长期项目，优先复用成熟库、组件与项目经验，减少手写和维护负担。已有[复用调查总览](reuse-landscape.md)，具体接入仍需要按功能验证。
- 尝试“UI 为中心”的 Agent 交互式开发：先建立可交互、可观察和可调试的 UI 底座，再通过原型形成对功能与界面表现的共同认识，在实际界面上逐步接入功能、持续迭代。
- 用户认可浏览器注释与 Figma 结合的方向，尚未决定具体接入工具、席位或完整工作流。运行中的原型与设计画布各有用途，不要求每轮修改都经过 Figma。
- 当前停止继续排查 Orca 环境问题；用户自行迁移项目到 Windows，迁移后再恢复讨论。本轮没有执行迁移，也不由此改变应用三平台构建与验收要求。

## 已完成的最小路径实验

当时原型与完整结果见 [Orca UI 路径实验](orca-ui-path-prototype.md)。实验时使用 `?prototype=orca-ui` 与 `OrcaUiPrototype.tsx`；当前共享工作台入口和启动说明见[开发文档](../../../docs/development.md#共享工作台与日常交互)。

原型包含两份示例材料、指令输入、提交时的材料快照、固定示例结果和重置。没有真实模型、文件读取、内核连接或持久化；它验证协作路径，不代表科研功能已实现。

- Orca 能读取页面语义状态、操作输入与按钮、观察控制台及网络，已验证 HMR 保留页面状态。
- 用户发送指令 `1223` 后，Agent 能读取实际结果；用户提交的截图显示正常界面及红色手绘标注，Agent 可以观察该图片。
- Orca 自动截图曾只返回背景，未证明可靠的视觉审查能力；也未验证 Orca 原生注释能否自动被 Agent 读取。用户主动发送图片与工具自动取得注释是两条不同路径。
- Biome、桌面端类型检查、构建和已有 Electron smoke 的选定用例通过，具体命令及验证范围见实验记录；尚未在 Windows 上运行这些检查。

## 远程环境遇到的问题

用户日常从 Windows 主机 `192.168.13.22` 远程开发，Linux 开发主机当时为 `192.168.13.13`。原型服务曾改为监听 `0.0.0.0:5173`，开发主机上的 localhost 与局域网地址请求均成功；用户反馈这仍未解决 Orca 本地浏览器注释的使用问题。服务可达不能证明浏览器已切换到本地模式。

用户考虑过通过 RDP 使用开发机桌面，也发现开发机 Orca 长期运行于 `orca serve` 模式。尚未确认 serve 与 GUI 能否共存、能否从 serve 模式再打开窗口；在图形桌面中启动 serve 不能作为可打开窗口的保证。本轮未停止 serve，用户随后要求先不管 Orca。

以上地址、端口和运行中的服务只描述当时环境，不是 Windows 迁移后的配置，也不保证新会话中仍存活。不能在迁移后直接沿用 Linux 终端 ID、浏览器标签 ID 或进程状态。

## 浏览器注释与 Figma 的取舍

浏览器注释贴近真实运行页面，适合指出具体位置的问题并验证交互、加载、错误状态和修改结果。Figma 的额外价值在于直接编辑目标布局、并排比较方案，以及管理组件、样式、自动布局和设计库；文件链接、评论及版本也便于异步共享。

代价是代码与设计稿需要协调。Code to canvas 可以把运行中的 UI 捕获为可编辑图层，但不保留应用执行逻辑，也不自动持续同步代码变化。仅为反馈某个按钮或局部交互问题而维护一份设计稿，可能增加负担。

主 Agent 的建议是以运行中的 React 原型作为共同底座，用浏览器注释处理日常反馈；出现较大的布局分歧、需要比较设计方案或调整设计规范时，再使用 Figma。用户认可结合方向，具体分工与反馈传递方式留到迁移后验证。

### 费用与 Agent 调用限制

依据 2026-10-11 核查的[官方定价](https://www.figma.com/pricing/)及[MCP 限制](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/)：

- Starter 免费，可用于基础设计、原型、分享和评论；包含无限草稿，团队文件及高级能力受限。
- Professional Full 席位按月付为 20 美元／月，按年付折合 16 美元／月，即 192 美元／年。查看与评论无需额外购买付费席位。
- Starter 的 MCP 读取工具限额为 20 次／月；Professional Full／Dev 为 200 次／天、10 次／分钟。View／Collab 席位在付费计划中仍为 20 次／月，不能把购买任意席位视为增加读取额度。
- 限额针对读取工具调用，并非对话轮数；部分写入工具豁免。手动操作画布与评论不消耗这项 MCP 读取额度。

用户认为 200 次／天对高频迭代也可能偏紧。实际每轮调用量尚未测量；不能据此承诺免费档或 Professional 足够，也不因此要求升级到更高计划。价格与限制可能调整，购买前以实际结算页及最新文档为准。

### 评论接入仍须单独验证

Figma 设计 MCP 的官方工具索引没有独立评论读取工具；官方 REST API 提供评论接口。设计读取、设计写入、评论读取是不同能力，连接 MCP 不自动证明 Agent 可以取得用户评论。向自己的 drafts 捕获 UI 与编辑已有文件的席位权限也不能混为一谈。

平台事实与官方链接集中在[外部平台能力核查](ui-centered-development-platforms.md)，其中包括 Penpot、Storybook／Chromatic、网页反馈工具、GitHub Projects 和 Jira。它们仍是候选；没有连接账号、安装扩展、购买订阅或建立外部任务板。任务管理是否需要 GitHub Projects 或 Jira 后续再议，不作为 UI 协作试验的前置条件。

## Windows 迁移后的续接顺序

2026-10-11 本机续接已完成原型恢复。用户手动打开链接后，Agent 在同一 Orca 标签验证了输入、材料快照、发送、重置、刷新、HMR 与正常自动截图；用户发送的结构化 Design Feedback 可被 Agent 读取，并已用于增大输入框。具体结果、初始 CLI 错误与剩余边界见 [Windows 本机验证](orca-ui-windows-validation.md)。输入框大小仍待用户确认；未验证独立轮询未发送注释或 Figma 接入。

1. 先读本记录、[开发说明](../../../docs/development.md)与原型实验记录，核对迁移后的代码、未提交文件和实际工具环境；不假设原服务仍在运行。
2. 在用户授权的 Windows 环境中恢复现有简单原型，验证用户正常显示与操作、Agent 页面读取及操作、HMR、截图和注释获取。分别记录通过与失败，不能用语义快照正常替代视觉通道验收。
3. 如果当地浏览器注释可用，先完成一次“用户标注 → Agent 取得反馈 → 修改代码 → 用户操作确认”的完整闭环，再判断是否需要补充工具。
4. 选一个确实需要设计比较的页面试验 Figma：取得设计上下文、验证评论传递、按目标设计修改代码，再回到实际运行页面确认效果。记录必要的调用量与人工步骤，再决定是否付费及如何分工。
5. 路径验证后再讨论稳定的 UI 交互／调试框架及后续功能原型。沿用 OpenSpec 的业务契约和现有 Electron e2e 验证边界，浏览器页面不能代替原生能力与生命周期验收。

以上为续接建议，不是安装依赖、连接账号、启动服务器或实施业务功能的自动授权。当前先记录，待用户完成迁移再继续。

## Question

Agent 会话怎样通过工具与研究任务对象交互？何时建立研究任务，执行中追加指令怎样生效？

## Answer

用户于 2026-10-13 采纳完整 Agent 工作能力、研究任务建立方式及追加指令行为，并进一步明确：Agent 会话统一建模，不区分自由对话与研究任务对话；研究任务是系统中的业务对象，Agent 通过工具与之交互，会话与研究任务不建立显式绑定关系。

### 对话与研究任务

会话沿用通用 Agent harness 的基本角色：提供交流、上下文和执行能力，具体工作由用户与 Agent 控制。用户可以开启多个会话讨论不同话题，也可以在同一会话自然转换话题；多个会话可以同时编辑同一个文件或处理同一研究任务，对象不由会话独占。

Scholoom 的科研特性体现在工具、材料访问、领域对象和专业交互上。增加会话机制或限制须有实际需求，不为统一工作组织方式而强加流程或预先划分协作关系。内容保护落实在实际读写处，协调已发生的修改冲突，不以潜在冲突为由禁止多会话编辑。

Agent 会话承载提问、探索、讨论和实际工作；研究任务表达需要持续管理的研究目标、责任、进展与成果，是系统中可通过工具查询和操作的业务对象。

会话不设置“自由对话／研究任务对话”类型，也不通过绑定任务决定工作能力或运行模式。Agent 按实际需要通过工具读取、创建和更新研究任务；处理某个任务不会改变会话类型。使用工具、修改文件或执行多步工作本身不触发研究任务创建；建立任务也不要求使用固定工作流。

工作台提供统一会话入口与恢复方式，用户能够找回对话和相关产物。任务导航用于访问研究任务对象；从对象发出指令时提供相关材料和操作语境，不建立会话所属任务。切换会话时各自保留草稿和附加材料，正在阅读或编辑的对象保持原状；会话与对象导航独立。具体布局和材料附加体验继续细化。

### Agent 工作能力

Agent 可以在已有授权内读取材料、使用工具、编辑文件、执行计算和委派协作。具体能力由 Agent 配置与授权决定。实际修改和执行仍保留必要记录，文件与研究事实沿既有权威保存。

### 建立研究任务

用户可以明确提出建立任务；Agent 发现需要持续组织的研究目标时可以提出建议，经用户确认后建立。首条指令不自动创建研究任务。

Agent 可以通过工具把已有材料、成果与相关工作记录写入或关联到任务对象，继续原来的交流，无需另开或绑定会话。创建时明确足够开始工作的目标与范围，计划随研究推进逐步形成。

### 执行中追加指令

追加消息默认送给当前会话中交流的 Agent，在下一次能够处理指令的执行边界调整后续工作，无需等待整轮工作结束。界面区分“已收到”和“已处理”，此行为适用于所有会话。

已执行的修改保留实际结果；需要立即停止时使用明确的停止操作，并沿已有取消规则报告实际停止状态。浏览其他材料不改变消息归属。追加消息不自动扩大授权范围。

- 会话的执行环境、资源授权、执行与产物记录位置仍须细化，不按自由对话或研究任务对话分别设计。

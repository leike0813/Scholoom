## 本票需要讨论

- 吸纳 ResearchSpec 的工作区承接设计，核对研究目标、约束、分析、进展、产物、决定理由、已知问题与下一步的保存、查找和更新责任。
- 明确开放文件、项目结构化事实、长期文献库及任务记录的协作，不形成两份当前正文或两套研究事实。
- 讨论工作区概览与深入材料的关系：概览帮助找到工作，完整内容可按需取回，简短交接摘要不能代替所需上下文。
- 核对同一项目多份稿件、材料共享、跨项目复用及研究条件的保留；项目结论不自动成为全局判断。
- 以新 session／Agent 接续、用户修改材料后接续和补充材料后接续核对体验；目录移动、材料缺失和归档沿已有存储决定。

## Answer

2026-10-09，用户确认 Q1，并在修订后采纳 Q2。科研过程及接续所需内容持久化为工作区工件，概览、发现与读取基于已有事实源；以下为正式结论。

### 工作区上下文入口（Q1）

2026-10-09，用户确认统一的工作区概览、上下文发现与内容读取接口。概览按项目或任务展示目标、约束、相关稿件、工作进展、重要决定、已知问题与下一步，附各项实际来源引用。概览是读取事实源形成的视图，正文、研究事实与执行状态仍由各自来源管理。

发现支持按问题、任务、稿件、材料及内容查询，定位相关笔记、分析与研究关系；读取可沿引用展开完整内容、研究条件与历史依据，并说明当前材料及已知缺项。普通工作文件可以直接发现与读取，沿既有开放文件原则按需建立研究关系。接续内容来源同时遵守下面用户明确的约束。

### 会话独立的承接约束

2026-10-09，用户明确科研承接不能依赖 Agent 的 session context 或 transcript。所需研究内容必须能从工作区持久化材料、研究记录及事实取得。

### 科研过程持续保存为工作区工件（Q2）

将科研过程中的分析、推导、方案比较、判断理由及未解决问题直接保存为工作区研究材料，关联对应问题、任务、稿件和来源。保留有接续价值的完整论证及条件，概览按 Q1 派生；不能只保存最终结论或一段交接摘要。

Agent 在提出方案、完成分析、改变研究条件或明确下一步时，通过文件或领域工具保存相应研究内容，并把这些记录作为该段科研工作的实际产物。内核负责持久化工具、产物关联、实际执行记录及上下文发现；程序核对保存结果，研究含义由 Agent 编写和检查。重要理由在形成时落到工作区，后续步骤直接使用这些已保存材料。

普通笔记、分析和论证保留开放文件形式；目标、正式决定及证据关系沿对应事实源保存，文档引用这些对象。必要更新沿已有低摩擦协同原则局部处理。更新触发与相关步骤的交付接线由[harness／科研业务协作票](25-harness-business-integration.md)落实，避免仅有提示词要求、没有可读取产物。

### 资产关系与当前内容

沿[领域边界](06-research-domain-boundaries.md)与[存储模型](13-storage-and-change-model.md)，同一项目的多份稿件共享来源和研究成果，各稿件采用哪些主张、如何表述及其审稿轮次分别关联。跨项目复用保留必要来源与成立条件，项目结论按明确整理形成可复用成果。开放文件、项目结构化事实与长期文献库继续保持各自权威，普通文件按需建立关系。

用户修改正文、代码或材料后，接续 Agent 核对当前内容与已保存研究条件，再调整相关工作。补充材料及分析更新沿[自动维护契约](34-analysis-synthesis-maintenance.md)发现并核对影响；目录移动、材料缺失与归档继续沿已有存储决定处理。

### 承接行为例子与验证边界

以下根据已确认方向核对实际续做所需内容，实际验收在业务初步实现后结合科研任务开展。

| 情境 | 应能支持的续做行为 |
| --- | --- |
| 更换 Agent 后继续研究 | 从工作区找到目标与约束，依据保存的方案比较、结果和理由辨别已放弃的路线、未决问题及下一步，继续相关研究工作。 |
| 用户修改材料后继续 | 读取当前材料，对照记录的分析条件，判断哪些已有结果仍适用、哪些工作需要调整，并保存实际后续成果。 |
| 补充材料后继续 | 找到新材料及相关分析，核对它们对已有论证的影响；区分新增发现、待复核判断与已确认决定，按授权继续推进。 |

工作区记录是否足够支持上述续做，决定承接质量；旧会话隔离本身不能证明记录完整、依据充分或下一步正确。原“移除旧 context／transcript”验收建议未采纳，正常权限边界沿 harness 约定落实。

具体工具 Schema、保存接线与中断处理留到实现规格。本轮仅记录设计和静态调查，未实测科研内容保存完整性或跨 Agent 续做效果。

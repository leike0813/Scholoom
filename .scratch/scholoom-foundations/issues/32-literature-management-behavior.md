## Question

- 明确人和 Agent 在同一文献库中查询与操作的可观察行为，兼容插件操作也落实到同一权威。
- 梳理获取／管理结果如何交给分析模块与当前项目，自动分析的具体生命周期由对应票讨论。

## Answer

2026-10-09，用户分四轮确认 Q1–Q8，明确文献获取、整理、附件、阅读批注、删除恢复及模块协作的业务行为。本票解决，以下为正式约定；具体接口和运行效果继续随模块设计与实现验证。

### 获取入口

2026-10-09，用户确认以下入口作为文献管理的业务覆盖：

| 入口 | 行为 |
| --- | --- |
| Agent 线上检索 | 根据研究目的搜索、筛选，在任务授权范围内收录文献，保留必要的来源与筛选依据。 |
| 浏览器 Connector | 研究者浏览网页时保存条目及可取得的附件。 |
| 标识符添加 | 根据 DOI、ISBN、PMID、arXiv 等标识取得题录。 |
| 文件与题录导入 | 导入 PDF、题录文件等材料，识别或补全元数据、关联附件。 |
| 已有库迁入与手动管理 | 承接旧资产，支持手动建项、更正和整理；具体迁移策略留到生态接入票。 |

线上搜索的具体来源与工具另行核对，translators 的网页抓取能力不能直接等同于搜索能力。既有 translators、Connector 复用及人、Agent、插件访问同一文献权威的决定继续有效；入口确认不表示具体来源或兼容链路已经验证。

### 渐进完成与实际结果

用户确认分别表达搜索候选、是否已收录、附件可用情况与分析可用情况。题录可先收录并供查询、整理，随后继续获取原文与分析；已有附件无需等待分析完成才能阅读。

下载失败保留失败信息，可继续补取；批量操作返回各篇的实际结果，后续研究可利用已经可用的材料。条目保存、附件获取和分析完成分别判断，缺少某一层材料时不把其他已经可用的内容一并判为不可使用。分析的具体生命周期留到对应票。

### 集合、标签、主题与项目

用户确认保留集合、子集合和标签管理。同一文献可加入多个集合，仍为同一条目；从集合移除只改变分组。主题承载知识组织与综合，集合承载文献分组，两者可以关联；项目采用哪些材料、如何评价它们，继续归项目管理。

### 重复收录、差异与合并

- 确认是同一文献、同一发表版本时，复用已有条目，补齐缺项并关联新附件。
- 已有字段冲突时，按来源与实际内容核对后更正，保留可检查的变更。
- 疑似重复先保留，供人或 Agent 在授权范围内判断、合并。合并保留附件、笔记、批注，并保持既有引用和项目关联可定位。
- 预印本与正式发表版沿已有领域决定显式关联，保留版本差异。

### 附件管理与替换

附件默认托管，支持已有外部链接与缺失后的重新定位，沿既有存储决定。一篇文献可以关联正文、补充材料等多个附件，明确各自用途。

补入附件或再次下载时核对已有材料；替换影响批注或关键证据时，保留它们所依赖的材料与必要版本。新文件中的位置需核对后再关联，无法定位的问题只影响相关内容，不扩展为对所有普通材料的完整冻结或版本留存。

### 人与 Agent 共享阅读成果

人和 Agent 共同保存、查询和编辑书签、批注及文献笔记，按授权协作，能辨别原文摘录、批注作者与 Agent 的解释。Agent 通过共同内核独立读取原文与批注，不依赖打开阅读窗口，沿已有阅读决定。

可复用的文献理解随来源保存，当前项目的证据选择和研究判断归项目。批注可供后续分析使用，具体消费方式留到分层知识访问票。

### 删除与恢复

| 操作 | 行为 |
| --- | --- |
| 从集合移除 | 只移除分组关系，文献仍在库中。 |
| 删除文献或附件 | 默认进入回收站，可恢复相关内容与关系。 |
| 永久删除、清空回收站 | 明确对象范围及已知影响，沿已有破坏性操作授权处理。 |
| 移除外部链接附件 | 移除库内关联；删除外部原文件作为单独操作。 |

库内删除保留项目已保存的研究事实与必要历史材料，关联来源的当前可用情况如实表达。

### 共同操作结果与模块协作

- 人、Agent 和兼容插件的管理操作返回实际成功、失败或部分完成的结果；相关界面与任务可观察到同一份已保存事实。
- 文献管理提供稳定文献身份、题录、附件、批注及实际变化；分析模块按可用材料开展工作，判断哪些分析需要更新。工作台按受影响范围刷新。
- 项目关联库中的来源，按研究目的采用材料与分析；日常继续研究无需导出文献包，研究包继续沿既有独立交付、迁移与归档用途。

### 后续细化与验证责任

- 具体线上检索来源与工具由[科研方法、能力与工作流](36-research-business-methods-workflows.md)核对，不由 translators 捕获能力推定。
- 分层读取、分析内容与批注消费由[分层知识访问](33-layered-literature-knowledge.md)细化；分析启动、补齐、更新与维护由[分析与综合维护](34-analysis-synthesis-maintenance.md)细化。
- Translators、Connector、插件适配与已有库迁入由[生态接入](41-zotero-ecosystem-integration.md)细化。

本票未运行真实获取、去重合并、附件替换、批注往返、删除恢复或跨模块更新链路。上述业务约定不表示实现或兼容验收已经完成；实现规划仍由用户决定时机。

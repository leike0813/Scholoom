### 自动启动、补齐与持续主题

沿文献场景已确认的 Q7–Q12：入库且可用材料就绪后自动生成基础分析，缺失或受材料实质变化影响的成果后台补齐、更新，当前研究需要的材料优先。首批吸纳 Digest、参考文献提取、引用分析与文献评价；缺少必要材料时保留真实缺项与可用层级，补齐后继续。

基础分析面向文献自身，定向分析按研究语境组织。长期保留的知识主题与持续研究主题自动维护，人和 Agent 可调整目的、范围及主题组织；临时语义查询沿既有决定即时探索，有持续价值时再保留为维护主题。主题综合的方法、主张、争议、局限及未来方向吸纳旧项目成熟实践。

### Q1：维护依赖与发现范围

分析产物记录实际使用的材料、分析与必要版本或状态，以及用途、方法和主题条件。主题另保留目的与可发现材料范围：前者用于追踪既有成果受哪些变化影响，后者用于发现尚未采用的新文献。

变化沿实际依赖传播，程序识别变化与候选影响范围，Agent 判断科研影响及局部补充或重做方式。题录的展示性更正更新展示与检索；正文、补充材料或所用分析发生变化时，检查相关分析及综合。未实际用到的批注变化不默认重做全部基础分析。更新已采用成果与评估范围内新文献分别组织，不因尚未建立依赖而遗漏新来源。

### Q2：已有成果与更新过程分别表达

保存上次成功交付与正在开展的更新各自的情况；旧产物继续可读取，显示实际采用的材料、尚未纳入的新材料及已知来源问题。新结果满足对应交付要求后更新该用途的当前产物；不同目的、方法或观点仍按既有决定并存。

更新失败、中断或缺材料时保留已有可用成果与障碍。新增文献尚未纳入综合与原证据被更正或无法定位分别表达，由消费 Agent 根据当前用途核验；已知来源问题不能仅因旧产物可读取而隐去。受影响的项目论证进入相关研究工作的复核，正式判断和稿件修改沿既有授权。

当前无人工作的项目受到库更新影响时，处理时机与启动方式以[跨模块走查确认的决定](42-cross-module-research-walkthrough.md#q1-已确认无人工作的项目受到库更新影响)为准。

### 四类变化核对

| 变化 | 结果行为 |
| --- | --- |
| 文献入库 | 题录及已取得附件立即可用；必要材料就绪后自动分析，缺项等待补齐，不阻断其他可用内容。 |
| 补齐原文 | 补齐依赖原文的分析，核对已有分析与综合受影响的部分；旧产物说明所用材料与未纳入变化。 |
| 新增相关文献 | 按主题的目的与发现范围评估，纳入后维护综合及来源关系；当前报告在新结果交付前保留，并说明覆盖变化。 |
| 修正基础分析 | 沿实际依赖核对相关综合及项目采用结果，按科研影响补充或重做；正式判断与稿件修改沿已有授权。 |

以上为已确认契约的情境核对，未运行真实分析或更新任务。

### 执行、提示与实现边界

状态和障碍通过共同工具与工作台呈现；当前工作涉及缺材料、来源更正或定位问题时，读取与研究上下文保留这些信息。普通变化与可重建索引问题沿[低摩擦协同原则](13-storage-and-change-model.md)局部处理，避免扩张为全局人工待办。

取消、恢复、分批交付与部分成果复用沿[原生执行契约](18-native-capability-runtime-and-content.md)；模型请求的重试、执行限制与发送授权沿[模型与执行政策](22-model-data-and-execution-policy.md)，不另建一套维护重试或授权规则。

使用已确认的 LangGraph 原生 Agentic 流水线组织自动生成与维护。具体依赖 Schema、变化事件、合并调度策略、图节点与技术参数留到实现规格；图完成状态和主题报告更新不自动确认项目科研判断。分析与综合方法的组成继续由[科研方法、能力与工作流](36-research-business-methods-workflows.md)细化。

本轮仅记录设计与静态源码依据，未验证触发、恢复、增量维护的正确性、质量或性能。

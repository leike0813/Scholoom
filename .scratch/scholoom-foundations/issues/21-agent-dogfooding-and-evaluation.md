## Question

主要功能与接线具备后，怎样在隔离环境中通过产品入口真实调用 Scholoom 的科研 Agent，验证从文献管理到写作修订的工作效果，并形成有解释力、可持续维护的量化评价？

用户已确认参考 ResearchSpec 的方法，利用 Orca worktree 与 terminal 管理，在独立文献库、项目、应用配置和输出空间中运行 Scholoom 原生科研 Agent。依据[科研 Agent 内核](07-agent-runtime-boundaries.md)、[原生执行契约](18-native-capability-runtime-and-content.md)和[工程纪律](14-agent-development-discipline.md)，落实场景、材料、实际调用入口、数据及运行时隔离、必要权限、模型配置、输出采集、重复执行、取消／恢复、超时及费用控制。

[ResearchSpec 当前事实核查](../research/orca-ui-and-researchspec-dogfooding.md)已区分静态矩阵、真实外部宿主调用、独立模型评价和人工审阅。其 worktree 主要承载 worker，临时项目与 Bubblewrap 提供隔离；合成材料及当前代码不能证明真实研究质量或当前 live 路径已跑通。Scholoom 场景应面向自己的产品与原生科研 Agent，不沿用旧宿主协议或将外部 Agent 直接写文件视为产品验收。

沿用程序检查客观行为、独立评估者判断产物质量、人工重点审阅争议／失败／代表性成果的分工，细化具体场景和评价入口。任务完成、依据正确、产物可用、人工纠正、持续工作及执行代价等评价方向已确认；本票定义具体指标、分母、尺度、阈值及校准方式。首次结果与重试／恢复分别保留，基础设施失败与产品失败分别统计，未知不算通过，关键失败不被平均分掩盖。确定代表性任务、真实材料与合成样本的职责和重复次数，避免仅依靠执行者自评、单次成功或一个总分判断产品成熟度。

遵循开放文件与低摩擦协同约定，按评价需要保存输入背景、结果和诊断，不把测试记录要求扩张为日常科研工作门禁。具体阈值、首次样本和运行机制在本票讨论后选择；本票不直接启动 Agent、调用付费模型或修改用户实际文献资产。

第一轮建议（Q1–Q3 待确认）：

- Q1 场景组织：以一条真实原创研究论文的完整链路作整体验收，覆盖文献获取与管理、阅读分析与综合、研究数据／计算／图表、论文规划与整篇写作、投稿及审稿修订；同时从同一材料池拆出可独立重复的局部任务，分别定位文献／证据、计算与写作、审稿回应及持续工作问题。持续工作包含无工作台启动后接入、关窗续做、暂停／取消／恢复、用户同时改稿及部分材料缺失。根据已实现功能逐步运行，局部成功不能代替完整产品验收，也不预设固定庞大场景矩阵。
- Q2 材料组成：公开可读取的真实论文与研究材料用于持续评价；少量有已知答案的合成材料用于验证错引、缺项、矛盾和编辑变化等边界；用户的一篇真实原创研究项目用于最终整体验收，运行前明确实际项目、任务目标及授权，并复制到隔离空间。来源、可读范围与已知事实应可核对；开放科研任务按交付要求和依据判断，不以复述唯一参考答案作为质量标准。具体样本在首次实际运行前确定，不由本轮讨论臆造。
- Q3 评价组织：程序检查实际产物、持久化、可解析／可编译性、引用目标及计算结果等能稳定判定的行为；未参与执行的独立评估者读取实际来源、产物与必要过程记录，判断主张是否获依据支持、方法是否适用、表述是否准确及交付是否可用。可解析、存在引用或流程结束不自动表示科研质量通过。模型评估与执行分会话，评估结论附具体位置、依据及不确定项，人工抽查代表性成功、失败和争议结果以校准判断。报告分别展示任务完成、依据正确、产物可用、人工纠正、持续工作及代价，不压成一个总分；关键失败单独报告。

恢复讨论后，先根据初步实现核对本轮草案，再定义指标分母、评分尺度、通过条件，以及模型、重复次数、时间／费用预算、隔离和记录安排。本轮没有运行 Agent 或模型评价，也没有选定模型供应商或授权付费调用；子 Agent 的委派模型偏好不自动成为产品执行或评估模型配置。

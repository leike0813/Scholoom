## Question

采用 LangGraph 系列之后，用户怎样配置模型与供应商、选择不同任务所用模型，并控制外部数据发送、凭据、诊断信息及执行资源？

本票确定产品运行配置，承接[科研 Agent harness](07-agent-runtime-boundaries.md)、[领域模块与 Electron 架构](09-electron-architecture.md)和[原生内容与执行契约](18-native-capability-runtime-and-content.md)。前置票均已 resolved，本票可提前讨论，无需等待科研效果评价。

需要明确以下问题：

- 用户怎样配置模型、供应商及不同任务的模型选择；配置在应用、项目和任务之间怎样生效。
- 哪些材料可以发送给外部模型；密钥怎样保存和使用，诊断记录怎样处理可能包含的研究材料与凭据。
- 超时、限流、重复失败、并发及费用上限怎样控制；触及限制时怎样向用户说明实际状态及继续工作的条件。
- 切换模型时怎样保留任务上下文，并明确实际采用的模型；自动重试、回退或切换是否需要用户选择，以及怎样影响数据发送和费用约束。

讨论应考虑现有模型适配与运行时组件能直接提供哪些能力，项目需要补充哪些政策与配置，具体能力以供应商官方说明及固定版本实现为依据。无法获得准确用量或价格时，应明确可控制的范围，不能把估算宣称为可靠的费用上限。

### 与已有票的职责关系

[#21 真实科研 Agent dogfooding 与评价](21-agent-dogfooding-and-evaluation.md)在初步功能形成后选择评价场景、样本、指标和实验预算。本票定义日常产品运行的模型、数据与资源政策；评价运行遵循该政策，并另外选择本轮实验配置。

用户指定的编码子 Agent 委派模型是开发协作偏好，不自动成为 Scholoom 的默认产品模型、支持供应商或科研评价模型。

## Answer

2026-10-08，用户第一轮回复“全部采纳”，确认 Q1–Q3；第二轮回复“Q6: 暂不设此功能。其余采纳”，确认 Q4、Q5、Q7，并暂不设置金额预算功能。本票解决，正式政策如下。

### 模型配置与选择（Q1）

- 应用保存供应商连接与命名模型配置，由用户设置默认模型；项目和任务按需覆盖。
- 主 Agent、执行者和审查者等职责可分别指定模型，未指定则继承。
- 每次执行记录实际使用的供应商、模型和必要参数。修改默认配置影响后续执行，正在进行的请求保持原配置。
- 首阶段采用明确选择，不做自动模型路由。开发子 Agent 的委派模型偏好不自动成为产品默认模型。

### 研究材料发送授权（Q2）

- 项目或文献库设置可使用的模型连接及可发送的材料范围，任务继承并可进一步收紧。
- 读取权限与外部发送权限分别表达。在已授权范围内无需逐次确认；新增接收方或扩大材料范围时，由用户确认。
- 限制依据明确的材料范围或标记，不默认让模型自行判断材料是否敏感。
- 同一规则覆盖委派、上下文压缩及其他模型调用。

### 凭据与诊断（Q3）

- 应用级凭据管理统一提供凭据，优先使用系统凭据库，并支持环境变量注入，使独立内核无需打开工作台即可使用。
- 项目只保存连接引用；密钥不进入项目文件、会话或日志。系统凭据库不可用时明确提示，由用户选择保存方式。
- 日常诊断默认记录调用状态、耗时、用量和必要错误信息；科研会话与产物按既有留存约定保存。
- 详细诊断由用户显式开启，导出前查看包含内容，默认不自动上传。

### 时间、并发与执行上限（Q4）

- 应用提供连接级请求超时、并发与限流配置。所有经内核管理的调用共用这些限制，包括 worker、上下文压缩和重试。
- 任务可设置调用次数、累计用量和总时长上限，但不能自行突破应用约束。
- 请求超时和并发提供有限默认值，具体初值在供应商接入时核对；持续科研任务默认不设硬性总时限。
- 达到限制时停止相关后续调度，保留已完成成果，并显示原因、在途工作与继续条件。
- 外部后端能落实哪些限制，按实际支持范围说明，不将内核调度限制宣称为对任意外部程序的强制隔离。

### 自动重试与重复失败（Q5）

- 对确认可安全重试的临时失败，默认最多额外重试两次，采用退避并尊重供应商的等待提示。
- 应用与 SDK 共用这一次数上限，避免多层重试叠加。
- 凭据错误、参数错误和授权不足直接报告。
- 超时或断线后，若原请求是否完成无法确认，先核查或暂停相关调用；已执行或效果未知的写入不盲目重放。
- 重试耗尽后保留障碍，其余独立工作可以继续。取消沿既有执行约定处理，不将本地中止宣称为供应商停算或停费。

### 金额预算的范围决定（Q6）

首阶段暂不提供金额预算功能。Q3 的基础用量诊断与 Q4 的次数、累计用量、时间和并发限制保留；本轮未采纳金额预算、价格估算、预算阈值或金额封顶控制方案。后续如需该功能，另行确认范围与可靠性依据，不作为当前实施前置条件。

### 模型切换与任务延续（Q7）

- 首阶段由用户明确切换，不静默回退到其他模型或供应商。
- 切换在请求结束或中止后的安全边界生效，重新核对接收方、材料发送授权和剩余执行额度。
- 沿用原研究任务；目标未变时，也沿用原能力调用。
- 从任务摘要、当前材料、产物和可适配的会话继续，记录实际切换，不要求跨模型精确恢复全部执行历史。

### 实施与验收承接

具体供应商支持名单、SDK 版本、模型参数、超时与并发初值、系统凭据库接入及外部后端支持范围，在相应 OpenSpec 功能变更中核对和验证。基础诊断中缺失的用量不能作为零用量使用。

本票确认配置职责、默认行为和调整边界，没有实现接口、安装依赖、调用模型或处理实际研究材料。[真实科研 Agent 验收](21-agent-dogfooding-and-evaluation.md)仍留到功能初步实现后讨论；业务实现规划的启动时机继续由用户决定。

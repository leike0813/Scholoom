## Answer

经用户逐轮采纳并确认，本票于 2026-10-03 解决。

### 产品定位

Scholoom 是面向完整科研流程的独立 Agent 系统。内核由 Agent 运行时及其外围配套 harness 构成；Electron Agent 工作台是人类参与这一系统的界面，形态参考为文献管理与写作定制的 VS Code 类工作台。

内核必须能够在未打开工作台的情况下执行完整科研任务。工作台随后接入时，能够查看并介入已经开展的工作。具体入口、进程划分和执行引擎由后续票决定。

### 全流程与工作组织

- 覆盖文献获取与管理、阅读与分析、研究综合、研究材料与结果整理、论文规划和整篇写作、投稿材料、审稿修订及回复；各环节缺一不可。开发可以分步推进。
- 接入已有数据、图表和结果，也支持 Agent 执行分析脚本、调用计算工具并产出研究材料。
- 以研究项目作为当前工作空间；长期文献库跨项目共享，也支持独立管理和阅读。
- 普通文件与文献条目、批注、分析结果、研究任务都是可浏览、搜索、打开并交给 Agent 操作的科研资源。
- 支持从任意环节进入，包括已有稿件、局部章节和审稿修订，按任务需要补充上下文。
- 迁移后默认主要使用 Scholoom，同时保留 Zotero 共存的过渡体验。具体兼容、迁移与数据一致性由相关票决定。

### 真实使用验收

以用户的一篇真实原创研究论文验证从文献到最终修订的完整链路，使用文献、方法与结果、图表和整篇稿件，而非仅以单章演示替代产品能力。交付物包括完整稿件、参考文献与图表、投稿材料，以及审稿后的修订和回复；声称完成的工作应有对应依据。

同一研究链路需要验证无工作台执行，以及工作台随后接入、查看和介入已有工作。从开发开始维护 Windows、macOS、Linux 构建，先在用户日常平台验证完整流程，首个稳定版本完成三平台验收。

### 交给后续票的细化问题

Agent 能力与权限、harness 职责及执行引擎、研究对象与存储权威、Zotero 兼容实现、具体工作台布局、主编辑格式和技术栈仍由对应票决定。四工作区作为导航或视图的方案尚未定案。

具体论文样本与用户日常平台需要在实际验收前补齐；它们不阻塞当前产品定位。产品术语见 [CONTEXT.md](../../../CONTEXT.md)。

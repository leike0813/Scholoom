## Answer

2026-10-09，用户三轮回复“同意”，确认 Q1–Q6。以下为正式决定；四类情境语义核对未发现新的阻塞决策，本票设为 resolved。

### Q1：在已授权范围内自动准备并复用环境

应用／工具配置或任务授权明确允许准备的环境与依赖范围。已获授权时，运行时可自动取得声明所需的解释器、依赖或 TeX 宏包并复用环境，不逐次请求同一授权。准备失败时报告具体缺项与已采取操作，其他独立工作可继续。

新增授权范围外的依赖或改动用户已有环境时，取得相应授权。默认将新准备内容放在受管环境，已有 Conda／解释器按用户配置使用。内置工具依赖与用户工程环境的版本管理沿技术栈已确认约定。

### Q2：按项目配置运行，科研产物直接保存到工作区

默认在当前研究项目中按工程配置或工具声明设置工作目录，代码、输入数据、报告和图件作为普通工作区工件保存，GUI 与 Agent 读取同一份文件。临时缓存和纯中间文件使用受管临时目录，不默认复制整个工程到隐藏目录，也不要求每次执行建立独立工程副本。

输出路径及已有结果的覆盖沿工作包与开放文件的授权约定处理。本轮确认的是产品执行契约，没有安装依赖、创建虚拟环境或执行用户科研代码。

### Q3：保留最后成功预览，按实际完整程度复用计算结果

渲染预览另行保留最后一次成功产物，当前失败不将其标为最新。普通计算按实际产物检查，只复用已经完整并满足用途的部分；未完成文件仍可查看，但明确标为未完成，不能作为完成结果交付。不默认为每次运行复制全部数据与工程。

运行状态、错误、必要日志及产物引用由共同执行记录提供，GUI 和 Agent 使用同一份事实。已有结果遭破坏时如实记录，不能仅因曾成功而宣称文件仍完整；具体产物检查与预览发布保护需实现验证。

### Q4：普通预览与获授权工程执行分别处理

普通预览读取正文与已有结果，采用应用提供的转换与排版链路，不自动触发工程中的计算代码、自定义 pre／post-render hook 等构建脚本。依赖这些步骤才能完整生成的内容，提示需要工程渲染，并按任务授权进入该执行路径；已有授权继续复用，不反复确认。

不能只加 `--no-execute` 就认为自定义工程脚本已被阻止。自定义 Lua filter 等可执行扩展也按实际调用处理，不能当作被动模板资源。具体预览适配随实现验证；界面布局与响应门槛仍由预览票后续讨论。

### Q5：程序执行时限与工具请求等待分别处理

由工具声明和运行配置给通常短时完成的命令设置有限默认时限；长计算按任务明确配置，默认不套用短命令的时限，可在受管后台持续运行。持续任务总时长沿既有政策，不额外增加统一硬上限。

界面和 Agent 可查看实际状态并主动取消，程序一段时间没有日志不自动视为卡死。工具请求等待超时与程序执行超时分别处理；等待结束后已经转入受管后台的计算仍可继续查询，不能把等待超时报告成计算失败。实际执行时限到达则按取消路径收尾，并记录超时原因；具体初值按工具实际行为验证。

### Q6：确认执行停止后完成取消，重启先核查再续做

收到取消请求后先标为取消中，停止后续调度并请求执行退出；宽限期后终止仍未退出的受管执行单元及受管子进程。确认已停后再标记已取消，无法确认时保留状态未知和原因。已完成产物与修改保留，普通取消不撤销先前效果。

内核重新启动时核查未正常结束的执行、可能存活的进程与实际产物，再决定重新接入监测、从可用 checkpoint／已完成步骤继续，或对可安全重试的部分有限重试。已明确取消的执行不自动重启，效果未知的写入、下载或外部操作先核查；其余独立工作继续。

后台重新接入、进程树终止及恢复能力按实际平台验收，不预先宣称所有外部程序均可重接或断点续算。关闭工作台后任务继续、共享宿主故障及有限安全重试沿既有架构与共同运行时处理。

### 代表性情境核对

| 情境 | 环境、执行与交付 | 失败、取消或继续 |
| --- | --- | --- |
| 统计脚本缺少 SciPy | 沿 Q1 在已有授权范围内准备受管环境，按 Q2 使用项目配置和工作区材料，代码与结果由人和 Agent 共用。 | 准备失败说明缺项；已有环境变更或依赖越权先取得授权，独立工作可继续。 |
| QMD／LaTeX 普通预览与工程渲染 | 沿 Q4 普通预览读取正文及已有结果，需要项目代码或构建脚本时进入获授权工程执行；成功预览沿 Q3 单独保留。 | 编译失败表达当前失败与旧成功产物的对应关系；半成品不能作为完整交付，原结果损坏如实报告。 |
| 长计算暂时没有日志，随后用户取消 | 沿 Q5 按任务配置运行，可转入受管后台，等待响应超时不等于计算停止；结果按 Q3 检查完整程度。 | 沿 Q6 停止后续调度并收尾受管进程，确认停止后完成取消；保留已经完成的结果与修改。 |
| 内核退出后重启，程序或结果可能仍存在 | 沿 Q6 核查实际进程、结果和已完成步骤，能重接则恢复监测，能续算则使用可用进展。 | 效果未知的操作先核查；可安全重试的部分有限重试，已取消执行保持取消，其他独立工作继续。 |

这是依据已确认决定做的语义核对，没有启动科研程序或模拟进程故障。未发现需要新增产品决策的缺口；具体状态字段、环境路径、工具时限和进程接线交给后续实现规格。

### 隔离范围与实施验收

执行能力归属与调用沿[模块依赖决议](../../runtime-architecture/issues/01-module-dependencies-and-authority.md#answer)，进程分工、归属收尾、旧实例与已受理操作、共享故障及资源保护范围沿[进程决议](../../runtime-architecture/issues/03-session-execution-processes.md#answer)。首阶段按可信代码执行，不承诺任意代码强隔离；程序自身可直接访问哪些系统资源与内核工具授权分别表达。资源约束不能替代安全隔离，额外强隔离需求需另行明确任务及威胁边界。

实现时核对并验收：首次环境准备与离线复用、已有解释器／Conda 接入、同一工作区的 GUI／Agent 结果读取、预览与工程脚本执行边界、最后成功产物发布保护、请求等待与程序时限、跨平台取消及进程树收尾、内核重启后的实际效果核查和可支持的续算范围。内置工具锁定与用户工程声明继续沿技术栈，模型与材料授权、上限及诊断继续沿资源政策，不另立配置或记录权威。

本票完成的是产品契约讨论。未修改业务代码、安装依赖、创建虚拟环境、运行用户科研代码或验证取消恢复；业务实现及 OpenSpec 启动仍由用户决定时机。下一项可讨论[细化 Zotero 生态接入、插件行为与文献迁入](41-zotero-ecosystem-integration.md)，实时预览布局及未定体验继续按用户要求后置。

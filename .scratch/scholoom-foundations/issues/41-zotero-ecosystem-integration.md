## Answer

2026-10-09 至 2026-10-10，用户分轮确认 Q1–Q8；生态能力的目标行为、迁入范围、适配边界和实际验收责任已明确，本票 resolved。以下为正式决定，讨论定案不表示实现或兼容验收已经完成。

### Q1：自有 Scholoom Connector，复用 Zotero 采集能力

提供独立命名、独立发布和维护的 Scholoom Connector，复用适合的 Zotero 页面识别、translator 执行、附件与快照采集代码，自行提供保存交互并接入 Scholoom 文献服务、库／集合选择、状态及必要配置。沿用 [#12 的项目许可](12-technology-stack.md#项目许可q1)，扩展按 AGPL-3.0 开源，保留来源声明，并按实际分发提供完整对应源码及必要构建脚本；第三方代码和资源仍逐项核对适用许可。

Scholoom Connector 默认保存到 Scholoom，Zotero 官方扩展继续保存到 Zotero；两款扩展并用纳入验收。保存目标及库／集合明确，目标不可用时提示原因并提供重试机会，不静默改存其他应用或云端。条目保存与附件获取分别表达。首阶段以自有扩展承接收录，前序“官方 Connector 直接接入 Scholoom”的承诺由此替换，相关政策已同步。

扩展的浏览器适配、发布、上游更新与维护由 Scholoom 承担。[固定源码核查](../research/scholoom-connector-source-reuse.md)定位了采集模块，也确认品牌、官方域名、本机协议和云端保存存在耦合；独立接收与配对、源码复用后的构建、各浏览器运行及扩展共存仍需真实验收。本轮没有实现或运行扩展。

### Q2：单向迁入，后续由 Scholoom 独立维护

首阶段采用可检查的单向迁入，源库保持原状，迁入部分后续由 Scholoom 维护。保留来源身份映射和迁入记录，重复导入时核对已迁入对象及差异；源库后续更改通过明确再次导入／更新处理，不默认双向持续同步。

目标库已有字段、附件、笔记等变更时按实际差异协调，不整库覆盖。个人库／群组库范围、附件存放与插件状态迁入见 Q6；检查与恢复见 Q8。本轮没有读取或迁移真实文献库。

### Q3：已有引用键稳定保留

迁入键、用户指定键及已生成的键默认保留，题录更正不自动改变它们；新增条目按 BBT 配置生成键。重新生成作为明确操作，处理实际键冲突并核对受影响的已知项目引用。已有项目键与库键的差异继续由映射关联；自动导出只更新用户选定的导出文件，沿 [#13](13-storage-and-change-model.md#引用文件与题录权威) 保留人工维护的 `.bib`／CSL JSON 内容。

引用键稳定保留是产品默认行为；通过未修改的 BBT 原包落实该行为、重生成时的引用核对及各类导出链路，仍需实现验收。

正式引用键、插件状态与项目映射的职责归属，以及不建立反向引用表条件下的影响核对，采用[生态职责决定](../../domain-development/issues/08-zotero-ecosystem-constraints.md#q1引用键与插件状态归属)。

### Q4：元数据自动填空，已有字段冲突先核对

人或 Agent 发起识别／补全后，在授权范围内自动补齐空字段，记录来源；已有标题、作者、DOI 等冲突时保留候选差异，由人或获授权 Agent 核对后应用。批量处理返回每篇实际结果，失败不清空原字段。中文作者处理等会改写已有内容的插件行为按明确配置启用，并让实际变更进入共同文献服务。

本轮只确认业务规则，未运行真实在线补全、字段冲突处理或批量更新；原型中的合成响应与作者处理证据仍按各自验证范围使用。

### Q5：插件按已验证版本升级，translators／CSL 独立更新

沿 [#05](05-zotero-compatibility-policy.md#兼容版本与维护责任) 已确认的兼容版本政策，BBT／茉莉花只升级到 Scholoom 已验证的支持版本，宿主不直接启用插件的上游自动升级。translators 和 CSL 可通过明确的维护来源独立更新，记录实际来源与版本，保护用户自定义内容；更新失败保留上一份可用资源，更新后出现问题可回退。

具体下载和发布机制由实现规格确定，实际采用的基线及支持范围沿 #15 记录；本决定不表示任意上游版本已兼容，本轮未执行实际更新或回退。

### Q6：迁入选定个人库与本机可读取的群组库材料

首阶段覆盖用户选择的个人库及本机已可读取的群组库内容，保留来源库区分、来源身份映射、集合层级与文献分组关系、标签、题录、引用键、笔记／批注和附件关系。群组库迁入后是 Scholoom 独立维护的内容，账号、群组成员权限及 Zotero 在线同步关系不随内容迁入。

托管附件复制到 Scholoom 的托管位置；已有链接附件默认保留链接，也可按用户选择转为托管。源库及源附件保持原状；缺失、未下载或不可读取的材料逐项列明，不把它们当作已迁入的文件。字段或批注无法完整表达时保留可恢复的原始材料并报告差异。

首批插件的必要状态按语义迁入，包括引用键及固定状态、可映射的引用键规则与相关偏好；导出任务和路径作为配置候选保留，核对目标路径后再启用写文件行为。缓存和索引重建，不能完整映射的配置列为差异，不承诺复制任意插件内部数据库。

本轮确认范围和保护规则，未读取源库、复制附件或验证插件状态映射；迁入结果与恢复路径仍需实际验收。

### Q7：原插件大纲／书签能力接入自有阅读器

沿 [#12](12-technology-stack.md#pdf-阅读组件q7) 的 EmbedPDF 阅读组件与 [#32](32-literature-management-behavior.md#人与-agent-共享阅读成果) 的共享阅读事实约定，宿主适配原插件所需的阅读接口，让茉莉花的大纲／书签能力作用于 Scholoom 中同一附件，由自有阅读器呈现。书签标题、层级和目标位置应可读取、编辑、导航并在重启后保留；人和 Agent 通过共同文献／材料服务使用同一份结果，Agent 操作不依赖打开可见阅读窗口。原插件内部所需页面由兼容宿主承接，原包保持不修改。

涉及 PDF 文件写回时按实际影响保留原材料及必要版本，保护已有批注和证据定位；适配或写回失败保留已有内容并报告实际结果。已有 PDF 内嵌书签、应用保存的阅读状态与批注按材料和领域服务的既有归属接入，兼容层不另立一份可自由修改的阅读事实。

验收覆盖插件生成、用户编辑、Agent 读取／修改、PDF 导航及重启读回，独立宿主的真实链路仍待实现验证；此前完整 Zotero 参考宿主中的成功不能替代这项验收。

### Q8：检查迁入结果，支持失败、中断后的续做与安全撤回

开始前检查选定范围、可读取材料、目标库差异及已知缺项；完成后提供可检查的迁入记录，逐项表达成功、失败、缺失与不能完整转换的内容。核对来源身份、字段及关系，并抽样实际打开附件、笔记／批注、检查引用键导出与重启读回，不能仅凭条目数量宣布全部迁入成功。

失败或中断保留已确认完成部分，重试前核查来源映射、实际对象与附件，按差异续做，避免重复建项和覆盖迁入后的编辑。撤回按本次迁入记录定位对象；只撤销仍可安全撤销的变更，保护后续编辑和项目使用关系，不能安全撤回的部分列明并协调处理。源库及源附件保持原状。

正式使用前沿 [#15](15-validation-and-release-discipline.md#高影响变更与恢复q4) 在副本／样本中验证失败、中断、重试和撤回，并实际恢复必要备份后核对。本轮未执行真实迁入，也未验证恢复结果。

不维护反向引用表条件下的撤回安全判断，采用[生态职责决定的保留原则](../../domain-development/issues/08-zotero-ecosystem-constraints.md#q3迁入撤回采用保留原则)；具体规则在该票维护。

### 实现验收承接

- 自有 Connector 的独立构建、浏览器适配、配对、共存、保存和附件结果，以及更新回退随接入实现验收，许可按实际纳入代码与分发核对。
- BBT 的引用键稳定、BibTeX／BibLaTeX、自动导出、pull export 与对外 JSON-RPC 按既有首批功能目标验收；内部桥接 RPC 不替代对外接口证据。
- 茉莉花的真实在线元数据、translators／CSL、附件匹配及独立阅读器大纲／书签写回按实际链路验收；合成 HTTP 结果和独立 RIS 对照不替代原任务分支修复与运行。
- 迁入内容、必要插件状态映射、失败／中断／重试／撤回与备份实际恢复按 Q6、Q8 验收，保护源材料和迁入后的研究成果。

共同权威与操作结果已沿前序决定核对，后续接口、存储映射和运行接线由实现规格落实。实现规划的启动时机仍由用户决定。

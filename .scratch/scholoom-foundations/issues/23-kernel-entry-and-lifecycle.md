## Question

开发骨架已交付后，共同内核入口与生命周期这一变更应交付哪些可观察行为，怎样划定 GUI、CLI、浏览器开发入口和共同客户端的职责，以及怎样验证独立内核、单实例、连接恢复与明确停机？

沿用[领域模块、Electron 进程与扩展宿主架构](09-electron-architecture.md)已经确认的独立 Node 内核、本地双向 JSON-RPC／WebSocket、同一数据配置单实例及关闭工作台不自动停止内核约定。本票决定首个变更的交付边界与用户可见行为，具体启动协调、认证、传输库、接口字段及文件变化留到相应 OpenSpec 调查与设计中核对。

需要明确：

- 此步是否先交付真实后台连接与生命周期，研究任务、模型调用和文献业务在后续变更接入；完成后哪些行为应立即可用。
- Electron 工作台、CLI 和浏览器开发入口如何连接同一内核，首次启动、连接失败与重连怎样呈现。
- 内核状态查询与明确停止的入口、权限和用户可见结果；关闭客户端与停止内核的区别如何体现。
- 本轮必须验收的多客户端、并发启动、断线、崩溃及配置隔离行为，以及三平台与分发验证的范围。

相关依据为[技术栈与工具链](12-technology-stack.md)、[验证与发布纪律](15-validation-and-release-discipline.md)、[UI／Electron e2e](20-ui-debugging-and-e2e-harness.md)、[模型与执行配置](22-model-data-and-execution-policy.md)、[开发说明](../../../docs/development.md)及[骨架实际交付](../../../openspec/changes/archive/2026-10-08-initialize-project-skeleton/delivery.md)。

## Answer

2026-10-08，用户两轮回复“全部采纳”，依次确认 Q1–Q2 的交付范围，以及 Q3–Q5 的入口、恢复和停机行为。本票解决，正式决定如下。

### 交付边界（Q1）

本步交付真实后台连接与生命周期：GUI／CLI 能启动或连接同一内核，查询实际运行状态；同一数据配置并发启动只产生一个内核实例；关闭工作台后 CLI 仍可访问该内核，重新打开工作台可再次接入；客户端断线后可恢复连接并读取当前状态；用户可明确停止内核，其他客户端正确显示停机结果。

持续研究任务与真实 Agent 执行由后续变更接入。本步落实既有独立 Node 内核、本地双向 JSON-RPC／WebSocket、客户端身份验证和同一数据配置单实例约定；连接状态不代表科研任务已经可执行。

### 交付环境（Q2）

本步交付开发环境中的真实 Node＋Electron 链路，Linux 本机和三平台 CI 使用同一组生命周期检查。目录包的独立 Node 分发由后续专门变更落实，最终产品的独立运行与三平台分发要求保留。测试使用独立数据配置，实际平台结果以本轮运行证据为准。

### 启动与连接（Q3）

- 打开 Electron 工作台时，自动发现并连接内核；确认尚未运行时再启动。
- CLI 分别提供启动、查询状态和停止操作；查询状态与停止操作不会创建新内核。
- 浏览器开发启动命令负责启动或发现内核，并安全提供连接信息；页面复用共同客户端。
- 各入口使用同一数据配置与启动协调逻辑，关闭客户端后内核继续保留。具体启动桥、连接资料传递与共享模块位置在 OpenSpec 中确定。

### 断线与故障恢复（Q4）

- 短暂断线采用有界退避重连，成功后重新读取当前状态；持续失败时显示实际原因和重试入口。
- 内核仍活着但无法连接时，不自动另起实例或强制替换。
- 确认内核退出后，由用户重试连接来重新启动；不增加常驻重启守护程序。
- 协议不兼容、认证失败等问题直接说明，避免反复重试。
- 明确停止内核后，已有客户端停止自动重连，不把内核重新拉起。

### 明确停机（Q5）

- CLI 提供停止操作，工作台菜单提供明确的“停止内核”动作，说明它影响连接到该内核的所有客户端。正常关窗及退出工作台只关闭人类界面。
- 停机先停止接受新操作，再完成必要清理；客户端收到停机通知并更新状态。
- 停机失败或超时如实显示，不能把连接断开当作内核已经停止。
- 后续接入任务时，按已确认的暂停／恢复约定处理正在进行的工作，不在本步构造研究任务假实现。

### 验收与实现规格交接

验收覆盖真实 GUI／CLI 连接与状态查询、同一数据配置的并发启动、关窗后内核继续可访问、工作台重新接入、断线后的状态恢复、内核存活但不可连接、内核退出后用户重试、协议或认证失败、明确停止后的多客户端状态及不会自动拉起的行为。开发与测试沿既有规则使用独立配置，浏览器入口使用共同客户端验证实际连接。

待用户决定进入实现规划时，使用项目默认 scholoom-dev schema 形成实现规格。调查与设计核对具体启动协调、实例发现和存活判断、认证与浏览器连接资料传递、传输库、协议 Schema／DTO、有限重连与停机等待策略、文件变化及必要验证；具体命令语法和 UI 文案由实现确定，不作为精确文本测试契约。

本票提供首个变更的决策依据，不表示该行为已经实现、完整开发路线已经确定或业务实施已经获授权。[真实科研 Agent 验收](21-agent-dogfooding-and-evaluation.md)继续留到功能初步实现后讨论。

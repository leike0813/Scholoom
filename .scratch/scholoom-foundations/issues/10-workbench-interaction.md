## Question

用户处理首条真实工作链路时，研究对象、阅读或编辑区域、Agent 会话、任务状态和待审查产物应如何组织？哪些操作适合直接交互，哪些适合通过 Agent 发起？

工作台是科研内核的人类界面。能力、工作流和任务的交互表达以[原生科研能力核心模型](17-native-research-capability-model.md)为依据，避免在界面原型中提前决定内核概念关系。

制作可供用户反应的低成本交互原型，检验对象切换后的上下文、长期库与项目导航、修改理由和证据查看、冲突处理，以及无会话时仍能找回产物。四工作区、左中右布局和 Nimbalyst 的组织方式都是候选。原型不是正式 UI 实现；需要安装依赖或启动服务时遵守用户授权边界。

## Answer

第一轮用户倾向 Agent 工作优先的方案 B，并希望支持多种布局，其余三项采纳；第二轮五项建议全部采纳。本票于 2026-10-03 解决工作台组织与交互方向。两轮文字线框已经用于用户选择，随后制作可操作草图并完成代表性交互检查；尚未收到对该 HTML 版本的进一步视觉反馈，具体视觉和细节可以继续调整。

2026-10-04 按用户确认的[低摩擦协同方案](13-storage-and-change-model.md)同步日常编辑、审查和待处理范围；已有原型检查仍仅代表当时的示例行为。

### 默认 Agent 工作优先，提供四种布局

首次进入采用 Agent 布局，中央主要呈现当前 Agent 交流及其承担的工作，相关材料可以预览和展开。提供 Agent、文献、写作与审查四套预设，分别强调 Agent 工作、文献管理阅读、稿件编辑、修改与回应核验。

允许调整区域大小、折叠面板、分栏和保存常用布局；后续进入恢复上次安排。切换布局保留持续任务、编辑草稿、未发送指令和附加材料。布局改变信息安排，不另设研究对象、任务状态或权限权威。

### 任务、Agent 与会话分别可访问

日常工作导航以持续任务为主。任务页连接目标、计划、执行者、会话和产物；Agent 页管理执行者，查看委派关系及承担的工作；会话页支持检索和继续交互。

Agent 工作页以交流为主体，目标、进展、产物和待处理事项同时可见。研究计划、委派关系和工具活动按需展开，具体结果可以打开。当前交流对象明确显示，主 Agent 与 worker 的工作均可查看；切换接收者保持任务归属清楚。同一 Agent 多任务、任务跨 Agent 或会话的关系沿用核心模型。

任务与产物可在会话视图关闭后找回。后台工作及工作台随后接入的实际执行机制沿用已确认内核职责，由架构实现。

### 材料建议、指令与实际使用可辨

输入区显示目标任务、接收 Agent 和材料标签。当前文档或选区可以作为建议，支持附加、固定和移除，发送时明确交给 Agent。

浏览对象、交给 Agent 的材料与实际使用材料分别可辨。切换标签页本身不改变既有任务和授权；Agent 可以主动查询更多资料。关键证据可查看来源、位置及必要版本，普通材料保持直接访问。

### 日常操作与 Agent 工作共用内核

文献导入、集合与标签整理、元数据编辑、阅读批注和普通稿件编辑都有直接入口，按操作需要采用按钮、菜单和快捷操作。批量整理、分析、综合与跨对象工作提供 Agent 入口。

直接操作与 Agent 调用共同领域能力和状态管理，结果可以继续被 Agent 使用。已有授权及变更规则适用于两类入口，不因采用布局或按钮而另外设立控制器。

### 文献库独立使用，也可从项目访问

长期文献库有独立入口，无项目时可以管理、阅读及开展库任务。项目工作中可以打开库材料，保留当前项目和任务；正在浏览的来源与指令接收任务分别显示。

项目、库、稿件与产物归属沿用领域模型，浏览或切换布局不自动迁移资产。工作范围明确时，相应对象与任务导航保持可辨，项目审查等事项可从对应入口打开。

### 按研究目的组织修改审查

按研究目的或审稿意见聚合相关修改，再逐项查看差异、修改理由、依据、含义变化和实际应用情况。正文、图表、证据关系、回复等相关对象可以一起核对。

普通授权修改直接应用，提供差异与撤销。用户要求先审或授权需要时，支持局部接受及剩余工作追踪。Agent 自行适应常见文件变化，无法合理协调的局部冲突可以对照已知内容处理，保护手工编辑。

修改应用、回复声明和整体交付分别核对。部分修改完成仍可找到剩余事项；实际完成情况沿用内核事实，不以会话消息或单份 diff 代替整体完成。

### 待处理工作有持续入口

设置“需要你处理”入口，仅汇总确需用户判断的回复、正式决定、审查和无法合理协调的冲突，支持按项目或文献库筛选。普通重定位、重试和索引刷新由系统或 Agent 处理，不要求用户逐项清空待办。

普通运行进展保持可查看。关闭会话视图、切换布局或项目后，工作仍可以找回；无工作台启动后接入的待处理事项也进入同一组织方式。界面读取、投影及高频更新应有界，具体实现由架构落实。

### 原型与验证

- [第一轮文字线框](../prototypes/workbench-round-1.md)和[第二轮候选](../prototypes/workbench-round-2.md)：用于两轮人工讨论及选择。
- [可操作工作台草图](../prototypes/workbench-prototype.html)：可直接打开的单文件 HTML，通过 `?variant=agent|library|writing|review` 或切换条使用四种布局。
- [走查说明](../prototypes/workbench-prototype-guide.md)及[默认 Agent 布局预览](../prototypes/workbench-agent-preview.png)：记录操作方法、示例范围和观察重点。

Node 的 `vm.Script` 语法检查通过。Playwright 在浏览器中检查了四布局切换、指令与材料保持、元数据和批注草稿、稿件保存时机、冲突保护及保留手工修改的示例重做、局部应用与整体核验、会话视图关闭后找回任务、项目内访问库与独立库入口、待处理筛选、布局保存恢复和方向键行为；代表情境均通过。另用 Chrome 的本地 `file:` 入口确认了审查 URL variant 的实际渲染。

Playwright 环境限制直接访问 `file:`，因此交互检查使用原 HTML 在浏览器内存中加载，另外以本地 Chrome 核对文件入口。检查没有证明真实 Agent、PDF 阅读器、科研核验、权限、后台进程、持久化、崩溃恢复、性能或三平台交付。

原型只包含一个示例项目与独立文献库，状态保存在当前页面。重做提案仅演示预置语句的修改；普通文件、图表、计算及多稿件等完整产品能力仍沿已有范围实现。临时 HTML 不确定正式框架、编辑格式、diff 或数据模型的物理实现，不直接作为生产 UI。

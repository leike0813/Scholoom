## Question

在已确认的原生科研核心模型与 LangGraph 系列基础上，科研能力、Skill 和工作流如何被编写、发现、调用、交付、检查与延续？

本票将[核心模型](17-native-research-capability-model.md)落实为内容与执行契约，并沿用[科研 Agent harness](07-agent-runtime-boundaries.md)的统一生命周期。表达任务与调用、必要方法与材料信息、交付、正式决定、委派和授权，支持按当前材料及研究上下文继续工作。

具体源码、Rust、进程和 IPC、物理存储、编辑格式与依赖版本由后续票决定。本票不实现应用或迁移其他仓库；ResearchSpec 可选学科与工具扩展仍留待后续。

## Answer

用户确认了三轮各四项决策：首轮采纳前三项，并明确第四项为“不承诺兼容。本项目是为了替代旧项目，不需要兼容旧项目”；第二、三轮均回复“全部采纳”。本票于 2026-10-03 解决。术语见 [CONTEXT.md](../../../CONTEXT.md)。

2026-10-04 按用户确认的[低摩擦协同方案](13-storage-and-change-model.md)同步材料与方法留存、局部修改和恢复范围；普通任务直接工作，完整复现按明确需要采用。

以下是内容与执行契约草图，可用于后续实现规划。精确字段名、Schema 方言、SDK 签名和实现文件由实现规格确定；信息归属、接口职责和可观察行为按本票执行。

### 原生替代与能力吸纳

- Scholoom 不承诺兼容 zotero-agents 或 ResearchSpec。原生内容和运行接口按本项目需求组织，可以借鉴或复用已有方法、模板、科研约定、资源与实现；旧包格式、API、CLI 和运行方式不构成设计约束。
- 不预设旧包兼容层或导入转换器为必须交付。旧 workflow、Procedure、profile 和 Companion 所承载的方法、编排与协调职责，按已选原生结构吸纳或重建；具体源码取舍另票决定。
- Zotero 生态兼容目标沿用已确认政策，包含指定版本插件原发布包的兼容要求。标准 Skills 的采用属于本项目原生内容设计。

### 方法、声明与程序

- 方法使用标准 `SKILL.md` 及配套脚本、参考资料和模板。普通 Skill 可以直接作为方法使用，无需先补全科研能力声明。
- 需要明确可发现、可调用的科研能力入口时，增加独立 YAML 声明，由 Schema 校验。程序实现按需提供；同包可容纳多项方法与能力，引用共同资源，避免重复维护。
- 参数与结构化交付采用 JSON Schema，复杂程序检查引用检查器；科研判断沿方法与交付要求检查。结构有效与科研判断成立分别表达。
- 普通方法由通用科研 Agent 执行；稳定计算或转换提供程序入口；复杂编排使用 JavaScript/TypeScript 函数、LangGraph 图或子图。无需每项能力都编写图，也不另建完整图编排语言。
- 声明加载后归一为共同契约，目录、调用、校验与界面消费同一份可检查约定。实际作用域、出处与授权由目录和调用上下文提供。

| 声明部分 | 保存的约定 |
| --- | --- |
| 身份、格式版本与用途 | 稳定能力身份、内容版本、声明格式版本及简短用途 |
| 输入与参数 | 语义角色、必需性、接受的引用类型、参数结构与必要约束 |
| 方法与执行绑定 | Agent 可读方法，或注册的程序、图实现引用 |
| 资源需求 | 工具、材料及运行环境要求；声明本身不授予权限 |
| 交付与检查 | 产物角色和结构、必要程序检查及科研判断要求 |

身份、用途、执行绑定与交付要求构成能力入口的基础；输入、参数和资源按实际需要声明。

### 内容来源、发现与选择

- 内置内容、用户内容和项目内容进入共同目录；纯文献库任务可以使用全局内容。目录管理方法和能力定义，报告及其他任务产物通过材料与产物引用复用。
- 定义具有稳定身份和版本，记录出处与作用域。同名或同身份候选可以并存，由配置或本次调用明确选择；查询和执行记录显示实际采用内容，不依赖目录顺序静默覆盖。
- 先提供当前任务和可见范围相关的摘要，再按需读取声明、方法与资源；保留主动搜索和精确读取入口，无需把所有正文及能力展开成常驻工具。
- GUI、内置 Agent、CLI 和外部 Agent 使用相同定义与版本。内容可见性与执行授权分别判断。

### 调用输入、提交与运行时结果

| 接口部分 | 承载的信息 |
| --- | --- |
| 调用输入 | 负责的任务、必要方法与材料信息、参数及约束；按需指定固定版本 |
| 执行者提交 | 产物、必要来源、科研发现与限制、未解决问题及按需提出的变更 |
| 运行时结果 | 产物、进展与必要检查结果，区分实际完成工作和科研发现 |

- 材料引用接受研究对象、普通文件和既有产物，保留必要来源、方法与适用条件；关键证据及明确复现任务保存所需实际版本。报告正文和大文件通过引用交付。
- 初始材料是查询起点。新材料按实际使用关联调用及任务上下文，其文献库或项目归属沿用领域规则。
- 执行者提供产物与必要检查结果，Agent 结合当前材料判断进展。重要交付与正式决定按明确要求处理，不能把尚未完成的研究工作声称为已完成。
- 支持分批交付和部分产物复用。各批、步骤和调用按相应要求核验，整体任务仍需满足整体交付和正式要求。
- 普通修改核对实际目标范围，已有编辑由局部覆盖保护保留；Agent 适应常见变化，实质歧义局部处理。待审提案和明确固定版本的操作按相应约定核对。

### 原生执行扩展

- 注册的执行适配接入共同科研 runtime，基本执行形状为 `execute(request, context) -> submission`。上下文提供任务和调用身份、获授权服务、事件、取消信号及交付通道。
- 默认 Agent、程序或脚本、LangGraph 图与子图按这一职责连接；共享调用、资源、授权、核验和应用机制。具体 SDK 与进程调用形式由实现规格和架构票确定。
- GUI、CLI 和 Agent 调用共同内核；执行上下文不要求工作台存在。事件供工作台及其他客户端观察既有工作，正式研究事实仍通过共同服务读取和更新。
- 科研计划沿已确认模型作为持续任务工件保存与调整，计划勾选、图的技术终态和科研交付各保留自身含义。普通获授权安排和正式研究要求按对应规则处理。

### worker 工作包

- 工作包表达目标、任务和调用关联、初始材料、可用方法与工具、授权范围、交付要求及检查标准。
- worker 可以在权限内继续检索与读取。实际权限同时受父任务授权与工作包限制，执行者不能自行扩大。
- 主 Agent 统筹普通协作，executor 与 reviewer 是可配置职责预设。进一步委派和独立任务创建按目标、责任与授权安排，不因加载方法或执行一次工具自动拆任务。
- worker 返回产物、检查发现和 blocker；主 Agent 检查交付，正式状态由内核依规则推进。旧项目的 worker 限制不自动成为本项目要求。

### 程序执行与授权

- 领域对象写入、正式状态及结果应用通过共同内核接口；普通文件、临时产物和计算通过获授权文件或执行通道操作。
- 内容声明提出工具、资源与环境需求，实际权限由任务授权和内核配置决定。支持 Node 库和外部计算工具，由受管环境落实读写、命令、网络、中断和取消范围。
- 仅传入受限 runtime context 或限制文件工具路径，不代表任意代码受到相同约束。实际进程与权限边界由架构票选择，不能以声明代替有效执行约束。
- 普通获授权修改可以自动应用，需要审查或正式决定的操作遵循相应规则。已完成操作的撤销沿已有模型作为独立变更处理。

### 正式步骤与决定

- 科研步骤通过共同服务检查依赖、交付与正式要求，等待和恢复进入原生执行机制。
- 正式决定形成跨 GUI、CLI 和 Agent 入口可查询的共同事项，绑定提案、依据材料及版本、条件和授权主体，按相同规则处理。
- 回复后继续推进前，核对决定对当前材料和条件是否适用。材料更新不自动使所有决定失效，实质影响按已有变更规则处理。
- Agent 或执行者回报不替代正式决定、交付核验或实际应用事实。图技术状态和科研进展各表达自身事实，由统一内核协调。

### 方法记录、重试与恢复

- 普通调用保留必要方法、材料及结果信息。明确要求复现时，保存所需实际定义、程序、输入与环境；显示版本不能替代所留存的具体内容。
- 日常中断或更换后端时，从任务摘要、当前材料与可用会话／checkpoint 继续，针对下一步核查必要结果。恢复以继续工作为目标，不要求复原完整执行历史。
- 一次调用可关联重试、后端与会话；普通材料变化由 Agent 适应，需要独立科研使用或不同整体交付目标时再建立关联新调用。
- 不可轻易重复、代价较高或明确受管的关键操作保留必要身份与结果线索。能够确认已完成时使用既有结果；回报缺失时核查相关实际效果，不能盲目重复。
- 授权、正式决定或实际效果的未知问题只影响相关操作。Agent 可以在授权内核查与续做，其余工作继续。
- 数据库用自身事务，普通文件操作使用轻量保存与局部覆盖保护；不默认建设文件与数据库的通用事务。迁移等高影响工作按实际风险选择更强恢复。

### 内容编写、启用与积累

- Agent 可以按内容管理授权编写、修改和启用任务、项目或用户范围的内容。当次候选做法可以先保留在任务中，再选择沉淀。
- 启用检查声明结构、资源引用、程序入口及必要工具和环境，缺项返回结构化诊断。维护检查与运行期交付核验分别执行。
- 科研方法的适用条件和可靠性依据真实使用与检查记录积累，一次成功不自动成为全局默认。
- 授权范围内的局部编写与使用无需逐次人工确认；跨作用域启用、共享及外部发布遵循相应授权。
- 普通调用可在授权内读取更新后的方法并调整工作；明确固定版本的任务继续使用约定内容。内置内容可以派生为用户或项目版本，再明确选择使用。

### 情境核对

以下是契约语义检查，未运行应用、SDK、原型或真实科研任务。

| 情境 | 契约检查结果 |
| --- | --- |
| 文献管理、单篇阅读与精读 | 可独立使用文献库、全局方法与能力，不要求先建立项目；Zotero 兼容实现仍由原型票验证 |
| 批量精读中部分缺全文 | 产物可分别核验和复用，依赖缺失材料的部分保留障碍；worker 可继续获授权检索，不自动完成整体任务 |
| 文献综合、原创研究与完整稿件 | 文献及自己的数据、代码、结果和图件按角色绑定，证据、主张与稿件持续关联；投稿准备沿共同交付规则执行 |
| 审稿后补充计算、用户同时改稿 | 原有任务及产物继续可用，按独立目标决定是否新增任务；提交和应用检查稿件版本，回复声明依据实际结果和修改 |
| 暂停期间原地编辑能力 | 普通任务读取当前方法并按需调整；明确复现任务使用所保留的版本 |
| 修改已应用但回报缺失 | 结合当前材料与必要结果线索核查相关效果，避免盲目重复，其余工作继续 |
| 关闭工作台等待正式决定 | 待决定身份和依据持续存在，可由其他入口处理；续做前检查授权及当前适用条件 |

这些情境未暴露新的内容或执行契约决策。实际行为需要后续实现与运行验证。

### Agent、方法与科研工作

- Agent 按角色、资源与权限承担科研工作，可以使用多项能力；同一能力也可以由不同 Agent 执行。需要并行、独立检查或独立上下文时再委派 worker，加载 Skill 本身不必创建专用 Agent。
- 工具提供具体可调用操作，Skill 提供方法与资源，科研能力明确可复用工作及其输入、产物与检查约定。一项能力可使用不同方法，一种方法可服务不同工作；允许在同一个内容包承载方法与约定，避免重复维护定义。
- 没有现成能力时，Agent 仍可使用获授权工具和方法，根据目标形成工作安排与交付要求，进入共同授权、产物与审查机制。

### 持续任务、调用与执行

- 按独立目标、责任和交付需要划分任务与子任务。批量精读可以是一个任务；需要分别负责、并行处理或独立验收时再拆子任务，新增计算是否成为任务取决于是否形成独立工作目标。
- 一个任务可以包含多次能力调用，每次调用有一个明确直接负责的任务；调用本身不自动创建子任务。其他任务可以复用产物及其研究条件，无需共同拥有同一次调用的完成状态。
- 调用对应一次具体科研使用，重试、中断与常见材料变化可在原调用内继续。更换 Agent、会话或引擎不自动改变科研身份；形成独立科研使用或实质不同的整体交付目标时，再关联新调用。
- 任务、调用、执行记录和会话分别表达持续目标、具体使用、实际执行经过和交互上下文。执行引擎标识的映射、恢复与重试的技术判定留给运行时契约票。
- 沿用已确认的文献库独立使用要求，纯文献库工作无需建立研究项目；按工作需要使用任务、计划及交付约定。

### 工作流与研究计划

- 工作流组织内部工作；具有明确输入和整体交付约定的可复用工作流，可以通过同一科研能力入口被发现和调用。内部步骤、依赖与正式要求可检查，由共同 runtime 组织；临时工作安排无需全部注册成能力。
- 步骤以可独立交付、核验或作出正式决定的科研工作段为主要边界。每段明确目标、输入、产物与约束，Agent 自主选择具体方法与工具；需要稳定复现的过程可以规定必要操作与顺序。
- 研究计划是任务中的持续工件，供人和 Agent 查看、调整下一步、备选路径及理由。真实进展依据产物、校验与正式决定，计划勾选不独立宣布完成。
- 普通安排可以在授权范围内调整；改变已确认研究承诺、授权范围或正式要求，遵循相应决定与变更原则。普通任务与正式流程由同一内核执行，沿用已确认的正式控制要求。

### 输入、产物与交付

- 按用途声明输入，调用保留必要材料与方法信息。普通文件可直接使用；关键证据、重要交付及明确复现任务保存所需实际版本，不要求每次调用先固定全部输入。
- 入口明确必要输入，Agent 可在授权范围内继续查询新材料并记录实际使用来源，保持开放的上下文获取。
- 分开表达执行情况、交付是否满足约定，以及科研发现与限制。有依据的否定发现可以完成评估任务；依赖缺失材料的验证可以保留产物并记录阻塞；程序或工具失败保留实际错误。
- 步骤与调用按当前用途进行必要检查，缺项和问题局部处理。整体交付及必需正式节点沿明确要求判断完成，局部成果可继续使用。
- 消费结果依据本次约定及已核验产物，不能只凭返回文本或生成文件认定完成。科研发现按领域规则渐进形成候选证据与主张，保留依据与条件；报告完成不自动确认研究主张。

### 分支与正式决定

- 可直接判定的条件由程序检查；科研判断由 Agent 提供分析依据，在授权与工作安排范围内选择或提出路径。
- 运行时检查必要输入、依赖、交付与正式要求。正式决定遵守已有授权和确认原则，Agent 自主段可以组织新路径。
- 证据不足后的继续检索、补充计算或待解决工作，按当前任务目标、交付约定与授权选择。需要确认的正式要求保持明确，程序状态推进仍以实际产物、校验和决定为依据。

### 定义更新与做法沉淀

- 普通调用记录必要方法、来源与结果，材料或方法更新后 Agent 可在授权内调整工作。重要成果保留必要研究条件，在相关工作中按需核验。
- 明确复现任务和正式流程要求固定版本时保存相应内容；普通任务不完整冻结方法、材料与环境，不另建完成状态权威。
- Agent 可以提炼和编辑候选 Skill、能力及工作流。当次做法先留在任务中，选择沉淀时保留原始用途、适用条件、来源与验证结果，按内容管理授权启用或共享。
- 一次任务成功不自动使定义成为全局默认或证明通用可靠；新增定义沿用任务与资源授权边界，具体编写和启用机制由后续票细化。

### 四类科研情境核对

以下是概念与语义检查，没有执行应用、SDK、原型或真实科研数据测试。

| 情境 | 模型中的工作安排 | 交付与延续检查 |
| --- | --- | --- |
| 单篇精读 | 库任务或项目任务绑定材料版本，Agent 选择方法、读取材料并交付分析 | 可独立使用文献库；评估证据时，充分说明证据不足可以是有效交付；依赖缺失全文的工作可以保留结果并记录阻塞 |
| 文献综合到稿件 | 工作流组织来源比较、论证形成、写作与检查，调用关联实际材料和稿件版本 | 证据表完成可供写作使用，稿件及整体要求尚未满足时继续工作；普通文件与渐进结构化研究对象均可使用 |
| 自己的实验或计算支撑原创研究 | 数据、代码、结果与图件作为来源，按需组织计算、分析和写作 | 所用版本和条件可追溯；科研发现逐步关联候选证据与主张，完成计算或报告不自动确认研究承诺 |
| 补充验证的审稿修订 | 意见、稿件及结果按版本关联，计划安排新增工作，需要独立目标和责任时建立子任务 | 回复完成声明依据实际结果与稿件修改；中断、重试或更换 Agent 后沿任务及调用继续，正式要求仍须满足 |

上述情境未暴露需要新增的核心概念。剩余接口、内容和执行机制由后续票承接。

# 交互式科研界面的原生接口与工作流接入

Labels: wayfinder:decision
Status: resolved
Assignee: Codex；主 Agent 与用户讨论（2026-10-13）
Parent: [产品与工程基础决策地图](../map.md)

## Question

如何将 Agent 生成的交互式科研界面作为一等原生能力，并供迁入的科研工作流共同使用？

## Answer

2026-10-13，用户明确希望支持，并指出这对用户体验非常重要。交互式科研报告作为正式产品需求纳入范围；本票确认产品方向，不代表运行接口和具体实现已经定案。

用户进一步明确：这种交互式界面应像其所参考的 Codex 体验一样，成为一等原生接口，使从 zotero-agents 和 ResearchSpec 迁入的许多工作流能够无缝接入。Codex 在此是交互定位参考，未指定复用其协议或 SDK。

### 一等原生交互接口

Agent、科研能力与工作流共用可调用的原生交互接口，能够呈现和更新交互界面、接收用户在界面中的选择与输入，并在共同执行路径中继续工作。工作台负责承载界面和传递交互；科研判断、实际执行及持久化仍由既有模块负责。

交互报告是这一能力的用途之一，界面也可服务于工作过程中的材料筛选、方案比较、结果探索和审阅处理。工作流按需要使用同一入口，不为每个迁入工作流单独建设呈现与交互回传机制。

迁入后的 zotero-agents 与 ResearchSpec 工作流以顺畅接入该原生接口为设计目标，沿 [#18 原生内容契约](18-native-capability-runtime-and-content.md)与 [#25 共同执行接线](25-harness-business-integration.md)吸纳方法和实现。具体迁入适配与效果仍须验证，本票未选择旧协议兼容层。

### 科研产物的呈现与保存

文字分析、推导与审阅意见沿用 Markdown／QMD；表格和图件提供适合内容的查看与交互。支持 Agent 按研究需要生成 HTML 交互报告，用于文献方法对比、结果探索或参数展示等场景。

报告及所需文件保存在工作区，能够再次打开并由 Agent 继续修改。工作台内可以操作报告中的筛选、排序、展开、缩放等交互；具体组织方式由用户和 Agent 按需要决定，不要求每一种分析都预先对应固定业务页面。

工作台提供共同的打开、查看、附加材料和向 Agent 提问入口。用户可以将报告中当次选择的条目或内容交给 Agent 继续分析或修改。选择的具体传递契约仍需细化，不依赖持续精确原文定位。

### 已有执行与会话边界

浏览和筛选已有结果可在报告内完成；需要工程环境的新计算、实验或构建沿共同受管执行与已有授权规则处理。报告内交互脚本的能力边界另行细化，不能仅因报告采用 HTML 就推定其拥有任意文件、网络或内核访问能力，也不把所有页面交互一概变成科研执行。

报告是工作区工件，不要求绑定会话或研究任务。后续工作沿 [#43 统一会话](43-free-agent-conversation-and-research-tasks.md)、[#44 定位范围约束](44-defer-continuous-precise-source-location.md)及 [#40 执行约定](40-research-execution-environment.md)。

## 待细化的契约

- 原生交互接口的输入输出、界面更新和用户交互回传契约；如何附加当前选择、发送指令或请求执行，是否直接调用领域工具，以及如何表达实际运行状态。
- 页面运行隔离、工作区资源读取、外部资源与网络访问的边界。
- 文件组织、资源依赖、报告更新及交互状态保留方式；尚未选定单文件封装、报告 SDK 或特定前端框架。
- 浏览器与 Electron 共同工作台中的接入、无工作台时的呈现与交互等待行为，以及代表性迁入工作流的实际体验验证。

## 验证边界

本轮仅确认需求并同步产品文档；未生成报告原型、修改运行代码或验证页面与 Agent 的真实交互。业务实施时机仍由用户决定。

## Answer

2026-10-09，用户确认 Q1、Q2，随后明确采纳 Q3–Q5。本票解决对象交互的行为方向，沿[已有工作台组织](10-workbench-interaction.md)、[原生格式与定位](11-reading-writing-format.md)、[低摩擦协同](13-storage-and-change-model.md)及[工作区承接](35-research-workspace-context.md)落实；具体组件和运行接线留到实现。

### Q1：对象旁与 Agent 面板共用指令

选区旁可就地输入，也可把选区加入 Agent 面板补充材料；两个入口共用同一条待发送指令。发送前显示目标任务、接收 Agent 和选区，目标与辅助材料分别可辨。后续交流与结果回到同一任务，原位置可打开对应修改。浏览和切换对象不自动改变任务、授权或已附加材料。

### Q2：对象选择与图片区域标注

图表／报告支持对象选择与区域标注。有结构信息时可选子图、图例、坐标轴标题等具体对象；普通图片可框选区域。界面明确显示实际选取目标，图表修改沿可找到的生成来源进行并重新生成图件。没有已知编辑结构时，区域标注只提供指令定位，不宣称已取得其中元素的可编辑语义。

### Q3：原位查看结果与依据

修改后在对象原位提供入口，可展开差异、修改理由、依据和执行者；任务页汇总关联产物。普通修改沿已有授权直接应用，需要先审时显示候选。对象当前内容、实际应用情况与任务进展沿共同事实源展示，界面不另立研究事实或完成状态。

### Q4：局部撤销与 Agent 变化通知

撤销记录回到原任务，并向负责 Agent 提供变化线索，后续修改前读取当前内容。撤销本身不自动重启任务；遇到后续编辑重叠，仅协调受影响部分，保护后续编辑。通知的具体接线沿共同内核与 harness 契约实现；不能用界面提示冒充 Agent 已读取或已经适应变化。

### Q5：审阅意见关联实际修订与回应

从意见直接向主 Agent 发指令，补充材料或要求，沿当前任务安排修订。保留各角色原意见，关联正文、图表、回应及处理理由；应用修改后，依据实际回应判断是否解决。意见处理、实际应用和整体交付分别可查看，沿[多模型协作](37-multi-model-research-collaboration.md)保留角色职责与用户介入。

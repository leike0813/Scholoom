## 本票需要讨论

- 保留三层：题录／元数据（可含 abstract）、Digest 分析产物、原文；Digest 不等同论文摘要。
- 明确主题／项目／集合等使用范围、跨层检索结果、继续深入原文及证据返回来源的行为；范围名称以已确认模型为准。
- 以 zotero-agents 成熟的 Digest、参考文献提取、引用分析与文献评价实践为内容依据，核对其在原生文献身份、材料与产物关系中的组织方式；旧文件名和 Schema 按已确认的原生用途原则处理。
- 核对通用分析与面向问题的分析怎样被发现与区别，保留方法、目的、来源和适用条件，避免仅因更新较晚覆盖旧观点。
- 讨论原文或分析暂缺、分析状态变化时的读取体验；自动补齐与维护交给综合维护票。
- 沿文献管理票确认的共享阅读方式，明确批注与文献笔记如何被分析读取，区分原文摘录、作者批注与 Agent 解释，以及库级理解和项目判断。

### 分析内容依据

以 zotero-agents 的成熟实践吸纳 Digest、参考文献提取、引用分析和文献评价的内容与方法。原生文献身份、材料与产物关系按 Scholoom 已确认模型组织，旧文件名与 Schema 沿文献场景已确认的原生用途原则处理。

### 统一混合检索接口（Q3）

2026-10-09，用户确认模块组合词法匹配与语义召回，Agent 选择查询、范围与所需层级。

| 内容 | 索引与关联方式 |
| --- | --- |
| 题录／元数据 | 按字段检索，关联稳定文献身份。 |
| 四类分析产物 | 按各自产物内容检索，保留类型、目的及原文关联。 |
| 原文 | 按可定位的内容片段检索，关联附件、材料版本与原文位置。 |
| 主题综合 | 作为综合产物参与发现，保留关联文献与分析。 |

索引承载可重建的检索数据，实际内容从对应材料或产物读取。沿用已确认的三层知识关系，主题综合参与发现，不新增必须逐层通过的工作流程。

- 标识符、标题、术语等明确查询保留精确与词法匹配，自然语言研究问题结合语义召回。
- 模块融合检索结果，同一文献的多个命中归组，保留不同层级、产物与原文位置，避免长论文因片段多而挤满结果。
- 返回有界命中、来源引用、定位及覆盖情况；后续读取接受这些引用，展开产物或原文上下文。
- Agent 可指定范围与层级；使用统一发现接口，无需分别调用多个索引再自行拼接排名，各层仍可单独查询和读取。

融合权重、切分参数与具体索引实现留到有依据的实验与技术讨论。召回质量、结果融合与性能尚未验证。

### 直接交付内容的读取接口（Q4）

2026-10-09，用户确认读取工具直接交付 Agent 可消费的内容，并保留文件与原材料访问。

| 对象 | 读取结果 |
| --- | --- |
| 题录、结构化分析产物 | 结构化内容与关联引用。 |
| Digest、主题报告、笔记 | 正文及来源、适用条件和定位。 |
| PDF／EPUB／网页原文 | 可读内容及原文位置，支持局部展开和分批读取。 |
| 需视觉核验的图表、公式等 | 页面或区域访问入口，保留原材料关联。 |

原生读取模块承担格式解析，复用和维护解析结果。搜索命中的来源引用可以直接用于读取；Agent 自主选择文本、结构化内容或原材料，特殊处理仍可访问文件并使用其他工具。

材料暂缺、解析未完成或定位失效时，沿[文献管理行为](32-literature-management-behavior.md)的渐进完成原则返回真实可用情况。具体解析工具、读取 Schema 与分页参数在实现规格中确定。

## Question

首阶段用什么主格式承载稿件和笔记，提供什么阅读、批注、引用、公式及图表能力？编辑体验、可导出文件与 Agent 可操作结构之间如何取舍？

根据真实工作链路和原型讨论 Markdown、LaTeX、结构化富文本及 DOCX 互操作，明确主编辑格式与交付格式的关系。考察 Zotero 阅读器和引用相关能力的可复用边界，明确证据位置与稿件修改的稳定定位需求。不要默认已经选择 Markdown，也不要提前承诺多种格式之间的无损双向编辑。具体组件与版本在路线明确后调查和选定。


## Answer

用户已确认两轮建议，并修正阅读组件的复用优先级，本票于 2026-10-03 解决。以下是首阶段的阅读与写作路线；具体组件、版本、物理存储与执行隔离沿后续票选择。

2026-10-04 按用户确认的[低摩擦协同方案](13-storage-and-change-model.md)同步普通定位、工程执行和版本留存范围；编辑格式与阅读选型方向保留。

### 正文格式与权威

- 默认新稿件使用 Quarto Markdown（QMD）；普通笔记和报告可使用 Markdown（MD）。
- 已有 LaTeX 工程直接作为原生稿件使用，支持源码编辑、编译和版本审查。保留主文件、多文件结构、引用资源、模板及图表资源，不要求先转换为 QMD。
- 每份稿件明确其权威源文件或文件组。编辑器状态、解析结构、预览和导出产物不另立一份当前正文；研究关系与执行状态继续沿既有领域权威保存。
- 各格式通过共同科研内核进入研究对象、版本与变更管理，按实际支持的语法提供内容操作。接受多种原生格式带来的解析、预览、编译和导出维护成本。

### 人类编辑与终稿排版

- 源码编辑是共同基础。QMD／MD 同时提供覆盖已支持学术语法的可视编辑；LaTeX 提供源码与编译 PDF 预览。
- 源码与可视模式编辑同一份文稿。无法完整表示的内容保留并提供源码编辑入口，切换模式不能丢失内容。编辑器序列化与格式规范化边界需用代表性文稿验证。
- 以连续正文编辑为主，提供公式、引文、表格、图表及结构查看能力；投稿版式由目标模板与渲染配置生成并预览。

### 阅读组件独立选型

- 阅读引擎、阅读与批注 UI、科研证据和材料版本关系分别评估。阅读组件独立选型，不预设优先复用 Zotero reader。
- PDF.js 与 EmbedPDF 是值得重点比较的开放候选；Zotero reader 可作为科研阅读功能参考和候选。此票没有选择具体库或版本，也没有认定某一候选性能更好。
- PDF、EPUB 与网页快照可采用适合各格式的组件，由科研内核维护共同的来源、版本、书签、批注与证据关系。
- 组件承担显示、搜索、选区和批注交互；Agent 可以通过科研内核独立读取材料、位置及批注，不依赖打开阅读窗口。SDK 的 headless 名称不代替这一要求的运行验证。
- 已确认的 Zotero 生态及原包插件功能承诺继续保留。阅读组件的选择与原插件所需接口分别验收，宿主接入沿兼容策略与宿主票决定。
- 比较候选时覆盖多栏和扫描论文、数学与图表、跨页选区、大文件、批注导入导出、完全离线打包、维护情况及许可条件。

### 学术内容与引用

- 引文、公式、图表和交叉引用沿原格式的标准写法。QMD 使用 Pandoc／Quarto 引文与标识；LaTeX 保留其原生引用与编译路线。
- 内核为 GUI 和 Agent 提供相关查询与编辑操作，包括定位文稿内容、插入或修改引用、读取关联材料及提交变更。
- 稳定来源身份与 DOI、Zotero key、citekey 等映射沿领域模型管理。正文无需改用 Scholoom 私有引文语法。
- 引文可包含文献组合与页码等定位信息，样式渲染与依据核验分别表达。CSL 或 BibTeX／Biber 等输出路线按格式与工程配置选择，不用格式化引文替代证据核验。
- 公式保留 TeX 表达；图表资源保留标题、标识与出处，编号和交叉引用显示由渲染规则生成。具体可编辑结构与不支持语法的保留方式在组件选型中验证。

### 原文、证据与稿件定位

- 原文位置关联实际材料版本，并保留相应格式的位置与上下文，如 PDF 页索引和页面区域、EPUB／网页文本范围。结构化文本或 OCR 提取的位置需能回到原材料。
- 日常稿件位置按文件、结构及当前内容定位；重要交付与审稿轮次关联留存版本。章节、引文、公式与图表可沿格式标识定位，普通段落与选区采用适合内容的位置表示。
- GUI 中的选区和 Agent 的材料引用进入同一定位契约。批注位置、结构化文本映射与跨版本恢复分别处理，不假定几何坐标或文本映射自动解决材料改版。
- 段落移动、重写或拆分后，先按需重定位；仍无法确定含义对应时在相关工作中提示核验，不阻塞无关编辑。

### 普通预览、工程渲染与科研执行

- 打开文稿和日常预览读取正文与已有结果；科研代码由人或 Agent 按授权明确发起执行。
- 工程渲染按实际项目配置处理代码、过滤器和构建步骤，实际执行、结果与错误进入共同科研内核记录，不建立独立于原生运行时的文稿执行控制器。
- 日常渲染保留必要来源、配置与结果信息；重要交付或明确复现要求时保存所需正文、引用资源、模板及其他依赖版本，不默认冻结每次预览的全部输入。
- 已有结果保留其来源与执行状态。运行失败或尚未执行时，不能把旧结果显示为已经完成的新结果；恢复与重试沿共同运行时契约处理。

### 交付与外部改稿

- 支持 DOCX、PDF 和 LaTeX 源文件交付，交付内容关联其实际采用的稿件版本与资源。
- 收到外部文稿时保留原文件，将可识别的正文修改、批注和修订关联到稿件、待解决问题或变更，再按项目授权应用。
- 导入、导出与修改回收明确各自的保真边界。复杂版式、宏、引用字段和审阅信息无法完整转换时保留原材料并说明限制，不承诺多种格式的完整无损双向编辑。

- [阅读与批注源码边界](../research/reading-and-annotation-boundaries.md)：Zotero reader／note-editor 的宿主、位置、保存和许可事实；同时修正了参考文档对 PDF 批注坐标的概括。
- [现代阅读组件](../research/modern-reader-components.md)：PDF.js、EmbedPDF、React-PDF、EPUB 组件、内置查看器与商业 SDK 的候选事实和待验证样本。
- [CSL 引文数据](https://citeproc-js.readthedocs.io/en/latest/csl-json/markup.html)与[处理器接口](https://citeproc-js.readthedocs.io/en/latest/running.html)：文献、引文组、定位与渲染更新的区别。

实施后应验证源码／可视切换保留内容、已有多文件 LaTeX 工程直接使用、GUI 与 Agent 操作同一文稿及材料版本、重要引用返回原文、旧版本变更不覆盖新正文、科研执行失败与已有结果区分，以及外部反馈回收可追溯。本段是验证要求，不代表当前已有这些实现。

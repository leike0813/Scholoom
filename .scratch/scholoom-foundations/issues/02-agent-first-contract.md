## Question

在科研 Agent 内核由运行时及配套 harness 构成、工作台作为人类界面的定位下，Agent 作为一等公民具体拥有哪些能力、可见状态和决策权限？当图形界面关闭、会话结束或执行引擎更换时，哪些研究工作必须仍可发现、执行、检查和延续？

[全流程产品形态与真实使用验收](01-first-product-loop.md)已确定：内核可以无工作台执行完整科研任务，工作台随后可接入、查看和介入已有工作。本票进一步明确相应的能力和状态契约。

用实际情境明确人类工作台和 Agent 如何接入科研内核，内置与外部 Agent 的身份和职责、工具发现、任务状态与产物归属，以及自主修改、变更提案和人工决定的边界。不要默认所有操作都需人工确认，也不要默认一个可写文件的执行进程已经受到应用权限规则约束。“All by agents”在开发协作中的含义交由工程纪律票讨论。

## Comments

用户对科研能力调用、内置与外部 Agent、上下文获取、自主执行与人工决定、任务与会话关系、人的介入与同时工作六项建议回复“全部采纳”。

## Answer

2026-10-03 经用户采纳，本票解决。以下是产品使用侧 Agent 一等公民的约束；“All by agents”在开发协作中的具体纪律仍由对应工程票决定。

2026-10-04 用户确认[低摩擦协同方案](13-storage-and-change-model.md)，下述持续上下文、局部覆盖保护与人的介入规则已同步。

### 科研能力可直接调用

文献搜索与整理、阅读分析、脚本执行、稿件修改、引用检查等科研业务能力提供 Agent 可直接调用的接口，返回结构化结果。工作台操作和 Agent 调用进入同一套领域能力与状态管理。

### 内置与外部 Agent 共用领域契约

支持内核运行的 Agent 和外部 Agent 接入文献库、研究项目、任务与产物。两者共享领域接口和状态契约，分别配置授权范围。接入协议和首个执行引擎尚未选择。

### 按任务主动获取上下文

提供与当前任务相关的初始上下文，Agent 可以在授权范围内主动检索文献、读取来源上下文、查看稿件和研究决定。材料可定位到来源和版本，查询与读取具有明确范围。

### 以任务级授权支持连续执行

明确任务范围后，Agent 可连续推进分析、计算和产物编辑，变更能够检查和撤销。正式研究决定、原始材料的破坏性修改及对外提交设置明确的授权或人工节点，具体节点可以配置。

授权节点的分类与配置、执行进程的权限落实和变更应用机制交由后续领域、harness 与存储票细化。

### 研究任务独立于会话持续存在

研究任务具有独立身份、进展和产物，长期保留目标、关键约束、计划、产物、重要决定、已知问题与下一步。会话承担即时上下文，执行记录用于必要诊断与继续工作。任务可跨会话、跨 Agent 和跨执行引擎开展，无需先复原完整执行历史。

跨执行引擎延续以读取已有研究状态和产物续做为目标；具体会话恢复与迁移方式由执行引擎路线票决定。术语定义见 [CONTEXT.md](../../../CONTEXT.md)。

### 支持人的介入和并行工作

人可以在 Agent 执行期间继续编辑材料、补充指令、暂停或取消任务。Agent 修改实际目标时保护已有编辑，普通变化通过重新读取、重做补丁或调整工作处理；无法合理协调的含义歧义或持续竞争只暂停相关修改。工作台可查看进展、差异与产物，仅将确需用户判断的事项交给人。

### 验收情境

- 内置与外部 Agent 在各自授权范围内通过领域接口完成科研操作，工作台呈现对应研究状态与产物。
- Agent 从初始任务出发，按需获取来源上下文；材料引用可定位到来源和版本，读取范围明确。
- 一个任务可在结束会话或更换 Agent 后，从既有目标、进展、产物与决定继续开展。
- 用户改稿后，Agent 适应相关变化并保留已有编辑；无法合理协调的局部冲突明确呈现，其他工作继续。
- 用户可以查看正在执行的任务，追加指令、暂停或取消；配置的授权或人工节点仍适用。

上述情境沿用已确认的无工作台执行和工作台随后接入要求。接口 Schema、状态模型、权限执行机制及具体验证方式由后续票确定。

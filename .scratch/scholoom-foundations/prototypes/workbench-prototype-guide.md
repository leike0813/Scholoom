# 工作台交互原型走查说明

配套文件：[workbench-prototype.html](./workbench-prototype.html)（单文件，可直接打开）

决策依据：[用粗原型确定对象、Agent 任务与变更审查的工作台组织](../issues/10-workbench-interaction.md)。两轮文字选择已经确认，这份可操作的草图用于进一步讨论信息密度、区域排列和操作衔接，尚待用户界面反馈。

## 怎么打开

双击 `workbench-prototype.html`，用浏览器打开即可，不需要安装依赖、启动服务或联网。若双击后页面行为异常，可用浏览器的“打开文件”手动选择该文件。

四套布局对应四个 URL variant，可直接以地址栏进入，也可从页面底部的切换条在四者之间循环：

```text
workbench-prototype.html?variant=agent
workbench-prototype.html?variant=library
workbench-prototype.html?variant=writing
workbench-prototype.html?variant=review
```

首次打开以 Agent 布局进入。四套预设各自偏重的中央区域如下，切换只是换组织方式，不换任务：

| variant | 中央主要呈现 | 常见辅助区域 |
| --- | --- | --- |
| `agent` | 当前任务的 Agent 工作、交流、进展与交付 | 任务导航、执行者、相关材料预览 |
| `library` | 文献列表、示例原文选段 | 元数据、标签、批注、Agent 指令 |
| `writing` | 稿件编辑区、可选来源分栏 | 相关主张、来源、Agent 指令 |
| `review` | 按研究目的或意见归并的修改与核验 | 事项导航、差异、依据、回复文本 |

## 验证范围

可直接操作布局、输入、材料标签、编辑草稿、示例版本冲突和待处理入口。浏览材料、附加材料和任务已读材料分别显示；发送指令会加入任务交流记录，原型没有模拟 Agent 实际读取新材料。

文献、Agent 进展、提案及版本来自内置示例，支持一个项目与独立文献库。原文阅读区是选段草图，不是真正的 PDF 阅读器。权限、计算、模型调用、存储与恢复机制需要在正式内核中实现和验证。

## 建议走查路径

下面六条各自有可观察的结果。顺序不必强求，遇到与预期不符的地方随时停下记录更有价值。

1. **四套布局连续切换。** 在任一布局下切换到另外三套，再切回来。观察：当前任务、编辑中的稿件草稿、输入框里未发出的指令和已附加的材料是否原样保留；区域大小、折叠与分栏的局部调整是否在切换后仍在，以及能否保存并恢复。

2. **材料附加与指令定向。** 在文献视图选中一段示例来源作为选区，附加若干材料后发送一条指令。观察：发送前是否显示清楚指令的目标任务与接收者；界面能否区分当前正在浏览的材料、用户附加的材料、以及 Agent 实际列为已读的材料；三者不一致时是否有可见的说明。

3. **项目内的库与独立库任务。** 先在项目上下文中打开全局文献库并在其中浏览来源，然后离开项目、直接以库为上下文建立一个任务。观察：浏览库时当前项目与任务是否被保留；指令接收任务与被浏览材料是否分开表述；无项目时能否独立管理、阅读并推进任务。

4. **手工改稿与保存时机。** 在写作布局直接编辑正文草稿，期间来回切换布局，之后点保存。观察：主稿版本号在点击保存之前是否保持不变；草稿在切换过程中是否持续存在；保存之后主稿是否才更新，以及是否能看出更新前后的差别。

5. **审查、冲突与逐项应用。** 给原正文末尾增加一句作者说明并保存，再进入审查。旧提案的接受操作应提示冲突；选择按当前版本重做后，作者说明保留。逐项接受正文与回复，观察剩余事项和实际应用情况；两项均应用后，整体回应仍需单独核对。示例重做仅演示收窄预置句子；修改该句本身时会提示需要重新判断，不模拟通用 Agent 写作。

6. **后台事项与重新找回。** 关闭会话视图，从任务或会话入口重新打开；也可从“需要你处理”定位审查、范围决定或缺全文材料。观察范围筛选及任务归属，在项目与独立库之间切换后找回工作。此过程只保留页面中的示例状态，没有真正后台进程。

## 记录方式

建议按上面六条逐条写：哪里符合预期、哪里别扭、哪个信息找不到、哪个区域该常驻不该折叠。反馈可以直接写进[决策票](../issues/10-workbench-interaction.md)或在原型旁边另记，走查结论确认后再更新票中的确认范围。

## 原型限制

- 所有文献、Agent 进展、修改提案、版本与冲突均为示例数据，不代表真实科研内核行为，也没有经过任何权限、计算或模型调用的验证。
- 状态全部保存在内存中。刷新或重新打开页面即重置，布局与材料也不会跨页面保存。
- 没有真实 PDF 打开与阅读，没有批注落盘，没有真实的元数据写回。
- 布局的分区比例、折叠与“保存布局”只在本次打开期间有效，不跨会话保留。
- 未做跨平台与性能验证，不同浏览器、窗口尺寸下的表现可能不一致。
- 这是一次性讨论材料，不接入任何外部服务，也不发布到公开位置；确认后的结论需要落到正式 UI 规格，原型本身届时可丢弃。

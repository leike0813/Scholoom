# Agent 工作优先与多布局：第二轮候选

依据第一轮选择，以 Agent 工作优先的方案 B 深化默认工作台，并研究多种布局。用户已采纳第二轮五项建议；本稿保留讨论素材，确认细节以[决策票](../issues/10-workbench-interaction.md#answer)为准，可操作版本见[工作台草图](workbench-prototype.html)。以下仍是文字原型。

## 布局预设

| 候选预设 | 中央主要区域 | 常用辅助区域 |
| --- | --- | --- |
| Agent | 当前任务的 Agent 工作、交流、进展与交付 | 任务导航、执行者及相关材料预览 |
| 文献 | 文献列表或 PDF 阅读，可展开对照材料 | 集合与标签、元数据、批注及 Agent 交互 |
| 写作 | 稿件编辑，可与来源或图表分栏 | 章节结构、证据、引文及 Agent 交互 |
| 审查 | 当前研究目的或意见的相关修改与核验 | 事项导航、差异、依据、冲突及回复文本 |

```text
Agent：任务导航 │ Agent 工作与交流 │ 材料预览
文献：集合导航 │ 文献列表／PDF    │ 元数据与批注
写作：章节导航 │ 稿件  │ 来源／图件 │ Agent 交互
审查：事项导航 │ 修改与核验       │ 依据／回复
```

候选切换规则：首次以 Agent 布局进入，后续恢复上次工作安排；用户可主动切换预设，调整区域大小、折叠面板和分栏，保存常用布局并恢复默认。布局只组织展示，现有任务、选定材料、未发送指令与编辑草稿保持连续；切换后明确显示指令接收任务和 Agent。草稿的实际保存机制留给存储与编辑规格。

## Agent 工作页

候选默认信息为当前目标和下一步、Agent 交流、工作进展、产物及需要处理的事项。研究计划、委派关系与工具活动可以展开；具体工具结果可打开为科研材料。逐条技术日志可按需查看，不作为主要工作内容。

交互默认面向负责当前任务的 Agent。查看 worker 或其他会话时能辨认所属任务与接收者，定向发出的指令沿用实际授权范围。能力调用、尝试与会话记录由共同事实供界面查询，不重新设立 UI 完成状态。

## 日常文献与编辑操作

候选提供直接操作：文献搜索、导入、集合和标签整理、元数据编辑、PDF 阅读批注，以及稿件的普通编辑。按钮、菜单、快捷操作与命令入口按实际需要提供；Agent 承担批量整理、分析、综合及跨对象工作。直接操作与 Agent 调用共用内核，批量修改的预览、检查与恢复沿用其规则。

## 文献库、项目和后台工作

候选让文献库有独立入口，也能从项目中打开。正在工作的项目与任务可以保留；浏览库来源与指令接收任务分别显示。不进入项目时也能管理、阅读和建立库任务。

候选设置持续可见的待处理入口，汇总等待输入、正式决定、修改审查、冲突和需处理的失败；可按文献库、项目及任务筛选，点入相应任务或对象。普通运行进展保持可查看，用户不必逐条阅读执行消息。切换布局或项目后工作仍沿共同内核继续，下次接入可以找到相关事项。

## 第二轮问题

1. 是否采用四种布局预设及局部调整、保存与恢复的方式。
2. Agent 工作页如何组织默认信息、进展与交流。
3. 日常文献管理和编辑提供哪些直接操作入口。
4. 独立文献库与项目内访问怎样衔接。
5. 后台待处理事项怎样集中呈现和导航。

## 后续原型计划

本轮明确后，以临时交互原型呈现布局切换及工作走查。验证重点是：独立文献库、并行阅读与 Agent 工作、选区指令、跨对象审查、用户同时改稿，以及后台任务再次接入。界面样例不替代真实内核的权限、计算、版本冲突和恢复验证。具体格式、组件和正式 UI 工程分别由[阅读写作格式](../issues/11-reading-writing-format.md)、[架构](../issues/09-electron-architecture.md)及[技术栈](../issues/12-technology-stack.md)决定。

# 工作台组织：第一轮文字线框

本稿是第一轮讨论使用的临时文字原型，保留三种候选供比较。问题是：人类如何在同一个工作台中组织 Agent 工作、操作科研对象并审查产物？覆盖文献管理至整篇写作、投稿准备和审稿修订的使用场景。用户倾向方案 B 并希望支持多种布局，其余三项采纳；确认细节以[决策票](../issues/10-workbench-interaction.md#answer)为准，可操作版本见[工作台草图](workbench-prototype.html)。

本轮只使用文字线框。默认结构确定后，再制作可切换布局和走查情境的交互粗原型；当前没有 UI 代码、持久化或真实材料操作，也没有选择前端及编辑器技术。

## 已确认的依据

- 工作台是科研 Agent 内核的人类界面，形态参考文献管理与写作定制的 VS Code；内核可以无工作台执行，工作台随后接入。
- 长期文献库可以独立使用；项目容纳稿件、研究材料与工作。普通文件和结构化科研对象均可访问。
- 任务、Agent、会话和执行记录含义不同。任务与产物持续存在，更换会话或执行者后仍可继续工作。
- 人和 Agent 可以同时工作，提交和应用修改检查材料版本。普通获授权修改可以自动应用，正式要求与审查按已有规则处理。
- Agent 能在授权范围内继续查询材料；当前可见对象不构成其全部资源范围。

具体决定见[产品定位](../issues/01-first-product-loop.md)、[Agent 产品约束](../issues/02-agent-first-contract.md)、[领域模型](../issues/06-research-domain-boundaries.md)、[核心模型](../issues/17-native-research-capability-model.md)和[执行契约](../issues/18-native-capability-runtime-and-content.md)。

## 三个候选结构

### A：资源与编辑为默认入口

```text
项目／文献库切换                    搜索与命令     待处理
┌──────────────┬────────────────────────┬──────────────┐
│ 文献／材料树 │ PDF／稿件／矩阵标签页  │ Agent 交互   │
│ 集合与文件   │                        │ 当前任务摘要 │
│ 任务入口     │ 阅读和编辑             │ 材料与指令   │
├──────────────┴────────────────────────┴──────────────┤
│ 运行中工作 · 等待输入 · 待审查 · 失败与障碍          │
└─────────────────────────────────────────────────────┘
```

默认进入资源、阅读和编辑，Agent 交互在侧面；任务详情可从任务入口打开。便于连续精读和手工写作，监督多个 Agent 时需要主动展开任务视图。

### B：Agent 工作为默认入口

```text
项目／文献库切换                    搜索与命令     待处理
┌──────────────┬────────────────────────┬──────────────┐
│ 任务与执行者 │ 任务目标、计划与进展   │ 相关材料     │
│ 运行／待处理 │ Agent 会话与工具结果   │ PDF／稿件    │
│ 工作关系     │ 委派工作与交付         │ 产物预览     │
├──────────────┴────────────────────────┴──────────────┤
│ 当前任务材料与补充指令                              │
└─────────────────────────────────────────────────────┘
```

默认监督和推进 Agent 工作，材料在侧面预览；需要手工编辑时放大材料。适合长任务及并行研究，连续对照 PDF 与稿件时需要调整区域。

### C：任务与科研对象共用可分栏工作区

```text
项目／文献库切换                    搜索与命令     待处理
┌──────┬─────────────┬────────────────────────┬─────────┐
│ 导航 │ 资源或任务  │ 标签页：任务／PDF／稿件 │ Agent   │
│      │             ├────────────┬───────────┤ 快捷交互│
│      │             │ Agent工作页│ 稿件     │         │
│      │             │ 计划／执行 │ 手工编辑 │ 材料提示│
│      │             │ 会话／交付 │ 证据定位 │ 补充指令│
├──────┴─────────────┴────────────┴───────────┴─────────┤
│ 运行中工作 · 等待输入 · 待审查 · 失败与障碍          │
└─────────────────────────────────────────────────────┘
```

任务工作页与 PDF、稿件、文献矩阵、修订审查均可在中央区域打开和分栏。监督 Agent 时，工作页可以占满中央区域；阅读和写作时，材料可以占满中央区域。侧面保留快捷交互入口，完整 Agent 工作始终可以在中央展开。

同一任务工作页按需展示目标、研究计划、负责的 Agent、委派关系、实际进展、会话与交付。会话是一种交互视图；不要求把全部信息塞进一条聊天流，也不要求每个任务预设多个执行者。

各候选均使用共同内核事实；布局不会决定任务是否仍在执行、是否完成或谁拥有产物。图中面板位置和默认可见项只是候选。

## 第一轮讨论的问题

1. 默认组织选择 A、B、C 或混合，明确中央工作区可承载哪些工作。
2. 常用工作导航主要按任务、Agent 还是会话组织，任务页如何连接执行者与会话。
3. 用户切换阅读对象时，新的指令材料如何提示和携带，既有任务上下文如何保持可辨。
4. 修改审查主要按对象还是研究意图组织，如何同时呈现跨对象变更及局部差异。

这四项是 UI 取舍。任务持续存在、主动查询、版本冲突和授权规则已经决定，本轮不重新决定这些内核语义。

## 第一轮提出的具体交互

- 常用工作导航优先找持续任务。Agent 与会话也各有独立入口：Agent 视图可以查看和管理执行者、委派关系及其承担的工作；会话视图可以检索和重新打开交互记录。任务页关联这些视图，一位 Agent 服务多个任务、一项任务多次执行时，仍能辨认各自归属。
- 打开对象提供新指令的材料建议，可附加、固定或移除。发送前可见目标任务、材料与所选范围；Agent 实际读取按版本记录。切换标签页本身不提交新指令，也不改变既有授权与材料绑定。
- 任务材料可按授权主动查询。用户查看的对象、交给 Agent 的材料、Agent 已实际读取的材料分别可辨，避免把界面焦点当作全部上下文。
- 审查按研究目的或具体意见聚合相关修改，再逐项查看正文、图表、证据关系等差异。显示修改理由、依据、是否改变研究判断及待解决问题。
- 待审查修改与已获授权应用的修改分别显示。部分接受保留实际应用情况及剩余工作；整体完成沿用内核交付要求。冲突时可以对照依据版本、当前版本与候选修改。

## 后续细化

以下在首轮组织选择后继续讨论，尚未构成确认：导航与文献库独立使用；文献列表、阅读及元数据的默认组合；稳定日常操作与 Agent 指令的入口；分栏、停靠和常用布局；项目切换与后台待处理工作；原生/外部 Agent 及方法配置的呈现。

具体编辑格式、编辑器和 diff 实现由[阅读写作格式](../issues/11-reading-writing-format.md)与[技术栈](../issues/12-technology-stack.md)确定。数据读取、投影与高频更新需有界，具体机制由架构落实；文字线框不证明实际性能。

## 必须走查的情境

| 情境 | 需要看见和完成的操作 |
| --- | --- |
| 不打开项目，整理长期文献库 | 搜索、导入、集合与元数据操作；可以建立库任务并找到其结果 |
| 选定多篇文献开展分析，同时阅读 PDF | 找到批量进展与缺材料的部分，打开来源和比较结果，阅读焦点不改变批量任务 |
| Agent 综合文献并修订稿件，用户手工编辑同一稿件 | 稿件与任务可同时查看；旧基版本修改的冲突可以发现和处理 |
| 原创研究涉及数据、代码、图件及结果 | 可打开和交给 Agent 使用普通文件；计算进展、结果和支持关系可找到 |
| 审稿意见要求补充校核与改稿 | 将意见、补充结果、稿件修改和回复一起核对；尚未完成的工作保持可辨 |
| 整篇稿件与投稿材料的交付 | 找到各产物及整体交付要求，准备、审查与对外提交的实际状态分别可见 |
| 关闭会话或重新接入无工作台启动的任务 | 从持续任务及待处理入口找回目标、产物、实际进展与决定，按条件继续工作 |
